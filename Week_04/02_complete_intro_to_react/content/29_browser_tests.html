Browser Tests

🚨 สิ่งนี้เป็น experimental และมีแนวโน้มสูงที่จะเปลี่ยนในอนาคต ให้ถือว่านี่เป็น sneak peak ของสิ่งที่จะมา ไม่ใช่สิ่งที่ควรทำในวันนี้

Vitest กำลังเริ่มรองรับ browser-based testing ที่ลึกขึ้น สำหรับพวกเราที่อยู่มานานพอจะจำ Selenium ได้ สิ่งนี้อาจทำให้หวาดกลัวถึงใจ แต่ไม่ต้องกลัว! Browser-based testing tools พัฒนาไปไกลมากตั้งแต่นั้น จนทั้งเร็วและเชื่อถือได้ โดยเฉพาะเพราะ Microsoft project Playwright

อย่างไรก็ตามนี่ก็ยังเป็นช่วงแรก ๆ ฉันจะสาธิตวิธีตั้งค่าให้ดู แต่ระวังว่ามันอาจเปลี่ยนได้ เพราะพวกเขายังทำงานกับมันอย่างแข็งขัน!

ดังนั้นก่อนอื่นมาติดตั้ง libraries ที่ต้องใช้

npm i -D @vitest/browser@2.1.3 playwright@1.48.0 vitest-browser-react@0.0.1

คุณเห็นว่า vitest-browser-react library ยังเป็น 0.0.1 ณ เวลาที่เขียน จึงระวังเป็นพิเศษว่ามันน่าจะเปลี่ยนไปเมื่อคุณอ่านสิ่งนี้

โอเค ตอนนี้เราอยากเขียน browser based tests แต่เราก็มี Node.js-based tests อยู่เดิมจำนวนมาก บาง Node.js based tests ที่มีอยู่แล้วจะใช้ใน browser ไม่ได้ แต่ไม่ต้องห่วง Vitest/Vite มี tool สำหรับสิ่งนี้พอดี คือ workspaces จริง ๆ มันสร้างมาเพื่อจัดการ monorepos แต่ใช้ที่นี่ได้ดีพอกัน สร้าง file ชื่อ vitest.workspace.js (ปกติไม่ต้องใช้ เพราะ Vite config ของคุณปกติก็พอ)

import { defineWorkspace } from "vitest/config";

export default defineWorkspace([
  {
    extends: "./vite.config.js",
    test: {
      include: ["**/*.node.test.{js,jsx}"],
      name: "happy-dom",
      environment: "happy-dom",
    },
  },
  {
    extends: "./vite.config.js",
    test: {
      setupFiles: ["vitest-browser-react"],
      include: ["**/*.browser.test.{js,jsx}"],
      name: "browser",
      browser: {
        provider: "playwright",
        enabled: true,
        name: "firefox", // you can use chromium or webkit here too
      },
    },
  },
]);

ตอนนี้ลบ test items ออกจาก vite.config.js file ของคุณ

นี่คือ test-only config สำหรับ Vite (และจึงสำหรับ Vitest) ตอนนี้หาก test ลงท้ายด้วย .node.test.jsx มันจะ run ผ่าน happy-dom based environment และถ้าลงท้ายด้วย .browser.test.jsx มันจะ run ใน browser-based environment ใหม่ของเราพร้อม Playwright ไป rename tests ของเราให้สะท้อนสิ่งนี้กัน

Snapshotting ทำงานใน browser ดังนั้นอันนั้นใช้ได้ Anything ที่ใช้ vitest-fetch-mock เป็น Node.js only ดังนั้นสำหรับสิ่งเหล่านั้นเราต้องกำกับว่า node เราจะสร้าง Pizza file ใหม่ จึงปล่อยอันนั้นไว้ และ custom hook test ของเรา mock fetch ดังนั้นเป็น Node only

โอเค ตอนนี้สร้าง Pizza.browser.test.jsx

import { render } from "vitest-browser-react";
import { expect, test } from "vitest";
import Pizza from "../Pizza";

test("alt text renders on image", async () => {
  const name = "My Favorite Pizza";
  const src = "https://picsum.photos/200";
  const screen = render(
    <Pizza name={name} description="super cool pizza" image={src} />
  );

  const img = await screen.getByRole("img");

  await expect.element(img).toBeInTheDocument();
  await expect.element(img).toHaveAttribute("src", src);
  await expect.element(img).toHaveAttribute("alt", name);
});
  • render จะรับ React component แล้ว render มันในสุญญากาศ จากนั้นคุณ poke และ prod มันได้ตามต้องการเพื่อ test
  • ส่วนสำคัญมากของสิ่งที่ Playwright และ vitest-browser-react อยากให้คุณทำคืออย่า test implementation details แต่ให้ test user experiences จริง อย่า test internal state ของ React component แต่ test สิ่งที่ผู้ใช้จะเห็นและสัมผัส ด้วยเหตุนี้ สิ่งที่เราจะ test จำนวนมากจึงอยู่รอบ roles, attributes เป็นต้น
  • @testing-library มี document ดี ๆ ว่าทำไมพวกเขาเลือกทดสอบแบบนี้
  • โดยทั่วไป vitest-browser-react มุ่งเป็น drop in replacement สำหรับ @testing-library/react

ดูคล้ายมากใช่ไหม? โอเค มารันมัน npm run test คุณควรเห็น Vitest UI เดิม แต่ตอนนี้บาง tests กำลัง run ใน browser จริง

มันน่าจะ prompt ให้คุณรัน command อย่าง npx playwright install คุณจะติดตั้ง local copies ของ browsers เพื่อให้รันได้เร็วมาก

เจ๋งใช่ไหม และเร็วจริง ๆ! มาทำอีกอัน สร้าง Header.jsx test เราจะ test ว่า cart number ถูกต้อง จำได้ไหมที่ Facebook notification numbers ผิดตลอด? เราจะทำให้แน่ใจว่าสิ่งนั้นไม่เกิดกับ cart indicator ของเรา ใน Header.jsx file ของคุณ:

data-testid="cart-number" // add to .nav-cart-number

ตอนนี้สร้าง Header.browser.test.jsx

import { render } from "vitest-browser-react";
import { expect, test } from "vitest";
import Header from "../Header";
import {
  RouterProvider,
  createRouter,
  createRootRoute,
} from "@tanstack/react-router";
import { CartContext } from "../contexts";

test("correctly renders a header with a zero cart count", async () => {
  const rootRoute = createRootRoute({
    component: () => (
      <CartContext.Provider value={[[]]}>
        <Header />
      </CartContext.Provider>
    ),
  });

  const router = createRouter({ routeTree: rootRoute });
  const screen = render(<RouterProvider router={router}></RouterProvider>);

  const itemsInCart = await screen.getByTestId("cart-number");

  await expect.element(itemsInCart).toBeInTheDocument();
  await expect.element(itemsInCart).toHaveTextContent("0");
});

test("correctly renders a header with a three cart count", async () => {
  const rootRoute = createRootRoute({
    component: () => (
      <CartContext.Provider
        value={[[{ pizza: 1 }, { pizza: 2 }, { pizza: 3 }]]}
      >
        <Header />
      </CartContext.Provider>
    ),
  });

  const router = createRouter({ routeTree: rootRoute });
  const screen = render(<RouterProvider router={router}></RouterProvider>);

  const itemsInCart = await screen.getByTestId("cart-number");

  await expect.element(itemsInCart).toBeInTheDocument();
  await expect.element(itemsInCart).toHaveTextContent("3");
});

เราต้องโค้งตัวไปข้างหลังสักหน่อยเพื่อให้ TanStack Router มีความสุข จึงมีการสร้าง root routes ทั้งหมดนั้น จำไว้ด้วยว่า cart ของเราได้ cart จาก context จึงต้องส่งมันเข้าแบบนั้น นอกเหนือจากนั้น มันทำงานคล้ายกันมาก!

อีกครั้ง นี่เป็นช่วงแรก ๆ ของ browser-based testing ด้วย Vite ดังนั้นใน professional settings ของคุณให้ทำด้วยความระมัดระวัง อย่างไรก็ตามอนาคตสดใสด้วย Playwright!

🚨 หมายเหตุ: หากต้องการเพิ่ม code coverage กลับเข้า project คุณต้องใช้ Istanbul เพราะ ณ เวลาที่บันทึกนี้ React 19 ไม่รองรับสิ่งนี้กับ V8

ก่อนอื่น คุณต้อง uninstall V8 และ install Istanbul:

npm uninstall @vitest/coverage-v8@2.1.3
npm install -D @vitest/istanbul

หมายเหตุผู้แปล: สำหรับ Vitest 2 ชื่อ package ที่ใช้งานได้คือ @vitest/coverage-istanbul; ให้รัน npm install -D @vitest/coverage-istanbul แทนคำสั่ง install ในตัวอย่างต้นฉบับ

จากนั้นย้าย coverage configuration ไปยัง vitest.workspace.js file:


export default defineWorkspace([
  {
    extends: "./vite.config.js",
    test: {
      // ...
      // add to the end of the happy-dom test object 
      coverage: {
        provider: "istanbul"
        reporter: ["text", "json", "html"],
      },
    },
  },
  {
    extends: "./vite.config.js",
    test: {
      // ...
      // add to the end of the browser test object 
      coverage: {
        reporter: ["text", "json", "html"],
      },
    },
  },
]);

หมายเหตุผู้แปล: ตัวอย่างต้นฉบับขาด comma หลัง provider: "istanbul"; เพิ่ม comma ก่อนนำไป run เพื่อให้ JavaScript ใช้งานได้
