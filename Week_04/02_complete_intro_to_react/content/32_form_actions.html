Form Actions ใน React 19

Form Actions

แอปของเรารันบน React 19 อยู่แล้วตั้งแต่บทที่ 8 เราจึงใช้ฟีเจอร์ในบทนี้ได้ทันที ไม่ต้องติดตั้งหรืออัปเกรดอะไรเพิ่ม

มาคุยเรื่อง form actions กัน web interfaces จำนวนมากคือการจัดการ form inputs ดังนั้นทีม React จึงตัดสินใจทำให้เรื่องนี้ง่ายขึ้น จริง ๆ คล้ายสิ่งที่เราทำไปแล้ว เพียงมี boilerplate น้อยกว่า เปิด contact.lazy.tsx แล้วปรับหน้านี้ให้ใช้ form action

mutationFn: function (formData: FormData) { // change to formData
  // remove e.preventDefault
  // remove formData constructor
  return postContact(
    String(formData.get("name")),
    String(formData.get("email")),
    String(formData.get("message")),
  );
},

// change onSubmit to action
<form action={mutation.mutate}>

เท่านั้นเอง! มันเป็น convenience function ที่ทำให้จัดการ submits ได้ง่ายขึ้น ไม่มีอะไรผิดกับวิธีเดิมของเรา และมันจะยังทำงานเหมือนเดิมต่อไป

สังเกตว่า type ของ parameter เปลี่ยนจาก React.FormEvent<HTMLFormElement> เป็น FormData เฉย ๆ นี่คือสิ่งที่ form action ทำให้เรา — React จัดการ event, กัน default behavior และสร้าง FormData ให้เสร็จสรรพ แล้วส่งเฉพาะสิ่งที่เราต้องการจริง ๆ เข้ามา การที่ type สั้นลงจึงสะท้อนว่าโค้ดเราทำงานน้อยลงจริง ๆ

ส่วน String(...) ยังต้องอยู่เหมือนเดิม เพราะ formData.get() ก็ยังคืน string | File | null อยู่ดี — form action ช่วยเรื่องการต่อสายกับ form แต่ไม่ได้รับประกันว่าในนั้นมีอะไร (ย้อนดูบทที่ 22 ถ้าอยากทบทวนว่าทำไม)

มาแปลง order.lazy.tsx ด้วย

// extract submission function from form
function addToCart() {
  if (!selectedPizza) return;
  setCart([...cart, { pizza: selectedPizza, size: pizzaSize, price }]);
}
// update to action
<form action={addToCart}>[…]</form>;

เหมือนด้านบน แต่ที่เจ๋งคือ หากใช้บางอย่างเช่น Next.js หรือ Remix เราใช้ directive 'use server' ตรงนี้และทำให้เป็น server action ได้ เช่น

function addToCart(formData: FormData) {
  "use server";
  sql(`INSERT INTO cart (user_id, pizza_type, size) VALUES ($1, $2)`, [
    formData.get("pizza_type"),
    formData.get("size"),
  ]);
}

หมายเหตุผู้แปล: ตัวอย่างต้นฉบับเขียน formData.pizza_type ซึ่งใช้ไม่ได้จริง เพราะ FormData ไม่ใช่ object ธรรมดา ต้องอ่านค่าผ่านเมธอด .get() เสมอ — พอเราใส่ type FormData ให้ parameter แล้ว TypeScript ก็ฟ้องข้อผิดพลาดนี้ให้ทันที ทั้งที่มันหลุดรอดมาในเวอร์ชัน JavaScript ได้สบาย ๆ

เพราะมันอยู่บน server เราจึง insert เข้า database ได้อย่างปลอดภัย จากภายใน React component โดยตรง React/Next.js จะจัดการรายละเอียดทั้งหมดของการ execute บน server ให้ เจ๋งใช่ไหม? นี่เป็นเรื่องของ React ฝั่ง server ซึ่งอยู่นอกขอบเขตคอร์สนี้

มาทำอีก trick ที่เจ๋งกัน มี hook ใหม่ชื่อ useFormStatus ที่ให้ children components รู้ว่าตัวเองอยู่ใน form ที่กำลัง submit อยู่หรือไม่ โดยไม่ต้องส่งข้อมูลจำนวนมากไปมา

ใน contact.lazy.tsx

// at top
import { useFormStatus } from "react-dom"; // note react-dom, not react

// replace the two inputs
<ContactInput name="name" type="text" placeholder="Name" />
<ContactInput name="email" type="email" placeholder="Email" />

// at the bottom
type ContactInputProps = {
  name: string;
  type: React.HTMLInputTypeAttribute;
  placeholder: string;
};

function ContactInput(props: ContactInputProps) {
  const { pending } = useFormStatus();
  return (
    <input
      disabled={pending}
      name={props.name}
      type={props.type}
      placeholder={props.placeholder}
    />
  );
}

React.HTMLInputTypeAttribute คือ union ของค่า type ที่ <input> รับได้จริงทั้งหมด ("text", "email", "password", "checkbox" …) เราจะเขียน type: string เฉย ๆ ก็ได้ แต่การใช้ตัวนี้ทำให้ <ContactInput type="emial" /> ที่พิมพ์ผิดถูกจับได้ และได้ auto-complete รายชื่อ type ทั้งหมดมาให้เลือกด้วย

นี่เป็นนิสัยที่ดีเวลาเขียน component ที่ห่อ HTML element: ลองหาดูก่อนว่า React มี type สำเร็จรูปให้อยู่แล้วหรือเปล่า ก่อนจะเขียน string กว้าง ๆ ไปเอง วิธีหาที่ง่ายที่สุดคือกด Ctrl (หรือ Cmd) แล้วคลิกที่ prop type บน <input> ธรรมดาใน editor เพื่อกระโดดเข้าไปดู type จริงของมัน

💡 ถ้า component ของคุณต้องรับ prop ของ <input> หลายตัวจนเขียนไม่ไหว มีทางลัดที่นิยมกันมากคือ type ContactInputProps = React.ComponentProps<"input"> ซึ่งจะได้ prop ทั้งหมดของ <input> มาในทีเดียว แล้วส่งต่อด้วย <input {...props} disabled={pending} /> ลองดูเป็นแบบฝึกหัดได้

  • นี่เป็นตัวอย่างง่าย ๆ แต่ลองนึกภาพว่า inputs ของคุณซับซ้อนมาก มี design system, tool tips และ UI อื่น ๆ อีกมาก ซึ่งพบได้บ่อยใน React codebases ขนาดใหญ่ สิ่งนี้อาจมีประโยชน์มาก
  • อีกอย่าง ถ้ามี component เล็กมากอย่าง ContactInput การเก็บไว้ใน file เดียวกันแบบที่ทำตรงนี้ก็เป็น pattern ที่ใช้ได้ บางคนเคร่งครัดกับกฎ one file, one component แต่มันไม่ใช่กฎตายตัว
  • เราไม่ได้ทำ button หรือ text area เพื่อความกระชับ แต่คุณทำได้
  • เพราะเรารันใน local pending state จะสั้นมาก แต่คุณจะสังเกตเห็น background กระพริบเป็นสีเทา นั่นคือ disabled state

และนั่นคือ form actions!
