การทดสอบด้วย Vitest

Vitest

เนื้อหานี้ตั้งใจให้เป็นบทความสั้นมากว่าด้วยวิธีทำ testing กับ React applications นี่จะเป็นบทนำสั้น ๆ ว่าจะตั้งค่า Vitest tests สำหรับแอปพลิเคชันที่เราเพิ่งสร้างอย่างไร สำหรับข้อมูลเพิ่มเติมเกี่ยวกับ Vite, Vitest และการทดสอบโดยทั่วไป ดู Build Tools & Testing Learning Path

Testing with Vitest

Vitest คือ test runner ที่สร้างโดยทีมชั้นยอดผู้สร้าง Vite (รวมถึง Vue) แนวคิดเบื้องหลัง Vitest คือคุณมี build pipeline ที่สมบูรณ์สำหรับสร้างแอปอยู่แล้ว แล้วทำไม pipeline นั้นจึงควรต่างออกไปสำหรับ test? มันไม่ควรต่างกัน; คุณอยากให้ testing environment เหมือน app environment ของคุณมากที่สุดเท่าที่ทำได้

พวกเขาออกแบบมันให้เป็นตัวแทนแบบเสียบแทนได้เลยของ Jest ซึ่งเป็นสิ่งที่ฉันสอนในคอร์สนี้มาตั้งแต่ต้น Jest เยี่ยมมากและยังเป็นเครื่องมือที่ใช้งานได้ดีมากสำหรับ testing แม้ใช้กับ Vite เราจะใช้ Vitest เพราะ 1. เราไม่ต้องตั้งค่าเพิ่มอีก และ 2. 100% ของสิ่งที่คุณจะเรียนที่นี่มีประโยชน์หากคุณใช้ Jest เช่นกัน ชนะทั้งคู่ ถ้าอยากเรียน Jest โดยเฉพาะ ลองดูส่วน testing ของ Intermediate React v4

เกร็ดสนุก: Jest เป็นโครงการของ OpenJS แล้ว และไม่ได้อยู่ภายใต้ Facebook โดยตรงอีกต่อไป

แม้ Vitest จะไม่ได้ใช้ Jasmine โดยตรง แต่ APIs ของมันเลียนแบบ Jasmine APIs (เช่นเดียวกับ Jest)

เริ่มกันเลย รัน npm install -D vitest@2.1.3 @testing-library/react@16.0.1 happy-dom@15.7.4

@testing-library/react ที่เคยชื่อ react-testing-library คือเครื่องมือที่มี convenience features มากมายซึ่งทำให้ testing React ง่ายขึ้นอย่างมาก และปัจจุบันเป็นวิธีที่แนะนำสำหรับ testing React โดยเข้ามาแทนที่ Enzyme เวอร์ชันก่อนหน้าของคอร์สนี้สอน Enzyme ถ้าคุณอยากดู (แม้ฉันจะไม่แนะนำ เว้นแต่จำเป็น)

เราต้องบอก Vitest ว่าต้องการ environment คล้าย browser ซึ่งมันจะทำให้ผ่าน package happy-dom happy-dom คล้าย jsdom มาก แต่เล็กกว่า ไม่ได้ทำ 100% ของสิ่งที่ browser ทำ และเร็วกว่า มาก

ต่อไปเข้าไปใน src directory แล้วสร้าง folder ชื่อ __tests__ สังเกตว่ามี underscores สองตัวทั้งสองด้าน ทำไมสองตัว? พวกเขายืมมาจาก Python ที่ double underscores (ที่ฉันเคยได้ยินเรียกว่า “dunders”) หมายความว่าจะมี magic เกิดขึ้น (โดยแก่นคือชื่อมีความสำคัญในตัวเอง และมีบางสิ่งกำลังมองหา path name นั้นตรงตัว) ในกรณีนี้ Vitest สมมติว่า JS files ทั้งหมดในนี้เป็น tests

ไปเพิ่ม npm script กัน ใน package.json ของคุณ

"test": "vitest"

ทริกสนุก: ถ้าคุณเรียกมันว่า test, npm ให้คุณรัน command นั้นเป็นเพียง npm t

command นี้ให้คุณรัน Vitest ใน interactive mode ซึ่งจะ re-run tests แบบเลือกเฉพาะเมื่อคุณ save นั่นทำให้คุณได้ instant feedback ว่า test ทำงานหรือไม่ นี่น่าจะเป็น feature ที่ฉันชอบที่สุดของ Vitest

โอเค มี configuration เล็กน้อยอย่างหนึ่งที่ต้องเพิ่มใน vite.config.js ของคุณ

// add this to the config object
test: {
  environment: "happy-dom",
},

ตอนนี้เราตั้งค่านี้แล้ว ไปเขียน test กัน
