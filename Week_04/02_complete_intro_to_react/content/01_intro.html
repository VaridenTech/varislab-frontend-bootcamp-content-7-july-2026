บทเรียน 01 · ยินดีต้อนรับ (Welcome)

บทนำ: React คืออะไร และทำไมต้องใช้

Intro

ก่อนจะลงมือเขียนโค้ดบรรทัดแรก เรามาทำความเข้าใจกันก่อนว่า React คืออะไร มันเกิดมาเพื่อแก้ปัญหาอะไร และทำไมมันถึงกลายเป็นเครื่องมือที่ทีมส่วนใหญ่เลือกใช้สร้างหน้าเว็บในปัจจุบัน เมื่อคุณเข้าใจ “ทำไม” แล้ว การเรียน “อย่างไร” ในบทต่อ ๆ ไปจะง่ายขึ้นมาก

React คืออะไร

React คือ ไลบรารี JavaScript สำหรับสร้างส่วนติดต่อผู้ใช้ (User Interface) พูดง่าย ๆ คือมันมีหน้าที่เดียว: รับข้อมูลของคุณเข้าไป แล้วแสดงผลออกมาเป็นหน้าจอ และคอยอัปเดตหน้าจอนั้นให้ตรงกับข้อมูลเสมอ

สังเกตคำว่า “ไลบรารี” ไม่ใช่ “เฟรมเวิร์ก” React ไม่ได้บังคับว่าคุณต้องจัดโครงสร้างโฟลเดอร์อย่างไร ต้องเรียก API ด้วยอะไร หรือต้องจัดการ routing แบบไหน มันสนใจแค่เรื่องการแสดงผล UI ส่วนที่เหลือคุณเลือกเองได้ — ซึ่งเป็นทั้งข้อดี (ยืดหยุ่นมาก) และข้อเสีย (ต้องตัดสินใจเองเยอะ) และนี่คือเหตุผลที่หลักสูตรนี้จะพาคุณประกอบเครื่องมือรอบ ๆ React ทีละชิ้นด้วยตัวเอง

สามคำที่อธิบาย React ได้ครบที่สุดคือ:

  • Component-based — เราแบ่ง UI ออกเป็นชิ้นเล็ก ๆ ที่ทำงานได้ด้วยตัวเอง แล้วนำมาประกอบกันเป็นหน้าจอใหญ่ เหมือนต่อเลโก้
  • Declarative — เราบอกว่า “หน้าจอควรมีหน้าตาแบบไหนเมื่อข้อมูลเป็นแบบนี้” แล้ว React จัดการเปลี่ยนหน้าจอให้เอง เราไม่ต้องสั่งทีละขั้นว่าให้ไปแก้ element ไหน
  • Learn once, write anywhere — แนวคิดเดียวกันนี้ใช้เขียนเว็บ (React DOM) แอปมือถือ (React Native) หรือแม้แต่แสดงผลบนเซิร์ฟเวอร์ได้

ปัญหาที่ React เข้ามาแก้

ลองนึกถึงการเขียน JavaScript ล้วน ๆ เพื่อทำปุ่มนับจำนวนคลิก ที่ต้องหยุดทำงานเมื่อครบ 10 ครั้ง

const button = document.getElementById("btn");
const label = document.getElementById("count");
let count = 0;

button.addEventListener("click", () => {
  count = count + 1;
  label.textContent = `คลิกไปแล้ว ${count} ครั้ง`;
  button.disabled = count >= 10;
});

โค้ดนี้ทำงานได้ แต่สังเกตให้ดี: ทุกครั้งที่ count เปลี่ยน เรา ต้องเป็นคนไล่สั่งเองว่าต้องไปแก้ label.textContent และ button.disabled เราต้องจำเองว่ามีที่ไหนบ้างบนหน้าจอที่พึ่งพาข้อมูลตัวนี้ วิธีเขียนแบบนี้เรียกว่า imperative (สั่งการทีละขั้น)

ตราบใดที่หน้าจอมีแค่สองจุด มันก็ยังไหว แต่แอปจริงมีข้อมูลหลายสิบตัวและจุดที่ต้องอัปเดตหลายร้อยจุด ปัญหาที่ตามมาคือ:

  • เพิ่มที่แสดงผลใหม่หนึ่งจุด แต่ลืมไปอัปเดตมันตอนข้อมูลเปลี่ยน → หน้าจอแสดงข้อมูลเก่า
  • ข้อมูลจริงกระจายอยู่ในตัวแปร JavaScript บ้าง อยู่ใน DOM บ้าง จนไม่รู้ว่าอันไหนคือความจริง
  • โค้ดผูกติดกับ id และโครงสร้าง HTML จนแก้ดีไซน์ทีไรก็พังทุกที

React แก้ปัญหานี้ด้วยการกลับด้านความรับผิดชอบ คุณมีหน้าที่แค่ประกาศว่า “ข้อมูลตอนนี้เป็นแบบนี้ หน้าจอต้องออกมาแบบนี้” ส่วนงานไล่แก้ DOM ให้ตรงกันเป็นหน้าที่ของ React

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>คลิกไปแล้ว {count} ครั้ง</p>
      <button onClick={() => setCount(count + 1)} disabled={count >= 10}>
        คลิก
      </button>
    </div>
  );
}

ในโค้ดนี้ไม่มีบรรทัดไหนสั่งแก้ข้อความหรือสั่งปิดปุ่มเลย มีแค่การบอกว่า “ข้อความคือค่านี้” และ “ปุ่มจะถูกปิดเมื่อเงื่อนไขนี้เป็นจริง” เมื่อ count เปลี่ยน React จะคำนวณหน้าจอใหม่แล้วไปแก้เฉพาะส่วนที่ต่างจากเดิมให้เอง นี่คือวิธีเขียนแบบ declarative (ประกาศผลลัพธ์)

💡 สูตรที่สรุปหัวใจของ React ได้ดีที่สุดคือ UI = f(state) — หน้าจอคือผลลัพธ์ของฟังก์ชันที่รับ state เข้าไป ถ้าอยากเปลี่ยนหน้าจอ ให้เปลี่ยน state ไม่ใช่ไปแก้หน้าจอตรง ๆ ถ้าคุณจำได้แค่ประโยคเดียวจากบทนี้ ขอให้เป็นประโยคนี้

แนวคิดหลักสามอย่าง

เนื้อหาเกือบทั้งหมดของหลักสูตรนี้จะวนอยู่รอบ ๆ สามคำนี้ ตอนนี้แค่รู้จักชื่อไว้ก่อนก็พอ เดี๋ยวเราจะลงรายละเอียดทีละอัน

  • Component — ฟังก์ชัน JavaScript ที่คืนค่าออกมาเป็นหน้าตาของ UI ชิ้นหนึ่ง เช่น ปุ่ม การ์ดสินค้า หรือทั้งหน้า ใช้ซ้ำได้ ซ้อนกันได้
  • Props — ข้อมูลที่ component แม่ส่งลงไปให้ component ลูก ทำให้ component เดียวกันแสดงผลต่างกันได้ตามข้อมูลที่ได้รับ
  • State — ข้อมูลที่เปลี่ยนแปลงได้ภายใน component เมื่อ state เปลี่ยน React จะ render หน้าจอส่วนนั้นใหม่ให้อัตโนมัติ

ทำไมเราจึงควรใช้ React

  • UI ที่คาดเดาได้ — เมื่อหน้าจอถูกกำหนดจาก state เพียงแหล่งเดียว การหาสาเหตุของบั๊กจะง่ายขึ้นมาก เพราะคำถามเหลือแค่ “ตอนนี้ state เป็นอะไร”
  • นำโค้ดกลับมาใช้ซ้ำได้จริง — component หนึ่งตัวใช้ได้ทั้งแอป แก้ที่เดียวเปลี่ยนทุกที่ ต่างจากการก็อป HTML ไปวางหลายหน้า
  • ระบบนิเวศที่ใหญ่มาก — routing, การดึงข้อมูล, ฟอร์ม, ตาราง, animation, การทดสอบ ล้วนมีไลบรารีที่โตเต็มที่รองรับ (เราจะได้ใช้ TanStack Router, TanStack Query และ Vitest ในหลักสูตรนี้)
  • ชุมชนและตำแหน่งงาน — React เป็นไลบรารี UI ที่มีคนใช้มากที่สุดในตลาด ปัญหาที่คุณเจอมักมีคนเจอและตอบไว้แล้ว และทักษะนี้เป็นที่ต้องการสูงในงานสาย frontend
  • ค่อย ๆ นำไปใช้ได้ — ไม่จำเป็นต้องเขียนใหม่ทั้งเว็บ คุณเอา React ไปใช้แค่บางส่วนของหน้าเว็บเดิมได้
  • ต่อยอดไปมือถือได้ — ความรู้ชุดเดียวกันนี้ใช้กับ React Native เพื่อสร้างแอป iOS และ Android ได้

แล้วเมื่อไหร่ที่ยังไม่ต้องใช้ React

React ไม่ใช่คำตอบของทุกอย่าง ถ้างานของคุณเป็นเว็บที่เนื้อหาเกือบทั้งหมดเป็นข้อความคงที่ มีการโต้ตอบน้อยมาก หรือเป็นหน้า landing page ธรรมดา การใช้ HTML กับ JavaScript เล็ก ๆ น้อย ๆ จะเบากว่าและเร็วกว่ามาก React จะเริ่มคุ้มค่าเมื่อ UI ของคุณมี สถานะ ที่เปลี่ยนไปมาเยอะ เช่น ฟอร์มหลายขั้นตอน แดชบอร์ด ตะกร้าสินค้า หรือหน้าจอที่ข้อมูลอัปเดตตลอดเวลา

🚨 อย่ารู้สึกผิดถ้าเลือกไม่ใช้ React การรู้ว่าเครื่องมือหนึ่งเหมาะกับงานแบบไหน มีค่าพอ ๆ กับการใช้มันเป็น

หลักสูตรนี้เหมาะกับใคร และคุณจะได้อะไร

หลักสูตรนี้เริ่มจากศูนย์ ไม่จำเป็นต้องมีประสบการณ์ React มาก่อน แต่ควรพอเขียน JavaScript พื้นฐานได้ — รู้จักตัวแปร ฟังก์ชัน array และ object (ถ้ายังไม่มั่นใจ ให้ย้อนกลับไปทบทวนบทเรียน JavaScript พื้นฐานก่อน) เราจะใช้ Node.js บ้างเพื่อรัน API เล็ก ๆ และเครื่องมือ build แต่ไม่ต้องมีความรู้ Node.js เชิงลึก คำสั่งที่ต้องใช้จะมีให้ครบ

เราจะเรียนแบบ เริ่มจากหลักการพื้นฐาน คือเริ่มด้วย React ล้วน ๆ ที่ไม่มีเครื่องมือ build ใด ๆ เลย เพื่อให้เห็นว่าจริง ๆ แล้ว React ทำงานอย่างไร จากนั้นค่อย ๆ เพิ่มเครื่องมือทีละชิ้น — npm, Prettier, ESLint, Git, Vite, JSX — จนได้ stack ที่คุณประกอบขึ้นมาเองและเข้าใจทุกชิ้นส่วน แล้วจึงต่อด้วยแนวคิดหลักอย่าง hooks, effects, context การจัดการฟอร์ม การทดสอบ ไปจนถึงความสามารถใหม่ ๆ ใน React 19 และการนำแอปขึ้นใช้งานจริง

พร้อมแล้วก็ไปเขียน React ตัวแรกของคุณกันเลย โดยเริ่มจากหน้าเว็บเปล่า ๆ ที่ไม่ต้องติดตั้งอะไรมากไปกว่าเบราว์เซอร์และ editor
