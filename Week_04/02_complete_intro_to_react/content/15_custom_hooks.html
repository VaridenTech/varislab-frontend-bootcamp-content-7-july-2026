Custom Hooks

Custom Hooks

สิ่งหนึ่งที่พิเศษมากเกี่ยวกับ hooks คือ composability ของมัน คุณใช้ hooks เพื่อสร้าง hooks อื่นได้! คนมักเรียกสิ่งเหล่านี้ว่า custom hooks มีคนถึงขั้นบอกว่า “อย่าทำ API request ใน component ให้ทำใน hook เสมอ” จะสุดทางขนาดนั้นหรือไม่ก็แล้วแต่คน แต่เหตุผลของมันฟังขึ้น หากคุณทำ custom hook สำหรับเรื่องแบบนั้น มันจะทดสอบแยกกันได้ และแยกการแสดง data ออกจาก logic ที่ใช้รับ data ได้ดี คำแนะนำกลาง ๆ คือสร้าง custom hooks สำหรับ logic ที่ซับซ้อนหรือใช้ซ้ำได้ ส่วนกรณีง่าย ๆ ก็ปล่อยให้มันง่ายไว้

โอเค เราต้องการเพิ่ม banner “Pizza of the Day” ที่ท้ายหน้า นี่ทำให้ต้องเรียก API พิเศษเพื่อเอา pizza of the day (ซึ่งควรเปลี่ยนทุกวันตามเวลาของคอมพิวเตอร์คุณ) ก่อนอื่นมาเขียน component ที่จะใช้มัน

สร้างไฟล์ชื่อ PizzaOfTheDay.tsx

import { usePizzaOfTheDay } from "./usePizzaOfTheDay";

// feel free to change en-US / USD to your locale
const intl = new Intl.NumberFormat("en-US", {
  style: "currency",
  currency: "USD",
});

const PizzaOfTheDay = () => {
  const pizzaOfTheDay = usePizzaOfTheDay();

  if (!pizzaOfTheDay) {
    return <div>Loading...</div>;
  }

  return (
    <div className="pizza-of-the-day">
      <h2>Pizza of the Day</h2>
      <div>
        <div className="pizza-of-the-day-info">
          <h3>{pizzaOfTheDay.name}</h3>
          <p>{pizzaOfTheDay.description}</p>
          <p className="pizza-of-the-day-price">
            From: <span>{intl.format(pizzaOfTheDay.sizes.S)}</span>
          </p>
        </div>
        <img
          className="pizza-of-the-day-image"
          src={pizzaOfTheDay.image}
          alt={pizzaOfTheDay.name}
        />
      </div>
    </div>
  );
};

export default PizzaOfTheDay;
  • ส่วนเจ๋งคือ usePizzaOfTheDay() ตอนนี้เราเพียงเชื่อใจได้ว่าสิ่งนี้จะให้ pizza of the day จากการทำงานภายใน black box ของ hook
  • สังเกตว่าเราไม่ได้เขียน type ให้ pizzaOfTheDay ตรงนี้เลย แต่ pizzaOfTheDay.sizes.S ยังมี auto-complete ครบ นั่นเพราะ TypeScript ดึง type มาจากสิ่งที่ hook คืนกลับมาให้เอง — เราเขียน type ไว้ที่เดียวคือในตัว hook แล้วทุกที่ที่เรียกใช้ก็ได้ประโยชน์ตาม
  • บรรทัด if (!pizzaOfTheDay) return <div>Loading...</div> ที่มีอยู่แล้วในโค้ดข้างบนกลายเป็นสิ่งที่ จำเป็น ไปด้วย ไม่ใช่แค่ทางเลือก เพราะ hook คืน Pizza | null ถ้าลบบรรทัดนั้นออก TypeScript จะฟ้องทุกบรรทัดที่แตะ pizzaOfTheDay. ทันที

โอเค มาสร้าง hook กัน! สร้างไฟล์ชื่อ usePizzaOfTheDay.ts

คราวนี้เป็น .ts ไม่ใช่ .tsx เพราะไฟล์นี้ไม่มี JSX อยู่เลย มันมีแต่ logic ล้วน ๆ นี่คือกฎที่ตรงไปตรงมาและคอร์สนี้จะใช้ตลอด: มี JSX ใช้ .tsx ไม่มี JSX ใช้ .ts ต่างจากตอนเขียน JavaScript ที่หลายโปรเจกต์ตั้ง .jsx ให้ทุกไฟล์ที่ "เกี่ยวกับ React" ไปเลย — ใน TypeScript ทำแบบนั้นไม่ค่อยดี เพราะในไฟล์ .tsx ไวยากรณ์ <T> สำหรับ generic จะชนกับ JSX tag ทำให้ต้องเขียนอ้อมโดยไม่จำเป็น
import { useState, useEffect } from "react";
import type { Pizza } from "./types";

export const usePizzaOfTheDay = () => {
  const [pizzaOfTheDay, setPizzaOfTheDay] = useState<Pizza | null>(null);

  useEffect(() => {
    async function fetchPizzaOfTheDay() {
      const response = await fetch("/api/pizza-of-the-day");
      const data: Pizza = await response.json();
      setPizzaOfTheDay(data);
    }

    fetchPizzaOfTheDay();
  }, []);

  return pizzaOfTheDay;
};
  • นี่ดูเหมือนสิ่งที่คุณจะเห็นตอนบนของ component ใช่ไหม? ตอนนี้มันถูกห่อเป็น hook จึงทดสอบด้วยตัวเองได้ง่าย! 🎉
  • เราใช้ useState, useEffect หรือ hook ใด ๆ ที่ต้องการที่นี่ได้! เรายังใช้ custom hooks อื่นได้ด้วย!
  • useState<Pizza | null>(null) เป็นอีกกรณีที่ generic จำเป็น จริง ๆ ถ้าไม่ใส่ TypeScript จะเดา type จากค่าเริ่มต้น null ว่าเป็น null เท่านั้น แล้ว setPizzaOfTheDay(data) จะถูกฟ้องทันที รูปแบบ useState<T | null>(null) นี้พบบ่อยมากกับ state ที่ "ยังไม่มีข้อมูล แล้วค่อยมาทีหลัง" จำไว้ให้ขึ้นใจได้เลย
  • สังเกตว่าเราไม่ต้องประกาศ return type ให้ hook เอง TypeScript สรุปให้เองว่าเป็น Pizza | null จาก state ที่เรา return ออกไป การปล่อยให้มันเดาในกรณีแบบนี้เป็นเรื่องปกติและดีด้วย เพราะถ้าวันหนึ่งเราเปลี่ยน state ข้างใน type ที่คนอื่นเห็นก็จะเปลี่ยนตามให้อัตโนมัติ

สุดท้าย มาเพิ่มสิ่งนี้ใน App.tsx เพื่อให้ component ของเรา render

// import at top
import PizzaOfTheDay from "./PizzaOfTheDay";

// under <Order />
<PizzaOfTheDay />

ตอนนี้คุณควรเห็น component ใหม่ที่ใช้ hook ใหม่ของเราที่ด้านล่าง!

มาเพิ่มเทคนิค debugging สนุก ๆ อีกหนึ่งอย่างที่ทำมาเพื่อ custom hooks โดยเฉพาะ ใส่สิ่งนี้ใน usePizzaOfTheDay.ts:

// import useDebugValue
import { useState, useEffect, useDebugValue } from "react";

// add under the hook being used in the render function
useDebugValue(pizzaOfTheDay ? `${pizzaOfTheDay.name}` : "Loading...");

ตอนนี้เปิด React Dev Tools และ inspect component PizzaOfTheDay ของเรา คุณจะเห็น debug value อยู่ตรงนั้น สิ่งนี้มีประโยชน์เมื่อคุณมี custom hooks จำนวนมาก และโดยเฉพาะ custom hooks ที่ใช้ซ้ำมากและมี values ต่างกัน มันช่วยให้แยกออกได้อย่างรวดเร็วว่า hook ไหนมี data ใดอยู่ข้างใน
