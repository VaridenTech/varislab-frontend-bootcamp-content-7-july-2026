ESLint

นอกเหนือจาก Prettier ที่ดูแลการจัดรูปแบบทั้งหมดแล้ว คุณอาจต้องการบังคับ code style บางอย่างที่เกี่ยวกับการใช้งานมากกว่า ตัวอย่างเช่น คุณอาจต้องการบังคับให้ทุกคนไม่ใช้ with ซึ่งเป็น JS ที่ถูกต้อง แต่ไม่ควรใช้ ESLint เข้ามามีบทบาทตรงนี้ มันจะ lint เพื่อหาปัญหาเหล่านี้

ก่อนอื่น รัน npm install -D eslint@9.9.1 eslint-config-prettier@9.1.0 globals@15.9.0 เพื่อติดตั้ง ESLint เป็น development dependencies ของโปรเจกต์ จากนั้นคุณจึงตั้งค่าได้

มี preset config สำหรับ ESLint หลายสิบชุด และคุณเลือกใช้ชุดใดก็ได้ config ของ Airbnb เป็นที่นิยมมาก เช่นเดียวกับ standard config (ทั้งสองอย่างที่ฉันเคยสอนในคลาสเวอร์ชันก่อน) ฉันจะใช้ชุดที่ผ่อนปรนกว่าสำหรับคลาสนี้: recommended JS config จาก ESLint มาเริ่ม lint โปรเจกต์ด้วยการสร้างไฟล์ eslint.config.mjs กัน

เราใช้ .mjs (module JS) เพราะเราต้องการใช้ import/export สำหรับ modules แทน require

เพิ่มสิ่งนี้ลงในไฟล์ eslint.config.mjs:

import js from "@eslint/js";
import globals from "globals";
import prettier from "eslint-config-prettier";

/** @type {import('eslint').Linter.Config[]} */
export default [
  js.configs.recommended,
  {
    files: ["**/*.js"],
    languageOptions: {
      globals: { ...globals.browser, ...globals.node },
      parserOptions: {
        ecmaFeatures: {
          jsx: true,
        },
      },
    },
  },
  prettier,
];
  • ESLint เปลี่ยนไปมากใน version 9 ในเวอร์ชันก่อนของหลักสูตรนี้ เราใช้ configuration แบบ JSON ซึ่งไม่รองรับอีกต่อไป คุณ ต้อง ใช้ config แบบ “flat” ใหม่กว่า (พูดตรง ๆ ว่ามันดีกว่า)
  • /** @type {import('eslint').Linter.Config[]} */ เป็นเทคนิคของ VS Code / TypeScript เพื่อให้ทำ auto-completions บน config object ได้ การมี type ใช้ได้ใน VS Code มีประโยชน์มาก มันไม่จำเป็น
  • globals เป็น package ที่เป็นเพียงไฟล์ JSON ขนาดใหญ่ของสิ่งที่ใช้ได้ในแต่ละ environment เราจะอยู่ใน environment ของ Node.js และ Browser จึงใช้สองค่านั้น หากฉันเลือกให้ละเอียดกว่านี้สักหน่อย ฉันจะใช้ browser configs เฉพาะกับ browser files และ Node configs เฉพาะกับ Node.js files อย่างระมัดระวัง
  • config objects ถูกใช้ตามลำดับ เราใส่ JS config ของ ESLint ก่อน แล้วจึงใส่ของเราที่ปรับเองเพื่อให้เขียนทับตรงที่ต้องการ และ config ของ Prettier ควรอยู่ท้ายสุดเสมอ เพราะสิ่งที่มันทำคือปิด rules ที่ Prettier ทำเองเท่านั้น มันไม่ได้เพิ่มอะไร

นี่คือการรวม recommended configs ของ ESLint และ Prettier มันจะ lint ทั้งเรื่อง JS ปกติและ JSX มาเพิ่ม ESLint เข้า scripts ของเรากัน:

"lint": "eslint",

รัน npm run lint ตอนนี้ แล้วคุณจะเห็นว่าเรามี errors อยู่หลายอัน

🚨 ESLint จะมี errors มากมายตอนนี้ ไม่ต้องสนใจ เราจะแก้ในอีกสักครู่

มีสามเรื่องที่ควรเพิ่มไว้ตรงนี้:

  • สำหรับ npm scripts คุณส่ง parameters เพิ่มไปยังคำสั่งได้หากต้องการ เพียงใส่ -- แล้วตามด้วยสิ่งที่อยากต่อท้าย ตัวอย่างเช่น หากต้องการ debug output จาก ESLint ฉันรัน npm run lint -- --debug ได้ ซึ่งจะแปลเป็น eslint --debug
  • เราใช้เคล็ดลับ fix ได้ด้วยวิธีนี้: npm run lint -- --fix
  • เราจะใช้ทั้ง JS และ JSX

ESLint ทำงานกับ Visual Studio Code ได้ง่ายมาก เพียงดาวน์โหลด extension

oxlint และ Biome

มีสองโปรเจกต์ที่น่าจับตาต่อจากนี้: Biome (เดิมชื่อ Rome) และ oxlint ทั้งคู่เขียนด้วย Rust และออกแบบมาให้เร็วกว่า ESLint (ที่เขียนด้วย JavaScript) ESLint อาจช้าได้บ้างเมื่อใช้ในระดับใหญ่มาก และสองโปรเจกต์นี้ตั้งเป้าจะแก้ bottleneck นั้น ฉันยังคิดว่ายังอยู่ในช่วงแรกของสองโปรเจกต์นี้ และ 99% ของเวลานั้น ESLint เร็วเพียงพอ ถึงอย่างนั้นก็ยังดีที่จะจับตาดูทั้งสองไว้ ท้ายที่สุดทั้งสองโปรเจกต์ตั้งเป้าจะแทนที่ Prettier ด้วยเช่นกัน
