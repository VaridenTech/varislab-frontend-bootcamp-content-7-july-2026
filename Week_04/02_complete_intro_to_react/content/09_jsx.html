การเขียน UI ด้วย JSX

JSX

JSX

จนถึงตอนนี้เราเขียน React โดยไม่ใช้ JSX ซึ่งฉันไม่รู้จักใครที่ทำแบบนั้นจริง ๆ กับแอปของตน ทุกคน ใช้ JSX ฉันแสดงวิธี createElement ให้คุณดูเพื่อให้คุณเข้าใจว่า JSX กำลังทำอะไรจริง ๆ มันแทบไม่ได้ทำอะไรเลย เพียงทำให้โค้ดของคุณอ่านง่ายขึ้นเล็กน้อย

ถ้าฉันเขียน React.createElement("h1", { id: "main-title" }, "My Website"); สิ่งที่ฉันพยายามให้ render ออกมาจริง ๆ คืออะไร <h1 id="main-title">My Website</h1> ใช่ไหม JSX พยายามตัดชั้นการแปลในสมองของคุณนี้ออกไป เพื่อให้คุณเขียนสิ่งที่คุณหมายถึงได้เลย

สร้างไฟล์ใหม่ชื่อ Pizza.jsx

ต้องแน่ใจว่าเรียกไฟล์ว่า .jsx ไม่ใช่ .js Vite จะไม่ทำ JSX transpilation หากไฟล์ไม่ได้มีนามสกุล JSX
const Pizza = (props) => {
  return (
    <div className="pizza">
      <h1>{props.name}</h1>
      <p>{props.description}</p>
    </div>
  );
};

export default Pizza;

ฉันไม่รู้ว่าคุณเป็นอย่างไร แต่ฉันว่าแบบนี้อ่านง่ายกว่ามาก และถ้าการนำ HTML มาไว้ใน JavaScript ทำให้คุณรู้สึกไม่คุ้นเคย ฉันอยากชวนให้คุณลองใช้จนจบเวิร์กช็อป เมื่อถึงตอนนั้นมันน่าจะรู้สึกคุ้นขึ้น และคุณก็กลับไปใช้วิธีเดิมได้เสมอ

อย่างไรก็ดี ตอนนี้คุณรู้แล้วว่า JSX ช่วยคุณทำอะไร มันเพียงแปล HTML tags เหล่านั้นเป็นการเรียก React.createElement แค่นั้นเอง จริง ๆ ไม่มีเวทมนตร์อื่นอีก JSX ไม่ได้ทำอย่างอื่นเลย หลายคนที่เรียน React ไม่ได้เรียนเรื่องนี้

สังเกต syntax แปลก ๆ {props.name}: นี่คือวิธีแสดง JavaScript expressions ใน JSX expression คืออะไรก็ตามที่เป็นด้านขวาของ assignment operator ใน JavaScript ได้ เช่น const x = <anything that can go here> หากเอา {} ออก มันจะแสดง props.name ลงใน DOM ตามตัวอักษร

สังเกตว่าเราไม่จำเป็นต้องเขียน import React from 'react' ที่นี่เหมือนเมื่อก่อน JSX เวอร์ชันล่าสุดจัดการให้คุณแล้ว ดังนั้นคุณต้อง import React package อย่างชัดเจนก็ต่อเมื่อต้องใช้บางสิ่งจากมัน นอกนั้นใช้ JSX ได้โดยไม่ต้อง import React!

ESLint

มาแก้ ESLint ของเรากัน เพราะ JSX เพิ่มรายละเอียดใหม่ ๆ ที่เราต้องการความช่วยเหลือ โปรดติดตั้ง

npm i -D eslint-plugin-react@7.37.1

จากนั้นใน eslint.config.mjs ของคุณ

// at top, import the ESLint reactPlugin
import reactPlugin from "eslint-plugin-react";

// under js.configs.recommended line
{
  ...reactPlugin.configs.flat.recommended,
  settings: {
    react: {
      version: "detect",
    },
  },
},
reactPlugin.configs.flat["jsx-runtime"],

// add to files
files: ["**/*.js", "**/*.jsx"], // add JSX

//after the languageOptions object:
rules: {
  "react/no-unescaped-entities": "off",
  "react/prop-types": "off",
},

ถ้าไม่แน่ใจว่าประกอบร่างถูกหรือไม่ นี่คือหน้าตาของ eslint.config.mjs ฉบับเต็มหลังแก้เสร็จ

import js from "@eslint/js";
import globals from "globals";
import prettier from "eslint-config-prettier";
import reactPlugin from "eslint-plugin-react";

/** @type {import('eslint').Linter.Config[]} */
export default [
  js.configs.recommended,
  {
    ...reactPlugin.configs.flat.recommended,
    settings: {
      react: {
        version: "detect",
      },
    },
  },
  reactPlugin.configs.flat["jsx-runtime"],
  {
    files: ["**/*.js", "**/*.jsx"],
    languageOptions: {
      globals: { ...globals.browser, ...globals.node },
      parserOptions: {
        ecmaFeatures: {
          jsx: true,
        },
      },
    },
    rules: {
      "react/no-unescaped-entities": "off",
      "react/prop-types": "off",
    },
  },
  prettier,
];

เราต้องเพิ่มสอง configs: อันหนึ่งให้ ESLint เข้าใจ React และเพิ่มกฎ React พื้นฐาน และอีกอันทำให้ทันสมัยขึ้น เพราะ React 17 เปลี่ยนวิธีที่ ESLint โต้ตอบกับ React ไปเล็กน้อย

เรายังปิดสอง rules ที่ฉันคิดว่าไม่ค่อยมีประโยชน์ ได้แก่ unescaped entities (ซึ่งทำให้คุณต้องเปลี่ยนสิ่งอย่าง ' เป็น &apos) และ prop types ซึ่ง ณ จุดนี้ไม่มีใครใช้มาสิบปีแล้ว นอกนั้นเราก็น่าจะพร้อมใช้งาน

กลับไปที่ JSX

ตอนนี้ JSX ถูกไขความลับไปบ้างแล้ว มาแปลง App.js กัน

// rename the file App.jsx
// delete the React import
import { createRoot } from "react-dom/client";
import Pizza from "./Pizza";

// delete the Pizza component

const App = () => {
  return (
    <div>
      <h1>Pizza app – Order Now</h1>
      <Pizza name="Pepperoni" description="Mozzarella Cheese, Pepperoni" />
      <Pizza
        name="The Hawaiian Pizza"
        description="Sliced Ham, Pineapple, Mozzarella Cheese"
      />
      <Pizza
        name="The Big Meat Pizza"
        description="Bacon, Pepperoni, Italian Sausage, Chorizo Sausage"
      />
    </div>
  );
};

const container = document.getElementById("root");
const root = createRoot(container);
root.render(<App />);

ไปที่ index.html แล้วเปลี่ยน script tag ด้วย

<script type="module" src="./src/App.jsx"></script>

สังเกตว่า Pizza เป็น component สังเกตว่าตัว P ใน Pizza เป็นตัวพิมพ์ใหญ่ มันต้องเป็นเช่นนั้น หากทำให้เป็นตัวพิมพ์เล็ก มันจะพยายามใช้ pizza เป็น web component ไม่ใช่ React component

ตอนนี้เราส่ง props ลงไปเหมือนเราเพิ่ม attributes ให้ HTML tag เจ๋งดี

คุณทดสอบแอปได้ด้วยการรัน npm run dev และเปิด URL ที่แสดงใน terminal โดยทั่วไปคือ http://localhost:5173/

API / Image Server

ต่อจากนี้แอปของเราจะเริ่มดึงข้อมูลพิซซ่าและรูปภาพจาก backend แทนที่จะเขียนข้อมูลตายตัวไว้ในโค้ด หลักสูตรนี้จึงเตรียม API server ขนาดเล็กที่เขียนด้วย Fastify มาให้พร้อมแล้ว

เซิร์ฟเวอร์ตัวนี้เป็นคนละโปรเจกต์กับแอป React ของเรา และอยู่คนละ repository ให้ clone มาเก็บไว้ นอก โฟลเดอร์ pizza-app ทำครั้งเดียวแล้วใช้ได้ตลอดทั้งหลักสูตร

git clone https://github.com/VaridenTech/pizza-shop-api-demo.git

เมื่อ clone เสร็จ โครงสร้างในเครื่องคุณควรเป็นแบบนี้ จะวางไว้ที่ไหนก็ได้ ขอแค่สองโฟลเดอร์นี้ไม่ซ้อนอยู่ข้างในกันและกัน

โฟลเดอร์งานของคุณ/
├── pizza-app/              ← แอป React ที่เรากำลังสร้าง
└── pizza-shop-api-demo/    ← API server
    ├── server.js
    ├── package.json
    ├── pizza.sqlite        (ฐานข้อมูลพิซซ่าและออร์เดอร์)
    └── public/             (รูปพิซซ่าและ style.css)

เราจะใช้ Vite ทำ proxy ไปยัง API server นี้ เป็นเทคนิคที่มีประโยชน์มากสำหรับการพัฒนาบนเครื่องตัวเองเมื่อ frontend กับ backend แยกกันอยู่คนละที่ บนระบบจริงคุณอาจมี NGINX คอย route traffic ไปยัง frontend และ backend server ที่แยกกัน แต่ตอนนี้ให้ Vite ทำหน้าที่นั้นแทนไปก่อน

หมายเหตุ: นี่แปลว่าคุณต้องเปิด terminal ไว้ สอง หน้าต่างพร้อมกัน หน้าต่างหนึ่งสำหรับ API server (เปิดทิ้งไว้ ไม่ต้องแตะอีก) อีกหน้าต่างสำหรับ Vite dev server ของแอปเรา

เพิ่มสิ่งนี้ใน vite.config.js ของคุณ

// replace export
export default defineConfig({
  server: {
    proxy: {
      "/api": {
        target: "http://localhost:3000",
        changeOrigin: true,
      },
      "/public": {
        target: "http://localhost:3000",
        changeOrigin: true,
      },
    },
  },
  plugins: [react()],
});

รัน API Server

เปิด terminal ใหม่อีกหน้าต่างหนึ่ง (อย่าปิดหน้าต่างที่รัน Vite อยู่) แล้วเข้าไปที่โฟลเดอร์ pizza-shop-api-demo ที่เพิ่ง clone มา ย้ำอีกครั้งว่ามันเป็นคนละโปรเจกต์กับ pizza-app มี package.json และ node_modules เป็นของตัวเอง

ใช้ Node.js เวอร์ชัน 20 ขึ้นไป ติดตั้ง dependencies แล้วสั่งรัน (ทำครั้งแรกครั้งเดียว ครั้งต่อ ๆ ไปข้าม npm install ได้เลย)

cd pizza-shop-api-demo
npm install
npm run dev

เซิร์ฟเวอร์จะเริ่มทำงานที่ port 3000 เพื่อยืนยันว่ามันทำงานจริง ให้เปิด http://localhost:3000/api/pizzas ในเบราว์เซอร์ คุณจะเห็นข้อมูลพิซซ่าเป็น JSON ออกมาเป็นชุดยาว ๆ

🔍 ถ้าติดปัญหา — EADDRINUSE แปลว่ามีอย่างอื่นใช้ port 3000 อยู่แล้ว ให้ปิดโปรแกรมนั้นก่อน หรือสั่ง PORT=3001 npm run dev แล้วอย่าลืมแก้ค่า target ใน vite.config.js ให้ตรงกัน · ถ้า npm install ล้มเหลวที่แพ็กเกจ sqlite3 ให้ตรวจสอบว่าใช้ Node.js เวอร์ชัน 20 ขึ้นไปด้วย node -v · รายละเอียดเพิ่มเติมเกี่ยวกับเซิร์ฟเวอร์นี้และรายการ endpoint ทั้งหมด อ่านได้ใน README.md ของ repository นั้น

คุณต้องให้เซิร์ฟเวอร์ทั้งสองตัวทำงานพร้อมกัน ด้วย proxy configuration ข้างต้น Vite จะดักคำขอที่ขึ้นต้นด้วย /api และ /public จากแอป React แล้วส่งต่อไปยัง API server ให้เอง แอปของเราจึงเรียก fetch("/api/pizzas") ได้ตรง ๆ เหมือนกับว่าทุกอย่างอยู่ที่เดียวกัน

ตอนนี้มาเพิ่ม images ให้ Pizza ของเรา

// return inside Pizza, inside div, under <p>
<img src={props.image} alt={props.name} />

ตอนนี้ใน App.jsx

// add to first Pizza
image={"/public/pizzas/pepperoni.webp"}

// add to second Pizza
image={"/public/pizzas/hawaiian.webp"}

// add to third Pizza
