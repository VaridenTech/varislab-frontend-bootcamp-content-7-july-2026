การเขียน UI ด้วย JSX

JSX

JSX

จนถึงตอนนี้เราเขียน React โดยไม่ใช้ JSX ซึ่งแทบไม่มีใครทำแบบนั้นจริง ๆ กับแอปของตัวเอง เกือบทุกคน ใช้ JSX เหตุผลที่เราเริ่มจาก createElement ก่อน ก็เพื่อให้คุณเข้าใจว่า JSX กำลังทำอะไรอยู่เบื้องหลัง มันแทบไม่ได้ทำอะไรเลย เพียงทำให้โค้ดของคุณอ่านง่ายขึ้นเล็กน้อย

ถ้าเราเขียน React.createElement("h1", { id: "main-title" }, "My Website"); สิ่งที่เราพยายามให้ render ออกมาจริง ๆ คืออะไร <h1 id="main-title">My Website</h1> ใช่ไหม JSX พยายามตัดชั้นการแปลในสมองของคุณนี้ออกไป เพื่อให้คุณเขียนสิ่งที่คุณหมายถึงได้เลย

สร้างไฟล์ใหม่ชื่อ Pizza.tsx

ต้องแน่ใจว่าเรียกไฟล์ว่า .tsx ไม่ใช่ .ts Vite จะไม่ทำ JSX transpilation หากไฟล์ไม่ได้มีนามสกุล .tsx (หรือ .jsx ในโปรเจกต์ที่ไม่ได้ใช้ TypeScript)
type PizzaProps = {
  name: string;
  description: string;
};

const Pizza = (props: PizzaProps) => {
  return (
    <div className="pizza">
      <h1>{props.name}</h1>
      <p>{props.description}</p>
    </div>
  );
};

export default Pizza;

คนส่วนใหญ่เห็นตรงกันว่าแบบนี้อ่านง่ายกว่ามาก และถ้าการนำ HTML มาไว้ใน JavaScript ทำให้คุณรู้สึกไม่คุ้นเคย ขอชวนให้ลองใช้ไปจนจบคอร์สก่อน เมื่อถึงตอนนั้นมันน่าจะรู้สึกคุ้นขึ้น และคุณก็กลับไปใช้วิธีเดิมได้เสมอ

props กับ TypeScript

เราเริ่มให้ type กับ props ตอนเปลี่ยน App.js เป็น App.tsx ในบทที่แล้ว และตอนนี้ย้าย type นั้นมาอยู่กับ Pizza.tsx ซึ่งเป็น pattern ที่เราจะใช้ซ้ำตลอดคอร์สนี้ หลักการมีแค่นี้: props ก็คือ parameter ตัวหนึ่งของฟังก์ชัน ดังนั้นเราให้ type กับมันเหมือนที่ให้ type กับ parameter ทั่วไป

  • เราประกาศ type PizzaProps ไว้เหนือ component ธรรมเนียมที่พบบ่อยที่สุดคือตั้งชื่อว่า ชื่อคอมโพเนนต์ + Props และวางไว้ในไฟล์เดียวกันกับ component นั้น
  • ทุก field ที่ไม่ได้ใส่ ? คือ prop ที่ บังคับ ลองลบ description="..." ออกจากการเรียก <Pizza /> ดู แล้วคุณจะเห็นเส้นแดงขึ้นทันทีตรงที่เรียกใช้ ไม่ใช่ตอนเปิดเบราว์เซอร์
  • ถ้าอยากให้ prop ไหนใส่หรือไม่ใส่ก็ได้ ให้เติม ? เช่น image?: string; — แต่แลกมาด้วยการที่ type ของมันจะกลายเป็น string | undefined และ TypeScript จะบังคับให้คุณจัดการกรณีที่ไม่มีค่า เดี๋ยวเราจะได้ทำจริงตอนเขียนเทสต์ในบทที่ 22
  • คุณจะเห็นบางโปรเจกต์ใช้ interface PizzaProps { ... } แทน type ในกรณีนี้ทั้งสองแบบทำงานเหมือนกันแทบทุกประการ คอร์สนี้เลือก type เพราะใช้ได้กับทุกอย่าง (รวมถึง union type ที่เราจะได้ใช้ในบทถัดไป) ไม่ต้องสลับไปมา

อีกวิธีที่พบบ่อยพอ ๆ กันคือ destructure props ออกมาเลย ซึ่งทำให้ในตัว component ไม่ต้องเขียน props. นำหน้าทุกครั้ง

const Pizza = ({ name, description }: PizzaProps) => {
  return (
    <div className="pizza">
      <h1>{name}</h1>
      <p>{description}</p>
    </div>
  );
};

คอร์สนี้จะใช้แบบ props.name ไปก่อนเพื่อให้เห็นชัดว่าค่าไหนมาจาก props แต่ทั้งสองแบบถูกต้องเท่ากัน เลือกแบบที่คุณอ่านสบายกว่าได้เลย

อย่างไรก็ดี ตอนนี้คุณรู้แล้วว่า JSX ช่วยคุณทำอะไร มันเพียงแปล HTML tags เหล่านั้นเป็นการเรียก React.createElement แค่นั้นเอง จริง ๆ ไม่มีเวทมนตร์อื่นอีก JSX ไม่ได้ทำอย่างอื่นเลย หลายคนที่เรียน React ไม่ได้เรียนเรื่องนี้

สังเกต syntax แปลก ๆ {props.name}: นี่คือวิธีแสดง JavaScript expressions ใน JSX expression คืออะไรก็ตามที่เป็นด้านขวาของ assignment operator ใน JavaScript ได้ เช่น const x = <anything that can go here> หากเอา {} ออก มันจะแสดง props.name ลงใน DOM ตามตัวอักษร

สังเกตว่าเราไม่จำเป็นต้องเขียน import React from 'react' ที่นี่เหมือนเมื่อก่อน JSX เวอร์ชันล่าสุดจัดการให้คุณแล้ว ดังนั้นคุณต้อง import React package อย่างชัดเจนก็ต่อเมื่อต้องใช้บางสิ่งจากมัน นอกนั้นใช้ JSX ได้โดยไม่ต้อง import React!

ESLint

มาแก้ ESLint ของเรากัน เพราะ JSX เพิ่มรายละเอียดใหม่ ๆ ที่เราต้องการความช่วยเหลือ และตอนนี้เราเขียน TypeScript แล้ว ESLint ตัวเปล่า ๆ จะอ่านไฟล์ .ts / .tsx ไม่ออกเลย เพราะมันไม่รู้จักไวยากรณ์ type — เราต้องเปลี่ยน parser ให้มันด้วย โปรดติดตั้ง

npm i -D eslint-plugin-react@^7.37.5 typescript-eslint@^8.65.0

typescript-eslint เป็นแพ็กเกจรวมที่ให้สองอย่างมาพร้อมกัน: parser ที่ทำให้ ESLint อ่าน TypeScript ได้ และ ชุดกฎ ที่เฉพาะกับ TypeScript (เช่น เตือนเมื่อคุณเผลอใช้ any หรือประกาศตัวแปรทิ้งไว้เฉย ๆ)

จากนั้นใน eslint.config.mjs ของคุณ

// at top
import reactPlugin from "eslint-plugin-react";
import tseslint from "typescript-eslint";

// wrap the whole exported array in tseslint.config(...)

// under js.configs.recommended line
tseslint.configs.recommended,
{
  ...reactPlugin.configs.flat.recommended,
  settings: {
    react: {
      version: "detect",
    },
  },
},
reactPlugin.configs.flat["jsx-runtime"],

// change files from **/*.js to TypeScript
files: ["**/*.{ts,tsx}"],

//after the languageOptions object:
rules: {
  "react/no-unescaped-entities": "off",
  "react/prop-types": "off",
},

ถ้าไม่แน่ใจว่าประกอบร่างถูกหรือไม่ นี่คือหน้าตาของ eslint.config.mjs ฉบับเต็มหลังแก้เสร็จ

import js from "@eslint/js";
import globals from "globals";
import prettier from "eslint-config-prettier";
import reactPlugin from "eslint-plugin-react";
import tseslint from "typescript-eslint";

export default tseslint.config(
  js.configs.recommended,
  tseslint.configs.recommended,
  {
    ...reactPlugin.configs.flat.recommended,
    settings: {
      react: {
        version: "detect",
      },
    },
  },
  reactPlugin.configs.flat["jsx-runtime"],
  {
    files: ["**/*.{ts,tsx}"],
    languageOptions: {
      globals: { ...globals.browser, ...globals.node },
      parserOptions: {
        ecmaFeatures: {
          jsx: true,
        },
      },
    },
    rules: {
      "react/no-unescaped-entities": "off",
      "react/prop-types": "off",
    },
  },
  prettier,
);
  • เราห่อทั้งหมดด้วย tseslint.config(...) แทนที่จะเป็น array เปล่า ๆ มันเป็น helper function ที่คืน array หน้าตาเดิมออกมา แต่ระหว่างที่คุณพิมพ์ มันจะช่วย auto-complete และเตือนเวลาเขียน config ผิดรูป — เป็น TypeScript ช่วยเราอีกครั้ง แม้แต่ในไฟล์ที่เป็น .mjs
  • เพราะห่อด้วย tseslint.config() แล้ว เราจึงลบคอมเมนต์ /** @type {...} */ จากบทที่ 6 ทิ้งได้ เพราะ helper ตัวนี้ให้ type มาในตัวอยู่แล้ว
  • tseslint.configs.recommended คือชุดกฎ TypeScript พื้นฐาน และมันจะตั้ง parser ให้เราโดยอัตโนมัติ ทำให้ ESLint อ่านไฟล์ .ts / .tsx ได้
  • เราต้องเพิ่มสอง React configs: อันหนึ่งให้ ESLint เข้าใจ React และเพิ่มกฎ React พื้นฐาน และอีกอันทำให้ทันสมัยขึ้น เพราะ React 17 เปลี่ยนวิธีที่ ESLint โต้ตอบกับ React ไปเล็กน้อย
  • เราเปลี่ยน files จาก **/*.js เป็น **/*.{ts,tsx} เพราะโค้ดในโปรเจกต์ของเราเป็น TypeScript ทั้งหมดแล้ว

เรายังปิดสอง rules ที่ไม่ค่อยมีประโยชน์ในทางปฏิบัติ ได้แก่ unescaped entities (ซึ่งทำให้คุณต้องเปลี่ยนสิ่งอย่าง ' เป็น &apos) และ prop types ซึ่ง ณ จุดนี้ไม่มีใครใช้มาสิบปีแล้ว — และยิ่งไม่จำเป็นเข้าไปใหญ่สำหรับเรา เพราะ PropTypes คือความพยายามตรวจ props ตอน runtime ซึ่ง TypeScript ทำให้เราแล้วตั้งแต่ตอนพิมพ์ และทำได้ดีกว่ามาก นอกนั้นเราก็น่าจะพร้อมใช้งาน

🔍 ถ้ารัน npm run lint แล้วเจอ error ว่า Parsing error: ... 'types' ... หรือ ESLint ยังบ่นไวยากรณ์ TypeScript อยู่ ให้ตรวจว่า tseslint.configs.recommended อยู่ก่อน config object ของคุณเองในลิสต์ เพราะ config ถูกใช้ตามลำดับ

กลับไปที่ JSX

ตอนนี้ JSX ถูกไขความลับไปบ้างแล้ว มาแปลง App.tsx กัน

// delete the React import
import { createRoot } from "react-dom/client";
import Pizza from "./Pizza";

// delete the Pizza component

const App = () => {
  return (
    <div>
      <h1>Pizza app – Order Now</h1>
      <Pizza name="Pepperoni" description="Mozzarella Cheese, Pepperoni" />
      <Pizza
        name="The Hawaiian Pizza"
        description="Sliced Ham, Pineapple, Mozzarella Cheese"
      />
      <Pizza
        name="The Big Meat Pizza"
        description="Bacon, Pepperoni, Italian Sausage, Chorizo Sausage"
      />
    </div>
  );
};

const container = document.getElementById("root");
if (!container) {
  throw new Error("ไม่พบ element ที่มี id=\"root\" ใน index.html");
}
const root = createRoot(container);
root.render(<App />);

ไฟล์ชื่อ App.tsx อยู่แล้วตั้งแต่บทที่แล้ว จึงไม่ต้องเปลี่ยนชื่อไฟล์หรือแก้ script tag ใน index.html ซ้ำอีก มันควรเป็นแบบนี้อยู่

<script type="module" src="./src/App.tsx"></script>

สังเกตว่า Pizza เป็น component สังเกตว่าตัว P ใน Pizza เป็นตัวพิมพ์ใหญ่ มันต้องเป็นเช่นนั้น หากทำให้เป็นตัวพิมพ์เล็ก มันจะพยายามใช้ pizza เป็น web component ไม่ใช่ React component

ตอนนี้เราส่ง props ลงไปเหมือนเราเพิ่ม attributes ให้ HTML tag เจ๋งดี

คุณทดสอบแอปได้ด้วยการรัน npm run dev และเปิด URL ที่แสดงใน terminal โดยทั่วไปคือ http://localhost:5173/

API / Image Server

ต่อจากนี้แอปของเราจะเริ่มดึงข้อมูลพิซซ่าและรูปภาพจาก backend แทนที่จะเขียนข้อมูลตายตัวไว้ในโค้ด หลักสูตรนี้จึงเตรียม API server ขนาดเล็กที่เขียนด้วย Fastify มาให้พร้อมแล้ว

เซิร์ฟเวอร์ตัวนี้เป็นคนละโปรเจกต์กับแอป React ของเรา และอยู่คนละ repository ที่ github.com/VaridenTech/pizza-shop-api-demo ให้ clone มาเก็บไว้ นอก โฟลเดอร์ pizza-app ทำครั้งเดียวแล้วใช้ได้ตลอดทั้งหลักสูตร

git clone git@github.com:VaridenTech/pizza-shop-api-demo.git
คำสั่งนี้ clone ผ่าน SSH ซึ่งต้องตั้งค่า SSH key กับบัญชี GitHub ของคุณไว้แล้ว ถ้าเจอ error ประมาณ Permission denied (publickey) แปลว่ายังไม่ได้ตั้งค่า ให้ทำตามคู่มือ Connecting to GitHub with SSH ของ GitHub ก่อน หรือจะ clone ผ่าน HTTPS ไปก่อนด้วย git clone https://github.com/VaridenTech/pizza-shop-api-demo.git ก็ได้เช่นกัน

เข้าไปดูโค้ดของ API server ใน repository ได้เลยถ้าสนใจว่าข้อมูลพิซซ่าและออร์เดอร์ถูกเสิร์ฟออกมาอย่างไร แต่ไม่จำเป็นต้องเข้าใจโค้ดฝั่งนี้เพื่อเรียนต่อ

เมื่อ clone เสร็จ โครงสร้างในเครื่องคุณควรเป็นแบบนี้ จะวางไว้ที่ไหนก็ได้ ขอแค่สองโฟลเดอร์นี้ไม่ซ้อนอยู่ข้างในกันและกัน

โฟลเดอร์งานของคุณ/
├── pizza-app/              ← แอป React ที่เรากำลังสร้าง
└── pizza-shop-api-demo/    ← API server
    ├── server.js
    ├── package.json
    ├── pizza.sqlite        (ฐานข้อมูลพิซซ่าและออร์เดอร์)
    └── public/             (รูปพิซซ่าและ style.css)

เราจะใช้ Vite ทำ proxy ไปยัง API server นี้ เป็นเทคนิคที่มีประโยชน์มากสำหรับการพัฒนาบนเครื่องตัวเองเมื่อ frontend กับ backend แยกกันอยู่คนละที่ บนระบบจริงคุณอาจมี NGINX คอย route traffic ไปยัง frontend และ backend server ที่แยกกัน แต่ตอนนี้ให้ Vite ทำหน้าที่นั้นแทนไปก่อน

หมายเหตุ: นี่แปลว่าคุณต้องเปิด terminal ไว้ สอง หน้าต่างพร้อมกัน หน้าต่างหนึ่งสำหรับ API server (เปิดทิ้งไว้ ไม่ต้องแตะอีก) อีกหน้าต่างสำหรับ Vite dev server ของแอปเรา

เพิ่มสิ่งนี้ใน vite.config.ts ของคุณ

// replace export
export default defineConfig({
  server: {
    proxy: {
      "/api": {
        target: "http://localhost:3000",
        changeOrigin: true,
      },
      "/public": {
        target: "http://localhost:3000",
        changeOrigin: true,
      },
    },
  },
  plugins: [react()],
});

รัน API Server

เปิด terminal ใหม่อีกหน้าต่างหนึ่ง (อย่าปิดหน้าต่างที่รัน Vite อยู่) แล้วเข้าไปที่โฟลเดอร์ pizza-shop-api-demo ที่เพิ่ง clone มา ย้ำอีกครั้งว่ามันเป็นคนละโปรเจกต์กับ pizza-app มี package.json และ node_modules เป็นของตัวเอง

ใช้ Node.js เวอร์ชัน 20 ขึ้นไป ติดตั้ง dependencies แล้วสั่งรัน (ทำครั้งแรกครั้งเดียว ครั้งต่อ ๆ ไปข้าม npm install ได้เลย)

cd pizza-shop-api-demo
npm install
npm run dev

เซิร์ฟเวอร์จะเริ่มทำงานที่ port 3000 เพื่อยืนยันว่ามันทำงานจริง ให้เปิด http://localhost:3000/api/pizzas ในเบราว์เซอร์ คุณจะเห็นข้อมูลพิซซ่าเป็น JSON ออกมาเป็นชุดยาว ๆ

🔍 ถ้าติดปัญหา — EADDRINUSE แปลว่ามีอย่างอื่นใช้ port 3000 อยู่แล้ว ให้ปิดโปรแกรมนั้นก่อน หรือสั่ง PORT=3001 npm run dev แล้วอย่าลืมแก้ค่า target ใน vite.config.ts ให้ตรงกัน · ถ้า npm install ล้มเหลวที่แพ็กเกจ sqlite3 ให้ตรวจสอบว่าใช้ Node.js เวอร์ชัน 20 ขึ้นไปด้วย node -v · รายละเอียดเพิ่มเติมเกี่ยวกับเซิร์ฟเวอร์นี้และรายการ endpoint ทั้งหมด อ่านได้ใน README.md ของ repository นั้น

คุณต้องให้เซิร์ฟเวอร์ทั้งสองตัวทำงานพร้อมกัน ด้วย proxy configuration ข้างต้น Vite จะดักคำขอที่ขึ้นต้นด้วย /api และ /public จากแอป React แล้วส่งต่อไปยัง API server ให้เอง แอปของเราจึงเรียก fetch("/api/pizzas") ได้ตรง ๆ เหมือนกับว่าทุกอย่างอยู่ที่เดียวกัน

ตอนนี้มาเพิ่ม images ให้ Pizza ของเรา ใน Pizza.tsx เราต้องแก้สองที่ — เพิ่ม prop ใหม่เข้าไปใน type ก่อน แล้วค่อยเอาไปใช้ใน JSX

// add to PizzaProps
type PizzaProps = {
  name: string;
  description: string;
  image: string;
};

// return inside Pizza, inside div, under <p>
<img src={props.image} alt={props.name} />

ถ้าคุณเพิ่มแค่ <img> โดยลืมเพิ่มใน PizzaProps TypeScript จะฟ้องทันทีว่า Property 'image' does not exist on type 'PizzaProps' นี่คือจังหวะที่ type ทำงานให้เรา: มันบังคับให้ "สัญญา" ของ component กับสิ่งที่ component ใช้จริงตรงกันเสมอ

ตอนนี้ใน App.tsx

// add to first Pizza
image={"/public/pizzas/pepperoni.webp"}

// add to second Pizza
image={"/public/pizzas/hawaiian.webp"}

// add to third Pizza
image={"/public/pizzas/big_meat.webp"}

และตอนนี้คุณก็ควรมี images แล้ว!
