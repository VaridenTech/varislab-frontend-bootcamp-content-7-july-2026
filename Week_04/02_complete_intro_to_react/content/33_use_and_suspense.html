use and Suspense

เราพูดถึง React Suspense มานานมาก และในทางเทคนิคเราก็ยังไม่ควรใช้มันโดยตรง แต่ React 19 จะให้วิธีที่ได้รับการรับรองเพื่อเริ่มใช้มัน (libraries บางตัวใช้แล้ว)

แนวคิดเบื้องหลัง Suspense คือ React component สามารถเริ่ม render แล้ว suspend ตัวเองได้ หาก data ทั้งหมดยังโหลดไม่เสร็จ ซึ่งเจ๋งเพราะโค้ดของคุณอ่านง่ายมาก: มันเหมือนคุณสมมติว่า data มีอยู่แล้ว และ React จัดการการได้มาของมันอยู่เบื้องหลัง

นี่คือแนวคิดของ hook ใหม่ use จาก React คุณเขียน use(myPromise) แล้ว React component จะ render เมื่อ myPromise resolve แล้วเท่านั้น

โชคดีที่ TanStack Query มีวิธีทำสิ่งนี้อยู่แล้วหลายแบบ ดังนั้นเราจะใช้มัน แต่ให้รู้ว่า use ใช้กับ promise ใดก็ได้ ไม่ใช่แค่ TanStack Query

ก่อนอื่นเปิด App.tsx เราต้องเปิดใช้ experimental support สำหรับสิ่งนี้ใน TanStack Query (อนาคตคุณอาจไม่ต้องทำ)

// replace queryClient
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      experimental_prefetchInRender: true,
    },
  },
});

import type { Dispatch, SetStateAction } from "react";
import type { PastOrder } from "../types";

// move query and page hooks to ErrorBoundary component
function ErrorBoundaryWrappedPastOrderRoutes() {
  const [page, setPage] = useState<number>(1);

    queryKey: ["past-orders", page],
    queryFn: () => getPastOrders(page),
    staleTime: 30000,

  );
}

สิ่งที่ TypeScript ทำให้เห็นชัดในการ refactor นี้

การย้าย state ออกจาก component แล้วส่งลงไปเป็น props แบบนี้เป็นการ refactor ที่เสี่ยงพลาดง่ายมาก เพราะมีตัวแปรสามตัวย้ายที่พร้อมกัน ในเวอร์ชัน JavaScript คุณจะรู้ว่าพลาดตรงไหนก็ตอนเปิดเบราว์เซอร์แล้วเจอ error เท่านั้น แต่พอเราต้องเขียน PastOrdersRouteProps ให้ครบ TypeScript จะไล่เช็คให้ทั้งสองฝั่ง — ทั้งฝั่งที่ส่ง <PastOrdersRoute … /> และฝั่งที่รับ

  • loadedPromise: Promise<PastOrder[]> — สังเกตว่า type ยังไล่มาจาก getPastOrders ที่เราใส่ Promise<PastOrder[]> ไว้ตั้งแต่บทที่ 19 เหมือนเดิม ผลคือ const data = use(loadedPromise) ได้ PastOrder[] มาแบบไม่มี undefined ปนอยู่ด้วย ซึ่งต่างจากตอนใช้ useQuery ตรง ๆ ที่เราต้องเขียน isLoading || !data คอยกัน — นี่คือข้อดีที่แท้จริงของ Suspense ที่สัมผัสได้ผ่าน type: การรอข้อมูลถูกยกออกไปเป็นหน้าที่ของ <Suspense> แล้ว ตัว component จึงมองเห็นแต่กรณีที่ข้อมูลมาถึงแล้วจริง ๆ
  • setPage: Dispatch<SetStateAction<number>> — หน้าตาคุ้น ๆ ใช่ไหม? เป็น type เดียวกับที่เราเจอตอนทำ CartHook ในบทที่ 17 เพียงแต่คราวนี้เป็น number แทน CartItem[] การส่ง setter function ลงไปเป็น prop เป็น pattern ที่พบบ่อยมาก และนี่คือวิธีให้ type กับมัน
  • เราใช้ Suspense เพื่อบอก React ว่าจะหยุด render ตรงไหนจนกว่า ทุกอย่าง ข้างในจะ resolve หากมีหลายสิ่ง suspend มันจะไม่ render จนกว่าทั้งหมดจะเสร็จ
  • fallback บอกสิ่งที่จะ render ระหว่างถูก suspend
  • เราต้อง query ภายใน parent component (และจึงเก็บ page ด้วย) เพราะ promise ต้องมีอยู่ภายนอก component ที่กำลังถูก suspend ไม่เช่นนั้นมันจะถูกเรียกใหม่ทุกครั้งที่ component render คล้าย error boundaries
  • เราใส่ทุกอย่างใน error-boundary wrapping component ซึ่งน่าจะควรเปลี่ยนชื่อ
  • อีกครั้ง เราใช้ support ของ TanStack Query แต่จริง ๆ ใช้กับ promise ใดก็ได้ TanStack Query แค่ทำให้มันง่าย
  • TanStack Query มีวิธีอื่นอีกหลายแบบในการใช้ Suspense เราเพียงอยากลอง use hook
  • use มีการใช้งานอื่นอีกเล็กน้อย ลองดูใน docs
  • ไม่เหมือน hooks ส่วนใหญ่ use ใช้ใน conditionals และ for loops ได้ ค่อนข้างแปลกเมื่อเทียบกับ rules around hooks แต่จริง
