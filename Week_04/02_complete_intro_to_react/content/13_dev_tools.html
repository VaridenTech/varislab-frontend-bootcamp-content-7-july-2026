บทเรียน 13 · Core React Concepts

เครื่องมือสำหรับนักพัฒนา

Dev Tools

React มีเครื่องมือดีมากสำหรับยกระดับ developer experience ของคุณ เราจะดูบางส่วนที่นี่

NODE_ENV=development

React มี developer conveniences มากมายติดมาให้ตั้งแต่แรก สิ่งที่ดีกว่าคือมันตัดสิ่งเหล่านั้นออกโดยอัตโนมัติเมื่อคุณ compile โค้ดสำหรับ production

แล้วคุณจะได้ debugging conveniences อย่างไร? หากใช้ Vite.js มันจะ compile development server ด้วย environment variable NODE_ENV=development และเมื่อรัน vite build มันจะเปลี่ยนเป็น NODE_ENV=production โดยอัตโนมัติ ซึ่งเป็นวิธีตัด extra weight ทั้งหมดออก

ทำไมการตัด debug stuff ออกจึงสำคัญ? React dev bundle ใหญ่กว่าและช้ากว่า production build มากพอสมควร ต้องแน่ใจว่าคุณ compile ด้วย environmental variables ที่ถูกต้อง ไม่เช่นนั้นผู้ใช้ของคุณจะเดือดร้อน

Strict Mode

React มี strict mode ใหม่ หากคุณห่อแอปด้วย <StrictMode></StrictMode> มันจะให้ warnings เพิ่มเติมเกี่ยวกับสิ่งที่คุณไม่ควรทำ ฉันไม่ได้สอนสิ่งใดที่ทำให้ warnings จาก StrictMode หายไป แต่การคุมทีมไม่ให้ใช้ legacy features หรือสิ่งที่จะถูกเลิกใช้ในไม่ช้าก็เป็นเรื่องดี

พึงระวังว่า StrictMode จะ double-render components ของคุณอย่างต่อเนื่อง และจะรัน effects สองครั้ง มันทำเช่นนี้เพื่อจับ subtle bugs ที่แอปของคุณเปลี่ยนระหว่าง renders ทั้งที่ไม่ควรเปลี่ยน มันอาจมีประโยชน์ แต่พูดตามตรง เมื่อคุณเรียนรู้ที่จะเขียน React อย่างถูกต้อง คุณแทบจะไม่เจอ bug แบบนั้น

Dev Tools

React มี dev tools ยอดเยี่ยมที่ core team ดูแล มีให้ใช้ทั้ง browsers ที่ใช้ Chromium และ Firefox มันให้คุณทำหลายอย่าง เช่น สำรวจ React app เหมือน DOM tree, แก้ state และ props ได้ทันทีเพื่อทดลอง, แกะ performance problems และจัดการ components แบบ programmatically ควรดาวน์โหลดตอนนี้เลย ดูที่นี่สำหรับ links
