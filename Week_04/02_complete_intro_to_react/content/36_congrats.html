บทเรียน 36 · สรุปบทเรียน (Wrap Up)

ยินดีด้วย! ก้าวต่อไปของคุณ

Congrats

ยินดีด้วย!! คุณทำได้!

นี่เป็นเนื้อหาจำนวนมากที่ต้องรับมือ ดังนั้นขอชื่นชมที่คุณเรียนจนจบ หวังว่ามันสนุก และอาจทำให้คุณสนับสนุนร้านพิซซ่าในท้องถิ่นไปด้วย!

ตอนนี้คุณพร้อมเต็มที่สำหรับการเขียน React อย่างมืออาชีพ ทุกอย่างที่เรียนที่นี่คือ 95%+ ของสิ่งที่คุณต้องใช้เพื่อเขียน React ในบริษัทเทคโนโลยีใด ๆ ส่วนอีก 5% ที่เหลือคือเรื่อง server-side React และเทคนิค performance ขั้นสูง ซึ่งเป็นเนื้อหาระดับถัดไป แต่สำหรับตอนนี้ นี่คือเกือบทั้งหมดที่คุณต้องรู้!

และอย่าลืมว่าคุณทำสิ่งนี้ด้วย TypeScript มาตลอดตั้งแต่บทที่ 8 ซึ่งเป็นสิ่งที่ทีมส่วนใหญ่ในอุตสาหกรรมใช้กันจริงในโปรเจกต์ React วันนี้ ลองย้อนดูสิ่งที่คุณทำได้แล้ว

  • ให้ type กับ props ของ component รวมถึง prop ที่เป็น optional และ prop ที่เป็นฟังก์ชัน
  • ใช้ generic กับ hooks — useState<Pizza[]>, useState<T | null>, useRef<HTMLDivElement | null>
  • ให้ type กับ event handler ของ DOM และรู้ว่า e.target ต่างจาก e.currentTarget อย่างไร
  • ปิดประตูที่ชั้น API ด้วย Promise<T> แล้วปล่อยให้ type ไหลไปทั่วแอปเอง
  • ใช้ type narrowing จัดการค่าที่อาจไม่มีอยู่ แทนที่จะปิดปาก TypeScript ด้วย ! หรือ as
  • ให้ type กับ context, class component, mock data ในเทสต์ และ environment variables
  • augment type ของ library ด้วย declare module และไฟล์ .d.ts

บทเรียนที่อยากให้ติดตัวไปมากที่สุดคือสิ่งที่เกิดขึ้นซ้ำแล้วซ้ำอีกตลอดคอร์สนี้: เกือบทุกครั้งที่ TypeScript บ่น มันกำลังชี้ไปที่กรณีจริงที่โค้ดเรายังจัดการไม่ครบ ไม่ว่าจะเป็น find() ที่หาไม่เจอ, API ที่ error แล้วไม่มี data, หรือ getElementById ที่คืน null เวลาเจอเส้นแดง อย่าเพิ่งรีบหาวิธีทำให้มันหาย — ให้อ่านมันเป็นคำถามว่า "แล้วถ้าเกิดกรณีนี้ขึ้นจริงจะให้ทำยังไง" ก่อนเสมอ

แล้วจากนี้ควรทำอะไร?

  • สร้างแอปของคุณเอง!! ย้ำเท่าไรก็ไม่พอว่าแนวคิดแบบนี้ต้องลงมือสร้างเองถึงจะติดตัว เลือกไอเดียที่งี่เง่าที่สุดในหัวแล้วทำมันให้เสร็จ ไม่มีอะไรแทนประสบการณ์ได้!
    • เว็บไซต์ e-commerce ขายถุงเท้าข้างเดียว เพื่อจับคู่ถุงเท้าที่ไม่มีคู่
    • text editor สำหรับ AI prompts
    • แอปเพลงที่ให้เพิ่มเพลงจาก Spotify, Apple Music และ Tidal ได้
    • client สำหรับอ่าน Thread, X และ Bluesky ในแอปเดียว
  • เรียน React ฝั่ง server ต่อ ไม่ว่าจะเป็น Next.js หรือ Remix/React Router (ในไม่ช้าสองอย่างหลังจะเป็นสิ่งเดียวกัน)
  • เรียนเครื่องมือจัดการ state ที่ใหญ่ขึ้น เช่น Redux Toolkit หรือ Zustand เมื่อ context เริ่มไม่พอ
  • เรียน Tailwind เพื่อเขียน CSS ได้เร็วขึ้นในโปรเจกต์จริง
  • ลง TypeScript ให้ลึกขึ้นอีกขั้น — generic ที่เขียนเอง, utility type อย่าง Pick, Omit, Partial และการตรวจข้อมูลจาก API ตอน runtime ด้วย Zod ซึ่งจะปิดช่องว่างสุดท้ายที่เราพูดถึงไว้ในบทที่ 11 ว่า type ที่เราเขียนเป็นเพียง "ความเชื่อ" ว่า API จะส่งอะไรมา

มีเส้นทางต่อจากนี้ได้มากมายและทุกทางสนุก! ขอให้สนุกกับการเขียน React ต่อไป!
