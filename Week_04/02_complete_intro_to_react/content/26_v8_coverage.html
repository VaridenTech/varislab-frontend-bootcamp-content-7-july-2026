ความครอบคลุมด้วย v8

v8

มีทริกสุดเจ๋งอีกอย่างที่ Vitest มีมาให้: v8 v8 ใช้เครื่องมือ test coverage ที่ built-in ของ Chrome ซึ่งบอกว่าคุณครอบคลุม code ของคุณด้วย tests ไป มากแค่ไหน ผ่าน interactive viewer คุณดูได้ว่า lines ใดถูกหรือไม่ถูกครอบคลุม การตั้งค่านี้เคยน่ารำคาญ แต่ Vitest ทำให้คุณได้เลย

รันต่อไปนี้

npm i -D @vitest/coverage-v8@2.1.3

คุณใช้ Istanbul ได้ด้วยหากต้องการ npm i -D @vitest/coverage-istanbul จะได้ package นั้น แต่โดยรวมแล้ว v8 เป็นเครื่องมือที่เหนือกว่า

ตอนนี้เพิ่มสิ่งนี้ใน vite.config.js ของคุณ

// inside the test object
coverage: {
  reporter: ["text", "json", "html"],
},

เพิ่ม command นี้ใน npm scripts ของคุณ: "coverage": "vitest --coverage" แล้วไปรัน npm run coverage และเปิด file นี้ใน browser: open coverage/index.html

ที่นี่คุณเห็น files ที่เราเขียน tests ให้แล้ว File หนึ่ง postContact ไม่มี coverage สอง lines (คลิกชื่อ file เพื่อดู): มันคือ line ที่อ่านกลับจาก cache เป็น file ที่เราไม่ได้เขียน test ให้ แต่มันถูก cover ผ่าน test สำหรับ contact page มันขาด test สำหรับ cover error cases ซึ่งอาจสำคัญ ถ้า contact API ของเราล่มล่ะ? เครื่องมือนี้ช่วยให้คุณดู code และเห็นว่า tests ของคุณไม่ cover อะไร บางอย่างอาจไม่เป็นไรและไม่คุ้มแรงที่จะเขียน test บางอย่างคุณจะดูแล้วพูดว่า “โอ้พระเจ้า เราต้อง cover สิ่งนั้นด้วย tests ตั้งแต่เมื่อวาน”

สุดท้าย เพิ่ม coverage/ ใน .gitignore เพราะไม่ควร check in สิ่งนี้

Istanbul

v8 ใช้ความสามารถ built-in ของ Chrome ในการครอบคลุม code เพื่อ run tests ของคุณ ซึ่งทำให้เร็วขึ้นอย่างมาก และ output ในรูปแบบที่เครื่องมือ Istanbul ทั้งหมดใช้ได้ คุณบอก Vitest ให้ใช้ Istanbul ได้ แต่เว้นแต่คุณมีเหตุผลเฉพาะมาก ให้ใช้ v8 ดู c8 เพิ่มเติมได้หากต้องการบริบทเกี่ยวกับเครื่องมือ coverage ที่เกี่ยวข้อง
