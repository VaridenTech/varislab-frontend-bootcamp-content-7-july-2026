Error Boundaries

บ่อยครั้ง APIs มี errors จากข้อมูลที่ malformed หรือแปลกอย่างอื่น มาตั้งรับเรื่องนี้ เพราะเรายังอยากใช้ API นี้แต่ควบคุมไม่ได้ว่าเมื่อไรจะได้ errors เราจะใช้ feature ชื่อ componentDidCatch เพื่อจัดการ นี่เป็นสิ่งที่ทำด้วย hooks ไม่ได้ ดังนั้นหากต้องการ functionality แบบนี้ คุณจะต้องใช้ class component

มันจะจับ 404s บน API ของเราด้วย หากใครให้ ID ที่ไม่ถูกต้อง!

component จับ errors ได้เฉพาะใน children ของมันเท่านั้น นี่เป็นเรื่องสำคัญที่ต้องจำ มันจับ errors ของตัวเองไม่ได้ ไปสร้าง wrapper สำหรับใช้กับ PastOrdersRoute กัน สร้างไฟล์ใหม่ชื่อ ErrorBoundary.tsx

นี่เป็นครั้งแรกที่เราจะได้เห็นวิธีเขียน components แบบเก่า ที่เรียกว่า class components เมื่อก่อน React code ทุกชิ้นเขียนแบบนี้ แม้มันยังไม่ deprecated แต่ React team ระบุชัดเจนว่าไม่แนะนำให้ใช้กับโค้ดใหม่ ทุกวันนี้แทบไม่มีใครเขียน class component ใหม่กันแล้ว คอร์สระดับเริ่มต้นจึงไม่สอนมันเป็นเรื่องหลัก อย่างไรก็ดี error boundaries เป็นสิ่งเดียวที่ยัง ต้อง เขียนด้วย class เราจึงจะเกริ่นสั้น ๆ ให้พอรู้จักกับของจริง และในโปรเจกต์จริงคุณเลือกใช้ react-error-boundary แทนได้ โดยไม่ต้องเขียน class component เลย!

class component คล้าย function component (สิ่งที่เราเขียนอยู่) มาก แต่มีความต่างสำคัญบางอย่าง

  • คุณใช้ hooks ใด ๆ กับ class components ไม่ได้ (useState, useEffect ฯลฯ)
  • class component ทุกตัวมี render() function ซึ่งทำงานคล้าย function component เป็นส่วนใหญ่
  • แทน useState hook คุณใช้ this.state ซึ่งเป็น object ที่เก็บ state ทั้งหมดของ component นั้น
  • หากจะเปลี่ยน state ใช้ this.setState({ key: "value" }) function สิ่งนี้ให้คุณเปลี่ยน state เหมือน setKey hook
  • แทน useEffect คุณใช้ lifecycle methods: componentDidMount, componentDidUpdate, componentWillUnmount ฯลฯ อ่านเพิ่มเติมได้ในเอกสารทางการของ React หัวข้อ Component
  • แทน props parameter ที่ส่งเข้า function คุณจะใช้ this.props
  • ใน TypeScript คุณบอก type ของ props และ state ให้ class component ผ่าน generic สองตัวของ Component คือ Component<Props, State> ต่างจาก function component ที่ใส่ type ให้ parameter ตรง ๆ
  • เท่านี้พอแล้ว คุณไม่ควรเขียน class components อีกต่อไป ยกเว้น error boundaries แต่อาจพบมันใน React codebases แบบ legacy
import { Component } from "react";
import type { ErrorInfo, ReactNode } from "react";
import { Link } from "@tanstack/react-router";

type ErrorBoundaryProps = {
  children: ReactNode;
};

type ErrorBoundaryState = {
  hasError: boolean;
};

class ErrorBoundary extends Component<
  ErrorBoundaryProps,
  ErrorBoundaryState
> {
  state: ErrorBoundaryState = { hasError: false };
  static getDerivedStateFromError(): ErrorBoundaryState {
    return { hasError: true };
  }
  componentDidCatch(error: Error, info: ErrorInfo) {
    console.error("ErrorBoundary caught an error", error, info);
  }
  render() {
    if (this.state.hasError) {
      return (
        <div className="error-boundary">
          <h2>Uh oh!</h2>
          <p>
            There was an error with this listing. <Link to="/">Click here</Link>{" "}
            to back to the home page.
          </p>
        </div>
      );
    }

    return this.props.children;
  }
}

export default ErrorBoundary;
  • ตอนนี้อะไรก็ตามที่เป็น child ของ component นี้จะมี errors ถูกจับที่นี่ คิดเหมือน catch block ของ try/catch
  • static method คือ method ที่เรียกบน constructor ได้ คุณจะเรียก method นี้แบบ: ErrorBoundary.getDerivedStateFromError(error) method นี้ต้องเป็น static
  • หากอยากเรียก error logging service componentDidCatch เป็นตำแหน่งที่ยอดเยี่ยม ตัวเลือกที่นิยมคือ Sentry และ TrackJS
  • this.props.children คือ child component ใด ๆ ภายใน component เช่น หากมีคน render <MyComponent><h1>hi</h1></MyComponent> แล้ว <h1>hi</h1> ถือเป็น “children” สิ่งนี้ใช้กับ function components ได้ด้วย
  • เพราะเรา return children หากไม่มี error ErrorBoundary component จึงไม่ render อะไรเองหากไม่มี errors

TypeScript กับ class component

  • Component<ErrorBoundaryProps, ErrorBoundaryState> — generic ตัวแรกคือ type ของ props ตัวที่สองคือ type ของ state ผลคือ this.props.children และ this.state.hasError มี type ครบ และถ้าคุณพิมพ์ this.state.hasErrors (มี s เกินมา) มันจะเป็น error ทันที ซึ่งเป็นบั๊กประเภทที่หายากมากที่จะหาเจอด้วยตาเปล่า
  • componentDidCatch(error: Error, info: ErrorInfo) — เราต้องใส่ type ให้ parameter ของ lifecycle method เอง ErrorInfo เป็น type ที่ React ให้มา (มี field componentStack อยู่ข้างใน) ลอง import แล้วเอาเมาส์ชี้ดูได้
  • ทั้ง ReactNode และ ErrorInfo เรา import ด้วย import type เพราะใช้เป็น type อย่างเดียว ส่วน Component ต้อง import แบบปกติ เพราะเรา extends มันจริง ๆ ตอนรัน

ไปให้ PastOrderRoute ใช้มันในกรณีที่ API throws an error

// add import
import ErrorBoundary from "../ErrorBoundary";

// replace Route export
export const Route = createLazyFileRoute("/past")({
  component: ErrorBoundaryWrappedPastOrderRoutes,
});

// beneath Route export
function ErrorBoundaryWrappedPastOrderRoutes() {
  return (
    <ErrorBoundary>
      <PastOrdersRoute />
    </ErrorBoundary>
  );
}
  • ตอนนี้มัน self-contained ทั้งหมด ไม่มีใครที่ render PastOrderRoute ต้องรู้ว่ามันมี error boundary ของตัวเอง คุณเลือกได้เองว่าชอบ pattern นี้ หรืออยากทำใน App.tsx ที่ระดับ Router มากกว่า ทั้งสองแบบมีคนใช้จริง
  • เราสร้าง ErrorBoundary ให้ยืดหยุ่นกว่านี้ได้ และให้มันรับ component ที่จะแสดงเมื่อเกิด errors มีกฎโค้ดที่เรียกว่า “WET” (ตรงข้ามกับ DRY, ฮ่า ๆ): Write Everything Twice หรือบางคนขยับเป็น Write Everything Thrice กรณีนี้เราใช้ component แค่ use case เดียว จึงไม่เสียเวลาทำให้มันยืดหยุ่น หากใช้ซ้ำอีกครั้ง ค่อยทำให้รองรับทั้งสอง use case แต่ไม่ใช่ ทุก use case เมื่อครั้งที่สามหรือสี่ จึงค่อยกลับมาลงทุนให้ยืดหยุ่น

ทีนี้ หากอยากลอง ให้เพิ่ม throw new Error("lol"); ใน render function ของ PastOrderRoute เพื่อดูมันทำงาน!
