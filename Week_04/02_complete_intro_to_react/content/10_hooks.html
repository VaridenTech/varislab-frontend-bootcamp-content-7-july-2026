โอเค ตอนนี้เราต้องการให้ผู้คนเพิ่ม pizzas ลงใน order ของตนได้ เราต้องมี form เล็ก ๆ ที่ให้เลือก pizza และขนาด สร้างไฟล์ใหม่ชื่อ Order.tsx แล้วเพิ่มสิ่งต่อไปนี้:

import Pizza from "./Pizza";

export default function Order() {
  const pizzaType = "pepperoni";
  const pizzaSize = "M";
  return (
    <div className="order">
      <h2>Create Order</h2>
      <form>
        <div>
          <div>
            <label htmlFor="pizza-type">Pizza Type</label>
            <select name="pizza-type" value={pizzaType}>
              <option value="pepperoni">The Pepperoni Pizza</option>
              <option value="hawaiian">The Hawaiian Pizza</option>
              <option value="big_meat">The Big Meat Pizza</option>
            </select>
          </div>
          <div>
            <label htmlFor="pizza-size">Pizza Size</label>
            <div>
              <span>
                <input
                  checked={pizzaSize === "S"}
                  type="radio"
                  name="pizza-size"
                  value="S"
                  id="pizza-s"
                />
                <label htmlFor="pizza-s">Small</label>
              </span>
              <span>
                <input
                  checked={pizzaSize === "M"}
                  type="radio"
                  name="pizza-size"
                  value="M"
                  id="pizza-m"
                />
                <label htmlFor="pizza-m">Medium</label>
              </span>
              <span>
                <input
                  checked={pizzaSize === "L"}
                  type="radio"
                  name="pizza-size"
                  value="L"
                  id="pizza-l"
                />
                <label htmlFor="pizza-l">Large</label>
              </span>
            </div>
          </div>
          <button type="submit">Add to Cart</button>
        </div>
        <div className="order-pizza">
          <Pizza
            name="Pepperoni"
            description="Mozzarella Cheese, Pepperoni"
            image="/public/pizzas/pepperoni.webp"
          />
          <p>$13.37</p>
        </div>
      </form>
    </div>
  );
}

ตอนนี้ไปที่ http://localhost:5173/ แล้วดูว่าคุณมี inputs สองแบบ หนึ่งสำหรับชนิด pizza และ radio buttons ชุดหนึ่งสำหรับขนาด ลองเลือกบางอย่างด้วย inputs คุณจะเห็นว่าคุณเปลี่ยนมันไม่ได้ ทำไม? ลองคิดว่า React ทำงานอย่างไร: เมื่อคุณโต้ตอบกับ inputs React ตรวจพบว่า DOM event เกิดขึ้น เมื่อเกิดขึ้น React คิดว่าบางสิ่งอาจเปลี่ยน จึงรัน re-render หาก render functions ของคุณเร็ว นี่เป็นการทำงานที่เร็วมาก จากนั้นมัน diff สิ่งที่มีอยู่ตอนนี้กับสิ่งที่ render pass สร้างขึ้น แล้วอัปเดต DOM ให้น้อยที่สุดเท่าที่จำเป็น

สังเกตว่าเราใช้ className แทน class บน HTML element สำหรับ CSS classes นี่เป็นเพราะ class เป็น reserved word ใน JS และ JSX ก็ยังเป็น JS อยู่ ดังนั้นจึงเลือกใช้ className ซึ่งเป็น ชื่อของ JS API สำหรับโต้ตอบกับ class names

เช่นเดียวกับ className เราใช้ htmlFor เพราะ for เป็น reserved word ใน JS

ดังนั้นหากเราพิมพ์ลงใน input และมัน re-render อะไรจะออกมาใน tags select หรือ radio button? value ของมันผูกอยู่กับ pizzaType และ pizzaSize และไม่มีอะไรเปลี่ยนสองค่านั้น ดังนั้นมันจึงเหมือนเดิม กล่าวอีกนัยหนึ่ง two way data binding ไม่ได้ได้มาฟรีใน React ถือเป็น feature มากกว่า bug เพราะมันบังคับให้คุณชัดเจนว่าจะจัดการ data อย่างไร มาแก้ให้มันทำงานกัน

ก่อนอื่น ขนาดพิซซ่าของเรามีได้แค่สามค่าเท่านั้น คือ S, M และ L นี่คือกรณีที่ union type เหมาะที่สุด และเราจะได้ใช้มันอีกหลายที่ในบทถัด ๆ ไป จึงขอเก็บไว้ในไฟล์กลาง สร้างไฟล์ใหม่ชื่อ src/types.ts (สังเกตว่าเป็น .ts ไม่ใช่ .tsx เพราะไม่มี JSX อยู่ในนี้เลย)

export type PizzaSize = "S" | "M" | "L";

การรวม type ที่ใช้ร่วมกันหลายไฟล์ไว้ที่เดียวเป็นธรรมเนียมที่พบบ่อยมากในโปรเจกต์ React + TypeScript ข้อดีคือเมื่อรูปร่างของข้อมูลเปลี่ยน คุณแก้ที่เดียวแล้ว TypeScript จะไล่บอกให้เองว่ามีที่ไหนบ้างที่ต้องแก้ตาม

onChange={(e: React.ChangeEvent<HTMLInputElement>) =>
  setPizzaSize(e.target.value as PizzaSize)

หมายเหตุผู้แปล: ตัวอย่างต้นฉบับ (ซึ่งเป็น JavaScript) ใช้ useState("medium") ทั้งที่ค่าของ radio และ key ใน sizes[pizzaSize] คือ S, M หรือ L — เป็นบั๊กที่ทำให้ราคาเริ่มต้นคำนวณไม่ออก ลองพิมพ์ useState<PizzaSize>("medium") ดูสักครั้งเพื่อดูสิ่งที่เกิดขึ้น: TypeScript จะฟ้องทันทีว่า Argument of type '"medium"' is not assignable to parameter of type 'PizzaSize' บั๊กที่เคยต้องไปเจอเอาตอนเปิดเบราว์เซอร์ กลายเป็นเส้นแดงใต้ตัวอักษรตั้งแต่ตอนพิมพ์

สามเรื่องเกี่ยวกับ TypeScript ในโค้ดชุดนี้

  • import type — เพราะเรา import PizzaSize มาใช้เป็น type เท่านั้น ไม่ได้ใช้เป็นค่าจริงตอนรัน เราจึงเขียน import type นี่คือผลของ verbatimModuleSyntax ที่เราเปิดไว้ใน tsconfig ข้อดีคืออ่านแล้วรู้ทันทีว่าบรรทัดนี้จะหายไปทั้งบรรทัดตอน build ไม่ได้เพิ่มขนาดให้ bundle เลย
  • useState<PizzaSize> — วงเล็บมุมคือการบอก type ให้ hook โดยตรง ในกรณีของ pizzaSize มันจำเป็น เพราะถ้าไม่ใส่ TypeScript จะเดา type จากค่าเริ่มต้น "M" ว่าเป็น string กว้าง ๆ แล้วเราจะเผลอ setPizzaSize("XL") ได้โดยไม่มีใครเตือน ส่วน useState<string> ของ pizzaType นั้นใส่หรือไม่ใส่ก็ได้ (TypeScript เดาถูกอยู่แล้ว) แต่คอร์สนี้จะใส่ให้ครบเพื่อให้อ่านแล้วเห็นชัดว่า state แต่ละตัวเก็บอะไร
  • React.ChangeEvent<HTMLSelectElement> — event ใน React มี type ของตัวเองที่บอกทั้งชนิดของ event และชนิดของ element ที่มันเกิดขึ้น ประโยชน์ที่ได้ทันทีคือ e.target.value จะรู้ว่าเป็น string จริง ๆ และถ้าคุณใส่ element ผิด เช่นเขียน HTMLInputElement บน <select> TypeScript ก็จะฟ้อง

แล้ว as PizzaSize ตรง radio button ล่ะ? นั่นคือ type assertion — เป็นการบอก TypeScript ว่า "ฉันรู้มากกว่าเธอตรงนี้" เหตุผลคือ DOM ไม่รู้จัก PizzaSize ของเรา มันมองว่า e.target.value ของ input ทุกตัวคือ string ธรรมดา แต่เรารู้ว่า radio ทั้งสามตัวมี value เป็น S, M, L เท่านั้น เพราะเราเขียน JSX นั้นเอง

⚠️ as เป็นเครื่องมือที่ควรใช้ให้น้อยที่สุด เพราะมันปิดการตรวจสอบ ไม่ใช่เพิ่มการตรวจสอบ ถ้าวันหนึ่งมีคนเพิ่ม radio ตัวที่สี่ที่ value="XL" โค้ดนี้จะยอมรับมันเงียบ ๆ ทั้งที่ type บอกว่าเป็นไปไม่ได้ ทุกครั้งที่คุณเขียน as ให้ถามตัวเองก่อนว่า "ฉันรู้จริงหรือเปล่า" — ถ้าไม่แน่ใจ ให้เขียนฟังก์ชันเช็คค่าจริง ๆ แทน
  • สิ่งนี้เรียกว่า hook frameworks อื่น เช่น Vue ก็นำมันไปใช้เช่นกัน
  • ที่เรียกว่า hook น่าจะเพราะมันเป็น hook ที่ถูกจับทุกครั้งที่ render function ถูกเรียก เนื่องจาก hooks ถูกเรียกตามลำดับเดิมทุกครั้ง มันจึงชี้ไปที่ state ชิ้นเดิมเสมอ ด้วยเหตุนี้มันจึงมี state ได้: คุณเก็บ mutable state ด้วย hooks แล้วแก้ไขภายหลังผ่าน updater functions ที่มันให้มาได้
  • แนวคิดที่สำคัญอย่างยิ่งที่คุณต้องเข้าใจคือ hooks พึ่งพาลำดับที่เคร่งครัดนี้ ดังนั้น อย่าวาง hooks ไว้ใน if statements หรือ loops หากทำ คุณจะเจอ bugs ประหลาดที่ useState คืนstate ที่ผิด หากคุณเห็น useState คืน state ผิดชิ้น นี่น่าจะเป็นสิ่งที่คุณทำ ทุก hook ต้องทำงานทุกครั้งในลำดับเดียวกัน
  • argument ที่ให้ useState คือ default value ในกรณีของเรา เราอาจให้ "" เป็น default value เพื่อบังคับให้ผู้ใช้เลือกบางอย่างก่อน แต่กรณีนี้เราต้องการตั้งค่าเริ่มต้นเป็น pepperoni pizza และขนาดกลาง
  • useState คืน array ที่มีสองสิ่ง: current value ของ state นั้น และ function สำหรับอัปเดต state เราใช้ JavaScript feature ที่เรียกว่า destructuring เพื่อเอาทั้งสองสิ่งออกจาก array
  • เราใช้ function setPizzaType / setPizzaSize ใน attribute onChange ของ input ทุกครั้งที่พิมพ์ใน input มันจะเรียก functions ที่เรียก setPizzaType และ setPizzaSize ด้วยสิ่งที่พิมพ์ เลือก หรือคลิกใน input เมื่อเรียก setPizzaType และ setPizzaSize React รู้ว่า state ถูกแก้ไขและเริ่ม re-render
  • คุณสร้าง custom hooks ของตัวเองได้; useState เป็นเพียงหนึ่งจากหลายตัว
  • ในอดีต React เขียนด้วย classes โดย state อยู่บน instance ของ component รูปแบบนี้ยังได้รับการสนับสนุนใน React เราจะดูวิธีทำภายหลัง
  • เราอาจวาง onChange handler บน radio buttons แต่ละอันได้ อย่างไรก็ตาม event bubbling ใน React ทำงานเหมือนใน DOM ปกติ และเราวางมันตรงบน div ที่ครอบ radio buttons ทั้งหมดได้ จึงทำเพียงครั้งเดียว
  • คุณใช้ useState ได้มากเท่าที่ต้องการสำหรับ state หลายส่วน! นี่เป็นอีกเหตุผลว่าทำไมลำดับจึงสำคัญ เพราะ React พึ่งพาให้เรียก useState ด้วยลำดับเดิมอย่างเคร่งครัดทุกครั้ง เพื่อส่ง state ชิ้นเดิมให้คุณ
  • คล้ายกับข้างต้น เราใช้ onChange เพราะทำให้เข้าถึงได้ง่ายกว่า
ตรงนี้เรากำลังทำ “controlled form” คือใช้ hooks ควบคุมแต่ละส่วนของ form ในความจริงควรปล่อยให้มัน uncontrolled (หรือไม่ตั้ง value) แล้วห่อทั้งหมดด้วย form จากนั้นฟัง submit events และใช้ event นั้นเก็บข้อมูลจาก form วิธีนี้เขียนโค้ดน้อยกว่าและไม่หนักมือ หากคุณต้องเขียน form มาตรฐาน ให้ทำเป็น uncontrolled form หากต้องทำ dynamic validation, ตอบสนองขณะที่ผู้ใช้พิมพ์แบบ typeahead (ความสามารถที่ให้คำแนะนำแบบ real-time) หรือคล้ายกัน controlled input จะเหมาะมาก นอกนั้นใช้ uncontrolled
สิ่งใหม่ใน React เรียกว่า “form action” ซึ่งถือว่ายังไม่เสถียร อนาคตคุณจะเพียงเพิ่ม <form action="blah">[…]</form> และ form action จะจัดการ form ทั้งหมดให้คุณ

ข้อสังเกตอีกอย่าง: event bubbling ใน React ทำงานเหมือนที่คุณคาด ในทางทฤษฎีคุณมี mega event handler ใน React ได้ แต่ lint rules และ React's dev tools จะส่งเสียงเตือนมากหากทำเช่นนั้น ดังนั้นโดยทั่วไปควรทำตามคำแนะนำของมัน

// you could replace the div surrounding the radio buttons and remove all the onChange handlers
<div
  onChange={(e: React.ChangeEvent<HTMLInputElement>) =>
    setPizzaSize(e.target.value as PizzaSize)
  }
>
  […]
</div>

สังเกตว่าถึงจะวาง handler ไว้บน div เราก็ยังใช้ HTMLInputElement อยู่ เพราะ e.target คือ element ที่เกิด event จริง ๆ ซึ่งก็คือ radio button ไม่ใช่ div ที่รับ event ต่อมา (ถ้าอยากได้ div ให้ใช้ e.currentTarget แทน)
