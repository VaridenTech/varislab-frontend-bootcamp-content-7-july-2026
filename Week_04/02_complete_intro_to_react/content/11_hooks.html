Hooks

โอเค ตอนนี้เราต้องการให้ผู้คนเพิ่ม pizzas ลงใน order ของตนได้ เราต้องมี form เล็ก ๆ ที่ให้เลือก pizza และขนาด สร้างไฟล์ใหม่ชื่อ Order.jsx แล้วเพิ่มสิ่งต่อไปนี้:

import Pizza from "./Pizza";

export default function Order() {
  const pizzaType = "pepperoni";
  const pizzaSize = "M";
  return (
    <div className="order">
      <h2>Create Order</h2>
      <form>
        <div>
          <div>
            <label htmlFor="pizza-type">Pizza Type</label>
            <select name="pizza-type" value={pizzaType}>
              <option value="pepperoni">The Pepperoni Pizza</option>
              <option value="hawaiian">The Hawaiian Pizza</option>
              <option value="big_meat">The Big Meat Pizza</option>
            </select>
          </div>
          <div>
            <label htmlFor="pizza-size">Pizza Size</label>
            <div>
              <span>
                <input
                  checked={pizzaSize === "S"}
                  type="radio"
                  name="pizza-size"
                  value="S"
                  id="pizza-s"
                />
                <label htmlFor="pizza-s">Small</label>
              </span>
              <span>
                <input
                  checked={pizzaSize === "M"}
                  type="radio"
                  name="pizza-size"
                  value="M"
                  id="pizza-m"
                />
                <label htmlFor="pizza-m">Medium</label>
              </span>
              <span>
                <input
                  checked={pizzaSize === "L"}
                  type="radio"
                  name="pizza-size"
                  value="L"
                  id="pizza-l"
                />
                <label htmlFor="pizza-l">Large</label>
              </span>
            </div>
          </div>
          <button type="submit">Add to Cart</button>
        </div>
        <div className="order-pizza">
          <Pizza
            name="Pepperoni"
            description="Mozzarella Cheese, Pepperoni"
            image="/public/pizzas/pepperoni.webp"
          />
          <p>$13.37</p>
        </div>
      </form>
    </div>
  );
}

ตอนนี้เพิ่มมันใน App.jsx ของคุณ:

// delete Pizza import, and add Order
import Order from "./Order";

// in App.jsx, replace all the Pizzas
<Order />
🚨 คุณจะมี errors ใน console บ้าง ซึ่งไม่เป็นไร

ตอนนี้ไปที่ http://localhost:5173/ แล้วดูว่าคุณมี inputs สองแบบ หนึ่งสำหรับชนิด pizza และ radio buttons ชุดหนึ่งสำหรับขนาด ลองเลือกบางอย่างด้วย inputs คุณจะเห็นว่าคุณเปลี่ยนมันไม่ได้ ทำไม? ลองคิดว่า React ทำงานอย่างไร: เมื่อคุณโต้ตอบกับ inputs React ตรวจพบว่า DOM event เกิดขึ้น เมื่อเกิดขึ้น React คิดว่าบางสิ่งอาจเปลี่ยน จึงรัน re-render หาก render functions ของคุณเร็ว นี่เป็นการทำงานที่เร็วมาก จากนั้นมัน diff สิ่งที่มีอยู่ตอนนี้กับสิ่งที่ render pass สร้างขึ้น แล้วอัปเดต DOM ให้น้อยที่สุดเท่าที่จำเป็น

ในหลักสูตรวิดีโอ layout เป็นแนวตั้งเพราะ order-pizza DIV อยู่ผิดตำแหน่ง ให้ใช้ markup ข้างบน Layout ควรมีลักษณะดังนี้:

สังเกตว่าเราใช้ className แทน class บน HTML element สำหรับ CSS classes นี่เป็นเพราะ class เป็น reserved word ใน JS และ JSX ก็ยังเป็น JS อยู่ ดังนั้นจึงเลือกใช้ className ซึ่งเป็น ชื่อของ JS API สำหรับโต้ตอบกับ class names

เช่นเดียวกับ className เราใช้ htmlFor เพราะ for เป็น reserved word ใน JS

ดังนั้นหากเราพิมพ์ลงใน input และมัน re-render อะไรจะออกมาใน tags select หรือ radio button? value ของมันผูกอยู่กับ pizzaType และ pizzaSize และไม่มีอะไรเปลี่ยนสองค่านั้น ดังนั้นมันจึงเหมือนเดิม กล่าวอีกนัยหนึ่ง two way data binding ไม่ได้ได้มาฟรีใน React ฉันว่ามันเป็น feature เพราะมันทำให้คุณชัดเจนว่าจะจัดการ data อย่างไร มาแก้ให้มันทำงานกัน

// in Order.jsx
import { useState } from "react";

// pizzaType and pizzaSize location
const [pizzaType, setPizzaType] = useState("pepperoni");
const [pizzaSize, setPizzaSize] = useState("medium");

// replace input
<select
  onChange={(e) => setPizzaType(e.target.value)}
  name="pizza-type"
  value={pizzaType}
>
  […]
</select>

// add to all the radio buttons
onChange={(e) => setPizzaSize(e.target.value)}

หมายเหตุผู้แปล: ตัวอย่างต้นฉบับใช้ useState("medium") แต่ค่าของ radio และ key ใน sizes[pizzaSize] คือ S, M หรือ L; ให้ใช้ useState("M") เพื่อให้เลือกขนาดกลางและคำนวณราคาเริ่มต้นได้ถูกต้อง

  • สิ่งนี้เรียกว่า hook frameworks อื่น เช่น Vue ก็นำมันไปใช้เช่นกัน
  • ในความคิดของฉัน hook ถูกเรียกเช่นนั้นเพราะเป็น hook ที่ถูกจับทุกครั้งที่ render function ถูกเรียก เนื่องจาก hooks ถูกเรียกตามลำดับเดิมทุกครั้ง มันจึงชี้ไปที่ state ชิ้นเดิมเสมอ ด้วยเหตุนี้มันจึงมี state ได้: คุณเก็บ mutable state ด้วย hooks แล้วแก้ไขภายหลังผ่าน updater functions ที่มันให้มาได้
  • แนวคิดที่สำคัญอย่างยิ่งที่คุณต้องเข้าใจคือ hooks พึ่งพาลำดับที่เคร่งครัดนี้ ดังนั้น อย่าวาง hooks ไว้ใน if statements หรือ loops หากทำ คุณจะเจอ bugs ประหลาดที่ useState คืนstate ที่ผิด หากคุณเห็น useState คืน state ผิดชิ้น นี่น่าจะเป็นสิ่งที่คุณทำ ทุก hook ต้องทำงานทุกครั้งในลำดับเดียวกัน
  • argument ที่ให้ useState คือ default value ในกรณีของเรา เราอาจให้ "" เป็น default value เพื่อบังคับให้ผู้ใช้เลือกบางอย่างก่อน แต่กรณีนี้เราต้องการตั้งค่าเริ่มต้นเป็น pepperoni pizza และขนาดกลาง
  • useState คืน array ที่มีสองสิ่ง: current value ของ state นั้น และ function สำหรับอัปเดต state เราใช้ JavaScript feature ที่เรียกว่า destructuring เพื่อเอาทั้งสองสิ่งออกจาก array
  • เราใช้ function setPizzaType / setPizzaSize ใน attribute onChange ของ input ทุกครั้งที่พิมพ์ใน input มันจะเรียก functions ที่เรียก setPizzaType และ setPizzaSize ด้วยสิ่งที่พิมพ์ เลือก หรือคลิกใน input เมื่อเรียก setPizzaType และ setPizzaSize React รู้ว่า state ถูกแก้ไขและเริ่ม re-render
  • คุณสร้าง custom hooks ของตัวเองได้; useState เป็นเพียงหนึ่งจากหลายตัว
  • ในอดีต React เขียนด้วย classes โดย state อยู่บน instance ของ component รูปแบบนี้ยังได้รับการสนับสนุนใน React เราจะดูวิธีทำภายหลัง
  • เราอาจวาง onChange handler บน radio buttons แต่ละอันได้ อย่างไรก็ตาม event bubbling ใน React ทำงานเหมือนใน DOM ปกติ และเราวางมันตรงบน div ที่ครอบ radio buttons ทั้งหมดได้ จึงทำเพียงครั้งเดียว
  • คุณใช้ useState ได้มากเท่าที่ต้องการสำหรับ state หลายส่วน! นี่เป็นอีกเหตุผลว่าทำไมลำดับจึงสำคัญ เพราะ React พึ่งพาให้เรียก useState ด้วยลำดับเดิมอย่างเคร่งครัดทุกครั้ง เพื่อส่ง state ชิ้นเดิมให้คุณ
  • คล้ายกับข้างต้น เราใช้ onChange เพราะทำให้เข้าถึงได้ง่ายกว่า
ฉันกำลังแสดงวิธีทำ “controlled form” ที่เราใช้ hooks ควบคุมแต่ละส่วนของ form ในความจริงควรปล่อยให้มัน uncontrolled (หรือไม่ตั้ง value) แล้วห่อทั้งหมดด้วย form จากนั้นฟัง submit events และใช้ event นั้นเก็บข้อมูลจาก form วิธีนี้เขียนโค้ดน้อยกว่าและไม่หนักมือ หากคุณต้องเขียน form มาตรฐาน ให้ทำเป็น uncontrolled form หากต้องทำ dynamic validation, ตอบสนองขณะที่ผู้ใช้พิมพ์แบบ typeahead (ความสามารถที่ให้คำแนะนำแบบ real-time) หรือคล้ายกัน controlled input จะเหมาะมาก นอกนั้นใช้ uncontrolled
สิ่งใหม่ใน React เรียกว่า “form action” ซึ่งถือว่ายังไม่เสถียร อนาคตคุณจะเพียงเพิ่ม <form action="blah">[…]</form> และ form action จะจัดการ form ทั้งหมดให้คุณ

ข้อสังเกตอีกอย่าง: event bubbling ใน React ทำงานเหมือนที่คุณคาด ในทางทฤษฎีคุณมี mega event handler ใน React ได้ แต่ lint rules และ React's dev tools จะส่งเสียงเตือนมากหากทำเช่นนั้น ดังนั้นฉันมักทำตามคำแนะนำของมัน

// you could replace the div surrounding the radio buttons and remove all the onChange handlers
<div onChange={(e) => setPizzaSize(e.target.value)}>[…]</div>
