บทเรียน 05 · เครื่องมือ (Tools)

การจัดรูปแบบโค้ด

Code Formatting

Prettier

การรักษาคุณภาพให้สูงขณะเขียนโค้ดเป็นเรื่องสำคัญ และนั่นคือเหตุผลที่ทีมส่วนใหญ่เลือกใช้ ESLint และ Prettier แนวคิดคือให้เครื่องรับงานน่าเบื่อไปทำแทน เราจะได้โฟกัสกับสถาปัตยกรรมและการแก้ปัญหามากขึ้น และสนใจ syntax กับ style น้อยลง แม้จะมีเครื่องมือมากมายที่ช่วยรักษาคุณภาพโค้ดได้ แต่สองตัวนี้คือแกนหลักของ workflow สมัยใหม่

Prettier คือเครื่องมืออันยอดเยี่ยมจากหัวสมองของ James Long James ก็เหมือนพวกเราหลายคนที่เบื่อการต้องกังวลเรื่อง style ของโค้ดอยู่ตลอด: จะวาง indent ตรงไหน กี่ตัว เมื่อไรควรตัดบรรทัด ฯลฯ เมื่อมาจากภาษาอย่าง Go, Reason หรือ Elm ที่ tooling ของภาษาจัดการทั้งหมดให้ เรื่องนี้ก็ชวนเหนื่อยได้เร็ว James จึงลงมือทำอะไรกับมัน และสร้างเครื่องมือมาจัดการให้: Prettier

Prettier เป็น pretty printer ที่หรูหรามาก มันนำโค้ดที่คุณเขียนมาแยกเป็น abstract syntax tree (AST) ซึ่งเป็นเพียงตัวแทนของโค้ดคุณ จากนั้นมันนำ AST นั้นไป ทิ้ง style โค้ดทั้งหมดที่คุณสร้างไว้ แล้วพิมพ์กลับออกมาโดยใช้ style ที่กำหนดไว้ล่วงหน้า แม้ฟังดูน่ากลัวเล็กน้อย แต่จริง ๆ แล้วเจ๋งมาก เพราะคุณไม่ควบคุม style ของโค้ดอีกต่อไป คุณจึงไม่ต้องคิดถึงมันเลย โค้ดของคุณสม่ำเสมออยู่เสมอ เช่นเดียวกับโค้ดจากทีมที่เหลือ ไม่มีการถกเถียงเรื่องเล็กน้อยอีกต่อไป!! ลองคิดแบบนี้: หากสมองของคุณคือ processor คุณจะได้ปล่อย thread ของสมองที่คอยกังวลเรื่อง style โค้ดและความอ่านง่ายให้ว่างลง เพราะมันเกิดขึ้นเอง ไม่ชอบ semicolon ใช่ไหม? ไม่ต้องเขียน! มันใส่ให้คุณเอง

อยากลองใช้มันสักหน่อยก่อนเชื่อใจหรือไม่? ไม่ต้องไปไหนไกล ในบทนี้เราจะติดตั้งแล้วลองรันกับโค้ดของเราเองเลย คุณจะเห็นว่ามันทำงานอย่างไร

มาเชื่อมสิ่งนี้เข้ากับโปรเจกต์กัน ขั้นตอนไม่ยากเลย

ติดตั้ง Prettier แบบ global ด้วย npm install --global prettier หรือถ้าไม่อยากติดตั้งแบบ global ทุกครั้งที่เห็นคำสั่ง prettier ให้แทนด้วย npx prettier (จาก root ของโปรเจกต์) จากนั้นรัน prettier src/App.js คำสั่งนี้จะ output ไฟล์เวอร์ชันที่จัดรูปแบบแล้ว หากต้องการเขียนทับไฟล์จริง ให้รัน prettier --write src/App.js ไปดู src/App.js แล้วคุณจะเห็นว่ามันถูกจัดรูปแบบใหม่เล็กน้อย ข้อสังเกตคือ สำหรับ React ที่ไม่ใช่ JSX prettier อาจทำให้โค้ดของคุณอ่านยากขึ้นเล็กน้อย โชคดีที่ Prettier รองรับ JSX! เราจะไปถึงเรื่องนั้นในไม่ช้า

Prettier มี configuration อยู่บ้าง แต่โดยหลักมันตั้งใจให้เป็นเครื่องมือที่ทุกคนใช้ และไม่ถกเถียง/bikeshed เกี่ยวกับกฎ style โค้ดต่าง ๆ ตัวเลือกที่ปรับได้มีไม่มาก เช่น semi (ใส่ semicolon ท้ายบรรทัดหรือไม่), singleQuote (ใช้ single quote หรือ double quote), tabWidth (ย่อหน้ากี่ช่อง) และ trailingComma ในคอร์สนี้เราจะใช้ค่าเริ่มต้นทั้งหมด ซึ่งเป็นสิ่งที่โปรเจกต์ส่วนใหญ่เลือกทำกัน Prettier เข้าใจ flow และ TypeScript ได้เช่นกัน

Prettier ใช้ร่วมกับ Visual Studio Code ได้ดีมาก เพียงเปิดแท็บ Extensions ใน VS Code แล้วค้นหา "Prettier - Code formatter" (publisher ชื่อ esbenp) จากนั้นกดติดตั้ง เคล็ดลับ: ตั้งให้มันรัน Prettier เฉพาะเมื่อตรวจพบไฟล์ config ของ Prettier วิธีนี้ทำให้คุณไม่ต้องปิดมันเลย โดยตั้ง prettier.requireConfig เป็น true และ editor.formatOnSave เป็น true

เพื่อให้เครื่องมือรู้ว่าโปรเจกต์นี้เป็นโปรเจกต์ Prettier เราจะสร้างไฟล์ชื่อ .prettierrc แล้วใส่ {} ลงไป นี่บอกทุกคนว่าเป็นโปรเจกต์ Prettier ที่ใช้ configuration ค่าเริ่มต้น คุณสามารถใส่ config อื่นในนี้ได้ หากคุณมีความเห็นเรื่องการจัดรูปแบบที่หนักแน่น

npm scripts

การพยายามจำคำสั่ง CLI ต่าง ๆ ที่ต้องรันในโปรเจกต์อาจเป็นเรื่องน่าปวดหัว คุณใส่คำสั่ง CLI ไว้ในนั้น แล้วรันชื่อของ tag และมันจะรัน script นั้น มาดูกันว่าทำงานอย่างไร ใส่สิ่งต่อไปนี้ลงใน package.json ของคุณ

ก่อนอื่นรัน npm install -D prettier@3.3.3 -D หมายความว่าใช้สำหรับ development เท่านั้น

"scripts": {
    "format": "prettier --write \"src/**/*.{js,jsx,css,html}\""
},

ตอนนี้คุณรัน npm run format ได้ และมันจะรันคำสั่งนั้น ซึ่งหมายความว่าเราไม่ต้องจำคำสั่งยาว ๆ นั้นแล้ว จำแค่ format ก็พอ ดีใช่ไหม? เราจะพึ่งสิ่งนี้มากในหลักสูตรนี้

สังเกตส่วน @3.3.3 เพื่อไม่ให้หลักสูตรนี้พังในอนาคต บทเรียนจะระบุเวอร์ชันแพ็กเกจที่ ตรงเป๊ะ กับที่ใช้ตอนเขียนเนื้อหา ตามธรรมชาติแล้วแพ็กเกจเปลี่ยนแปลงและพัฒนาไปตามเวลา ซึ่งคาดเดาล่วงหน้าไม่ได้ ดังนั้นแนะนำให้ใช้เวอร์ชันเดียวกับในบทเรียนขณะเรียน (แม้ npm จะตะโกนใส่คุณเรื่อง security vulnerabilities) เมื่อเรียนจบแล้ว คุณอัปเดตเวอร์ชันเป็นล่าสุดและดูว่ามีอะไรพังหรือไม่ได้ตามสบาย
