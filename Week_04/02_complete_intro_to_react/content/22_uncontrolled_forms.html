Uncontrolled Forms

ตอนนี้เราจะทำหน้า contact ให้เว็บไซต์ของเรา โดยรับ name, email และ message จากผู้ใช้ แล้ว submit ไป backend ของเรา เช่นเดียวกับ backends ที่ดีทั้งหลาย ของเราจะ log มันใน console แล้วก็ไม่สนใจมัน

เราจะได้เห็นสองแนวคิดใหม่: วิธีทำ post ด้วย TanStack Query (ที่เรียกว่า mutation) และวิธีทำ uncontrolled forms ด้วย React เริ่มจาก API query ของเรา ใน src/api สร้างไฟล์ชื่อ postContact.ts แล้วใส่:

export default async function postContact(
  name: string,
  email: string,
  message: string
) {
  const response = await fetch("/api/contact", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ name, email, message }),
  });

  if (!response.ok) {
    throw new Error("Network response was not ok");
  }

  return response.json();
}

สร้าง link ใหม่ไปหน้าของเราใน index.lazy.tsx

// after past orders

สร้าง route ใหม่ชื่อ contact.lazy.tsx ใน src/routes

import { createLazyFileRoute } from "@tanstack/react-router";
import { useMutation } from "@tanstack/react-query";
import postContact from "../api/postContact";

export const Route = createLazyFileRoute("/contact")({
  component: ContactRoute,
});

function ContactRoute() {
  const mutation = useMutation({
    mutationFn: function (formData: FormData) {
      return postContact(
        String(formData.get("name")),
        String(formData.get("email")),
        String(formData.get("message"))
      );
    },
  });

  return (
    <div className="contact">
      <h2>Contact</h2>
      {mutation.isSuccess ? (
        <h3>Submitted!</h3>
      ) : (
        <form
          onSubmit={(e: React.FormEvent<HTMLFormElement>) => {
            e.preventDefault();
            // ต้องอ่าน FormData ตรงนี้เลย เพราะ React ล้าง currentTarget ทิ้ง
            // ทันทีที่ handler จบ ส่วน mutationFn ถูกเรียกทีหลังแบบ async
            // currentTarget คือ <form> เสมอ ส่วน target อาจเป็นปุ่มข้างในได้
            mutation.mutate(new FormData(e.currentTarget));
          }}
        >
          <input name="name" placeholder="Name" />
          <input type="email" name="email" placeholder="Email" />
          <textarea placeholder="Message" name="message"></textarea>
          <button>Submit</button>
        </form>
      )}
    </div>
  );
}

หมายเหตุผู้แปล: ต้นฉบับของหลักสูตรส่ง mutation.mutate ให้ onSubmit ตรง ๆ แล้วให้ mutationFn รับ event เข้าไปสร้าง FormData เอง วิธีนั้นใช้ไม่ได้จริง เพราะ React จะล้าง e.currentTarget ทิ้งทันทีที่ handler ตัวนั้นจบ แต่ TanStack Query เรียก mutationFn ทีหลังแบบ async กว่าจะถึงตอนนั้น e.currentTarget เป็น null ไปแล้ว · อาการที่เจอคือ new FormData(null) โยน error แล้ว TanStack Query กลืนมันเข้าไปเก็บใน mutation error state ผลคือฟอร์มไม่ทำอะไรเลย ไม่มี request ไม่มีคำว่า Submitted! และไม่มี error ใน console ให้เห็นด้วย · เราจึงอ่าน FormData ให้เสร็จใน handler แบบ synchronous แล้วส่งเข้า mutate() เป็น parameter แทน สังเกตว่าพอถึงบทที่ 32 form actions ของ React 19 ก็พาเรามาลงที่รูปแบบเดียวกันนี้พอดี

  • เราใช้ mutation จาก TanStack React Query มันทำงานคล้าย normal gets มาก ยกเว้นตัวนี้ส่งข้อมูลไปยัง API แทนที่จะ get มัน
  • สังเกตว่าเราใช้ isSuccess เพื่อแสดงหรือซ่อน form เมื่อ mutation submit สำเร็จ เราแค่อยากแสดงสิ่งนั้นแก่ผู้ใช้ แล้วซ่อน form
  • สังเกตว่าเราไม่ใช้ state หรือ useState เลย เราใช้ “uncontrolled” form ซึ่งหมายถึงเราปล่อยให้ DOM จัดการ state เฉพาะเมื่อมี submit event เราจึงอ่านจาก DOM ด้วย FormData API แล้วใช้มัน submit contact data ไป API
  • ยังมี isError และ isIdle ด้วย แต่เราไม่ได้ใช้จาก TanStack Query
  • สังเกต mutations ใน dev tools ของ TanStack Query ด้วย (อยู่ในอีก tab)

FormData กับ TypeScript

uncontrolled form เป็นจุดที่ TypeScript ช่วยได้เยอะเป็นพิเศษ เพราะเรากำลังดึงข้อมูลออกจาก DOM ตรง ๆ ซึ่งเป็นแดนที่ไม่มีใครรับประกันอะไรให้เลย มีสองจุดที่ต่างจากเวอร์ชัน JavaScript

  • e.currentTarget ไม่ใช่ e.target — new FormData() ต้องการ HTMLFormElement เท่านั้น แต่ e.target มี type เป็น EventTarget กว้าง ๆ (มันคือ element ที่เกิด event ซึ่งอาจเป็นปุ่มข้างในก็ได้) ส่วน e.currentTarget คือ element ที่ handler ติดอยู่ ซึ่งก็คือ <form> แน่นอน และ React.FormEvent<HTMLFormElement> ก็ให้ type ที่ถูกต้องมาพอดี ไม่ต้อง cast อะไรเลย
  • String(formData.get("name")) — formData.get() คืน string | File | null เพราะ form อาจมีช่องอัปโหลดไฟล์ หรืออาจไม่มี field ชื่อนั้นเลย ส่วน postContact ของเรารับ string จึงต้องแปลงก่อน

จุดที่สองคือสิ่งที่ควรค่าแก่การหยุดคิดสักนิด ในเวอร์ชัน JavaScript ถ้าคุณพิมพ์ formData.get("nmae") ผิดสักตัว มันจะคืน null เงียบ ๆ แล้วส่ง null ขึ้น API ไปโดยไม่มีใครรู้ TypeScript บังคับให้เรามอง null ตัวนั้นและตัดสินใจกับมัน

เราเลือก String() เพราะมันง่ายและพอเหมาะกับตัวอย่างนี้ (ถ้าไม่มีค่า จะได้ "null" ซึ่งเห็นได้ชัดใน log ว่าผิด) แต่ในแอปจริงคุณควรตรวจแล้วแจ้งผู้ใช้ เช่น

const name = formData.get("name");
if (typeof name !== "string" || name.trim() === "") {
  throw new Error("กรุณากรอกชื่อ");
}

นี่เป็นบทเรียนสำคัญเกี่ยวกับ TypeScript โดยรวม: มันบอกเราได้ว่า "ตรงนี้มีกรณีที่คุณยังไม่ได้จัดการ" แต่มันเลือกวิธีจัดการแทนเราไม่ได้ ส่วนนั้นยังเป็นงานของเราเสมอ
