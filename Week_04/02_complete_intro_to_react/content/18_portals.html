Portals

ถ้าคุณกำลัง render หน้าอยู่ และอยาก render บางอย่างในอีกส่วนของหน้าไปพร้อมกันล่ะ? ลองนึกถึง contextual right navigation และหน้าหนึ่งที่อยาก render เข้า contextual nav เราอาจใช้ context ทำได้และนั่นก็ยอมรับได้ทั้งหมด แต่ยังมีอีกวิธีเจ๋ง ๆ ชื่อ portal สำหรับทำสิ่งนี้ มันยังให้เรา render ออกนอกแอปโดยสิ้นเชิงได้ด้วย เหมือนที่กำลังจะทำ

เราจะทำ modal หรือ “popover” หลายคนมองว่ามันเป็น user experience ที่ไม่ค่อยดี แต่มันเป็น use case ที่สมบูรณ์แบบสำหรับ portal เราจึงจะลองทำดู! กรณีของเรา เพราะอยากให้ modal render อยู่หน้าทุกอย่าง div ที่ modal render เข้าไปต้องอยู่ก่อนใน DOM ดังนั้นไปสร้าง div ที่ทำสิ่งนั้น เปิดไฟล์ index.html แล้วใส่:

<!-- above #root -->
<div id="modal"></div>

โดย default มันจะไม่มีอะไรอยู่ข้างใน แต่เมื่อ render modal มันจะ render ใน div นี้แทนที่จะเป็น root สร้างไฟล์ใหม่ใน src ชื่อ Modal.tsx

// basically stolen from the React docs
import { useEffect, useRef } from "react";
import type { ReactNode } from "react";
import { createPortal } from "react-dom";

type ModalProps = {
  children: ReactNode;
};

const Modal = ({ children }: ModalProps) => {
  const elRef = useRef<HTMLDivElement | null>(null);
  if (!elRef.current) {
    elRef.current = document.createElement("div");
  }

  useEffect(() => {
    const modalRoot = document.getElementById("modal");
    const el = elRef.current;
    if (!modalRoot || !el) return;

    modalRoot.appendChild(el);
    return () => {
      modalRoot.removeChild(el);
    };
  }, []);

  return createPortal(<div>{children}</div>, elRef.current);
};

export default Modal;
  • นี่ใช้ ref ref คือ reference ไปยังบางสิ่งที่ต้องเหมือนเดิมเป๊ะระหว่าง renders hook จะถูก generate / create ใหม่ ดังนั้นเราต้องใช้ ref เพราะมันจะสร้าง div แล้วส่ง div เดิม กลับมาทุก render สิ่งสำคัญคือมันต้องเป็น div เดิม เพราะมันคือ div ที่เราจะใช้ render portal
  • เราใช้ createPortal เพื่อ render เข้า modal div ใหม่นี้ที่เลือกไว้สำหรับ modal แต่จะเป็น contextual nav หรือ DOM div อื่นใดก็ได้
  • เราใช้ function ที่ return จาก effect เพื่อ clean up เมื่อ Modal นี้ถูก unmount จาก DOM ไม่เช่นนั้น memory จะรั่ว

TypeScript ใน component นี้

  • children: ReactNode — ReactNode คือ type สำหรับ "อะไรก็ได้ที่ React render ออกมาได้" ครอบคลุมทั้ง JSX, string, number, array ของสิ่งเหล่านั้น, null และ undefined เมื่อไรที่ component ของคุณรับ children ให้ใช้ตัวนี้ ทุกครั้ง
  • useRef<HTMLDivElement | null>(null) — เหมือน useState เลย ถ้าเริ่มด้วย null ต้องบอก type ให้มันรู้ว่าเดี๋ยวจะมีอะไรมาอยู่ในนั้น มิฉะนั้นเราจะกำหนดค่า document.createElement("div") ลงไปไม่ได้
  • const el = elRef.current; — บรรทัดนี้สำคัญกว่าที่เห็น ถ้าคุณใช้ elRef.current ตรง ๆ ทั้งใน appendChild และใน cleanup function TypeScript จะฟ้องว่ามันอาจเป็น null ได้ เพราะ .current เป็นค่าที่เปลี่ยนได้ — TypeScript จึงไม่ยอมจำ narrowing ข้ามขอบเขตของ closure การคัดลอกมาเก็บใน const ก่อนจึงแก้ปัญหาได้

และเช่นเคย จุดที่ TypeScript บ่นคือจุดที่โค้ดเดิมมีปัญหาจริง ๆ ในเวอร์ชัน JavaScript ถ้าคุณลืมใส่ <div id="modal"></div> ใน index.html แอปจะพังด้วย Cannot read properties of null (reading 'appendChild') ส่วนการเก็บ elRef.current ไว้ใน const ก่อนก็เป็น pattern ที่ React docs แนะนำอยู่แล้ว เพราะตอน cleanup ทำงาน ค่าใน .current อาจถูกเปลี่ยนไปแล้วก็ได้ — เราจึงอาจเผลอลบ element ผิดตัว

ก่อนใช้ Modal เราต้องมี API call function อีกตัวเพื่อ get a past order ในตัวอย่างนี้ เราจะให้คุณคลิกแถวหนึ่งในหน้า past orders เพื่อดูว่ามีอะไรใน order นั้น ก่อนอื่นเพิ่ม type ใน src/types.ts

// เพิ่มต่อจาก PastOrder
export type PastOrderItem = {
  pizzaTypeId: string;
  name: string;
  size: PizzaSize;
  quantity: number;
  price: number;
  total: number;
  image: string;
};

export type PastOrderDetail = {
  orderItems: PastOrderItem[];
};

จากนั้นใน src/api เพิ่มไฟล์ชื่อ getPastOrder.ts (ไม่มี s) แล้วใส่:

import type { PastOrderDetail } from "../types";

export default async function getPastOrder(
  order: number
): Promise<PastOrderDetail> {
  const response = await fetch(`/api/past-order/${order}`);
  const data = await response.json();
  return data;
}

จากนั้น render modal หากมี focusedOrder:

// import at top
import getPastOrder from "../api/getPastOrder";
import Modal from "../Modal";

// NOTE: In the course, Brian makes this a hook/module
const intl = new Intl.NumberFormat("en-US", {
  style: "currency",
  currency: "USD",
});

// top of the render function
const [focusedOrder, setFocusedOrder] = useState<number | undefined>();

const { data: pastOrderData } = useQuery({
  queryKey: ["past-order", focusedOrder],
  queryFn: () => getPastOrder(focusedOrder!),
  enabled: !!focusedOrder,
  staleTime: 24 * 60 * 60 * 1000, // one day in milliseconds,
});

// last thing before closing div
{
  focusedOrder ? (
    <Modal>
      <h2>Order #{focusedOrder}</h2>
      {pastOrderData ? (
        <table>
          <thead>
            <tr>
              <td>Image</td>
              <td>Name</td>
              <td>Size</td>
              <td>Quantity</td>
              <td>Price</td>
              <td>Total</td>
            </tr>
          </thead>
          <tbody>
            {pastOrderData.orderItems.map((pizza) => (
              <tr key={`${pizza.pizzaTypeId}_${pizza.size}`}>
                <td>
                  <img src={pizza.image} alt={pizza.name} />
                </td>
                <td>{pizza.name}</td>
                <td>{pizza.size}</td>
                <td>{pizza.quantity}</td>
                <td>{intl.format(pizza.price)}</td>
                <td>{intl.format(pizza.total)}</td>
              </tr>
            ))}
          </tbody>
        </table>
      ) : (
        <p>Loading …</p>
      )}
      <button onClick={() => setFocusedOrder(undefined)}>Close</button>
    </Modal>
  ) : null
}
  • เราใช้ React Query อีกครั้ง ใช้ key enabled เพื่อ request เฉพาะเมื่อผู้ใช้ตั้ง focusedOrder แล้ว หากไม่มี focusedOrder ก็จะไม่ request !! มีความหมายเดียวกับ “not not” มันทำให้ตัวเลขอย่าง 5 เป็น true และตัวเลขอย่าง 0 หรือ undefined เป็น false
  • เราตั้ง staleTime เป็นหนึ่งวัน orders เหล่านี้ไม่น่าจะเปลี่ยนบ่อยนัก
  • หากไม่มี focusedOrder เราไม่ render Modal จึงไม่มีการใช้ portal
  • หากมี focusedOrder เรา render modal และแสดง loading indicator ว่ากำลังโหลดข้อมูลที่เหลือ
  • เมื่อผู้ใช้คลิก Close เราตั้ง focusedOrder เป็น undefined อีกครั้ง ซึ่งทำให้ Modal unrender

สามจุดที่ TypeScript เปลี่ยนโค้ดชุดนี้

  • setFocusedOrder(undefined) ต้องใส่ undefined ให้ครบ — เวอร์ชัน JavaScript เขียน setFocusedOrder() เฉย ๆ ได้ แต่ TypeScript ถือว่า setter จาก useState รับ argument หนึ่งตัวเสมอ จึงต้องส่ง undefined เข้าไปตรง ๆ ความหมายเหมือนกันทุกประการ แค่ต้องเขียนให้ชัดเจนขึ้น
  • เราเปลี่ยนจาก !isLoadingPastOrder เป็น pastOrderData ? — ด้วยเหตุผลเดียวกับบทที่แล้ว: isLoading ไม่ narrow pastOrderData ให้เรา แต่การเช็คตัวข้อมูลเองทำได้ และผลลัพธ์ที่ผู้ใช้เห็นก็เหมือนเดิม (แถมยังครอบคลุมกรณี API error ไปด้วย) พอเราไม่ได้ใช้ isLoadingPastOrder แล้ว ก็ลบมันออกจากการ destructure ไปเลย ไม่งั้น ESLint จะเตือนว่ามีตัวแปรที่ประกาศทิ้งไว้เฉย ๆ
  • getPastOrder(focusedOrder!) — จำที่เตือนไว้ในบทที่ 10 ได้ไหมว่า ! และ as ควรใช้ให้น้อยที่สุด? ตรงนี้คือหนึ่งในไม่กี่กรณีที่มันสมเหตุสมผลจริง เพราะ enabled: !!focusedOrder รับประกันว่า queryFn จะไม่มีวันถูกเรียกตอนที่ focusedOrder เป็น undefined — แต่ TypeScript มองไม่เห็นความสัมพันธ์ระหว่างสอง option นี้ นี่เป็น pattern ที่เอกสารของ TanStack Query เองก็แนะนำ

สุดท้ายเราต้องมีวิธีเปิด modal เปิด past.lazy.tsx ทำค่า order.order_id ให้เป็น button และเพิ่ม onClick event เพื่อให้การคลิกเปิด Modal:

<td>
  <button onClick={() => setFocusedOrder(order.order_id)}>

  </button>
