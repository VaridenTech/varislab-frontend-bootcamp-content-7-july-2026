Handling User Input

ก่อนอื่น ของหนึ่งชิ้นในตะกร้าไม่ใช่แค่พิซซ่า แต่เป็น "พิซซ่า + ขนาดที่เลือก + ราคาที่คิดแล้ว" มาเพิ่ม type ของมันใน src/types.ts กัน

// เพิ่มต่อจาก Pizza
export type CartItem = {
  pizza: Pizza;
  size: PizzaSize;
  price: string;
};

สังเกตว่า price เป็น string ไม่ใช่ number เพราะเราเก็บค่าที่ผ่าน intl.format() มาแล้ว (เช่น "$12.50") นี่เป็นจุดที่ type ช่วยเตือนความจำเราได้ดีมาก — พอเห็นว่ามันเป็น string ก็รู้ทันทีว่าเอาไปบวกลบเลขไม่ได้ ต้องย้อนไปหยิบตัวเลขจริงจาก pizza.sizes แทน ซึ่งเป็นสิ่งที่ Cart ทำอยู่พอดี

ทีนี้มาเพิ่มสิ่งที่เราต้องใช้ใน Order.tsx กัน

// add import
import Cart from "./Cart";
import type { CartItem } from "./types";

// add another hook
const [cart, setCart] = useState<CartItem[]>([]);

// replace <form>
<form
  onSubmit={(e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    if (!selectedPizza) return;
    setCart([...cart, { pizza: selectedPizza, size: pizzaSize, price }]);
  }}
>
  […]
</form>;

// just inside the last closing div
{
  loading ? <h2>LOADING …</h2> : <Cart cart={cart} />
}

ตอนนี้เราใช้ onSubmit เพื่อจัดการการเพิ่มลง cart ยอดเยี่ยม! จากนั้นเราส่งมันเข้า Cart เพื่อให้แสดงผลอย่างสวยงาม

  • useState<CartItem[]>([]) — array ว่างเป็นอีกกรณีที่ TypeScript เดา type ไม่ออก ถ้าไม่ใส่ generic มันจะได้ never[] แล้วคุณจะใส่อะไรลงไปไม่ได้เลย เป็นคู่หูของ useState<T | null>(null) ที่เจอในบทที่แล้ว
  • if (!selectedPizza) return; เป็นบรรทัดที่ TypeScript บังคับให้เราเพิ่ม เพราะ selectedPizza ยังเป็น Pizza | undefined อยู่ (จำบทที่ 13 ได้ไหม) และ CartItem.pizza รับเฉพาะ Pizza ผลคือเราจะไม่มีวันเผลอใส่ของว่างเปล่าลงตะกร้าตอนที่ยังโหลดข้อมูลไม่เสร็จ

มาสร้าง cart กัน สร้างไฟล์ชื่อ Cart.tsx แล้วเพิ่ม

import type { CartItem } from "./types";

const intl = new Intl.NumberFormat("en-US", {
  style: "currency",
  currency: "USD", // feel free to change to your local currency
});

type CartProps = {
  cart: CartItem[];
  checkout?: () => void;
};

export default function Cart({ cart, checkout }: CartProps) {
  let total = 0;
  for (let i = 0; i < cart.length; i++) {
    const current = cart[i];
    total += current.pizza.sizes[current.size];
  }
  return (
    <div className="cart">
      <h2>Cart</h2>
      <ul>
        {cart.map((item, index) => (
          <li key={index}>
            <span className="size">{item.size}</span> –
            <span className="type">{item.pizza.name}</span> –
            <span className="price">{item.price}</span>
          </li>
        ))}
      </ul>
      <p>Total: {intl.format(total)}</p>
      <button onClick={checkout}>Checkout</button>
    </div>
  );
}
โดยปกติการทำ key แบบนี้เป็นความคิดที่ไม่ดี แต่เราคงไม่จัดลำดับ list นี้ใหม่ และก็ไม่สนว่ามัน rerender อยู่แล้ว จึงผ่านได้

เรื่องน่าสังเกตใน CartProps คือ checkout?: () => void เครื่องหมาย ? ทำให้มันเป็น prop ที่จะส่งหรือไม่ส่งก็ได้ ซึ่งจำเป็นตรงนี้ เพราะข้างบนเราเพิ่ง render <Cart cart={cart} /> โดยยังไม่มี checkout — ถ้าไม่ใส่ ? TypeScript จะฟ้องทันที ส่วน () => void อ่านว่า "ฟังก์ชันที่ไม่รับ argument และไม่คืนค่า" นี่คือวิธีให้ type กับ prop ที่เป็นฟังก์ชัน ซึ่งเราจะได้ใช้บ่อยมากตั้งแต่นี้ไป

ตอนนี้เรามีประสบการณ์ shopping cart ที่ดี แล้วจะ checkout บน server จริงอย่างไร? มาทำกัน! เราน่าจะทำที่ระดับ Order มันมี Cart อยู่แล้ว และเราปล่อย Cart ไว้เป็น dumb display component ได้ เราเพียงส่ง function เข้า Cart component แล้วเรียกมัน และรัน function ที่ระดับ Order

// inside the render body
async function checkout() {
  setLoading(true);

  await fetch("/api/order", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      cart,
    }),
  });

  setCart([]);
  setLoading(false);
}

// replace Cart
<Cart checkout={checkout} cart={cart} />;

ตอนนี้เราส่ง checkout function เข้าไปได้ และเมื่อใครคลิกใน form มันจะรัน checkout function จาก Order components เรากำลังทำ loading animation ง่าย ๆ ทำ fetch แล้วล้าง status เมื่อทุกอย่างเสร็จ ไม่เลวเลย!
