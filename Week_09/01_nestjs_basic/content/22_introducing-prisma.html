รู้จัก TypeORM Module

เมื่อจบบทนี้ คุณจะสามารถ

  • ติดตั้ง dependencies ที่จำเป็นสำหรับใช้ TypeORM กับ PostgreSQL ใน NestJS
  • ตั้งค่า TypeOrmModule.forRoot() ใน AppModule ให้เชื่อมต่อฐานข้อมูลได้จริง
  • อธิบายได้ว่า autoLoadEntities และ synchronize ทำอะไร และทำไม synchronize ห้ามใช้ใน production

TypeORM คือสะพานระหว่าง TypeScript กับ SQL

TypeORM เป็น Object-Relational Mapper (ORM) ที่ให้เรานิยามตารางเป็น class และ query ข้อมูลผ่าน method ของ TypeScript แทนการเขียน SQL ดิบทุกครั้ง NestJS มี integration ทางการผ่านแพ็กเกจ @nestjs/typeorm ซึ่งห่อ TypeORM ไว้ในระบบ module และ dependency injection ของ Nest ทำให้เราขอใช้ repository ของ entity ใดก็ได้จาก constructor โดยตรง

เริ่มจากติดตั้ง 3 แพ็กเกจ: ตัว integration ของ Nest, ตัว TypeORM เอง และ driver ของ PostgreSQL

npm install @nestjs/typeorm typeorm pg

ตั้งค่า forRoot ที่ AppModule เพียงครั้งเดียว

TypeOrmModule.forRoot() ใช้ตั้งค่า connection หลักของทั้งแอป จึงเรียกครั้งเดียวที่ root module ค่าที่ใส่คือค่าเดียวกับที่เรากำหนดใน docker-compose.yml เมื่อบทที่ 20

import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { AppController } from './app.controller';
import { AppService } from './app.service';
import { CoffeesModule } from './coffees/coffees.module';

@Module({
  imports: [
    CoffeesModule,
    TypeOrmModule.forRoot({
      type: 'postgres',
      host: 'localhost',
      port: 5432,
      username: 'postgres',
      password: 'pass123',
      database: 'postgres',
      autoLoadEntities: true,
      synchronize: true,
    }),
  ],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}
ตัวเลือกหน้าที่ข้อควรระวัง
type, host, port, username, password, databaseระบุชนิดฐานข้อมูลและวิธีเชื่อมต่อต้องตรงกับค่าใน docker-compose.yml ไม่เช่นนั้นแอป start ไม่ขึ้น
autoLoadEntities: trueโหลด entity ทุกตัวที่ลงทะเบียนผ่าน forFeature() อัตโนมัติช่วยให้ไม่ต้อง maintain array entities เองในทุก ๆ ครั้งที่เพิ่ม entity ใหม่
synchronize: truesync โครงสร้าง entity กับตารางในฐานข้อมูลให้อัตโนมัติทุกครั้งที่แอปรันสะดวกมากตอน dev แต่ต้องปิดใน production เพราะอาจแก้/ลบโครงสร้างตารางจริงโดยไม่ตั้งใจ

synchronize: true เหมาะกับการเรียนรู้และ prototype เท่านั้น ใน production ให้ปิดแล้วจัดการโครงสร้างผ่าน migrations ซึ่งเราจะทำกันในบทที่ 31

เชื่อม iluvcoffee เข้ากับ Postgres

ติดตั้ง dependencies แล้วเพิ่ม TypeOrmModule.forRoot() เข้าไปใน imports ของ AppModule ตามโค้ดด้านบน จากนั้นรันแอปโดยที่ Docker container ยังเปิดอยู่

npm install @nestjs/typeorm typeorm pg docker-compose up -d npm run start:dev

ผลลัพธ์ที่คาดหวัง

แอป start ขึ้นตามปกติโดยมี log ของ InstanceLoader แสดงว่า TypeOrmCoreModule ถูก initialize สำเร็จ ถ้า connection ผิด (เช่น ลืมเปิด Docker หรือรหัสผ่านไม่ตรง) แอปจะ throw error ตอน start ทันที ซึ่งเป็นสัญญาณที่ดี — ปัญหา config โผล่เร็วดีกว่าโผล่ตอน runtime

ตรวจว่าใช้งานได้จริง

  • package.json มี @nestjs/typeorm, typeorm และ pg อยู่ใน dependencies
  • npm run start:dev ขึ้นข้อความ initialize สำเร็จ ไม่มี ECONNREFUSED หรือ authentication error
  • ทดลอง docker-compose down แล้วรันแอปอีกครั้ง — ควรเห็น connection error เพื่อยืนยันว่าแอปเชื่อมกับ container นี้จริง (อย่าลืม up -d กลับ)
  • endpoint เดิมของ coffees ยังตอบสนองได้ตามปกติ เพราะเรายังไม่ได้เปลี่ยน service ไปใช้ฐานข้อมูล
