สร้าง Dynamic Module

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายข้อจำกัดของ static module ที่ config ตายตัวจนใช้ซ้ำข้ามบริบทไม่ได้
  • เขียนเมธอด static register(options) ที่ return DynamicModule
  • ใช้ dynamic module รับค่าจากผู้เรียก (เช่น connection options) ตอน import

ปัญหา: module แบบ static ปรับแต่งไม่ได้

ลองนึกถึง DatabaseModule ที่สร้าง connection provider ไว้ภายใน: ถ้าเขียน host/port ตายตัวใน module ผู้ใช้ทุกคนจะได้ connection เดียวกันหมด ปรับต่อไม่ได้เลย นี่คือรูปแบบที่เราจะเริ่มจากมันก่อน

# สร้าง DatabaseModule
nest g mo database
// ความพยายามแรก: provider "CONNECTION" ที่ config ฝังตายตัว
{
  provide: 'CONNECTION',
  useValue: new DataSource({
    type: 'postgres',
    host: 'localhost',
    port: 5432
  }).initialize(),
}

Module ประเภทนี้ต้องการสิ่งเดียวกับที่ TypeOrmModule.forRoot(...) หรือ ConfigModule.forRoot(...) ทำให้เราเห็นมาตลอด: ให้ผู้ import เป็นคนส่ง config เข้ามา — กลไกเบื้องหลังของ pattern นั้นคือ Dynamic Module

ทางออก: static register() ที่ return DynamicModule

Dynamic module คือ module ที่มี static method (ตามธรรมเนียมชื่อ register, forRoot หรือ forFeature) รับ options แล้ว return object ตาม interface DynamicModule ซึ่งประกอบ providers ขึ้น ณ ตอนเรียก จึงฝังค่าจากผู้ใช้ลงไปได้

// โครงเริ่มต้น
export class DatabaseModule {
  static register(options: DataSourceOptions): DynamicModule {  }
}

// เวอร์ชันสมบูรณ์: สร้าง CONNECTION จาก options ที่ผู้เรียกส่งมา
export class DatabaseModule {
  static register(options: DataSourceOptions): DynamicModule {
    return {
      module: DatabaseModule,
      providers: [
        {
          provide: 'CONNECTION',
          useValue: new DataSource(options),
        }
      ]
    }
  }
}

ฝั่งผู้ใช้ import ด้วยการเรียกเมธอดแทนการอ้างชื่อ class เฉย ๆ

// ใช้ dynamic DatabaseModule ใน imports ของ module อื่น
imports: [
  DatabaseModule.register({ // ส่งค่าจริงเข้าไปตอน import
    type: 'postgres',
    host: 'localhost',
    username: process.env.DATABASE_USER,
    password: process.env.DATABASE_PASSWORD,
  })
]

คอร์สต้นฉบับย้ำหลายรอบ: ถ้าคุณโค้ดตามและจะเก็บ dynamic module นี้ไว้ใช้ต่อ อย่าลืมส่ง username และ password เข้า DatabaseModule.register() ด้วย ไม่อย่างนั้น DataSource จะต่อฐานข้อมูลไม่สำเร็จในบทหลัง ๆ

สร้าง DatabaseModule.register ของตัวเอง

generate DatabaseModule, เขียน static register(options: DataSourceOptions) ตามตัวอย่าง แล้ว import จาก CoffeeRatingModule (บทที่ 32) พร้อมส่ง options ครบทั้ง type, host, username, password จากนั้น inject token 'CONNECTION' ที่ไหนสักแห่งเพื่อดูว่าได้ DataSource ที่ config ตรงกับที่ส่ง

nest g mo database // coffee-rating.module.ts imports: [ DatabaseModule.register({ type: 'postgres', host: 'localhost', username: process.env.DATABASE_USER, password: process.env.DATABASE_PASSWORD, }), ] npm run start:dev

ผลลัพธ์ที่คาดหวัง

แอป start ได้ปกติ และเมื่อ log ค่า DataSource.options จากตัวที่ inject มา จะเห็น host/username ตรงกับที่ส่งเข้า register() — module เดียวกันนี้สามารถถูก import ที่อื่นด้วย options คนละชุดได้ทันที ซึ่งเป็นสิ่งที่ static module ทำไม่ได้

ตรวจว่าใช้งานได้จริง

  • ตรวจว่า register() return object ที่มีทั้ง module: DatabaseModule และ providers
  • log options ของ DataSource ที่ inject มา แล้วเทียบกับค่าที่ส่งตอน import ว่าตรงกัน
  • ทดลอง import DatabaseModule.register() ด้วย host ปลอมใน module อื่น — สอง instance ต้องได้ config ต่างกัน
  • ยืนยันว่าใส่ username/password แล้วตามคำเตือนของคอร์ส
