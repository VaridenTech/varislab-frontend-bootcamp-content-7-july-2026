Validate ตัวแปรแวดล้อมด้วย Schema

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายประโยชน์ของ fail fast: ให้แอปปฏิเสธการ start เมื่อ environment ไม่ครบ แทนที่จะพังกลางทาง
  • ติดตั้ง Joi และประกาศ validationSchema ให้ ConfigModule
  • กำหนดตัวแปรแบบ required และแบบมีค่า default ได้

ทำไมต้อง validate environment ตั้งแต่ตอน start

ถ้า DATABASE_HOST หายไป แอปจะ start สำเร็จแต่ไปพังตอนพยายามต่อฐานข้อมูล — อาการแบบนี้วินิจฉัยยากเพราะ error โผล่ไกลจากต้นเหตุ วิธีที่ดีกว่าคือประกาศ schema ของตัวแปรที่จำเป็นทั้งหมด แล้วให้ ConfigModule ตรวจตอน bootstrap: ถ้าขาดหรือผิดชนิด แอปจะ throw ทันทีพร้อมข้อความบอกว่า key ไหนมีปัญหา

ติดตั้ง Joi และประกาศ schema

คอร์สต้นฉบับใช้ไลบรารี Joi สำหรับเขียน object schema แบบ declarative:

npm install @hapi/joi
npm install --save-dev @types/hapi__joi
// app.module.ts
import * as Joi from '@hapi/joi';

@Module({
  imports: [
    ConfigModule.forRoot({
      validationSchema: Joi.object({
        DATABASE_HOST: Joi.required(),
        DATABASE_PORT: Joi.number().default(5432),
      }),
    }),
    // ...
  ],
})
export class AppModule {}

สองบรรทัดใน schema นี้เล่าเรื่องต่างกัน: DATABASE_HOST เป็นค่า required — ไม่มีแล้ว start ไม่ได้; ส่วน DATABASE_PORT ต้องเป็นตัวเลข แต่ถ้าไม่ตั้งมาก็ fallback เป็น 5432 ให้อัตโนมัติ

แพ็กเกจ @hapi/joi ถูก deprecated แล้ว — เวอร์ชันปัจจุบันย้ายไปอยู่ที่แพ็กเกจชื่อ joi (import ด้วย import * as Joi from 'joi' และไม่ต้องติดตั้ง types แยก) แนวคิดและ API ที่ใช้ในบทนี้เหมือนเดิมทุกประการ ตรวจรายละเอียดจากเอกสาร NestJS หัวข้อ Schema validation

ทำให้แอป fail fast เมื่อ env ไม่ครบ

เพิ่ม validationSchema ให้ครอบคลุมตัวแปร DATABASE_* ของ iluvcoffee จากนั้นทดสอบโดยลบ DATABASE_HOST ออกจาก .env ชั่วคราวเพื่อดู error ตอน start แล้วใส่กลับ

npm install @hapi/joi npm install --save-dev @types/hapi__joi // เพิ่ม validationSchema ใน ConfigModule.forRoot() // จากนั้นทดสอบ fail fast: # 1) คอมเมนต์บรรทัด DATABASE_HOST ใน .env # 2) npm run start:dev → ควรเห็น validation error # 3) เอาคอมเมนต์ออก แล้ว start ใหม่

ผลลัพธ์ที่คาดหวัง

เมื่อ DATABASE_HOST หายไป แอปหยุดทันทีพร้อมข้อความประมาณ Config validation error: "DATABASE_HOST" is required — ไม่ใช่ start สำเร็จแล้วไปพังตอน query และเมื่อใส่ค่ากลับ แอปกลับมา start ได้ปกติ

ตรวจว่าใช้งานได้จริง

  • ลบ DATABASE_HOST แล้ว start — เห็น validation error ที่ระบุชื่อ key ชัดเจน
  • ลบ DATABASE_PORT แล้ว start — แอปทำงานได้โดยใช้ default 5432 (ต่อฐานข้อมูลสำเร็จ)
  • ตั้ง DATABASE_PORT=abc — เห็น error ว่าต้องเป็น number
  • เมื่อ .env ครบถ้วน GET /coffees ยังทำงานปกติ
