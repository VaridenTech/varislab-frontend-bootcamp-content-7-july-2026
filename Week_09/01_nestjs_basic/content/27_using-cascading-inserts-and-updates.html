ใช้ Cascading Inserts และ Updates

เมื่อจบบทนี้ คุณจะสามารถ

  • เปิด cascading บน relation ด้วย option cascade: true และบอกได้ว่ามันช่วยอะไร
  • เขียน helper preloadFlavorByName ที่ reuse flavor เดิมหรือสร้างใหม่เมื่อยังไม่มี
  • ปรับ create และ update ให้บันทึกกาแฟพร้อม flavors ได้ในคำขอเดียว

ให้การ save กาแฟพา flavor ไปด้วย

ตอนนี้ POST /coffees พร้อม flavors จะยังไม่บันทึกความสัมพันธ์ลงตารางเชื่อม เพราะ TypeORM ไม่รู้ว่าควรทำอะไรกับ entity ปลายทางที่ยังไม่มีอยู่ Cascading คือการบอกว่า "เมื่อ save ฝั่ง owner ให้ save entity ที่ผูกอยู่ด้วย" เปิดได้ที่ option ตัวที่สามของ @ManyToMany()

/* coffee.entity.ts */
@JoinTable()
@ManyToMany(
  type => Flavor,
  flavor => flavor.coffees,
  {
    cascade: true, // หรือระบุเฉพาะบางอย่าง เช่น ['insert']
  },
)
flavors: Flavor[];

สังเกตว่า type ของ property เปลี่ยนจาก string[] เป็น Flavor[] แล้ว — ข้อมูลที่ไหลผ่าน service ต่อจากนี้เป็น entity จริง ไม่ใช่ string เปล่า

reuse flavor เดิม อย่าสร้างซ้ำ

ถ้าปล่อยให้ cascade สร้าง flavor ใหม่ทุกครั้ง ตาราง flavor จะเต็มไปด้วย chocolate ซ้ำ ๆ วิธีแก้คือ helper ที่ค้นหาด้วยชื่อก่อน: เจอก็คืนตัวเดิม ไม่เจอจึงสร้างใหม่ ซึ่งต้องฉีด repository ของ Flavor เพิ่มเข้ามาใน service ด้วย

@Injectable()
export class CoffeesService {
  constructor(
    @InjectRepository(Coffee)
    private readonly coffeeRepository: Repository<Coffee>,
    @InjectRepository(Flavor)
    private readonly flavorRepository: Repository<Flavor>,
  ) {}

  async create(createCoffeeDto: CreateCoffeeDto) {
    const flavors = await Promise.all(
      createCoffeeDto.flavors.map(name => this.preloadFlavorByName(name)),
    );

    const coffee = this.coffeeRepository.create({
      ...createCoffeeDto,
      flavors,
    });
    return this.coffeeRepository.save(coffee);
  }

  async update(id: string, updateCoffeeDto: UpdateCoffeeDto) {
    const flavors =
      updateCoffeeDto.flavors &&
      (await Promise.all(
        updateCoffeeDto.flavors.map(name => this.preloadFlavorByName(name)),
      ));

    const coffee = await this.coffeeRepository.preload({
      id: +id,
      ...updateCoffeeDto,
      flavors,
    });
    if (!coffee) {
      throw new NotFoundException(`Coffee #${id} not found`);
    }
    return this.coffeeRepository.save(coffee);
  }

  private async preloadFlavorByName(name: string): Promise<Flavor> {
    const existingFlavor = await this.flavorRepository.findOne({ where: { name } });
    if (existingFlavor) {
      return existingFlavor;
    }
    return this.flavorRepository.create({ name });
  }
}

ใน update เงื่อนไข updateCoffeeDto.flavors && ... สำคัญมาก: PATCH ที่ไม่ได้ส่ง flavors มาจะได้ undefined และ preload จะไม่ไปยุ่งกับ relation เดิม — ส่งมาเมื่อไหร่จึงค่อยแทนที่ทั้งชุด

อย่าลืมว่า @InjectRepository(Flavor) ใช้ได้ก็ต่อเมื่อ Flavor ถูกลงทะเบียนใน TypeOrmModule.forFeature([Coffee, Flavor]) ของ module แล้ว ไม่เช่นนั้นจะเจอ error Nest can't resolve dependencies ตอน start

สร้างกาแฟพร้อม flavors ในคำขอเดียว

เปิด cascade: true ที่ entity, เพิ่ม flavorRepository และ preloadFlavorByName เข้า service แล้วปรับ create/update ตามโค้ดด้านบน จากนั้นทดสอบ

POST http://localhost:3000/coffees { "name": "Shipwreck Roast", "brand": "Buddy Brew", "flavors": ["chocolate", "vanilla"] } # ยิงซ้ำอีกครั้งด้วย flavor เดิมบางตัว POST http://localhost:3000/coffees { "name": "Salemander Roast", "brand": "Buddy Brew", "flavors": ["chocolate", "caramel"] }

ผลลัพธ์ที่คาดหวัง

คำขอแรกสร้างกาแฟพร้อม flavor chocolate และ vanilla ในตาราง flavor คำขอที่สอง reuse แถว chocolate เดิม (id เดิม) และสร้างเฉพาะ caramel เพิ่ม — ตาราง flavor มี 3 แถว ไม่ใช่ 4 และตารางเชื่อมผูกความสัมพันธ์ครบทุกคู่

ตรวจว่าใช้งานได้จริง

  • POST พร้อม flavors แล้ว GET /coffees เห็น flavors กลับมาเป็น object ที่มี id จริง
  • ตาราง flavor ไม่มีชื่อซ้ำ แม้จะ POST ด้วย flavor เดิมหลายครั้ง
  • PATCH โดยไม่ส่ง flavors — relation เดิมต้องไม่หาย; PATCH พร้อม flavors ชุดใหม่ — ต้องแทนที่ชุดเดิม
  • แอปไม่ throw Nest can't resolve dependencies แปลว่า repository ทั้งสองถูกลงทะเบียนครบ
