รู้จัก Jest

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายได้ว่า NestJS integrate กับ Jest ให้ตั้งแต่ scaffold โปรเจกต์ โดยไม่ต้องตั้งค่าเพิ่ม
  • รัน unit tests, เก็บ coverage และรัน e2e tests ด้วย npm scripts ที่มีให้
  • ชี้ได้ว่าไฟล์ทดสอบและ config ของ Jest อยู่ตรงไหนในโปรเจกต์

ทำไมถึงเป็น Jest

NestJS ไม่ได้บังคับ testing framework — จะใช้ตัวไหนก็ได้ แต่การตั้งค่าทุกอย่างเองตั้งแต่ต้น (test runner, assertion, mocking, TypeScript transform) เป็นงานน่าเบื่อ Nest จึงเลือก integrate กับ Jest มาให้แบบ out-of-the-box: โปรเจกต์ที่สร้างด้วย nest new มีทั้ง dependencies, config และไฟล์ทดสอบตัวอย่างพร้อมรันทันที

Jest ให้ครบในแพ็กเกจเดียว: เป็นทั้ง test runner, มี assertion API (expect), มีระบบ mock ในตัว (jest.fn(), jest.mock()) และรายงาน coverage ได้โดยไม่ต้องติดตั้งเครื่องมือเสริม

คำสั่งที่มีให้ตั้งแต่ scaffold

# รัน unit tests ทั้งหมด
npm run test

# รัน unit tests พร้อมเก็บ coverage
npm run test:cov

# รัน e2e tests
npm run test:e2e
คำสั่งทดสอบอะไรไฟล์ที่มอง
npm run testunit tests: class/function เดี่ยว ๆ พร้อม mock dependenciessrc/**/*.spec.ts
npm run test:covเหมือน test แต่สรุปสัดส่วนโค้ดที่ถูกทดสอบลงโฟลเดอร์ coverage/src/**/*.spec.ts
npm run test:e2eระบบทั้งเส้นทาง: boot แอปจริงแล้วยิง HTTP เข้าไปtest/**/*.e2e-spec.ts (config ที่ test/jest-e2e.json)

ตอน scaffold Nest สร้างไฟล์ตัวอย่างให้แล้วสองแบบ: src/app.controller.spec.ts (unit) และ test/app.e2e-spec.ts (e2e) — เปิดอ่านสองไฟล์นี้ได้เลยเพื่อเห็นโครงก่อนเราลงลึกในบทถัด ๆ ไป

รันชุดทดสอบที่มากับโปรเจกต์

ยังไม่ต้องเขียนอะไรใหม่ — รันคำสั่งทั้งสามใน iluvcoffee เพื่อดูว่าแต่ละแบบให้ผลอย่างไร และสังเกตว่าไฟล์ spec ตัวอย่างบางไฟล์อาจ fail ถ้าเราแก้ controller/service ไปมากแล้ว (ซึ่งเป็นเรื่องปกติ เราจะแก้กันในบทถัดไป)

npm run test npm run test:cov # e2e จะ boot แอปจริง — ถ้า fail เพราะ dependency ของ database ให้จดไว้ก่อน npm run test:e2e

ผลลัพธ์ที่คาดหวัง

Jest รายงานผลเป็นรายไฟล์ (PASS/FAIL พร้อมชื่อ test) และ test:cov พิมพ์ตาราง coverage ราย file ลง terminal พร้อมสร้างโฟลเดอร์ coverage/ — ถ้าบาง test fail เพราะโค้ดที่เราแก้ระหว่างคอร์ส ถือว่าตรงตามคาด และเป็นโจทย์ของบทถัดไป

ตรวจว่าใช้งานได้จริง

  • npm run test รันจบและพิมพ์สรุปจำนวน test suites/tests
  • เปิด coverage/lcov-report/index.html ในเบราว์เซอร์แล้วเห็นรายงาน coverage รายไฟล์
  • เปิด package.json ดูว่า scripts test, test:cov, test:e2e ชี้ไปที่ Jest จริง
  • เปิด test/jest-e2e.json และสังเกต testRegex ว่าจับเฉพาะ .e2e-spec.ts
