ดึง Entities พร้อม Relations

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายได้ว่าทำไม TypeORM ไม่โหลด relation มาให้อัตโนมัติ และต้องขอเองอย่างไร
  • ใช้ find option relations ใน find() และ findOne() เพื่อดึงข้อมูลที่ผูกกันมาด้วย
  • ตรวจสอบ response ว่ามี array flavors ติดมากับกาแฟแต่ละตัวจริง

Relation ไม่ถูกโหลดมาโดย default

หลังจากบทที่แล้ว ฐานข้อมูลของเรามี 3 ตาราง: coffee, flavor และ coffee_flavors_flavor ที่แทนความสัมพันธ์ many-to-many แต่ถ้ายิง GET /coffees ตอนนี้ จะพบว่า response ไม่มี flavors กลับมาเลย — TypeORM จงใจไม่ join ตารางให้อัตโนมัติ เพราะการโหลด relation ทุกครั้งโดยไม่จำเป็นคือต้นทุน query ที่แพงโดยเปล่าประโยชน์

เมื่อไหร่ที่อยากได้ relation มาด้วย เราต้องระบุอย่างชัดเจนผ่าน find options

return this.coffeeRepository.find({
  relations: {
    flavors: true,
  },
});

เพิ่ม relations เข้า findAll และ findOne

ใน CoffeesService จุดที่อ่านข้อมูลมีสองแห่งคือ findAll() และ findOne() เพิ่ม option เดียวกันเข้าไปทั้งคู่

import { Injectable, NotFoundException } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import { CreateCoffeeDto } from './dto/create-coffee.dto';
import { UpdateCoffeeDto } from './dto/update-coffee.dto';
import { Coffee } from './entities/coffee.entity';

@Injectable()
export class CoffeesService {
  constructor(
    @InjectRepository(Coffee)
    private readonly coffeeRepository: Repository<Coffee>,
  ) {}

  findAll() {
    return this.coffeeRepository.find({
      relations: {
        flavors: true,
      },
    });
  }

  async findOne(id: string) {
    const coffee = await this.coffeeRepository.findOne({
      where: {
        id: +id,
      },
      relations: {
        flavors: true,
      },
    });
    if (!coffee) {
      throw new NotFoundException(`Coffee #${id} not found`);
    }
    return coffee;
  }

  // create / update / remove คงเดิมจากบทที่ 24
}

รูปแบบ object relations: { flavors: true } รองรับ relation ซ้อนกันได้ด้วย เช่น { flavors: { someNested: true } } — ระบุเฉพาะเท่าที่หน้างานต้องใช้จริง response จะได้ไม่บวมและ query ไม่ join เกินจำเป็น

อย่าแก้ปัญหา "อยากได้ relation ทุกครั้ง" ด้วยการเปิด eager loading ที่ตัว entity ทั้งระบบ — มันทำให้ทุก query ในแอปแบกการ join นั้นไปด้วยโดยมองไม่เห็นจากโค้ดที่เรียก การระบุที่จุดเรียกแบบนี้ชัดเจนกว่า

ทำให้ endpoint คืน flavors มาด้วย

เพิ่ม relations ใน findAll() และ findOne() ตามโค้ดด้านบน จากนั้นเพิ่มข้อมูล flavor ลงตารางโดยตรงชั่วคราวเพื่อทดสอบ (บทถัดไปเราจะทำให้ POST จัดการเรื่องนี้ให้เอง)

# ใน pgAdmin Query Tool - ใส่ข้อมูลทดสอบ INSERT INTO flavor (name) VALUES ('chocolate'), ('vanilla'); INSERT INTO coffee (name, brand) VALUES ('Shipwreck Roast', 'Buddy Brew'); INSERT INTO coffee_flavors_flavor ("coffeeId", "flavorId") VALUES (1, 1), (1, 2); # แล้วยิงทดสอบ GET http://localhost:3000/coffees GET http://localhost:3000/coffees/1

ผลลัพธ์ที่คาดหวัง

ทั้งสอง endpoint คืนกาแฟพร้อม property flavors เป็น array ของ object เต็ม ๆ เช่น [{ "id": 1, "name": "chocolate" }, { "id": 2, "name": "vanilla" }] ไม่ใช่ array ว่างหรือหายไปเหมือนก่อนหน้า

ตรวจว่าใช้งานได้จริง

  • GET /coffees คืนทุกแถวพร้อม flavors ที่ join มาจากตารางเชื่อม
  • GET /coffees/1 คืนกาแฟเดียวพร้อม flavors ครบทุกตัวที่ผูกไว้
  • id ที่ไม่มีจริงยังได้ 404 Coffee #id not found เหมือนเดิม
  • ลองเอา relations ออกชั่วคราวแล้วยิงซ้ำ — flavors ต้องหายไป เพื่อยืนยันว่า option นี้คือตัวควบคุมจริง (แล้วใส่กลับ)
