สร้าง Relation ระหว่างสอง Entities

เมื่อจบบทนี้ คุณจะสามารถ

  • แยกความแตกต่างของ relation ทั้งสามแบบ: one-to-one, one-to-many/many-to-one และ many-to-many
  • ผูก Coffee กับ Flavor แบบ many-to-many ด้วย @ManyToMany() และ @JoinTable()
  • อธิบายได้ว่าฝั่ง owner ของ relation คือฝั่งไหน และตารางเชื่อมเกิดขึ้นได้อย่างไร

Relation สามแบบที่ต้องรู้จัก

Relation คือความสัมพันธ์ระหว่างตารางที่ผูกกันด้วยฟิลด์ร่วม โดยทั่วไปคือ primary key กับ foreign key TypeORM ให้เรานิยามความสัมพันธ์เหล่านี้ด้วย decorator บน entity โดยตรง

ชนิดความหมายDecorator
One-to-oneแถวในตารางหลักจับคู่กับแถวในตารางปลายทางได้แถวเดียวเท่านั้น@OneToOne()
One-to-many / Many-to-oneแถวในตารางหลักมีแถวที่เกี่ยวข้องในตารางปลายทางได้หลายแถว@OneToMany() คู่กับ @ManyToOne()
Many-to-manyทั้งสองฝั่งต่างมีแถวที่เกี่ยวข้องกันได้หลายแถว@ManyToMany()

กาแฟหนึ่งตัวมีได้หลาย flavor และ flavor หนึ่ง (เช่น chocolate) ก็อยู่ในกาแฟได้หลายตัว — ความสัมพันธ์ระหว่าง Coffee กับ Flavor จึงเป็น many-to-many

เปลี่ยน flavors จาก json เป็น entity จริง

สร้าง Flavor entity ใหม่ที่ src/coffees/entities/flavor.entity.ts แล้วแก้ property flavors ของ Coffee ให้ชี้ไปหา entity นั้นแทนคอลัมน์ json เดิม แต่ละฝั่งของ @ManyToMany() ต้องบอกด้วยว่า "ตัวฉันอยู่ตรงไหนในอีกฝั่ง" ผ่าน arrow function ตัวที่สอง

/* coffee.entity.ts */
import {
  Column,
  Entity,
  JoinTable,
  ManyToMany,
  PrimaryGeneratedColumn,
} from 'typeorm';
import { Flavor } from './flavor.entity';

@Entity()
export class Coffee {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  name: string;

  @Column()
  brand: string;

  @JoinTable() // ฝั่ง OWNER เท่านั้นที่ประกาศตารางเชื่อม
  @ManyToMany(
    type => Flavor,
    flavor => flavor.coffees, // "coffees" คืออะไรใน Flavor entity
  )
  flavors: string[];
}

/* flavor.entity.ts */
import { Column, Entity, ManyToMany, PrimaryGeneratedColumn } from 'typeorm';
import { Coffee } from './coffee.entity';

@Entity()
export class Flavor {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  name: string;

  @ManyToMany(
    type => Coffee,
    coffee => coffee.flavors, // "flavors" คืออะไรใน Coffee entity
  )
  coffees: Coffee[];
}

@JoinTable() ประกาศไว้ที่ฝั่ง owner ของความสัมพันธ์เพียงฝั่งเดียว — ในที่นี้คือ Coffee เพราะเรามองกาแฟเป็นตัวตั้งแล้วค่อยผูก flavor เข้าไป TypeORM จะสร้างตารางเชื่อมชื่อ coffee_flavors_flavor ให้เองเมื่อ synchronize ทำงาน

การเปลี่ยนคอลัมน์ flavors จาก json เป็น relation ทำให้ synchronize ลบคอลัมน์เดิมพร้อมข้อมูลในนั้นทิ้ง — บนเครื่อง dev ไม่เป็นไร แต่นี่คือเหตุผลที่ production ต้องใช้ migrations (บทที่ 31) แทน

อย่าลืมลงทะเบียน entity ใหม่ใน module ด้วย: TypeOrmModule.forFeature([Coffee, Flavor]) ไม่เช่นนั้น Nest จะหา repository ของ Flavor ไม่เจอในบทถัดไป

ผูก Coffee กับ Flavor เข้าด้วยกัน

สร้าง flavor.entity.ts, แก้ coffee.entity.ts ตามโค้ดด้านบน แล้วเพิ่ม Flavor เข้า forFeature ของ CoffeesModule จากนั้นรันแอปแล้วไปดูตารางที่เกิดขึ้นใหม่

npm run start:dev # ใน pgAdmin ควรเห็น 3 ตาราง: # coffee - ข้อมูลกาแฟ # flavor - ข้อมูล flavor # coffee_flavors_flavor - ตารางเชื่อม many-to-many

ผลลัพธ์ที่คาดหวัง

ฐานข้อมูลมี 3 ตาราง: coffee (ไม่มีคอลัมน์ flavors แล้ว), flavor และตารางเชื่อม coffee_flavors_flavor ที่ถือ foreign key ของทั้งสองฝั่ง ตอนนี้ endpoint สร้างกาแฟพร้อม flavor จะยังทำงานไม่ครบ — เราจะแก้ให้บันทึกลง relation จริงในบทที่ 27 เรื่อง cascading inserts

ตรวจว่าใช้งานได้จริง

  • แอป start ขึ้นโดยไม่มี error เรื่อง entity metadata
  • เห็นตาราง coffee_flavors_flavor ใน pgAdmin พร้อมคอลัมน์อ้างอิง id ของทั้งสองตาราง
  • คอลัมน์ flavors ชนิด json หายไปจากตาราง coffee แล้ว
  • CoffeesModule ลงทะเบียนทั้ง Coffee และ Flavor ใน forFeature
