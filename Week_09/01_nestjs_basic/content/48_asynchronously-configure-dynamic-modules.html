ตั้งค่า Dynamic Modules แบบ Asynchronous

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายปัญหาลำดับการโหลด: ทำไม forRoot อาจอ่าน process.env ก่อนที่ ConfigModule จะเติมค่าให้
  • เปลี่ยน TypeOrmModule.forRoot() เป็น forRootAsync() พร้อม useFactory
  • รู้ว่าแพทเทิร์น forRootAsync ใช้ซ้ำได้กับ dynamic module อื่น ๆ ทั่ว ecosystem

ปัญหา: ลำดับการประเมินค่าใน imports array

ค่าใน imports array ถูกประเมินตอนที่ JavaScript โหลดไฟล์ module — ก่อนที่ Nest จะเริ่ม bootstrap เสียอีก นั่นแปลว่า TypeOrmModule.forRoot({ host: process.env.DATABASE_HOST, ... }) อ่านค่า env ทันที ณ จุดประกาศ ถ้าลำดับการโหลดทำให้ ConfigModule ยังไม่ได้อ่านไฟล์ .env เข้า process.env ค่าที่ TypeORM ได้ก็จะเป็น undefined ทั้งชุด แล้วการต่อฐานข้อมูลล้มเหลวแบบงง ๆ

ทางแก้คือเลื่อนการสร้าง options object ออกไปไว้ใน factory function ซึ่ง Nest จะเรียกระหว่าง dependency injection phase — หลังจาก ConfigModule ทำงานเสร็จแล้ว

forRootAsync + useFactory

// app.module.ts
TypeOrmModule.forRootAsync({
  useFactory: () => ({
    type: 'postgres',
    host: process.env.DATABASE_HOST,
    port: +process.env.DATABASE_PORT,
    username: process.env.DATABASE_USER,
    password: process.env.DATABASE_PASSWORD,
    database: process.env.DATABASE_NAME,
    autoLoadEntities: true,
    synchronize: true,
  }),
}),

โค้ดข้างในเหมือนเดิมทุกบรรทัด ต่างกันแค่ถูกห่อด้วย function ทำให้ process.env ถูกอ่าน ตอนถูกเรียก ไม่ใช่ ตอนไฟล์ถูกโหลด — เท่านี้ปัญหาลำดับก็หายไป

useFactory ใน forRootAsync ยังรองรับ inject เหมือน factory provider ปกติ แพทเทิร์นที่พบบ่อยในโปรเจกต์จริงคือ inject ConfigService แล้วอ่านผ่าน configService.get(...) แทนการแตะ process.env ตรง ๆ ซึ่งทำให้ options ผ่านการ validate จาก schema ในบทที่ 44 ด้วย

forRoot(options)forRootAsync({ useFactory })
เวลาอ่านค่า optionsตอนไฟล์ถูก import (เร็วเกินไปสำหรับ env)ตอน DI phase หลัง ConfigModule พร้อม
Inject dependency อื่นได้ไม่ได้ได้ ผ่าน inject: [...]
เหมาะกับค่าคงที่ที่รู้ตั้งแต่เขียนโค้ดค่าจาก environment หรือ service อื่น

ย้าย TypeORM ไปใช้ forRootAsync

ใน AppModule ของ iluvcoffee เปลี่ยน TypeOrmModule.forRoot({...}) เป็น TypeOrmModule.forRootAsync({ useFactory: () => ({...}) }) โดยคง options ชุดเดิมทั้งหมด แล้ว restart ให้แน่ใจว่าโปรแกรมยังต่อฐานข้อมูลได้

// เปลี่ยนจาก TypeOrmModule.forRoot({ ... }) // เป็น TypeOrmModule.forRootAsync({ useFactory: () => ({ ... options ชุดเดิม ... }), }) npm run start:dev

ผลลัพธ์ที่คาดหวัง

แอป start และเชื่อมต่อ PostgreSQL สำเร็จเหมือนเดิม แต่ตอนนี้การอ่าน environment ถูกเลื่อนไปอยู่หลัง ConfigModule เสมอ จึงไม่ขึ้นกับลำดับ import ในไฟล์อีกต่อไป

ตรวจว่าใช้งานได้จริง

  • แอป start โดยไม่มี error และ log ของ TypeORM แสดงการเชื่อมต่อสำเร็จ
  • GET /coffees และ POST /coffees อ่าน/เขียนฐานข้อมูลได้ปกติ
  • ลองสลับตำแหน่ง ConfigModule.forRoot() ไปไว้หลัง TypeOrmModule.forRootAsync() ใน imports array — แอปยังทำงานได้ เพราะ factory ถูกเรียกทีหลังเสมอ
  • ไม่มีการอ่าน process.env ที่ระดับ top-level ของ imports array เหลืออยู่
