เขียน Unit Tests

เมื่อจบบทนี้ คุณจะสามารถ

  • สร้าง mock repository ที่ควบคุมค่าตอบกลับได้ด้วย jest.fn() แทน mock ว่าง
  • เขียน test ครอบคลุมทั้งขาสำเร็จ (พบ coffee) และขาล้มเหลว (throw NotFoundException) ของ findOne
  • จัดโครง describe ซ้อนกันให้อ่านเป็นสเปกพฤติกรรมได้

จาก mock ว่างสู่ mock ที่ตอบได้

บทที่แล้ว mock ของเราเป็น object ว่าง ซึ่งพอให้ DI resolve ได้แต่ทดสอบพฤติกรรมจริงไม่ได้ ปัญหาคือ findOne ของ service เรียก coffeeRepository.findOne ข้างใน — ถ้า mock ไม่มีเมธอดนี้ test จะพัง เราจึงยกระดับเป็น mock ที่มีเมธอดเป็น jest.fn() เพื่อกำหนดค่าตอบกลับได้ในแต่ละ test

type MockRepository<T = any> = Partial<Record<keyof Repository<T>, jest.Mock>>;
const createMockRepository = <T = any>(): MockRepository<T> => ({
  findOne: jest.fn(),
  create: jest.fn(),
});

Type helper นี้บอกว่า: mock ของเราเป็น object ที่ key เป็นชื่อเมธอดของ Repository และ value เป็น jest.Mock — ได้ autocomplete และกันพิมพ์ชื่อเมธอดผิดไปพร้อมกัน

โค้ดเต็มของ suite

/* coffees.service.spec.ts - FINAL CODE */
import { Test, TestingModule } from '@nestjs/testing';
import { CoffeesService } from './coffees.service';
import { DataSource, Repository } from 'typeorm';
import { getRepositoryToken } from '@nestjs/typeorm';
import { Flavor } from './entities/flavor.entity';
import { Coffee } from './entities/coffee.entity';
import { NotFoundException } from '@nestjs/common';

type MockRepository<T = any> = Partial<Record<keyof Repository<T>, jest.Mock>>;
const createMockRepository = <T = any>(): MockRepository<T> => ({
  findOne: jest.fn(),
  create: jest.fn(),
});

describe('CoffeesService', () => {
  let service: CoffeesService;
  let coffeeRepository: MockRepository;

  beforeEach(async () => {
    const module: TestingModule = await Test.createTestingModule({
      providers: [
        CoffeesService,
        { provide: DataSource, useValue: {} },
        {
          provide: getRepositoryToken(Flavor),
          useValue: createMockRepository(),
        },
        {
          provide: getRepositoryToken(Coffee),
          useValue: createMockRepository(),
        },
      ],
    }).compile();

    service = module.get<CoffeesService>(CoffeesService);
    coffeeRepository = module.get<MockRepository>(getRepositoryToken(Coffee));
  });

  it('should be defined', () => {
    expect(service).toBeDefined();
  });

  describe('findOne', () => {
    describe('when coffee with ID exists', () => {
      it('should return the coffee object', async () => {
        const coffeeId = '1';
        const expectedCoffee = {};

        coffeeRepository.findOne.mockReturnValue(expectedCoffee);
        const coffee = await service.findOne(coffeeId);
        expect(coffee).toEqual(expectedCoffee);
      });
    });
    describe('otherwise', () => {
      it('should throw the "NotFoundException"', async () => {
        const coffeeId = '1';
        coffeeRepository.findOne.mockReturnValue(undefined);

        try {
          await service.findOne(coffeeId);
          expect(false).toBeTruthy(); // ต้องไม่มาถึงบรรทัดนี้
        } catch (err) {
          expect(err).toBeInstanceOf(NotFoundException);
          expect(err.message).toEqual(`Coffee #${coffeeId} not found`);
        }
      });
    });
  });
});

สังเกตสองจุดสำคัญ: เราดึง mock กลับออกมาจาก container ด้วย module.get(getRepositoryToken(Coffee)) เพื่อสั่ง mockReturnValue ในแต่ละ test และโครง describe('findOne') → describe('when …') → it('should …') ทำให้รายงานผลอ่านเป็นประโยคสเปกได้ทันที

ขาที่คาดว่า throw ให้ยืนยันว่า throw เกิดขึ้นจริง — โค้ดนี้ใช้ expect(false).toBeTruthy() เป็นกับดักกันกรณี findOne ไม่ throw แล้ว test ผ่านแบบหลอก ๆ ถ้าลืมจุดนี้ test ขาล้มเหลวอาจ เขียว ทั้งที่ไม่เคยทดสอบอะไรเลย

ทดสอบ findOne ให้ครบสองขา

แทนที่เนื้อหา coffees.service.spec.ts ด้วยโค้ดเต็มด้านบน แล้วรันแบบ watch จนผ่านทั้ง 3 tests จากนั้นลองสลับค่า mock เพื่อดูว่า test จับความผิดปกติได้จริง

npm run test:watch -- coffees.service # ผ่านแล้วลองทดสอบว่า test แข็งแรง: # เปลี่ยน mockReturnValue(undefined) เป็น mockReturnValue({}) ชั่วคราว # → test ขา NotFoundException ต้อง fail

ผลลัพธ์ที่คาดหวัง

Suite รายงาน 3 tests ผ่านทั้งหมด: should be defined, ขา when coffee with ID exists และขา otherwise → should throw the "NotFoundException" โดยไม่ต้องต่อฐานข้อมูลจริงเลย

ตรวจว่าใช้งานได้จริง

  • npm run test:watch -- coffees.service เขียวทั้ง suite และไม่มี connection ไปยัง Postgres (ปิด Docker ก็ยังผ่าน)
  • ทดลอง sabotage: แก้ message ใน NotFoundException ของ service ชั่วคราว → test ต้อง fail ที่ err.message
  • ตรวจว่า coffeeRepository ที่ใช้ใน test เป็นตัวเดียวกับที่ดึงจาก getRepositoryToken(Coffee) ไม่ใช่ mock ของ Flavor
  • รัน npm run test:cov แล้วดูว่า coverage ของ coffees.service.ts ขยับขึ้นจากบทก่อน

  • Exception filters: NotFoundException และ HttpException family (NestJS)
