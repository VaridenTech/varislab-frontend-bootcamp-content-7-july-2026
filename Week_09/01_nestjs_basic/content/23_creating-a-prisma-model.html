สร้าง TypeORM Entity

เมื่อจบบทนี้ คุณจะสามารถ

  • นิยาม entity ด้วย @Entity(), @PrimaryGeneratedColumn() และ @Column()
  • ลงทะเบียน entity ใน scope ของ module ด้วย TypeOrmModule.forFeature()
  • ยืนยันว่า synchronize สร้างตาราง coffee ใน PostgreSQL ให้ตรงกับ entity จริง

Entity คือ class ที่แทนหนึ่งตาราง

Entity คือ class ธรรมดาที่ติด decorator @Entity() — TypeORM จะ map class นี้เป็นหนึ่งตาราง SQL โดยใช้ชื่อ class ตัวพิมพ์เล็กเป็นชื่อตาราง (class Coffee จึงกลายเป็นตาราง coffee) และ map แต่ละ property ที่ติด @Column() เป็นคอลัมน์ เราสร้างไฟล์นี้ไว้ที่ src/coffees/entities/coffee.entity.ts

import { Column, Entity, PrimaryGeneratedColumn } from 'typeorm';

@Entity() // ตาราง SQL ชื่อ 'coffee'
export class Coffee {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  name: string;

  @Column()
  brand: string;

  @Column('json', { nullable: true })
  flavors: string[];
}
  • @PrimaryGeneratedColumn() สร้าง primary key ชนิด auto-increment ให้อัตโนมัติ
  • @Column() เฉย ๆ อนุมานชนิดคอลัมน์จาก type ของ TypeScript เช่น string → varchar
  • @Column('json', { nullable: true }) ระบุชนิดเองเป็น json และยอมให้เป็นค่าว่างได้ — เหมาะกับ flavors ที่ตอนนี้ยังเป็น array ของ string ก่อนจะแยกเป็น entity ของตัวเองในบทที่ 25

ลงทะเบียน entity ด้วย forFeature ใน module ที่เป็นเจ้าของ

ในขณะที่ forRoot() ตั้งค่า connection ที่ระดับแอป forFeature() ใช้ลงทะเบียนว่า module นี้ทำงานกับ entity ตัวไหนบ้าง เมื่อรวมกับ autoLoadEntities: true ที่ตั้งไว้ในบทที่แล้ว entity ที่ลงทะเบียนตรงนี้จะถูกโหลดเข้า connection โดยไม่ต้องไปแก้ config กลาง

import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { CoffeesController } from './coffees.controller';
import { CoffeesService } from './coffees.service';
import { Coffee } from './entities/coffee.entity';

@Module({
  imports: [TypeOrmModule.forFeature([Coffee])],
  controllers: [CoffeesController],
  providers: [CoffeesService],
})
export class CoffeesModule {}

เมื่อแอป start ขึ้นอีกครั้ง synchronize: true จะเทียบ entity กับฐานข้อมูลแล้วสร้างตารางให้เองทันที

+-------------+--------------+----------------------------+
|                          coffee                         |
+-------------+--------------+----------------------------+
| id          | int          | PRIMARY KEY AUTO_INCREMENT |
| name        | varchar      |                            |
| brand       | varchar      |                            |
| flavors     | json         |                            |
+-------------+--------------+----------------------------+

ตั้งชื่อไฟล์ entity ตาม convention <ชื่อ>.entity.ts และเก็บไว้ในโฟลเดอร์ entities/ ของ domain นั้น — ทั้ง Nest CLI และเพื่อนร่วมทีมจะหาไฟล์เจอได้ทันทีจากชื่อ

สร้างตาราง coffee ตัวแรกของโปรเจกต์

สร้างไฟล์ src/coffees/entities/coffee.entity.ts ตามโค้ดด้านบน เพิ่ม TypeOrmModule.forFeature([Coffee]) เข้า CoffeesModule แล้วรันแอปโดยเปิด Docker ไว้

docker-compose up -d npm run start:dev # แล้วเปิด pgAdmin (บทที่ 21) ดูตาราง: # Databases > postgres > Schemas > public > Tables > coffee

ผลลัพธ์ที่คาดหวัง

แอป start สำเร็จ และเมื่อ refresh ใน pgAdmin จะเห็นตาราง coffee โผล่ขึ้นมาพร้อมคอลัมน์ id, name, brand, flavors ตรงตาม entity ทุกประการ — โดยที่เราไม่ได้เขียน SQL CREATE TABLE เองแม้แต่บรรทัดเดียว

ตรวจว่าใช้งานได้จริง

  • ไฟล์อยู่ที่ src/coffees/entities/coffee.entity.ts และ export class Coffee
  • CoffeesModule มี TypeOrmModule.forFeature([Coffee]) ใน imports
  • ใน pgAdmin หรือ GUI ที่ใช้ เห็นตาราง coffee พร้อม 4 คอลัมน์ และ id เป็น primary key
  • ลองเพิ่ม property ใหม่ชั่วคราวใน entity แล้ว save — ตารางควรได้คอลัมน์ใหม่ทันทีจาก synchronize (ลบออกแล้ว save กลับด้วย)
