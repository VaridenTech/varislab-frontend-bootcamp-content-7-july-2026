เพิ่ม Pagination ที่ชั้นฐานข้อมูล

เมื่อจบบทนี้ คุณจะสามารถ

  • สร้าง PaginationQueryDto ไว้ในโฟลเดอร์ common เพื่อใช้ซ้ำได้ทุก resource
  • เปิด enableImplicitConversion ให้ query string ถูกแปลงเป็น number อัตโนมัติ
  • ส่ง limit/offset ลงไปเป็น take/skip ของ TypeORM เพื่อให้ฐานข้อมูลเป็นผู้แบ่งหน้า

ย้าย pagination จากหน่วยความจำลงฐานข้อมูล

ในบทที่ 11 เราเคยรับ limit/offset จาก query string มาแล้ว แต่ตอนนั้นข้อมูลอยู่ใน array การหั่นข้อมูลจึงเกิดในหน่วยความจำ พอข้อมูลจริงอยู่ใน PostgreSQL การดึงทุกแถวมาก่อนแล้วค่อยหั่นเป็นการเสียทั้ง memory และเวลา — เราต้องให้ฐานข้อมูลแบ่งหน้าให้ตั้งแต่ใน query ผ่าน skip และ take ของ TypeORM

เนื่องจาก pagination เป็นสิ่งที่ resource อื่น ๆ ในอนาคตต้องใช้เหมือนกัน เราจะเก็บ DTO นี้ไว้ในโฟลเดอร์กลาง common/ โดยใช้ Nest CLI สร้างให้

nest g class common/dto/pagination-query.dto --no-spec

PaginationQueryDto: validate และแปลงชนิดในที่เดียว

import { Type } from 'class-transformer';
import { IsOptional, IsPositive } from 'class-validator';

export class PaginationQueryDto {
  @Type(() => Number)
  @IsOptional()
  @IsPositive()
  limit: number;

  @Type(() => Number)
  @IsOptional()
  @IsPositive()
  offset: number;
}
  • @IsOptional() — ไม่ส่งมาก็ได้ endpoint จะคืนทั้งหมดตามเดิม
  • @IsPositive() — กันค่า 0 และค่าติดลบที่ทำให้ query เพี้ยน
  • @Type(() => Number) — query string มาเป็น string เสมอ ต้องแปลงเป็น number ก่อน validate

จริง ๆ แล้วเราไม่ต้องติด @Type ทีละฟิลด์ก็ได้ ถ้าเปิดการแปลงชนิดแบบ implicit ที่ ValidationPipe กลางใน main.ts:

app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,
    transform: true,
    forbidNonWhitelisted: true,
    transformOptions: {
      enableImplicitConversion: true,
    },
  }),
);

enableImplicitConversion: true ให้ class-transformer เดาชนิดจาก type ของ property ใน DTO โดยอัตโนมัติ — สะดวกทั้งแอป แต่การคง @Type(() => Number) ไว้ก็ทำให้ DTO ประกาศเจตนาของตัวเองชัดเจนโดยไม่พึ่ง config กลาง เลือกแนวใดแนวหนึ่งให้สม่ำเสมอทั้งทีม

ต่อท่อจาก controller ลงถึง query

รับ DTO ที่ controller ด้วย @Query() แล้วส่งต่อให้ service ใช้เป็น skip/take

/* CoffeesController */
@Get()
findAll(@Query() paginationQuery: PaginationQueryDto) {
  return this.coffeesService.findAll(paginationQuery);
}

/* CoffeesService */
findAll(paginationQuery: PaginationQueryDto) {
  const { limit, offset } = paginationQuery;
  return this.coffeeRepository.find({
    relations: {
      flavors: true,
    },
    skip: offset,
    take: limit,
  });
}

แบ่งหน้ารายการกาแฟ

สร้าง DTO, ปรับ main.ts, controller และ service ตามด้านบน จากนั้น POST กาแฟสัก 5 ตัวแล้วทดสอบการแบ่งหน้า

GET http://localhost:3000/coffees?limit=2&offset=0 GET http://localhost:3000/coffees?limit=2&offset=2 GET http://localhost:3000/coffees?limit=-1 # ต้องได้ 400 GET http://localhost:3000/coffees # ไม่ส่ง = ได้ทั้งหมด

ผลลัพธ์ที่คาดหวัง

คำขอที่ใส่ limit=2 ได้กาแฟทีละ 2 ตัวไม่ซ้ำชุดกันเมื่อเลื่อน offset, คำขอที่ไม่ส่ง query ได้ทั้งหมด และค่าที่ไม่ใช่จำนวนบวกถูกปัดตกด้วย 400 พร้อมข้อความจาก class-validator — ทั้งหมดนี้โดยฐานข้อมูลเป็นคนทำ LIMIT/OFFSET ไม่ใช่ JavaScript

ตรวจว่าใช้งานได้จริง

  • limit=2&offset=0 กับ limit=2&offset=2 คืนคนละชุดข้อมูลและไม่ซ้ำกัน
  • limit=abc หรือ limit=-1 ได้ status 400 ไม่ใช่ 500
  • ไม่ส่ง query เลยยังได้รายการทั้งหมดพร้อม flavors ตามปกติ
  • ไฟล์ DTO อยู่ที่ src/common/dto/pagination-query.dto.ts พร้อมให้ resource อื่น import ไปใช้
