การทำงานแบบไม่บล็อก (Non-blocking I/O)

จุดเด่นของ Node.js คือจัดการงาน I/O ได้ดีและรองรับการขยายระบบ เพราะใช้สถาปัตยกรรมแบบ Non-blocking และ Event-driven งาน I/O จึงทำแบบ Asynchronous โดยไม่หยุดโปรแกรมหลักไว้ระหว่างรอ

ถ้าเป็น I/O แบบ Blocking โปรแกรมต้องรอให้งานหนึ่งเสร็จก่อนจึงเริ่มงานถัดไป แต่ Node.js ส่งหลายงานไปทำต่อได้โดยไม่ต้องยืนรอทีละงาน

ภาพรวมการทำงานของ Event Loop

ก่อนจะลงรายละเอียด ลองดูภาพรวมกันก่อนว่าเมื่อเราสั่งงาน I/O หนึ่งครั้ง มีอะไรเกิดขึ้นบ้าง และทำไมโปรแกรมถึงไม่ต้องหยุดรอ

Node.js ทำ Non-blocking I/O ได้อย่างไร

  • Event Loop — Node.js ใช้ Event Loop ในการจัดการงาน I/O ตัว Event Loop คือลูปที่คอยเฝ้าฟังเหตุการณ์ (Event) และเรียกฟังก์ชัน Callback ที่เกี่ยวข้องให้ทำงาน เมื่อมีการเริ่มงาน I/O ขึ้น Node.js จะลงทะเบียนฟังก์ชัน Callback นั้นไว้กับ Event Loop และเมื่องานเสร็จสิ้น Event Loop จะเรียก Callback ให้ทำงานเพื่อประมวลผลผลลัพธ์ต่อไป
  • Callbacks — Callback คือฟังก์ชันที่ถูกส่งเข้าไปเป็น Argument ให้กับฟังก์ชันอื่น ใน Node.js เราใช้ Callback เพื่อจัดการผลลัพธ์ของงาน I/O เมื่อเริ่มงาน I/O เราจะส่งฟังก์ชัน Callback เข้าไปด้วย ซึ่งจะถูกเรียกเมื่องานเสร็จสิ้น การใช้ Callback ทำให้ Node.js สามารถรันโค้ดส่วนอื่นต่อไปได้ระหว่างที่รองาน I/O
  • Non-Blocking APIs — Node.js มีชุด API แบบ Non-blocking ให้นักพัฒนาใช้ทำงาน I/O แบบ Asynchronous เช่น Module fs ที่มีเมธอดแบบ Non-blocking สำหรับอ่านและเขียนไฟล์ เมื่อเรียกเมธอดเหล่านี้ Node.js จะคืนการควบคุมกลับให้โปรแกรมทันที เพื่อให้โปรแกรมรันโค้ดส่วนอื่นต่อไปได้ และเมื่องาน I/O เสร็จสิ้น ฟังก์ชัน Callback จึงจะถูกเรียกพร้อมกับผลลัพธ์
  • Single-Threaded — Node.js เป็นสภาพแวดล้อมแบบ Single-thread หมายความว่างาน I/O ทั้งหมดถูกจัดการด้วย Thread เพียงตัวเดียว สิ่งนี้ทำให้ Node.js รองรับการเชื่อมต่อพร้อมกันจำนวนมากได้โดยใช้ทรัพยากรของระบบไม่มาก ในทางกลับกัน สภาพแวดล้อมอื่นอย่าง Python หรือ Ruby ใช้หลาย Thread ในการจัดการงาน I/O ซึ่งอาจทำให้ใช้ทรัพยากรมากกว่าและทำงานได้ช้ากว่า

เปรียบเทียบ: Single-Thread กับ Multi-Thread

ข้อสุดท้ายเรื่อง Single-Thread มักเป็นจุดที่ทำให้สับสนมากที่สุด ลองดูภาพเปรียบเทียบว่าเมื่อมี Request เข้ามาพร้อมกันหลายตัว ระบบทั้งสองแบบรับมือต่างกันอย่างไร

มีสองเรื่องที่ควรเข้าใจให้ถูกต้องเกี่ยวกับคำว่า Single-Thread

  • โค้ด JavaScript ของเรารันบน Thread เดียว แต่ Node.js ทั้งระบบไม่ได้มีแค่ Thread เดียว — เบื้องหลัง libuv ยังมี Thread Pool ขนาดเล็กไว้ทำงานบางอย่างให้ เช่น การอ่านเขียนไฟล์ เพียงแต่เราไม่ต้องจัดการ Thread เหล่านั้นเอง
  • ถ้าเราเขียนโค้ดที่กินเวลาประมวลผลนาน ๆ ทุกอย่างจะหยุดชะงัก — เพราะมี Thread เดียวที่รันโค้ดของเรา การคำนวณหนัก ๆ ใน Callback ตัวเดียวจะบล็อก Request อื่นทั้งหมด จุดแข็งของ Node.js จึงอยู่ที่งานที่ต้องรอ I/O เป็นหลัก มากกว่างานที่ใช้ CPU หนัก

ตัวอย่าง

ตัวอย่างโค้ดแบบ Blocking

const getUserSync = (userId) => {
  const users = {
    1: { name: 'John', age: 35 },
    2: { name: 'Jane', age: 28 }
  };
  return users[userId];
}

const user = getUserSync(1);
console.log(user);

ตัวอย่างนี้ getUserSync ค้นหาและคืน Object ของผู้ใช้จากรายชื่อที่เขียนไว้ในโค้ด การทำงานเป็นแบบ Blocking เพราะทุกอย่างเกิดขึ้นแบบ Synchronous ก่อนโปรแกรมจะไปบรรทัดถัดไป

ตัวอย่างโค้ดแบบ Non-blocking

const getUserAsync = (userId, callback) => {
  const users = {
    1: { name: 'John', age: 35 },
    2: { name: 'Jane', age: 28 }
  };
  setTimeout(() => {
    callback(users[userId]);
  }, 1000);
}

getUserAsync(1, (user) => {
  console.log(user);
});

getUserAsync ค้นหาข้อมูลชุดเดียวกัน แต่ทำแบบ Asynchronous โดยใช้ setTimeout จำลองการรอหนึ่งวินาที ฟังก์ชันรับ Callback เป็น Argument ตัวที่สอง และเรียก Callback พร้อม Object ของผู้ใช้เมื่อข้อมูลพร้อมแล้ว

เจาะลึก: ข้างใน Event Loop มีอะไรบ้าง

ในทางปฏิบัติ Event Loop ไม่ได้มีคิวเดียว แต่แบ่งการทำงานออกเป็น เฟส (Phase) หลายเฟสที่วนซ้ำเป็นรอบ ๆ แต่ละเฟสมีคิวของตัวเอง และ Node.js จะรัน Callback ในคิวของเฟสนั้นจนหมดก่อน แล้วจึงเลื่อนไปเฟสถัดไป

ส่วนนี้เป็นเนื้อหาเสริม ยังไม่ต้องจำทุกเฟสตอนนี้ แค่เห็นภาพรวมไว้ก่อนก็จะช่วยให้ตามพฤติกรรมของโค้ด Asynchronous ได้ง่ายขึ้นในภายหลัง

อีกจุดที่ควรรู้คือ Callback ของ process.nextTick() และ Promise ซึ่งเรียกรวมกันว่า Microtask ไม่ได้อยู่ในเฟสใดเฟสหนึ่งโดยตรง Node.js จะแทรกงานเหล่านี้หลังจบแต่ละเฟส ก่อนที่ Event Loop จะขยับไปเฟสถัดไป

หากอยากอ่านรายละเอียดเพิ่มเติม เอกสารทางการของ Node.js อธิบายเรื่องนี้ไว้อย่างครบถ้วนที่ The Node.js Event Loop
