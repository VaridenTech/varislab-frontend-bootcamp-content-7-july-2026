สรุปทบทวนเนื้อหาทั้งหมด

มาถึงบทสุดท้ายแล้ว! ก่อนจบคอร์ส มาทบทวนสิ่งที่เราเรียนผ่านการสร้างแอป Todo แบบ CLI กันอีกครั้ง

แอปตัวนี้ใช้ Node.js ล้วน ๆ โดยไม่พึ่งแพ็กเกจภายนอกเลย ยกเว้น Jest สำหรับรันเทสต์ นั่นทำให้เราได้เห็นชัด ๆ ว่า Node.js มีเครื่องมือพื้นฐานอะไรให้ใช้บ้าง

ความรู้พื้นฐานเกี่ยวกับ Node.js

  • Node.js คือเทคโนโลยีที่ทำให้เรารันโค้ด JavaScript นอกเว็บ Browser ได้ สร้างโดย Ryan Dahl ในปี 2009 บนพื้นฐานของ V8 Engine
  • Node.js ใช้สถาปัตยกรรมแบบ Non-blocking I/O และ Event-driven โดยอาศัย Event Loop, Callback และ API แบบ Non-blocking ทำให้รองรับการเชื่อมต่อจำนวนมากได้ด้วยทรัพยากรที่ไม่มาก
  • เรารันโปรแกรม Node.js ได้ด้วยคำสั่ง node index.js และทดลองโค้ดสั้น ๆ แบบโต้ตอบได้ด้วย Node REPL
  • JavaScript บน Browser กับบน Node.js ต่างกันที่ Global Object (window vs. global), การมีหรือไม่มี DOM และวิธีการ Import Module
  • Object process ให้เราเข้าถึง Argument จาก Command Line (process.argv) และ Environment Variables (process.env)

การสร้าง CLI

  • เราสร้างโปรเจกต์ด้วย npm init แล้วลงทะเบียนชื่อคำสั่งไว้ใน Field bin ของ package.json
  • เราเพิ่ม Hashbang (#!/usr/bin/env node) ไว้บรรทัดแรกของไฟล์ เพื่อบอกระบบปฏิบัติการว่าให้ใช้ Node.js เป็นตัวแปลภาษา
  • เราใช้ npm link เพื่อสร้าง Symlink ทำให้เรียกคำสั่ง todo ได้จากทุกที่ในเครื่อง
  • เราอ่านคำสั่งและ Argument จาก process.argv.slice(2) แล้วใช้ switch แยกการทำงานของแต่ละคำสั่ง โดยไม่ต้องพึ่งไลบรารีช่วยแยก Argument เลย

Module และ NPM

  • Module ใน Node.js มี 3 ประเภท ได้แก่ Internal Module (เช่น fs, http, path), Module ที่เราสร้างเอง และ Module จากภายนอกผ่าน npm
  • require เป็นวิธีดั้งเดิมของ CommonJS ส่วน import เป็นมาตรฐาน ES6 ที่ใหม่กว่า
  • Module ที่ดีควรมีหน้าที่ชัดเจนเพียงอย่างเดียว ไม่ผูกติดกับ Module อื่นแน่นเกินไป และเราใช้ Index.js Pattern เพื่อรวม Export ไว้ที่เดียวได้
  • เราใช้ npm install เพื่อติดตั้งแพ็กเกจ และกำหนดคำสั่งลัดไว้ใน Field scripts ของ package.json
  • CLI ของเรามีคำสั่ง add, list, done, remove และ web

การทำงานกับไฟล์ (File I/O)

  • เราจัดการโค้ดแบบ Asynchronous ได้ 3 วิธี คือ Callback, Promise และ Async/Await พร้อมทั้งจัดการข้อผิดพลาดด้วย try/catch หรือ catch
  • FS Module มีเมธอดสำหรับอ่าน เขียน ลบ และเปลี่ยนชื่อไฟล์ โดยควรเลือกใช้เวอร์ชัน Asynchronous เป็นหลัก
  • เราใช้ไฟล์ db.json เป็นฐานข้อมูล และสร้างฟังก์ชันช่วยเหลือ readTodos กับ saveTodos ไว้ใน src/todos.js
  • เราสร้างฟังก์ชัน CRUD ได้แก่ addTodo, markDone และ removeTodo โดยตั้งใจเขียนให้เป็น Pure Function ที่รับ Array เข้ามาแล้วคืน Array ใหม่ออกไป ไม่ยุ่งกับไฟล์เลย
  • เราแยกส่วนที่คุยกับไฟล์ออกจากส่วนที่จัดการข้อมูล ซึ่งทำให้โค้ดอ่านง่ายขึ้นและทดสอบได้ง่ายขึ้นมาก

การทดสอบ

  • การทดสอบมีหลายประเภท ได้แก่ Unit, Integration, End-to-End (E2E) และ API Testing ซึ่งแต่ละแบบมีจุดประสงค์ต่างกัน
  • เราเขียน Unit Test ด้วย Jest โดยใช้ฟังก์ชัน test และ expect ทดสอบ addTodo, markDone และ removeTodo
  • เพราะฟังก์ชันเหล่านั้นเป็น Pure Function เราจึงทดสอบมันได้ตรง ๆ เลย ไม่ต้องเตรียมไฟล์หรือลบไฟล์ทิ้งหลังเทสต์เสร็จ นี่คือเหตุผลที่การออกแบบโค้ดให้ดีตั้งแต่แรกช่วยเราตอนเขียนเทสต์มาก

เซิร์ฟเวอร์

  • Server คือโปรแกรมที่คอยรับ Request จากเครือข่ายและตอบสนองกลับไป โดยรับผิดชอบการจัดการข้อมูลและสถานะ ในขณะที่ Client รับผิดชอบการนำเสนอข้อมูล
  • เราสร้างเว็บเซิร์ฟเวอร์ด้วย Module http ล้วน ๆ โดยใช้ http.createServer รับ Request แล้วตอบ HTML ที่สร้างจาก Template Literal กลับไปด้วย res.end
  • เรารู้จัก Error EADDRINUSE ที่เกิดเมื่อ Port ถูกใช้งานอยู่แล้ว และแก้ได้ด้วยการเปลี่ยนไปใช้ Port อื่น

ก้าวต่อไป

จากจุดนี้ ลองต่อยอดแอปด้วยฐานข้อมูลจริง สร้าง API ผ่าน Framework อย่าง Express หรือเชื่อม Node.js เข้ากับ Framework ฝั่ง Frontend เพื่อทำเว็บแบบ Full-stack สิ่งที่เรียนมาในคอร์สนี้จะเป็นฐานให้ตามเรื่องเหล่านั้นได้ง่ายขึ้น
