การเขียนโค้ดแบบ Asynchronous ใน Node.js

Asynchronous เป็นแนวคิดสำคัญของ Node.js เพราะทำให้โปรแกรมไม่ต้องหยุดรอทุกงาน ระหว่างที่งานหนึ่งยังไม่เสร็จ โปรแกรมก็ไปทำอย่างอื่นต่อได้

Callbacks

Callback เป็นวิธีดั้งเดิมของ Node.js เราส่งฟังก์ชันหนึ่งเข้าไปเป็น Argument ของงาน Asynchronous แล้ว Node.js จะเรียกฟังก์ชันนั้นเมื่องานเสร็จ

fs.readFile('file.txt', (err, data) => {
  if (err) {
    console.error(err)
    return
  }
  console.log(data)
})

ตัวอย่างนี้ readFile เริ่มอ่าน file.txt แล้วเรียก Callback เมื่อเสร็จ หากมีข้อผิดพลาด Callback จะได้รับ Error เป็น Argument ตัวแรก

Promises

Promise แทนค่าที่ยังไม่พร้อมในตอนนี้ และช่วยให้เราเชื่อมงาน Asynchronous หลายขั้นเข้าด้วยกันได้โดยโค้ดไม่ซ้อนลึกเหมือน Callback

const fs = require('fs/promises')

fs.readFile('file.txt')
  .then(data => {
    console.log(data)
  })
  .catch(err => {
    console.error(err)
  })

ครั้งนี้ readFile คืน Promise ถ้าสำเร็จ (Resolved) โค้ดใน then จะทำงาน แต่ถ้าล้มเหลว (Rejected) จะไปที่ catch แทน

Async/Await

Async/Await เป็นรูปแบบที่อ่านต่อเนื่องคล้ายโค้ด Synchronous เราใช้ Keyword async และ await เพื่อเขียนงาน Asynchronous ให้กระชับขึ้น

const fs = require('fs/promises')

async function readFile() {
  try {
    const data = await fs.readFile('file.txt')
    console.log(data)
  } catch (err) {
    console.error(err)
  }
}

readFile()

ฟังก์ชันตัวอย่างมี async กำกับไว้ จึงใช้ await รอให้ readFile ทำงานเสร็จก่อนเดินไปบรรทัดถัดไปได้ หากเกิดข้อผิดพลาด บล็อก try/catch จะรับไปจัดการ

การจัดการข้อผิดพลาด (Error Handling)

การจัดการข้อผิดพลาดเป็นส่วนสำคัญของการเขียนโค้ดแบบ Asynchronous ใน Node.js ในทุกตัวอย่างข้างต้น การจัดการข้อผิดพลาดทำได้ด้วยบล็อก try/catch หรือด้วยฟังก์ชัน catch

อย่าปล่อย Error ทิ้งไว้โดยไม่จัดการ เพราะอาจทำให้แอปหยุดทำงาน และควรเขียนข้อความ Error ให้บอกได้ว่าเกิดอะไรขึ้น เวลา Debug จะหาต้นเหตุได้เร็วกว่า
