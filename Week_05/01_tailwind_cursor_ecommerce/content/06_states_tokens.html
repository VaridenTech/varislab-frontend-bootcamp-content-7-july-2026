States & Design Tokens

บทสุดท้ายของหมวด Tailwind fundamentals จะปิดสามเรื่องที่เหลือ: ทำให้ UI ตอบสนองต่อการโต้ตอบของผู้ใช้ (states) ผูกสีของแบรนด์ My Store ไว้ที่เดียว (design tokens) และวิธีจัดระเบียบ class string ยาว ๆ ไม่ให้อ่านยากเกินไป หลังจากบทนี้คุณจะมีพื้นฐาน Tailwind ครบพอที่จะเริ่มทำงานกับ Cursor Agent ในบทถัดไป

States: hover, focus, active, disabled

เติมพฤติกรรมโต้ตอบให้ปุ่มจากบทที่ 2 ด้วย state modifier

<button
  className="rounded-lg bg-blue-600 px-4 py-2 font-medium text-white
    hover:bg-blue-700 focus-visible:outline-2 focus-visible:outline-blue-600
    active:bg-blue-800 disabled:cursor-not-allowed disabled:opacity-50"
>
  Add to Cart
</button>

hover: มีผลตอนเมาส์ชี้อยู่, active: มีผลระหว่างกดค้าง และ disabled: มีผลเมื่อ element มี attribute disabled ทั้งสามตัวนี้ตรงไปตรงมา ส่วนที่ต้องอธิบายเพิ่มคือ focus-visible:

🔍 ทำไมไม่ใช้ focus: เฉย ๆ — focus: จะแสดงกรอบ focus ทุกครั้ง ที่ element ได้รับ focus ไม่ว่าจะกดเมาส์คลิกหรือกด Tab บนคีย์บอร์ด ซึ่งทำให้ผู้ใช้เมาส์เห็นกรอบฟ้อง ๆ ทุกครั้งที่คลิกปุ่มโดยไม่จำเป็น ส่วน focus-visible: ฉลาดกว่า — เบราว์เซอร์จะแสดงกรอบเฉพาะตอนที่คาดว่าผู้ใช้กำลังนำทางด้วยคีย์บอร์ด (เช่นกด Tab) เท่านั้น ผู้ใช้คีย์บอร์ดยังเห็นกรอบชัดเจนเพื่อ accessibility ส่วนผู้ใช้เมาส์ก็ไม่เห็นกรอบรบกวนสายตา — บทที่ 12 ที่ว่าด้วยการตรวจ accessibility จะพูดเรื่องนี้ต่ออีกครั้ง

ตัวสุดท้ายที่มีประโยชน์มากคือ group กับ group-hover: ใช้เมื่ออยากให้ hover ที่ parent ไปกระตุ้นสไตล์ของ ลูก เช่น การซูมรูปสินค้าตอนเมาส์ชี้ที่การ์ดทั้งใบ (ไม่ใช่แค่ตัวรูป)

<div className="group overflow-hidden rounded-lg border border-gray-200">
  <img
    src="/thumbnail.webp"
    alt="Essence Mascara Lash Princess"
    className="aspect-square w-full object-cover transition-transform duration-300 group-hover:scale-105"
  />
</div>

ใส่ group ไว้ที่ parent (การ์ดทั้งใบ) แล้วใน <img> ใช้ group-hover:scale-105 แทน hover:scale-105 ธรรมดา — ผลคือแค่เอาเมาส์ไปชี้ที่ไหนก็ได้บนการ์ด รูปก็จะซูมขึ้น 5% แม้เมาส์จะไม่ได้อยู่บนตัวรูปโดยตรงก็ตาม (overflow-hidden ที่ parent ป้องกันไม่ให้รูปที่ซูมล้นออกนอกกรอบการ์ด)

Design Tokens ด้วย @theme

จนถึงตอนนี้เราใช้สีสำเร็จรูปของ Tailwind อย่าง blue-600 มาตลอด แต่ My Store มีสีแบรนด์ของตัวเองที่ไม่ตรงกับสีไหนใน palette เป๊ะ ๆ — Tailwind v4 ให้ประกาศสีของแบรนด์เป็น token ของตัวเองได้ตรง ๆ ใน CSS ผ่าน @theme

@import "tailwindcss";

@theme {
  --color-primary: #0d6efd;
  --color-primary-dark: #0b5ed7;
  --color-accent: #ffa200;
  --color-danger: #ff4136;
}

เพิ่มบล็อกนี้ต่อจาก @import "tailwindcss" ใน src/index.css แล้ว Tailwind จะ generate utility class ใหม่ให้อัตโนมัติจากชื่อ token ทุกตัว — bg-primary, text-primary, border-primary, hover:bg-primary-dark ใช้ได้ทันทีทุกที่ในโปรเจกต์ เหมือนกับที่ bg-blue-600 ใช้ได้

<button className="rounded-lg bg-primary px-4 py-2 font-medium text-white hover:bg-primary-dark">
  Add to Cart
</button>

ค่าสีทั้งสี่ตัวนี้ไม่ได้เดามาลอย ๆ แต่คัดลอกมาจาก _variables.scss ของแอปต้นแบบตรง ๆ — #0d6efd คือสีน้ำเงินหลักของแบรนด์ My Store, #ffa200 เป็นสีส้ม accent สำหรับดึงความสนใจ (เช่นป้ายส่วนลด), #ff4136 เป็นสีแดงสำหรับข้อความเตือนหรือ error ประโยชน์ของการรวมไว้ที่จุดเดียวคือถ้าแบรนด์เปลี่ยนสีวันหนึ่ง คุณแก้แค่ 4 บรรทัดนี้บรรทัดเดียว ทุก bg-primary ทั่วทั้งแอปจะเปลี่ยนตามทันทีโดยไม่ต้องไล่หาทีละไฟล์

ควบคุม class soup: ลำดับที่แนะนำ

ยิ่ง component ซับซ้อนขึ้น class string ก็ยิ่งยาวขึ้น เพื่อไม่ให้อ่านยากจนเกินไป ให้เรียง class ตามลำดับหมวดหมู่นี้อย่างสม่ำเสมอ

layout → sizing → spacing → typography → color → border/shadow → states

สังเกตปุ่มที่เพิ่งเห็นด้านบน: px-4 py-2 (spacing) และ font-medium (typography) มาก่อน ส่วน state modifier อย่าง hover:bg-primary-dark ควรอยู่ท้ายสุดเสมอ เพราะเป็นสไตล์ที่ “ทับ” สไตล์ปกติเฉพาะบางสถานการณ์ ยิ่งไว้ท้ายยิ่งเห็นชัดว่าคืออะไร พอทุกคนในทีมเรียงแบบเดียวกัน การอ่าน diff ที่ Agent สร้างให้จะเร็วขึ้นมาก เพราะรู้ว่าต้องมองหาอะไรตรงไหน

ไม่ต้องจำกฎนี้ให้แม่นแล้วมานั่งเรียงเองด้วยมือ ติดตั้ง prettier-plugin-tailwindcss แล้วให้ Prettier เรียงให้อัตโนมัติทุกครั้งที่ save ไฟล์ — ปลั๊กอินนี้เรียงตามลำดับมาตรฐานที่ทีม Tailwind กำหนดไว้ (ใกล้เคียงกับลำดับด้านบนมาก) ทำให้ทั้งโปรเจกต์เรียง class เหมือนกันหมดโดยไม่ต้องมีใครจำกฎเอง

แล้วทำไมไม่ใช้ @apply รวม class ยาว ๆ ไว้เป็นชื่อเดียว

Tailwind มี directive ชื่อ @apply ที่รวมหลาย utility ไว้เป็น class เดียวได้ เช่น .btn { @apply rounded-lg bg-primary px-4 py-2; } เห็นแล้วอาจคิดว่านี่คือทางออกของ class soup — แต่ลองสังเกตให้ดี นี่คือการย้อนกลับไปทำสิ่งเดียวกับที่ SCSS module ทำในบทที่ 2 ทุกประการ: ต้องตั้งชื่อ .btn อีกครั้ง เสีย locality อีกครั้ง (ต้องเปิดไฟล์ CSS แยกดูว่า .btn มีอะไรบ้าง) และสร้าง naming fatigue กลับมาอีกครั้ง — พูดง่าย ๆ คือ @apply พาเรากลับไปเจอปัญหาเดิมที่ utility-first ตั้งใจแก้ตั้งแต่แรก

คำตอบของ Tailwind ต่อการนำสไตล์กลับมาใช้ซ้ำไม่ใช่ CSS class ใหม่ แต่คือ React component — ห่อ <button className="rounded-lg bg-primary px-4 py-2 ..."> ไว้ใน <AddToCartButton /> ตัวเดียว แล้วเรียกใช้ซ้ำได้ทั้งแอป สไตล์ยังคงอยู่ที่เดียวกับ markup เหมือนเดิม (locality ไม่เสีย) เพียงแต่ห่อด้วยฟังก์ชัน JavaScript แทนที่จะห่อด้วยชื่อ CSS class เราจะฝึก refactor แบบนี้จริงในบทที่ 13

แบบฝึกหัดเล็ก ๆ

กลับไปที่การ์ดสินค้าฉบับเต็มจากบทที่ 4 แล้วลองทำสองอย่าง: (1) เพิ่มบล็อก @theme ด้านบนเข้าไปใน src/index.css ของ playground แล้วเปลี่ยนราคาสินค้า (text-blue-600) ให้เป็น text-primary แทน ดูว่าสีเปลี่ยนไปยังไง (2) เพิ่ม hover:shadow-md และ transition-shadow ให้ตัวการ์ด แล้วลองเอาเมาส์ไปชี้ดู — นี่คือแบบฝึกหัดเดียวกับสิ่งที่ Cursor Agent จะทำให้อัตโนมัติในบทถัดไป แต่ลองทำเองมือก่อนสักครั้งจะช่วยให้คุณตรวจทานงานของ Agent ได้แม่นยำขึ้นมาก
