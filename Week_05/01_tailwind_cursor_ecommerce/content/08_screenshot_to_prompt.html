จาก Screenshot สู่ Prompt

Screenshot to Prompt

บทที่แล้วคุณรู้จัก Agent panel แล้วรู้ว่าแนบรูปเข้าไปในแชทได้ตรง ๆ บทนี้จะสอนสิ่งสำคัญที่สุดของสัปดาห์นี้ นั่นคือจะเขียน prompt แบบไหนถึงจะได้ UI ที่ตรงกับดีไซน์จริง ไม่ใช่ UI ทั่วไปที่ Agent เดาขึ้นมาเอง

ทำไม prompt คลุมเครือถึงได้ UI มั่ว

ลองสั่ง Agent ด้วยประโยคสั้น ๆ แบบนี้ดู

ทำหน้าเว็บขายของให้หน่อย สวย ๆ

ประโยคนี้ฟังดูเหมือนคำสั่งที่ชัดเจนสำหรับคน แต่สำหรับ Agent มันเต็มไปด้วยช่องว่างที่ต้องเดาเอง

  • Layout เป็นแบบไหน — มี banner ไหม มีกี่ section เรียงกันยังไง
  • กี่คอลัมน์ในแต่ละขนาดจอ (breakpoint ตรงไหนถึงเปลี่ยน)
  • ใช้ tech stack อะไร — Tailwind เปล่า ๆ หรือ component library สำเร็จรูป
  • แยกเป็น component ไหนบ้าง หรือเขียนทุกอย่างรวมในไฟล์เดียว
  • “สวย” ของแต่ละคนไม่เหมือนกัน — สีอะไร ฟอนต์แบบไหน การ์ดสินค้าหน้าตายังไง

เมื่อ prompt คลุมเครือ Agent ก็ต้องเดา และคำตอบที่ได้จะเป็น UI ทั่วไปที่ Agent คิดว่า “เว็บขายของ” ควรมีหน้าตายังไง ไม่ใช่หน้าที่ทีมออกแบบของ My Store ตั้งใจไว้ ปัญหาไม่ได้อยู่ที่ Agent เขียนโค้ดไม่เก่ง แต่อยู่ที่มันไม่มีข้อมูลพอจะรู้ว่า “ตรงตามที่ต้องการ” หน้าตาเป็นยังไง

โครงสี่ส่วนของ prompt ที่ดี

คำตอบไม่ใช่การเขียน prompt ให้ยาวขึ้นเฉย ๆ แต่คือการเขียนให้ครบสี่ส่วนที่ Agent ต้องรู้เสมอ

  • บริบท (Context) — แอปนี้คืออะไร ใช้ stack อะไร ติดตั้งอะไรไว้แล้วบ้าง
  • โครงสร้าง (Structure) — หน้าจอมีส่วนไหนบ้าง เรียงจากบนลงล่าง พร้อมเนื้อหาจริงที่เห็นในดีไซน์ ไม่ใช่ placeholder กว้าง ๆ
  • ข้อกำหนดทางเทคนิค (Technical requirements) — ใช้ Tailwind เท่านั้น, mobile-first, semantic HTML, แยก component ไหนบ้าง
  • ขอบเขต (Scope) — อะไรที่ยังไม่ต้องทำตอนนี้ กันไม่ให้ Agent ทำเกินขอบเขตที่ขอ เช่นแอบไปต่อ API เองทั้งที่ยังไม่ถึงเวลา

โครงสี่ส่วนนี้จะเป็นแม่แบบที่ใช้ซ้ำทุกครั้งที่เขียน prompt ให้ Agent สร้าง UI ตลอดทั้งสัปดาห์ที่เหลือ ตั้งแต่บทที่ 10 ไปจนถึงบทสุดท้าย

ตัวอย่างจริง: จาก screenshot หน้า Home สู่ prompt

ลองแปลง screenshot จริงของหน้า Home ให้เป็น prompt ตามโครงสี่ส่วนด้านบนทีละขั้น

เริ่มจาก บริบท — สิ่งนี้ Agent เดาจาก screenshot เองไม่ได้เลย ต้องบอกตรง ๆ ว่านี่คือแอปอะไร ใช้ stack อะไร

ต่อด้วย โครงสร้าง — ไล่จากบนลงล่างตามที่เห็นจริงในภาพ: บนสุดคือ header มีโลโก้ข้อความ “My Store” อยู่ซ้าย เมนู Home / Products อยู่กึ่งกลาง และไอคอนตะกร้าอยู่ขวา ถัดลงมาคือ banner แบบ carousel เต็มความกว้างพร้อมปุ่มเลื่อนซ้าย-ขวา ตามด้วยแถวการ์ดเล็ก ๆ ที่สรุปจุดขายอย่าง Free Shipping จากนั้นเป็น section “Deals of the Day” ที่มี countdown timer นับถอยหลังและสินค้าลดราคาเรียงกัน ตามด้วย section สินค้าตามหมวดหมู่ที่มีเมนูหมวดอยู่ซ้ายและ grid สินค้าอยู่ขวา ปิดท้ายด้วย footer หลายคอลัมน์ สังเกตว่าทุกจุดที่อธิบายระบุ เนื้อหาจริง ที่เห็นในภาพ ไม่ใช่คำกว้าง ๆ อย่าง “ใส่สินค้าบางอย่าง”

ต่อด้วย ข้อกำหนดทางเทคนิค — ใส่กฎที่เรียนมาตลอดหกบทที่แล้ว: ใช้ Tailwind utility เท่านั้น, mobile-first (มือถือ 2 คอลัมน์ md ขึ้นไป 3 lg ขึ้นไป 4), semantic HTML, แยก component

ปิดท้ายด้วย ขอบเขต — บอกชัดว่ายังไม่ต้องต่อ API จริง ใช้ mock data ในไฟล์ไปก่อน และยังไม่ต้องทำ routing เพราะเรายังไม่ได้ตั้งโครงโปรเจกต์เต็มจนกว่าจะถึงบทที่ 9 นอกจากนี้ ถ้าสังเกตดี ๆ screenshot ยังมีแถว promo tiles (Luxury Collection, Headphone, Earphone, Smart ipad) และแบนเนอร์ “Photography Workshop” ที่เราตั้งใจไม่สร้างในเวอร์ชันย่อของสัปดาห์นี้ — prompt ที่ดีจึงต้องเอ่ยชื่อสิ่งที่ตั้งใจตัดออกด้วย ไม่ใช่บอกแค่ว่าต้องสร้างอะไร เพราะถ้า reference มีมากกว่าที่ต้องการให้ Agent สร้าง แล้วไม่พูดถึงส่วนเกินนั้นเลย Agent อาจตีความว่าคุณลืมสั่ง แล้วสร้างส่วนที่ไม่ได้ขอมาให้ด้วย

ประกอบทั้งสี่ส่วนเข้าด้วยกัน ได้ prompt เต็มแบบนี้ วางในช่องแชทของ Agent panel ได้เลย

สร้างหน้า Home ของเว็บ e-commerce "My Store" ตาม screenshot ที่แนบมา

บริบท: โปรเจกต์ React + TypeScript + Vite ที่ติดตั้ง Tailwind CSS v4 แล้ว

โครงสร้างจากบนลงล่าง:
- Header: โลโก้ข้อความ "My Store" ซ้าย, เมนู Home / Products ตรงกลาง, ไอคอนตะกร้าพร้อม badge จำนวนสินค้าด้านขวา
- Banner carousel เต็มความกว้าง สูงประมาณ 400px มีปุ่ม prev/next
- แถว feature cards 4 ใบ: Free Shipping, 24 X 7 service, Festival offer, Online payment (ไอคอน + หัวข้อ + คำอธิบายสั้น)
- Section "Deals of the Day" มี countdown timer และสินค้าลดราคา 5 ชิ้น
- Section สินค้าตามหมวด: เมนูหมวดหมู่ด้านซ้าย, grid สินค้า 12 ชิ้นด้านขวา (การ์ด: รูป, ชื่อ, ราคา, ราคาก่อนลดขีดฆ่า)
- Footer: ลิงก์ 3 คอลัมน์ + ข้อความลิขสิทธิ์

ข้อกำหนดทางเทคนิค:
- ใช้ Tailwind utilities เท่านั้น ห้ามสร้างไฟล์ .css/.scss เพิ่ม
- Mobile-first: มือถือ 2 คอลัมน์, md ขึ้นไป 3, lg ขึ้นไป 4 คอลัมน์
- ใช้ semantic HTML (header, nav, main, section, footer) และใส่ alt ทุกรูป
- แยกเป็น component: Header, Banner, FeatureCard, ProductCard, Footer

ขอบเขต: ใช้ mock data ในไฟล์ไปก่อน ยังไม่ต้องต่อ API และยังไม่ต้องทำ routing
- ยังไม่ต้องทำแถว promo tiles (Luxury Collection ฯลฯ) และแบนเนอร์ Photography Workshop ที่เห็นใน screenshot

🔍 สังเกตว่าตัวเลขในโครงสร้างข้างบนมาจากการนับจริงใน screenshot ไม่ใช่การกะประมาณ — feature cards มี 4 ใบพอดี ไม่ใช่ 5 ใบ ส่วนสินค้าใน “Deals of the Day” มี 5 ชิ้นพอดี ไม่ใช่ 4 ชิ้น ยิ่ง prompt ตรงกับสิ่งที่เห็นจริงมากเท่าไหร่ Agent ก็ยิ่งไม่ต้องเดา และคุณเองก็ตรวจทานผลลัพธ์ได้ง่ายขึ้น เพราะรู้ชัดเจนอยู่แล้วว่า “ตรงตามที่สั่ง” ควรมีหน้าตาแบบไหน — เมื่อมี screenshot ให้ดูตรง ๆ นับให้ตรงเสมอ ดีกว่ากะประมาณ

เทคนิคเพิ่มเติม

  • แนบรูป mobile กับ desktop คู่กัน — เมื่ออยากได้ responsive ที่ตรงกับดีไซน์จริงในทุกขนาดจอ อย่าแนบแค่ desktop แล้วหวังให้ Agent เดาเอาเองว่ามือถือควรเรียงยังไง ลาก screenshot ทั้งสองขนาดเข้าไปพร้อมกัน แล้วบอกในโครงสร้างว่า “เทียบกับ screenshot มือถือ” ตรงจุดที่ layout เปลี่ยน
  • wireframe หยาบ ๆ บนกระดาษก็ใช้เป็น input ได้ — ไม่จำเป็นต้องมี screenshot ของจริงเสมอไป ร่างกล่องสี่เหลี่ยมคร่าว ๆ บนกระดาษแล้วถ่ายรูป Agent อ่านโครงร่างนั้นได้เหมือนกัน เพียงแต่ “โครงสร้าง” ในข้อความต้องอธิบายเนื้อหาให้ชัดเจนกว่าเดิม เพราะภาพร่างไม่มีรายละเอียดให้อ้างอิง
  • requirement ที่เป็นข้อความล้วนก็แปลงด้วยโครงเดียวกัน — บางครั้งไม่มีภาพเลย มีแค่คำอธิบายจากทีมงาน (เช่น “อยากได้หน้าโปรไฟล์ที่มีรูป ชื่อ และปุ่มแก้ไข”) ก็ยังใช้โครงบริบท / โครงสร้าง / ข้อกำหนดทางเทคนิค / ขอบเขตเดิมได้ เพียงแต่ส่วน “โครงสร้าง” ต้องเขียนขึ้นเองจากคำอธิบายแทนที่จะอ่านจากภาพ

แบบฝึกหัด: เขียน prompt ของคุณเอง

ก่อนไปเริ่มตั้งโครงโปรเจกต์จริงในบทหน้า ลองฝึกมือเขียน prompt เองสักครั้ง ใช้ screenshot หน้า Category ด้านล่างนี้เป็นต้นแบบ

เขียน prompt ด้วยโครงสี่ส่วนเดียวกัน — บริบท, โครงสร้าง, ข้อกำหนดทางเทคนิค, ขอบเขต — แล้วเก็บไว้ ยังไม่ต้องส่งให้ Agent ตอนนี้ก็ได้ เราจะเอา prompt นี้กลับมาใช้จริงตอนสร้างหน้า Category ในบทที่ 16 ลองสังเกตดูว่าหน้านี้มีจุดที่ต่างจากหน้า Home ตรงไหนบ้าง เช่น pagination ด้านล่างสุดของ grid สินค้า ซึ่งเป็นรายละเอียดที่ต้องระบุไว้ในโครงสร้างด้วย ไม่งั้น Agent จะไม่รู้ว่าต้องใส่

บทถัดไปเราจะเริ่มตั้งโครงโปรเจกต์ My Store ตัวจริงกับ Cursor Agent — เตรียม prompt ของหน้า Home ที่เพิ่งเห็นไว้ให้พร้อม อีกไม่กี่บทก็จะได้ใช้จริง
