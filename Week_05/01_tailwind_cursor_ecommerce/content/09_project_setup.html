บทเรียน 09 · เริ่มสร้างโปรเจกต์ (Project Kickoff)

ตั้งโครงโปรเจกต์ E-commerce

Project Setup

ตอนนี้คุณมี prompt ของหน้า Home เตรียมไว้แล้วจากแบบฝึกหัดท้ายบทที่แล้ว และรู้จักทั้ง Agent panel กับ project rules ครบแล้ว แต่ก่อนจะเปิดแชทสั่งงานจริง ยังมีงานหนึ่งที่ควรทำเองด้วยมือ ไม่ปล่อยให้ Agent เดา — นั่นคือการตั้งโครงโปรเจกต์ my-store บทนี้เราจะรันคำสั่งสร้างโปรเจกต์เอง ต่อ Tailwind เอง จัดโฟลเดอร์เอง แล้วปิดท้ายด้วยการเขียนไฟล์กฎที่ Agent จะอ่านทุกครั้งตลอดทั้งสัปดาห์ที่เหลือ ตั้งแต่บทหน้าเป็นต้นไปทุกอย่างที่เราสร้างจะอยู่ในโปรเจกต์จริงนี้เท่านั้น ไม่ใช่ playground อีกต่อไป

สร้างโปรเจกต์ my-store

เหตุผลที่ขั้นตอนนี้ควรทำเอง: การตั้งโครงเริ่มต้นเป็นงานที่ deterministic — รู้ผลลัพธ์ที่ต้องการล่วงหน้าแน่นอนอยู่แล้ว ถ้าปล่อยให้ Agent เป็นคนเลือกเวอร์ชัน dependency หรือคิดโครงสร้างโฟลเดอร์เอง มันอาจเลือกไม่ตรงกับที่ทีมตกลงกันไว้ และแต่ละแชทอาจเลือกไม่เหมือนกันด้วย เก็บ Agent ไว้ใช้กับงานที่ต้องตัดสินใจเชิงสร้างสรรค์จริง ๆ ดีกว่า เปิด terminal แล้วรันคำสั่งชุดนี้เอง

npm create vite@latest my-store -- --template react-ts
cd my-store
npm install
npm install tailwindcss @tailwindcss/vite react-router @tanstack/react-query axios
npm install react-hook-form zod @hookform/resolvers swiper react-paginate

สามบรรทัดแรกสร้างโปรเจกต์ React + TypeScript เปล่า ๆ ด้วย Vite เหมือนที่ทำมาแล้วหลายรอบใน Week_04 และบทที่ 3 บรรทัดที่ 4 ติดตั้งของที่ต้องใช้ตลอดทั้งสัปดาห์: tailwindcss กับ @tailwindcss/vite (แบบเดียวกับบทที่ 3), react-router สำหรับ routing แบบ data mode ที่จะตั้งค่าในบทนี้เอง, @tanstack/react-query สำหรับดึงข้อมูลจริงจาก dummyjson ในบทที่ 15, และ axios เป็น HTTP client บรรทัดสุดท้ายเป็นแพ็กเกจเฉพาะทางที่หน้าถัด ๆ ไปต้องใช้: react-hook-form + zod + @hookform/resolvers สำหรับฟอร์ม checkout ที่ต้อง validate (บทที่ 19), swiper สำหรับ banner carousel หน้า Home (บทที่ 14) และ react-paginate สำหรับแบ่งหน้าสินค้าที่หน้า Category (บทที่ 16)

💡 ติดตั้งไว้ล่วงหน้าทั้งหมดตั้งแต่ตอนนี้ เพื่อไม่ต้องหยุดกลางบทเรียนหลัง ๆ ให้ Agent รัน npm install แพ็กเกจใหม่เอง — แยกขั้นตอน "ติดตั้งเครื่องมือ" ออกจากขั้นตอน "สร้าง UI" ให้ชัดเจน จะตรวจทานง่ายกว่ามาก

ต่อ Tailwind v4 เข้ากับโปรเจกต์จริง

ขั้นตอนต่อ Tailwind เหมือนกับบทที่ 3 เป๊ะ ๆ — เปิด vite.config.ts แล้วลงทะเบียนปลั๊กอิน

// vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
});

แล้วเปิด src/index.css ใส่บรรทัด @import เหมือนเดิม แต่คราวนี้ต่อด้วยบล็อก @theme ที่มีสีแบรนด์จากบทที่ 6 ทันที เพราะโปรเจกต์จริงต้องใช้สีของ My Store ตั้งแต่บรรทัดแรก ไม่ใช่สีเริ่มต้นของ Tailwind ที่ต้องมาเปลี่ยนทีหลัง

@import "tailwindcss";

@theme {
  --color-primary: #0d6efd;
  --color-primary-dark: #0b5ed7;
  --color-accent: #ffa200;
  --color-danger: #ff4136;
}

ตั้ง Path Alias @/

ยิ่งโครงสร้างโฟลเดอร์ลึกขึ้น relative import แบบ ../../../shared/components/Button ก็ยิ่งอ่านยากและย้ายไฟล์ทีไรก็พังทุกที ทางแก้คือตั้ง alias @/ ให้ชี้ตรงไปที่ src/ เสมอ ไม่ว่าไฟล์จะอยู่ลึกแค่ไหน เพิ่มส่วน resolve.alias ต่อจาก config ที่เพิ่งตั้งไว้ด้านบน

// vite.config.ts
import { fileURLToPath, URL } from "node:url";
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: {
    alias: { "@": fileURLToPath(new URL("./src", import.meta.url)) },
  },
});

แล้วบอก TypeScript ให้รู้จัก alias ตัวเดียวกันนี้ด้วย ไม่งั้น editor จะขีดเส้นแดงใต้ import ทุกครั้งแม้ตอน build จะผ่านจริง เปิด tsconfig.app.json เพิ่มสองบรรทัดนี้เข้าไปใน compilerOptions

{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}

ตั้งแต่นี้ไป import ภายในโปรเจกต์ทุกจุดจะเขียนเป็น @/shared/components/Button ได้เลย ไม่ว่าไฟล์ที่เรียกจะอยู่ลึกแค่ไหนก็ตาม

จัดโครงสร้างโฟลเดอร์

ลบไฟล์ตัวอย่างที่ Vite สร้างมาให้ออก แล้วสร้างโฟลเดอร์สี่ตัวนี้ใน src/ — นี่คือโครงเดียวกับที่แอปต้นแบบใช้จริง

src/
  app/        # router, providers, layout — โครงของแอป
  pages/      # component บาง ๆ หนึ่งไฟล์ต่อ route
  features/   # products, cart, checkout — แต่ละ feature มี api, queries, components ของตัวเอง
  shared/     # UI กลาง (Button, Modal), api client, utils, hooks

กฎที่ต้องจำให้ขึ้นใจคือ "pages บาง features หนา" — pages/ มีหน้าที่แค่ประกอบ component จาก features/ เข้าด้วยกันแล้ว render ไม่มี logic ดึงข้อมูลหรือคำนวณอะไรอยู่ในนั้นเลย ตรรกะจริงทั้งหมด (การเรียก API, custom hook, component ย่อยเฉพาะฟีเจอร์) อยู่ใน features/<name>/ กฎง่าย ๆ นี้ทำให้เปิดไฟล์ pages/Home.tsx แล้วอ่านจบได้ในสิบวินาที และทำให้ Agent รู้ทันทีว่าไฟล์ใหม่ควรไปสร้างตรงไหนโดยไม่ต้องถามซ้ำทุกครั้ง

เขียนกฎแรกให้ Agent: .cursor/rules/project.mdc

บทที่ 7 เกริ่นไว้ว่า project rules คือไฟล์ที่ Agent อ่านทุกครั้งโดยอัตโนมัติ ไม่ต้องพิมพ์เตือนซ้ำเองทุกแชท ตอนนี้ถึงเวลาเขียนไฟล์จริงแล้ว สร้าง .cursor/rules/project.mdc ที่ root ของโปรเจกต์

---
description: My Store — React e-commerce conventions
alwaysApply: true
---

- React 19 + TypeScript + Vite; styling ด้วย Tailwind CSS v4 utilities เท่านั้น ห้ามสร้างไฟล์ .css/.scss ใหม่
- โครงสร้าง: app/ (router, providers), pages/ (route components บาง ๆ), features/<name>/ (api, queries, components), shared/ (UI กลาง, utils, hooks)
- Component เป็น function component + TypeScript, ตั้งชื่อไฟล์ PascalCase.tsx ในโฟลเดอร์ชื่อเดียวกัน
- ใช้ react-router แบบ data mode (createBrowserRouter) และ TanStack Query v5 (queryOptions pattern) สำหรับ server state
- Mobile-first: class ไม่มี prefix สำหรับมือถือ แล้วขยายด้วย sm:/md:/lg:
- รูปทุกรูปต้องมี alt; ปุ่ม/ลิงก์ต้องเป็น <button>/<a> จริง และมี focus-visible state
- import ภายในโปรเจกต์ใช้ alias @/ เสมอ

สังเกตว่าทุกบรรทัดในนี้คือสิ่งที่เพิ่งเรียนหรือเพิ่งตั้งไปเองทั้งนั้น: utility เท่านั้น (บทที่ 2), โครงสร้างโฟลเดอร์ (ด้านบน), mobile-first (บทที่ 5), focus-visible (บทที่ 6), alias @/ (ด้านบน) — สิ่งที่ต่างไปคือตอนนี้กฎพวกนี้ไม่ได้อยู่แค่ในหัวคุณอีกต่อไป แต่เขียนไว้เป็นไฟล์ที่ Agent อ่านทุกครั้งที่คุณสั่งงาน เพราะ alwaysApply: true พูดง่าย ๆ คือนี่คือการสอน Agent ครั้งเดียว ใช้ได้ทุก prompt ตั้งแต่บทหน้าเป็นต้นไป คุณจะไม่ต้องพิมพ์ "ใช้ Tailwind นะ อย่าลืม mobile-first นะ" ซ้ำทุกครั้งอีกแล้ว เพราะมันอยู่ในไฟล์นี้ถาวร

Commit โครงเริ่มต้น

โครงพร้อมแล้ว ก่อนจะเปิด Agent panel สั่งงานอะไรทั้งสิ้น commit ไว้ก่อนเป็นจุดเริ่มต้นที่สะอาด

git init
git add -A
git commit -m "chore: scaffold my-store project"

นี่คือนิสัยเดียวกับที่ฝึกมาตลอด Week_04: commit เล็ก บ่อย checkpoint ของ Cursor ที่เจอในบทที่ 7 นั้นจำได้แค่ภายในแชทเดียวและหายไปเมื่อปิดโปรเจกต์ ส่วน git commit คือประวัติถาวรที่อยู่ข้ามแชท ข้ามวัน ข้ามเครื่อง ยิ่งงานถัดไปเป็นการให้ Agent แก้โค้ดหลายไฟล์พร้อมกัน ยิ่งอยากมีจุดย้อนกลับที่แน่นอนแบบนี้ไว้เสมอ

โครงโปรเจกต์พร้อมแล้ว ทั้ง dependency, Tailwind, path alias, โฟลเดอร์ และกฎของ Agent บทถัดไปเราจะเปิด Agent panel เป็นครั้งแรกในโปรเจกต์จริงนี้ แล้วใช้ prompt ที่เตรียมไว้ตั้งแต่บทที่ 8 สร้าง Layout แรกของ My Store
