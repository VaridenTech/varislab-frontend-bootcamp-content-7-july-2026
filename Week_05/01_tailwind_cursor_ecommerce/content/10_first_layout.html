บทเรียน 10 · เริ่มสร้างโปรเจกต์ (Project Kickoff)

สร้าง Layout แรกด้วย Agent

First Layout with the Agent

บทที่ 9 ตั้งโครงโปรเจกต์เสร็จแล้ว บทนี้เป็นครั้งแรกที่เราจะเปิด Agent panel สั่งงานจริงในโปรเจกต์ my-store และเป็นครั้งแรกที่ใช้ขั้นตอนการทำงานที่จะวนซ้ำทุกบทตั้งแต่นี้ไปจนจบสัปดาห์ เรียกว่า The Loop: ตั้งเป้าหมายให้ชัด (🎯) เขียน prompt ตามโครงสี่ส่วนจากบทที่ 8 (📝) ดูว่า Agent สร้างอะไรมา (🤖) ตรวจทานตามเช็กลิสต์ (🔍) แล้วค่อย refactor ให้สะอาด (🔧) — ทำทีละชิ้นเล็ก ๆ วนแบบนี้ไปเรื่อย ๆ จนกว่าจะครบทั้งแอป บทนี้เราจะวนครบทุกขั้นตอนของ Loop เป็นครั้งแรก โดยใช้ Layout เป็นชิ้นแรก

🎯 เป้าหมาย

งานของบทนี้คือ Layout โครงหลักของทั้งแอป — ส่วนที่ทุกหน้าต้องมีเหมือนกัน (Header, Footer) กับจุดที่แต่ละหน้าจะมาสลับแสดงผลกันทีหลัง (<Outlet />) ดูภาพหน้า Home ของแอปต้นแบบอีกครั้ง แต่รอบนี้ให้โฟกัสเฉพาะแถบบนสุดกับแถบล่างสุดเท่านั้น ตรงกลางทั้งหมด (banner, deals, สินค้าตามหมวด) ยังไม่แตะ เก็บไว้บทที่ 14

ถือว่า "เสร็จ" เมื่อ:

  • src/app/router.tsx มี createBrowserRouter ที่มี MainLayout เป็น layout route และ path "/" ที่ยัง render หน้า Home ว่าง ๆ ไปก่อน
  • src/main.tsx ครอบทั้งแอปด้วย RouterProvider แล้ว
  • MainLayout เรียง Header บน, เนื้อหาของแต่ละหน้าอยู่กลาง (ผ่าน Outlet), Footer อยู่ล่าง โดยส่วนกลางดันความสูงเต็มจอเสมอแม้เนื้อหาจะน้อย
  • Header มีโลโก้ข้อความ "My Store" ที่ลิงก์กลับหน้าแรก, เมนู Home / Products, และไอคอนตะกร้าพร้อม badge ตัวเลข 0
  • Footer แสดงผลเป็นโครงสามคอลัมน์ตาม screenshot
  • รัน npm run dev แล้วเห็น layout นี้จริงที่ http://localhost:5173/

📝 เขียน Prompt

ทบทวนโครงสี่ส่วนจากบทที่ 8 อีกครั้ง — บริบท / โครงสร้าง (หรืองาน) / ข้อกำหนดทางเทคนิค / ขอบเขต ครั้งนี้ต่างจากบทที่ 8 ตรงที่เราขอแค่ layout ไม่ใช่ทั้งหน้า ส่วน "โครงสร้าง" จึงเขียนเป็นรายการงานทีละไฟล์แทน เพราะ layout ไม่ได้มี section เรียงจากบนลงล่างแบบหน้า Home สังเกตด้วยว่าบรรทัด Footer อ้างอิงของจริงที่เห็นใน screenshot เป๊ะ ๆ — ข้อมูลติดต่อ My Store, Categories, Pages ไม่ใช่ Shop / Support / About ที่มักเจอในเทมเพลตทั่วไปตามอินเทอร์เน็ต เพราะ prompt ที่ดีต้องอ้างอิงของจริงที่แนบไป ไม่ใช่เดาจากเว็บอื่นที่ Agent เคยเห็นมาก่อน

สร้างโครง layout ของแอปตาม screenshot ที่แนบ (ดูเฉพาะส่วน header และ footer)

บริบท: โปรเจกต์ my-store ตามโครงสร้างใน rules มี react-router ติดตั้งแล้ว

งาน:
- src/app/router.tsx: createBrowserRouter มี MainLayout เป็น layout route และหน้า Home ว่าง ๆ ที่ path "/"
- src/main.tsx: ครอบด้วย RouterProvider
- MainLayout: Header บน, <Outlet /> ตรงกลาง (main ที่ดันความสูงเต็มจอ), Footer ล่าง
- Header: โลโก้ข้อความ "My Store" (ลิงก์กลับ "/"), nav มีลิงก์ Home และ Products, ไอคอนตะกร้า SVG พร้อม badge ตัวเลข 0 ด้านขวา
- Footer: 3 คอลัมน์ตาม screenshot — ข้อมูลติดต่อ My Store (ที่อยู่, เบอร์โทร, อีเมล), Categories (รายชื่อหมวดหมู่), Pages (ลิงก์ Home, Products, Cart)

ข้อกำหนด: Tailwind เท่านั้น, mobile-first, semantic HTML, focus-visible ทุกลิงก์
ขอบเขต: ยังไม่ต้องทำหน้าอื่น ยังไม่ต้องมี state ตะกร้าจริง

🤖 สิ่งที่ Agent สร้าง

วาง prompt นี้ในโหมด Agent พร้อมแนบรูป home_desktop.png แล้วปล่อยให้มันทำงาน ไฟล์ที่ได้ตรงตามที่ขอเป๊ะ — router.tsx กับ main.tsx ต่อสายกันครบ และ MainLayout เรียงลำดับ Header / Outlet / Footer ถูกต้องตามที่สั่ง

// src/app/layouts/MainLayout/MainLayout.tsx
import { Outlet } from "react-router";
import Header from "@/shared/components/Header/Header";
import Footer from "@/shared/components/Footer/Footer";

export default function MainLayout() {
  return (
    <div className="flex min-h-screen flex-col">
      <Header />
      <main className="flex-1">
        <Outlet />
      </main>
      <Footer />
    </div>
  );
}

ส่วนที่น่าดูใกล้ ๆ กว่าคือ Header.tsx — อ่านเผิน ๆ มันทำงานได้จริง เปิดจอกว้าง ๆ แล้วหน้าตาตรงกับ screenshot ทุกจุด

// src/shared/components/Header/Header.tsx
import { Link } from "react-router";

export default function Header() {
  return (
    <header className="border-b border-gray-200 bg-white">
      <div className="mx-auto flex h-16 w-[1200px] items-center justify-between px-4">
        <Link to="/" className="text-xl font-bold text-gray-900">
          My Store
        </Link>

        <nav className="hidden items-center gap-6 md:flex">
          <div className="cursor-pointer text-gray-700 hover:text-primary">Home</div>
          <div className="cursor-pointer text-gray-700 hover:text-primary">Products</div>
        </nav>

        <div className="relative">
          <svg className="h-6 w-6" viewBox="0 0 24 24" fill="none" stroke="currentColor">
            <path d="M3 3h18l-2 12H5L3 3z" strokeWidth="2" />
          </svg>
          <span className="absolute -right-2 -top-2 flex h-4 w-4 items-center justify-center rounded-full bg-primary text-[10px] text-white">
            0
          </span>
        </div>
      </div>
    </header>
  );
}

Agent ยังสร้าง Footer.tsx ที่มีสามคอลัมน์ตามที่สั่งไว้ด้วยเช่นกัน (ไม่แปะโค้ดเต็มตรงนี้ เพราะไม่มีอะไรน่าสงสัยเป็นพิเศษ) และแก้ main.tsx ให้ครอบด้วย RouterProvider ตามที่ขอ

🔍 โค้ดหน้าตาดี ใช้งานได้บนจอใหญ่ — แต่มีของซ่อนอยู่ บทที่ 5 (ตรวจทานโค้ดที่ AI สร้าง) จะพาไล่จับทีละตัว ตอนนี้แค่รู้ไว้ก่อนว่ามันมีอยู่จริง ยังไม่ต้องรีบแก้

🔍 ตรวจทาน

รอบนี้เป็นแค่การตรวจผ่าน ๆ อย่างเร็ว ยังไม่ใช้เช็กลิสต์เต็มรูปแบบ (เช็กลิสต์จริงมาบทที่ 11–13) รัน npm run dev แล้วลองสามอย่างนี้

  • ย่อหน้าต่างเบราว์เซอร์ให้แคบกว่า 1200px แล้วเกิด scrollbar แนวนอนโผล่มาที่ด้านล่าง ทั้งที่เว็บทั่วไปไม่ค่อยทำแบบนี้กัน — ทำไม container ถึงไม่ยอมหดตามขนาดจอ
  • คลิกที่ "Home" กับ "Products" ใน nav ดู ไม่มีอะไรเกิดขึ้นเลย ทั้งที่หน้าตาเหมือนลิงก์ทุกประการ (สีเปลี่ยนตอน hover, cursor เป็นมือ) — เป็นลิงก์จริงหรือแค่หน้าตาเหมือนลิงก์
  • กด Tab ไล่ผ่านทั้งหน้าโดยไม่แตะเมาส์เลย ไม่เห็นกรอบ focus ที่โลโก้หรือไอคอนตะกร้าจุดไหนเลย — ใครที่ใช้คีย์บอร์ดล้วนนำทางเว็บจะไม่รู้เลยว่าตอนนี้โฟกัสอยู่ตรงไหน

สามข้อนี้จดไว้เป็น TODO ก่อน ยังไม่ต้องแก้ตอนนี้ — บทที่ 5 (ตรวจทานโค้ดที่ AI สร้าง) จะพาคุณกลับมาไล่จับทีละข้อ พร้อมเหตุผลว่าทำไมมันถึงเป็นปัญหาและวิธีแก้ที่ถูกต้อง (สังเกตเพิ่มอีกจุดหนึ่งด้วยว่า พอจอแคบกว่า 768px เมนู Home/Products หายไปเฉย ๆ เพราะ class hidden md:flex ซ่อนมันไว้ตั้งแต่มือถือ โดยไม่มีอะไรมาแทนเลย — เรื่องนี้ไม่ใช่บั๊กที่ซ่อนอยู่ แต่เป็นสิ่งที่ Agent จงใจข้ามไปเพราะ prompt ไม่ได้ขอ เมนูมือถือจะเป็นงานหลักของบทที่ 11)

🔧 Refactor

ปกติขั้นตอนนี้คือที่เราแก้โค้ดจริงตามสิ่งที่เจอในขั้นตรวจทาน แต่รอบนี้ตั้งใจเว้นว่างไว้ก่อน สามข้อที่เพิ่งจดไว้ต้องใช้เครื่องมือและเช็กลิสต์เฉพาะทางที่ยังไม่ได้เรียน — breakpoint กับ container จริง ๆ มาในบทที่ 11, semantic link กับ accessibility เต็มรูปแบบมาในบทที่ 12 รีบแก้ตอนนี้โดยไม่มีเช็กลิสต์รองรับ เสี่ยงแก้ไม่ครบหรือแก้ผิดจุด บทที่ 5 ทั้งหมด (บทที่ 11–13) จะพาไล่จับและแก้ทีละข้อให้ครบถ้วน นี่คือเหตุผลที่ Loop รอบนี้ไม่มี refactor จริง — แต่สิ่งที่ยังต้องทำเสมอไม่ว่าจะมีบั๊กซ่อนอยู่หรือไม่คือ commit

git add -A
git commit -m "feat: add MainLayout, Header, Footer skeleton"

โค้ดใช้งานได้ ไม่พัง คอมไพล์ผ่าน แค่นี้ก็คุ้มค่าที่จะ commit ไว้เป็นจุดย้อนกลับที่ปลอดภัยแล้ว ค่อยแก้ทีละเรื่องในบทหน้า

ปิดท้ายบทนี้ด้วยหน้าตา router.tsx ที่ใช้งานอยู่ตอนนี้ — มี path เดียวคือ "/" ตรงกับจุดแรกในตาราง routes ของทั้งโปรเจกต์ ส่วนที่เหลือ (/categories, /products/:id, /cart, /checkout, /order/success) จะทยอยเพิ่มเข้ามาเป็น children ตัวใหม่ในบทถัด ๆ ไป ด้วย pattern เดียวกันนี้

// src/app/router.tsx
import { createBrowserRouter } from "react-router";
import MainLayout from "@/app/layouts/MainLayout/MainLayout";

const router = createBrowserRouter([
  {
    path: "/",
    element: <MainLayout />,
    children: [{ index: true, element: <div>Home (ว่างไว้ก่อน)</div> }],
  },
]);

export default router;

Layout แรกของ My Store พร้อมใช้งานแล้ว บทหน้าเราจะกลับมาที่ Header ตัวนี้เพื่อไล่จับปัญหาข้อแรกในสามข้อที่จดไว้ — เรื่อง responsive
