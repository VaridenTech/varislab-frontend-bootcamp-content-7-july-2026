Wrap Up

ย้อนกลับไปบทที่ 1 — ตอนนั้น 6 หน้าของ My Store เป็นแค่ screenshot ที่ให้ดูเป็นเป้าหมายปลายทาง พร้อมทักษะสี่ข้อที่บอกไว้ว่าจะฝึกซ้ำตลอดสัปดาห์ ตอนนี้ทั้ง 6 หน้านั้นเป็นโค้ดจริงที่คุณเขียนเอง ตรวจทานเอง และ refactor เอง ทุกบรรทัด ยินดีด้วยที่มาถึงบทสุดท้ายของสัปดาห์นี้ — มาย้อนดูกันว่าตลอดทางที่ผ่านมาสร้างอะไรไว้บ้าง

ครบทั้ง 6 route แล้ว

router.tsx เวอร์ชันสมบูรณ์ที่ประกอบเสร็จในบทที่ 19 มี 6 route ครบตามตารางในบทที่ 1 ทั้งหมดเป็น children ของ MainLayout เดียวกัน พร้อม errorElement ที่ RouteErrorFallback ดักจับทั้ง path ที่ไม่มีจริงและ error ที่ไม่มีใครดักจับไว้ก่อนหน้า

Route หน้า สร้างในบทที่
/ Home 14–15
/categories Category 16
/products/:id Product Detail 17
/cart Cart 18
/checkout Checkout 19
/order/success Order Success 19

ทักษะทั้งสี่ที่ฝึกซ้ำทั้งสัปดาห์

บทที่ 1 เขียนทักษะสี่ข้อไว้เป็นรายการเปล่า ๆ ที่ยังไม่มีบทเรียนไหนรองรับ ตอนนี้ทุกข้อผูกกับบทจริงที่คุณลงมือทำมาแล้ว

  • แปลง screenshot เป็น prompt → บทเรียน 08 สอนโครงสี่ส่วนของ prompt ที่ดี (บริบท / โครงสร้าง / ข้อกำหนดทางเทคนิค / ขอบเขต) ที่ใช้ซ้ำทุกครั้งตั้งแต่นั้นมา
  • ใช้ Cursor Agent สร้าง UI → บทเรียน 10 วน The Loop เต็มรูปแบบครั้งแรกกับ Layout แล้วทุกบทที่สร้างหน้า (14–19) ใช้ Loop เดียวกันนี้ซ้ำกับ Home, Category, Product Detail, Cart และ Checkout
  • ตรวจทานโค้ด Tailwind → บทเรียน 11–13 สร้างสามเลนส์ตรวจทาน (responsive, accessibility, maintainability) ที่ทุกบทหลังจากนั้นใช้ซ้ำที่ขั้นตอน 🔍 ของ Loop
  • refactor เป็น reusable component → บทเรียน 13 สร้าง Button ตัวแรกด้วยเหตุผลนี้โดยตรง แล้วทุก section 🔧 ตั้งแต่บทที่ 14 เป็นต้นไปทำซ้ำแบบเดียวกันกับโค้ดชิ้นใหม่ทุกครั้ง

ผลลัพธ์ของการวน Loop ซ้ำ ๆ ทั้งสัปดาห์คือคลัง shared component และ utility ที่ใช้ร่วมกันทั่วทั้งแอป — Button, PageBanner, ProductCard, FeatureCard, CountdownTimer, StarIcon, CategoryMenu, ฟังก์ชัน formatPrice และ calculateOffset/calculateTotalPages จาก shared/utils, hook useCart และ useProductRoute, และชั้น data ที่วางรากฐานไว้ตั้งแต่บทที่ 15 อย่าง apiClient กับ productQueries ไม่มีชิ้นไหนถูกออกแบบไว้ล่วงหน้าตั้งแต่ต้น ทุกชิ้นโผล่ออกมาจากการเจอโค้ดซ้ำจริง ๆ ระหว่างตรวจทาน แล้วค่อยแยกออกมาตอน 🔧 — นี่คือหลักฐานว่า Loop ทำงานได้จริงตลอดทั้งสัปดาห์ ไม่ใช่แค่ทฤษฎีที่พูดถึงในบทที่ 1

เทียบกับ Repo ต้นแบบ

My Store ที่คุณสร้างอ้างอิงจาก github.com/manjarb/varis-lab-project-06-react-ecommerce-app ตลอดทั้งสัปดาห์ ทั้ง routes, types และ endpoint แต่ไม่ได้ copy โค้ดมาทั้งหมด — ลองเปิด repo ต้นแบบเทียบกับสิ่งที่คุณสร้างเองดู จะเห็นความต่างที่ตั้งใจไว้สามจุด

  • Styling — repo ต้นแบบใช้ SCSS modules (ไฟล์ .module.scss แยกต่อ component) ส่วนของเราใช้ Tailwind utility ล้วนตามที่ตั้งเป้าไว้ตั้งแต่บทที่ 2 ลองเปิดไฟล์ SCSS สักไฟล์ในต้นแบบเทียบกับ JSX ของเราดู จะเห็นชัดว่า utility-first เปลี่ยน "จะเขียน class ชื่ออะไร" ให้กลายเป็น "จะประกอบ utility ไหนเข้าด้วยกัน" ไปเลย
  • Tests — repo ต้นแบบมีชุดทดสอบด้วย Vitest, React Testing Library และ MSW (mock service worker สำหรับดัก API call ในเทสต์) ครบทุก feature สัปดาห์นี้เราโฟกัสที่ Tailwind กับ Cursor workflow เท่านั้น เลยยังไม่ได้แตะเทสต์ของ My Store เลยสักบรรทัด ถ้าอยากอ่านต่อ ทักษะเทสต์ React ทั้งหมดสอนไว้แล้วที่ Week_04 บทเรียน 23–30 (Vitest, React Testing Library, custom hook, snapshot, coverage, browser tests) — ลองกลับไปเขียนเทสต์ให้ useCart หรือ CheckoutAddressForm ของ My Store เองดูเป็นแบบฝึกหัดต่อยอด
  • Library เสริม — repo ต้นแบบพึ่ง FontAwesome (ไอคอน), dayjs (จัดรูปแบบวันที่ในรีวิว) และ react-spinners (loading indicator) เพิ่มเติม ของเราตั้งใจใช้แค่สิ่งที่จำเป็นจริง ๆ (Swiper, react-paginate, react-modal, react-hook-form + zod) เพื่อให้เห็น Tailwind utility ทำงานเองโดยไม่มี library ช่วยบัง

💡 สองจุดที่น่าพูดถึงเป็นพิเศษ — ไม่ใช่แค่ "ต่างจากต้นแบบ" แต่คือจุดที่เวอร์ชันของเราดีกว่าต้นแบบจริง ๆ อย่างแรก: sidebar หมวดหมู่กับ grid สินค้าทับกันบนมือถือในแอปต้นแบบ (พบครั้งแรกตอนตรวจทาน responsive บทที่ 5 ยืนยันซ้ำในบทที่ 11 และแก้จริงตอนสร้างหน้า Category บทที่ 16) เวอร์ชันของเราเรียงต่อกันแนวตั้งอย่างถูกต้องและปรับเมนูให้ปัดซ้าย-ขวาได้บนมือถือด้วย อย่างที่สอง: บั๊กสเกลคะแนนดาว — component ดาวของต้นแบบเขียนไว้รองรับสเกล 0-10 แต่ดันรับ product.rating ที่เป็นสเกล 0-5 ตรง ๆ ทำให้ดาวเต็มแสดงต่ำกว่าความจริงเสมอ (พบและแก้ตอนสร้างหน้า Product Detail บทที่ 17) ทั้งสองจุดไม่ใช่บั๊กที่เราจงใจสร้างขึ้นเพื่อสอน แต่เป็นบั๊กจริงในแอปต้นแบบที่ตรวจทานอย่างละเอียดถึงจะเจอ — นี่คือใจความสำคัญที่สุดของทั้งสัปดาห์: ต้องตรวจทานโค้ดทุกจุดจริง ๆ แม้แต่โค้ดที่มาจาก repo ต้นแบบซึ่งดูน่าเชื่อถือ ไม่ใช่แค่โค้ดที่ AI สร้างให้เท่านั้น

ไอเดียต่อยอด

My Store ที่มีตอนนี้ใช้งานได้ครบ flow การซื้อของจริงแล้ว แต่ยังมีของอีกหลายอย่างที่เพิ่มได้ด้วยทักษะที่เพิ่งฝึกมาทั้งสัปดาห์ ลองหยิบไปทำต่อเป็นแบบฝึกหัดหลังคอร์ส

  • ช่องค้นหา — dummyjson มี endpoint GET /products/search?q= พร้อมใช้อยู่แล้ว วน The Loop เดิมกับหน้าใหม่ได้เลย: prompt → generate → review → refactor ด้วย productQueries pattern เดียวกับบทที่ 15
  • Favorites — ใช้ pattern เดียวกับตะกร้าในบทที่ 18 เป๊ะ (Context + useReducer + localStorage) แค่เปลี่ยนจาก "จำนวนในตะกร้า" เป็น "ถูกใจหรือไม่" เท่านั้น
  • Dark mode — เพิ่ม dark: variant ให้ utility ที่มีอยู่แล้วทั่วแอป ทดสอบว่า design tokens ที่วางไว้ตั้งแต่บทที่ 6 (--color-primary ฯลฯ) รองรับการสลับธีมได้ดีแค่ไหนโดยไม่ต้องเขียน override กระจัดกระจาย
  • Deploy จริง — ขั้นตอน deploy React app ขึ้น production สอนไว้ครบแล้วที่ Week_04 บทเรียน 35 — ใช้ขั้นตอนเดียวกันนั้นกับ My Store ได้ทันที

ส่งท้าย

สัปดาห์นี้เริ่มจาก Agent ที่เขียนโค้ดได้เร็วกว่าที่คุณเคยเขียนมือมาก แต่สิ่งที่ทำให้โค้ดนั้นใช้งานได้จริงไม่ใช่ความเร็วของ Agent — คือสามเลนส์ตรวจทานที่คุณฝึกซ้ำจนเป็นนิสัย ยิ่ง Agent generate โค้ดได้เร็วและเยอะขึ้นเท่าไหร่ ทักษะreviewก็ยิ่งสำคัญขึ้นเท่านั้น เพราะปริมาณโค้ดที่ต้องรับผิดชอบเพิ่มขึ้นเร็วกว่าที่คนคนเดียวจะเขียนเองไหวมาก

ทักษะที่ฝึกมาทั้งสัปดาห์นี้ — เขียน prompt ให้ชัดเจนพอที่ AI จะทำตามได้ ตรวจทานโค้ดที่ AI สร้างอย่างเป็นระบบ (responsive, accessibility, maintainability) และรู้ว่าเมื่อไหร่ควร refactor ออกเป็น component ที่ใช้ซ้ำได้ — คือทักษะเดียวกับที่ senior developer ใช้คุมงานของ AI agent ในทีมจริงทุกวันนี้ ไม่ว่า tool จะเปลี่ยนไปเป็นตัวไหนต่อจากนี้ วงจร prompt → generate → review → refactor ที่คุณเพิ่งฝึกจนคล่องจะยังใช้ได้เหมือนเดิม เพราะปัญหาที่มันแก้ไม่ใช่ "AI เขียนโค้ดไม่เก่ง" แต่คือ "คนที่ ship โค้ดออกไปต้องรับผิดชอบมันเสมอ ไม่ว่าใครจะเป็นคนพิมพ์บรรทัดแรก"

ขอบคุณที่ตามมาจนจบสัปดาห์นี้ — ไปสร้างต่อกันเลย 🎉
