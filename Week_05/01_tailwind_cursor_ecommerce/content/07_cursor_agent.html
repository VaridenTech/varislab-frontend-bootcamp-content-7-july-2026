บทเรียน 07 · Cursor Workflow

รู้จัก Cursor และ Cursor Agent

Meet Cursor

หกบทที่ผ่านมาคุณฝึกเขียน utility class ของ Tailwind ด้วยมือจนคล่อง นับจากบทนี้เป็นต้นไป บทบาทของคุณจะเปลี่ยนไป — ไม่ใช่พิมพ์ทุกบรรทัดเอง แต่เป็นการทำงานร่วมกับ AI agent ที่เขียนโค้ดแทนได้เร็วกว่ามาก โดยมีคุณเป็นคนกำกับทิศทางและตรวจทานทุกบรรทัดที่มันสร้างออกมา เครื่องมือที่จะพาเราทำแบบนั้นตลอดสัปดาห์ที่เหลือคือ Cursor

Cursor คืออะไร

Cursor เป็น code editor ที่ fork มาจาก VS Code — หน้าตา เมนู และ keyboard shortcut ส่วนใหญ่จึงเหมือน VS Code เกือบทุกอย่าง ถ้าคุณเคยใช้ VS Code เขียน Coffee Master ใน Week_04 มาแล้ว จะรู้สึกคุ้นเคยทันที เปิดใช้งานครั้งแรก Cursor จะถามว่าอยากนำเข้า (import) settings, keybindings และ extension ที่เคยติดตั้งไว้ใน VS Code หรือไม่ — กดตกลงได้เลย ทุกอย่างที่เคยตั้งไว้จะย้ายมาโดยไม่ต้องตั้งค่าใหม่

ส่วนที่ Cursor เพิ่มเข้ามาเหนือ VS Code ธรรมดาคือ AI ที่ฝังอยู่ลึกในทุกมุมของ editor ไม่ใช่แค่ extension autocomplete ตัวหนึ่งที่ติดตั้งเพิ่มเข้าไป แต่เป็นแกนหลักของเครื่องมือทั้งตัว

สามวิธีใช้ AI ใน Cursor: Tab, Inline Edit, Agent

Cursor ให้ AI เข้ามาช่วยเขียนโค้ดได้สามระดับ ต่างกันตรงขนาดของงานที่เหมาะจะให้มันทำ

  • Tab — เหมือน autocomplete ทั่วไปที่ขยายขึ้นไปอีกขั้น ระหว่างพิมพ์โค้ด Cursor จะเดาบรรทัดถัดไป (หรือทั้งบล็อก) แล้วแสดงเป็นตัวจาง ๆ ให้กด Tab เพื่อยอมรับ เหมาะกับงานซ้ำ ๆ ที่คาดเดาได้ เช่น เขียน property คล้ายกันหลายบรรทัดติดกัน
  • Inline Edit (Cmd+K หรือ Ctrl+K บน Windows/Linux) — เลือกโค้ดช่วงหนึ่งบนหน้าจอ กด Cmd+K แล้วพิมพ์คำสั่งสั้น ๆ ว่าต้องการแก้ตรงไหน Cursor จะแก้เฉพาะช่วงที่เลือกไว้ให้ทันที เหมาะกับงานแก้ไขจุดเดียวที่ชัดเจน เช่น “เปลี่ยนสีปุ่มนี้เป็นสีแดง”
  • Agent panel (Cmd+I หรือ Ctrl+I) — พระเอกของสัปดาห์นี้ เปิดเป็นแชทแยกจากไฟล์ที่เปิดอยู่ พิมพ์คำสั่งเป็นภาษาธรรมชาติแล้ว Agent จะอ่านโค้ดในโปรเจกต์ แก้ได้หลายไฟล์พร้อมกัน และรันคำสั่ง terminal ได้ด้วย (เช่น npm install แพ็กเกจที่มันต้องใช้) ต่างจาก Tab กับ Inline Edit ที่ทำงานแค่ในไฟล์เดียวตรงหน้า Agent มองเห็นภาพรวมทั้งโปรเจกต์

และนี่คือโหมดที่เราจะใช้สร้างทุกหน้าของ My Store ตั้งแต่บทที่ 10 เป็นต้นไป

Agent กับ Ask: สองโหมดในแชทเดียว

ในช่องแชทของ Agent panel มีตัวเลือกโหมดให้สลับอยู่มุมหนึ่ง สองโหมดหลักที่ต้องรู้จักคือ Ask กับ Agent

Ask ให้ Cursor อ่านโค้ดแล้วตอบคำถามหรืออธิบายเฉย ๆ โดยไม่ไปแตะไฟล์ใด ๆ เลย เหมาะตอนที่ยังไม่แน่ใจว่าโค้ดที่มีอยู่ทำงานอย่างไร เช่นถามว่า “ตอนนี้ CartContext ทำงานยังไง” หรือใช้วางแผนก่อนลงมือจริง เช่น “ถ้าจะเพิ่มหน้า Category ต้องแก้ไฟล์ไหนบ้าง” — ได้คำตอบมาอ่านก่อนตัดสินใจ

Agent คือโหมดที่ลงมือแก้จริง เมื่อพร้อมแล้วให้สลับมาโหมดนี้แล้วสั่งงานตรง ๆ เช่น “สร้างหน้า Home ตาม screenshot ที่แนบมา” มันจะเขียนไฟล์ สร้างไฟล์ใหม่ หรือรันคำสั่งให้ทันที กติกาง่าย ๆ คือ ไม่แน่ใจให้ถามด้วย Ask ก่อน พร้อมลงมือแล้วค่อยสลับเป็น Agent

ให้ context ด้วย @

Agent เดารู้เองบ้างว่าไฟล์ไหนเกี่ยวข้องกับคำสั่งของคุณ แต่ยิ่งคุณชี้เป้าให้ชัดเจนเท่าไหร่ คำตอบก็ยิ่งตรงเท่านั้น เครื่องมือหลักสำหรับชี้เป้าคือเครื่องหมาย @ พิมพ์ @ ในช่องแชทแล้ว Cursor จะโชว์เมนูให้เลือก

  • @ชื่อไฟล์ (@Files) — ผูกไฟล์นั้นเข้าไปในบริบทของคำสั่งโดยตรง เช่น พิมพ์ “แก้สีปุ่มใน @Header.tsx” Agent จะรู้ทันทีว่าต้องเปิดไฟล์ไหน ไม่ต้องเดาจากชื่อในประโยค
  • @ชื่อโฟลเดอร์ (@Folders) — ผูกทั้งโฟลเดอร์เข้าไป มีประโยชน์เวลาต้องการให้ Agent เห็นภาพรวมของฟีเจอร์หนึ่ง ๆ เช่น @cart เพื่อให้เห็นทุกไฟล์ที่เกี่ยวกับตะกร้าสินค้าพร้อมกัน
  • แนบรูปภาพ — ลาก screenshot จากเครื่องลงในช่องแชทได้ตรง ๆ ไม่ต้องอัปโหลดที่ไหนก่อน Agent อ่านภาพได้จริง ไม่ใช่แค่อ่านชื่อไฟล์ นี่คือหัวใจของบทถัดไปที่เราจะแปลง screenshot การออกแบบให้กลายเป็นหน้าเว็บจริง

Project Rules: ให้ Agent จำธรรมเนียมของโปรเจกต์

ปัญหาหนึ่งที่เจอบ่อยคือ Agent ลืมกฎที่คุณเคยบอกไปแล้วในแชทก่อนหน้า เพราะแต่ละแชทใหม่เริ่มนับหนึ่งใหม่เสมอ Cursor แก้ปัญหานี้ด้วย project rules — ไฟล์กฎที่ Agent จะอ่านทุกครั้งโดยอัตโนมัติ ไม่ต้องพิมพ์เตือนซ้ำเองทุกแชท

กฎพวกนี้เก็บอยู่ในโฟลเดอร์ .cursor/rules/ ที่ root ของโปรเจกต์ แต่ละไฟล์เป็นไฟล์นามสกุล .mdc (Markdown + metadata) หน้าตาประมาณนี้

my-store/
├── .cursor/
│   └── rules/
│       └── styling.mdc
├── src/
└── package.json

เปิดไฟล์ styling.mdc ดูข้างในจะเจอส่วน frontmatter (ระหว่าง --- สองแถบ) ตามด้วยเนื้อหากฎ

---
description: Styling conventions for My Store
globs: "src/**/*.tsx"
alwaysApply: true
---

ใช้ Tailwind utility classes เท่านั้น ห้ามสร้างไฟล์ .css หรือ .scss เพิ่ม
เรียง class ตามลำดับ layout → sizing → spacing → typography → color → border/shadow → states
ใช้ design token (bg-primary, text-primary) แทนสีตรง ๆ อย่าง bg-blue-600 เมื่อหมายถึงสีแบรนด์

description อธิบายว่ากฎนี้มีไว้ทำอะไร globs กำหนดว่ากฎนี้มีผลเฉพาะไฟล์ที่ตรง pattern นี้เท่านั้น — ในตัวอย่างคือไฟล์ .tsx ทุกไฟล์ใน src/ ส่วน alwaysApply: true บอกว่าให้แนบกฎนี้เข้าไปในทุกคำสั่งเสมอ ไม่ต้องรอให้ตรงกับ globs ก่อน (ถ้าตั้งเป็น false Agent จะโหลดกฎนี้เฉพาะตอนที่เกี่ยวข้องเท่านั้น) เนื้อหาส่วนที่เหลือหลัง --- ที่สองคือกฎจริง เขียนเป็นภาษาธรรมดาหรือ markdown ก็ได้

ตอนนี้ยังไม่ต้องสร้างไฟล์นี้เอง แค่รู้จักโครงสร้างไว้ก่อน บทที่ 9 ตอนตั้งโครงโปรเจกต์ My Store จริง เราจะเขียนไฟล์กฎชุดจริงที่ Agent ใช้ตลอดทั้งสัปดาห์

วินัยที่ต้องมีเมื่อทำงานกับ Agent

Agent เขียนโค้ดได้เร็วมาก แต่ความเร็วนั้นไม่มีประโยชน์ถ้าคุณปล่อยผ่านโดยไม่ตรวจ สามข้อนี้คือวินัยที่ควรทำให้เป็นนิสัยตั้งแต่บทแรก

  • อ่าน diff ทุกไฟล์ก่อนกด Accept — เมื่อ Agent แก้เสร็จ มันจะโชว์ diff ของทุกไฟล์ที่เปลี่ยน (เขียวคือเพิ่ม แดงคือลบ) เหมือน diff ใน git ที่คุณคุ้นเคยจาก Week_04 อย่ากด Accept All แบบไม่อ่าน — เผื่อไว้ว่า Agent อาจแก้ไฟล์ที่ไม่เกี่ยวข้อง หรือลบโค้ดที่คุณยังต้องการใช้อยู่โดยไม่ได้ตั้งใจ
  • ใช้ checkpoint / restore เมื่อ Agent พาไปผิดทาง — ก่อนแก้ทุกครั้ง Cursor จะบันทึกสถานะของโปรเจกต์ไว้เป็น checkpoint อัตโนมัติ ถ้าลองแล้วผลลัพธ์ออกมาไม่ตรงกับที่ตั้งใจ หรือ Agent เริ่มวนแก้ไปแก้มาจนโค้ดยุ่งเหยิง กด restore กลับไปที่ checkpoint ก่อนหน้าได้ทันที ไม่ต้อง Ctrl+Z ไล่ทีละครั้งหรือ git reset เอง
  • งานเล็ก ๆ ทีละงาน ดีกว่าสั่งใหญ่ทีเดียว — สั่ง “สร้างทั้งเว็บ My Store ให้ครบทุกหน้า” ในคำสั่งเดียวจะได้โค้ดปริมาณมหาศาลที่ตรวจทานไม่ไหว ยิ่งงานใหญ่ยิ่งมีโอกาสหลุดจุดที่ผิด แบ่งเป็นงานย่อยทีละหน้า ทีละ component ตรวจทานให้ผ่านก่อนค่อยสั่งงานถัดไป — วิธีนี้คือสิ่งที่บทที่ 10 เป็นต้นไปจะฝึกให้เป็นนิสัย

💡 หน้าตา UI ของ Cursor เปลี่ยนเร็วมาก ปุ่มอาจย้ายที่ ชื่ออาจเปลี่ยน คีย์ลัดอาจต่างไปจากที่เห็นในบทนี้เมื่อคุณเปิดใช้งานจริง เป็นเรื่องปกติของเครื่องมือ AI ที่อัปเดตทุกไม่กี่สัปดาห์ แต่แนวคิดหลักสี่อย่างที่เพิ่งเรียนไป (agent, context, rules, review) จะยังคงอยู่เสมอไม่ว่า UI จะเปลี่ยนไปแค่ไหน ถ้าจำหลักการเหล่านี้ได้ การหาปุ่มที่ย้ายที่ก็เป็นแค่เรื่องเล็ก

ตอนนี้คุณรู้จักเครื่องมือครบแล้ว บทถัดไปจะเจาะลึกทักษะที่สำคัญที่สุดของสัปดาห์นี้ — วิธีแปลง screenshot ดีไซน์ให้กลายเป็น prompt ที่ Agent เข้าใจตรงกับที่ตั้งใจไว้จริง ๆ
