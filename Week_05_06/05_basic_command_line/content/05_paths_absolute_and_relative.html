Path แบบ Absolute และ Relative

บทที่แล้วเราใช้ cd ย้ายไปมาระหว่างโฟลเดอร์ด้วยชื่อสั้น ๆ เช่น projects หรือ .. คำเหล่านี้ล้วนเป็น “path” รูปแบบหนึ่ง บทนี้จะแยกให้ชัดว่า path มีสองแบบ คือ absolute กับ relative ต่างกันอย่างไร และทำไมเข้าใจความต่างนี้ให้ดีถึงช่วยไม่ให้ รันคำสั่งผิดที่ผิดทางในอนาคต

Path คือที่อยู่ของไฟล์

path คือ “ที่อยู่” ของไฟล์หรือโฟลเดอร์หนึ่ง ๆ ในระบบไฟล์ เหมือนที่อยู่ทางไปรษณีย์ ลองเทียบกับชีวิตจริงดู

  • absolute path เหมือนที่อยู่เต็มบนซองจดหมาย เช่น “บ้านเลขที่ 12 ถนน สุขุมวิท แขวงคลองตัน เขตคลองเตย กรุงเทพฯ” ใช้ที่อยู่นี้ส่งของจากที่ไหนในโลกก็ถึงบ้านหลังเดิมเสมอ เพราะบอกครบทุกระดับตั้งแต่จุดเริ่มต้นบนสุด
  • relative path เหมือนคำบอกทาง “เลี้ยวขวาแล้วนับไปอีกสองบ้าน” คำบอกทางนี้ ใช้งานได้ก็ต่อเมื่อรู้ว่าตอนนี้ยืนอยู่ตรงไหนก่อน ถ้ายืนคนละจุด คำบอกทางเดียวกันจะพาไปคนละที่ทันที

ในโลก terminal ก็เหมือนกัน absolute path ใช้ได้จากทุกที่เสมอ ส่วน relative path ขึ้นอยู่กับว่า pwd ตอนนี้อยู่ที่ไหน

Absolute Path

absolute path คือ path ที่ขึ้นต้นด้วย / เสมอ นับจาก root มาตรง ๆ จนถึงปลายทาง ไม่ว่าจะรันจากโฟลเดอร์ไหนก็ตาม ผลลัพธ์คือไฟล์เดียวกันเสมอ 

/Users/mint/projects/coffee-master/index.html

path นี้ชี้ไปที่ไฟล์ index.html ตัวเดียวในเครื่องเสมอ ไม่ว่าตอนรันคำสั่งจะยืนอยู่ ที่ home directory, อยู่ในโฟลเดอร์อื่น หรืออยู่ลึกไปอีกกี่ชั้นก็ตาม เพราะ path เริ่มนับจาก / ซึ่งมีอยู่จุดเดียวในระบบเสมอ 

$ cd /
$ cat /Users/mint/projects/coffee-master/index.html
<html></html>

$ cd /Users/mint
$ cat /Users/mint/projects/coffee-master/index.html
<html></html>

สังเกตว่าคำสั่งที่สองเปลี่ยนตำแหน่งปัจจุบันไปแล้ว แต่ absolute path เดิมยังพาไปถึงไฟล์เดียวกันได้

Relative Path

relative path คือ path ที่ไม่ขึ้นต้นด้วย / ความหมายของมันขึ้นอยู่กับ pwd เสมอ relative path มีสัญลักษณ์พิเศษอยู่สี่แบบที่ใช้บ่อยมาก

สัญลักษณ์ ความหมาย
. โฟลเดอร์ปัจจุบัน
.. โฟลเดอร์แม่ (ขึ้นไปหนึ่งชั้น)
~ home directory ของเรา
/ root ของทั้งระบบ

. กับ .. เป็น relative path เพราะความหมายเปลี่ยนไปตามตำแหน่งที่ยืน อยู่เสมอ ส่วน ~ กับ / แม้จะดูเหมือนคงที่ แต่จริง ๆ แล้ว ~ ก็ขึ้นกับว่ากำลังล็อกอินเป็นใคร (บนเครื่องเดียวกันแต่คนละ user ค่า ~ ก็ต่างกัน) จึงมักถูกจัดอยู่ในกลุ่ม path แบบ relative-to-user เช่นกัน ต่างจาก / ที่มีความหมายเดียวตายตัวไม่ว่าใครหรือที่ไหนก็ตาม

ตัวอย่างเดินขึ้นแล้วลง

ลองดูสถานการณ์จริง สมมติ pwd ตอนนี้อยู่ที่ ~/projects/coffee-master/src และอยากไปเปิดไฟล์ notes.txt ที่อยู่ในโฟลเดอร์ projects

/ └── Users └── mint └── projects ├── notes.txt └── coffee-master └── src └── app.js

จากตำแหน่ง src ต้องเดินขึ้นสองชั้นก่อนถึงจะเจอ projects ขึ้นหนึ่งชั้น (..) จะถึง coffee-master ขึ้นอีกหนึ่งชั้น (../..) จะถึง projects พอดี 

$ pwd
/Users/mint/projects/coffee-master/src

$ cat ../../notes.txt
(เนื้อหาของ notes.txt)

หรือจะใช้ ~ เป็นจุดเริ่มต้นแทนก็ได้ผลลัพธ์เดียวกัน เพราะ ~/projects/notes.txt กับ ../../notes.txt (เมื่อยืนอยู่ที่ src) ต่างก็ชี้ไปที่ไฟล์เดียวกันในต้นไม้ด้านบน 

$ cat ~/projects/notes.txt
(เนื้อหาของ notes.txt)

~/projects/notes.txt จริง ๆ แล้วเป็น path แบบผสม เริ่มจาก ~ ซึ่งขยายเป็น /Users/mint เสมอ จึงทำงานได้แน่นอนไม่ว่าจะยืนอยู่ที่ไหนก็ตาม คล้ายกับ absolute path มากกว่า relative path ล้วน ๆ อย่าง ../../notes.txt ที่ต้องรู้ตำแหน่งปัจจุบันก่อนถึงจะตีความถูก

ชื่อไฟล์ที่มีช่องว่าง

บางครั้งชื่อโฟลเดอร์หรือไฟล์มีช่องว่างอยู่ในชื่อ เช่นโฟลเดอร์ที่ macOS สร้างให้อัตโนมัติ ชื่อ “My Documents” ถ้าพิมพ์ path แบบไม่ระวัง shell จะตีความช่องว่างผิดทันที 

$ cd My Documents
zsh:cd:1: string not in pwd: My

error นี้เกิดเพราะ shell ตัดคำที่เจอช่องว่างออกเป็น argument แยกกันเสมอ shell จึงเห็นว่า cd ได้รับสอง argument คือ My กับ Documents ไม่ใช่ argument เดียวที่ชื่อ “My Documents” (bash จะฟ้องคนละข้อความ ประมาณ cd: My: No such file or directory แต่สาเหตุเดียวกัน) วิธีแก้มีสองแบบ คือใส่ เครื่องหมายคำพูดครอบทั้งชื่อ หรือใส่ \ หน้าช่องว่างเพื่อบอกว่านี่คือช่องว่างจริง ๆ ไม่ใช่ตัวแบ่ง argument 

$ cd "My Documents"
$ pwd
/Users/mint/My Documents

$ cd ~
$ cd My\ Documents
$ pwd
/Users/mint/My Documents

บน Windows: path ที่ Explorer แสดงเป็น C:\Users\mint\projects จะเขียนใน Git Bash ว่า /c/Users/mint/projects คือเปลี่ยน \ เป็น / และเปลี่ยน C: เป็น /c ส่วนใน PowerShell ใช้รูปแบบเดิมของ Windows ได้เลย

ข้อผิดพลาดที่พบบ่อย: พิมพ์ relative path จากตำแหน่งที่ไม่ตรงกับที่คิดไว้ ในหัว เช่นจำว่าเพิ่งอยู่ที่โฟลเดอร์ src แต่จริง ๆ terminal สลับไปอยู่ที่อื่นแล้ว (จากการ cd ก่อนหน้า) ทำให้ ../notes.txt ชี้ไปผิดไฟล์หรือได้ error No such file or directory วิธีแก้ที่ได้ผลเสมอคือรัน pwd เช็กตำแหน่ง ก่อนพิมพ์ relative path ทุกครั้ง จนกว่าจะกลายเป็นความเคยชิน การเสียเวลาพิมพ์ pwd เพิ่มสามตัวอักษรนั้นถูกกว่าการเดา path ผิดแล้วต้องไล่หาว่าทำไมคำสั่งพัง

แบบฝึกหัด

สมมติ pwd รายงานว่าตอนนี้อยู่ที่ /Users/mint/projects/coffee-master/src เขียน

  1. relative path ไปยัง /Users/mint/projects/notes.txt
  2. absolute path ไปยัง index.html ที่อยู่ในโฟลเดอร์ coffee-master
ดูเฉลย

เริ่มนับจาก src ขึ้นหนึ่งชั้น (..) ถึง coffee-master ขึ้นอีกหนึ่งชั้น (../..) ถึง projects ซึ่งเป็นที่ที่ notes.txt อยู่พอดี ดังนั้น relative path คือ ../../notes.txt

ส่วน absolute path ไม่ต้องนับจากตำแหน่งปัจจุบันเลย เขียนเต็มจาก root ไปตรง ๆ ได้ทันทีว่า /Users/mint/projects/coffee-master/index.html path แบบนี้ใช้ได้ไม่ว่าจะรันคำสั่งจาก ตำแหน่งไหนในเครื่องก็ตาม เพราะเริ่มต้นจาก / ซึ่งมีความหมายเดียวเสมอ
