ดูและค้นหาเนื้อหาในไฟล์

บางครั้งเราแค่อยากดูว่าไฟล์มีอะไรอยู่ข้างใน โดยไม่จำเป็นต้องเปิด VS Code บทนี้จะแนะนำคำสั่งสำหรับอ่านและค้นหาไฟล์ห้าคำสั่ง แต่ละคำสั่งเหมาะกับงานคนละแบบ

ดูทั้งไฟล์ด้วย cat

cat ย่อจาก “concatenate” พิมพ์เนื้อหาทั้งไฟล์ออกมาที่หน้าจอรวดเดียว เหมาะกับไฟล์สั้น ๆ ที่พอดีกับหน้าจอเดียว 

$ cat README.md
# Demo Project

โปรเจกต์ตัวอย่างสำหรับฝึกดูเนื้อหาไฟล์ในบทที่ 8

ถ้าไฟล์ยาวเกินหนึ่งหน้าจอ cat ก็จะพิมพ์ออกมาทั้งหมดจนข้อความไหลผ่านไปเร็วมาก กรณีนี้ใช้คำสั่งอื่นในบทจะอ่านง่ายกว่า

ดูเฉพาะหัวและท้ายด้วย head และ tail

head แสดงเฉพาะบรรทัดแรก ๆ ของไฟล์ ส่วน tail แสดงเฉพาะบรรทัดท้าย ๆ ทั้งคู่รับ flag -n ตามด้วยจำนวนบรรทัดที่ต้องการ 

$ head -n 5 package.json
{
  "name": "demo-project",
  "version": "1.0.0",
  "description": "โปรเจกต์ตัวอย่างสำหรับฝึกคำสั่งดูไฟล์",
  "main": "index.js",

ใช้ head เมื่ออยากรู้ว่าไฟล์คืออะไรคร่าว ๆ โดยไม่ต้องอ่านทั้งไฟล์ เช่นเช็กว่า package.json นี้ชื่ออะไร เวอร์ชันเท่าไร ส่วน tail เหมาะกับไฟล์ log ที่เหตุการณ์ล่าสุดอยู่ท้ายไฟล์เสมอ

ไฟล์ debug.log นี้มีทั้งหมด 30 บรรทัด tail -n 20 จึงตัดสิบบรรทัดแรกทิ้งไป เหลือแค่ 20 บรรทัดหลังสุดเท่านั้น ถ้าไฟล์มีน้อยกว่า 20 บรรทัด tail ก็จะแสดงเท่าที่มีทั้งหมด โดยไม่ฟ้อง error แต่อย่างใด

ถ้าไฟล์ที่ระบุไม่มีอยู่จริง ทั้ง head และ tail บน macOS จะฟ้อง error ทันทีแทนที่จะแสดงอะไรเลย 

$ head nonexistent.txt
head: nonexistent.txt: No such file or directory

ไฟล์ยาว ๆ ใช้ less

ไฟล์ที่ยาวมาก เช่น package-lock.json ที่มักยาวเป็นพันบรรทัด ไม่เหมาะกับ cat เพราะจะพิมพ์ท่วมหน้าจอจนหาอะไรไม่เจอ คำสั่ง less เปิดไฟล์แบบเลื่อนดูทีละหน้าแทน ไม่พิมพ์ทุกอย่างออกมาพร้อมกัน 

$ less package-lock.json

เมื่อรันแล้ว terminal จะเปลี่ยนไปแสดงหน้าจอแบบเต็มจอ ประมาณนี้ (ตัวอย่างสมมติเพื่อให้เห็นภาพ เพราะ less เป็นโปรแกรมโต้ตอบแบบเรียลไทม์ ไม่มีทางบันทึกผลลัพธ์เป็นข้อความนิ่ง ๆ ได้) 

{
  "name": "demo-project",
  "version": "1.0.0",
  "lockfileVersion": 3,
  "requires": true,
  "packages": {
    "": {
      "name": "demo-project",
      "version": "1.0.0",
      "dependencies": {
        "react": "^18.2.0",
:

เลื่อนดูด้วยลูกศรขึ้นลง หรือกด Space เพื่อเลื่อนลงทีละหน้าจอ และ b เพื่อเลื่อนย้อนกลับขึ้นทีละหน้าจอ ค้นหาคำในไฟล์ด้วย / ตามด้วยคำที่ต้องการแล้วกด Enter เหมือนที่เคยใช้กับ man ในบทที่ 3 ส่วนคีย์ที่สำคัญที่สุดคือ กด q เพื่อออกจาก less แล้วกลับมาที่ prompt ปกติ มือใหม่จำนวนมากติดอยู่ในหน้าจอนี้ เพราะไม่รู้ว่าต้องกดอะไร การจำคีย์ q ไว้ให้แม่นจะช่วยได้มาก

ตามดู log แบบสด ๆ ด้วย tail -f

ตอน dev server กำลังรันอยู่ เช่น npm run dev log ใหม่จะถูกเขียนเพิ่มเข้าไฟล์ log ตลอดเวลา ถ้าใช้ tail ธรรมดาจะเห็นแค่ภาพนิ่ง ณ ตอนที่รันคำสั่งเท่านั้น แต่ถ้าเติม flag -f (follow) tail จะไม่ปิดตัวเอง แล้วพิมพ์บรรทัดใหม่ที่ถูกเขียนเพิ่มออกมาเรื่อย ๆ แบบเรียลไทม์ เหมือนเฝ้าดู log สด 

$ tail -f debug.log
2026-08-14 09:04:00 INFO  request completed in 98ms
2026-08-14 09:05:12 ERROR database connection lost
2026-08-14 09:06:03 INFO  request completed in 105ms
2026-08-14 09:07:41 INFO  new request received

ตัวอย่างนี้จำลองพฤติกรรมของ tail -f ซึ่งจะรอและแสดงบรรทัดใหม่ต่อไปเรื่อย ๆ แทนที่จะคืน prompt ทันที เมื่อต้องการหยุดให้กด Ctrl + C เราจะได้ใช้ปุ่มลัดนี้อีก ในบทถัดไป

ค้นหาข้อความด้วย grep

grep ค้นหาข้อความในไฟล์และแสดงเฉพาะบรรทัดที่พบ จึงไม่ต้องเปิดไฟล์แล้วเลื่อนหาเอง 

$ grep "scripts" package.json
  "scripts": {

ปกติ grep สนใจตัวพิมพ์เล็กใหญ่ ถ้าไม่แน่ใจว่าคำที่ค้นหาสะกดด้วยตัวพิมพ์แบบไหน เติม -i (ไม่สนตัวพิมพ์เล็กใหญ่) เพื่อจับได้ทั้งสองแบบในคำสั่งเดียว 

$ grep -i "error" debug.log
2026-08-14 09:01:15 ERROR failed to fetch user profile: timeout
2026-08-14 09:03:02 error: unhandled promise rejection
2026-08-14 09:05:12 ERROR database connection lost

ผลลัพธ์จับได้ทั้ง ERROR ตัวใหญ่ล้วนและ error ตัวเล็กล้วน ถ้าไม่ใส่ -i จะจับได้แค่บรรทัดที่สะกดตรงกับที่พิมพ์เป๊ะ ๆ เท่านั้น

และ grep ยังค้นได้ทั้งโฟลเดอร์ในคำสั่งเดียว ด้วย -r (recursive) ไล่ค้นทุกไฟล์ ในโฟลเดอร์นั้น รวมโฟลเดอร์ย่อยข้างในด้วย บวกกับ -n ให้แสดงเลขบรรทัดกำกับมาด้วย 

$ grep -rn "useState" src/
src/App.jsx:1:import { useState } from "react";
src/App.jsx:4:  const [count, setCount] = useState(0);
src/Counter.jsx:1:import { useState } from "react";
src/Counter.jsx:4:  const [value, setValue] = useState(0);

รูปแบบผลลัพธ์คือ ชื่อไฟล์:เลขบรรทัด:เนื้อหาบรรทัดนั้น ทำให้เปิดไฟล์แล้วกระโดดไปบรรทัดที่ต้องการได้ทันที คำสั่งเดียวนี้ค้นเจอทุกจุดที่เรียกใช้ useState ทั้งโปรเจกต์ โดยไม่ต้องเปิดไฟล์ทีละไฟล์เอง

อีกจุดที่ต่างกันเล็กน้อยระหว่างเครื่องคือสีของผลลัพธ์ เมื่อรันใน terminal จริงที่รองรับสี grep บน Linux หลายจัดจำหน่ายมักตั้ง alias ให้ไฮไลต์คำที่ค้นเจอเป็นสีแดงให้อัตโนมัติ ส่วนบน macOS ค่าเริ่มต้นจะไม่ไฮไลต์สีให้ ต้องเติม flag --color=auto เองถ้าต้องการ ผลลัพธ์ที่แสดงในหน้านี้จึงเป็นข้อความล้วนไม่มีสี

บน Windows: Git Bash มี cat, head, tail, less และ grep ครบ ส่วนใน PowerShell ให้ใช้ Get-Content แทน cat และ Select-String แทน grep

ข้อผิดพลาดที่พบบ่อย: รัน cat กับไฟล์ที่ใหญ่มากหรือเป็นไฟล์ binary เช่นไฟล์รูปภาพหรือไฟล์ที่ compile แล้ว จะได้ข้อความขยะเต็มหน้าจอ บางทีถึงขั้นเปลี่ยน encoding ของ terminal ไปเลยจนตัวอักษรที่พิมพ์ต่อไปอ่านไม่ออก ทางแก้เมื่อเจอสถานการณ์นี้คือกด Ctrl + C เพื่อหยุด แล้วรัน clear เพื่อล้างหน้าจอให้กลับมาอ่านง่ายเหมือนเดิม ครั้งต่อไปถ้าไม่แน่ใจว่าไฟล์ใหญ่แค่ไหนหรือเป็น binary หรือเปล่า ใช้ less หรือ head แทน cat จะปลอดภัยกว่า

แบบฝึกหัด

ในโปรเจกต์ใด ๆ ที่มีไฟล์ package.json ให้หาสองอย่างต่อไปนี้ด้วยคำสั่งเดียวต่ออย่าง

  1. แสดงเฉพาะบรรทัดที่มีคำว่า scripts ในไฟล์
  2. แสดงเฉพาะสิบบรรทัดแรกของไฟล์
ดูเฉลย

สองข้อนี้ตอบคำถามกันคนละแบบ grep กรองตามเนื้อหา คือหาว่าบรรทัดไหน “มีคำนี้อยู่” ไม่ว่าคำนั้นจะอยู่บรรทัดที่เท่าไรของไฟล์ก็ตาม ส่วน head กรองตามตำแหน่ง คือตัดมาเฉพาะ บรรทัดต้น ๆ ของไฟล์โดยไม่สนใจว่าข้างในมีคำว่าอะไรบ้าง ทั้งสองคำสั่งจึงไม่ใช่คำสั่งเดียวกันที่ใช้แทนกันได้ แต่เป็นเครื่องมือคนละชนิดที่เลือกใช้ตามคำถามที่ต้องการคำตอบ 

$ grep -n "scripts" package.json
6:  "scripts": {
$ head -n 10 package.json
{
  "name": "demo-project",
  "version": "1.0.0",
  "description": "โปรเจกต์ตัวอย่างสำหรับฝึกคำสั่งดูไฟล์",
  "main": "index.js",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "test": "vitest"
  },

เติม -n ให้ grep เพื่อแสดงเลขบรรทัดกำกับมาด้วย (ในตัวอย่างนี้คือบรรทัดที่ 6) ทำให้เปิด editor แล้วกระโดดไปบรรทัดนั้นได้ทันทีโดยไม่ต้องไล่หาเอง
