Environment Variables และ PATH

บทที่ผ่านมาทั้งหมดเน้นคำสั่งที่จับต้องได้ เช่นสร้างไฟล์ ย้ายไฟล์ ดูเนื้อหาไฟล์ บทนี้พาไปดูสิ่งที่มองไม่เห็นตรง ๆ แต่กำกับอยู่เบื้องหลังทุกคำสั่งที่พิมพ์ไป นั่นคือ environment variable และตัวที่สำคัญที่สุดในนั้นคือ PATH ซึ่งเป็นตัวตัดสินว่าพิมพ์ node แล้ว shell ไปเจอโปรแกรมชื่อนี้จากที่ไหน เรื่องนี้เป็นพื้นฐานที่ต้องเข้าใจก่อนติดตั้ง Node.js ในบทถัดไป เพราะปัญหาที่พบบ่อยที่สุดตอนติดตั้งเครื่องมือใหม่ ๆ ล้วนย้อนกลับมาที่ PATH ทั้งนั้น

Environment Variable คืออะไร

environment variable คือตัวแปรที่ shell เก็บไว้ให้ทุกคำสั่งที่รันในเซสชันนั้นมองเห็นและใช้งานได้ เปรียบเทียบง่าย ๆ ก็เหมือนการตั้งค่าระดับ session ที่ทุกโปรแกรมที่เปิดจาก terminal นี้อ่านค่าได้ร่วมกัน เช่น โปรแกรมจะรู้ได้ว่า home directory ของผู้ใช้อยู่ที่ไหน โดยไม่ต้องถามผู้ใช้เองทุกครั้ง เพราะมีตัวแปร HOME เก็บค่านั้นไว้ให้แล้ว environment variable ต่างจากตัวแปรในโปรแกรมทั่วไปตรงที่มันไม่ได้อยู่แค่ในโปรแกรมเดียว แต่ส่งต่อไปให้ทุกโปรเซสลูกที่ถูกรันจาก shell นั้นเห็นด้วย

อ่านค่าด้วย echo

ใช้ echo ตามด้วยเครื่องหมาย $ และชื่อตัวแปรเพื่ออ่านค่าของ environment variable ใด ๆ ก็ได้ 

$ echo $HOME
/Users/varis

$ echo $USER
varis

(ผลลัพธ์ข้างต้นคือค่าจริงจากเครื่องที่ใช้เขียนบทเรียนนี้ ไม่ใช่ตัวอย่างสมมติ บนเครื่องของคุณเองค่าทั้งสอง จะเปลี่ยนไปตาม username ที่ล็อกอินอยู่ เช่นถ้า username คือ mint ผลลัพธ์ก็จะเป็น /Users/mint และ mint ตามลำดับ)

จุดที่ต้องระวังคือเครื่องหมาย $ ในที่นี้ไม่ใช่ สัญลักษณ์ prompt แบบที่เจอในบทที่ 1 ตอนนั้น $ ที่อยู่หน้าสุดของบรรทัดเป็นแค่สัญลักษณ์บอกว่า “บรรทัดนี้คือคำสั่งที่พิมพ์” ไม่ต้องพิมพ์ตามจริง แต่ $ ที่อยู่หน้าชื่อตัวแปรแบบ $HOME นี้เป็นส่วนหนึ่งของคำสั่งจริง ๆ ที่ต้องพิมพ์ตาม ความหมายคือ “ให้เอาค่าของตัวแปรชื่อนี้มาแทนที่ตรงนี้” พิมพ์ echo HOME โดยไม่มี $ จะได้คำว่า HOME ออกมาเฉย ๆ ไม่ใช่ค่าของตัวแปร

PATH คือรายชื่อโฟลเดอร์ที่ shell ใช้ค้นหาโปรแกรม

PATH เป็น environment variable ที่สำคัญที่สุดตัวหนึ่ง เพราะเป็นตัวตัดสินว่าพิมพ์ชื่อคำสั่งสั้น ๆ แบบ node หรือ ls แล้ว shell ไปหาโปรแกรมที่ชื่อนี้จากที่ไหน 

$ echo $PATH
/Users/varis/.nvm/versions/node/v22.23.2/bin:/opt/homebrew/bin:/opt/homebrew/sbin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin

(ตัวอย่างนี้ตัดบางรายการที่เป็นเฉพาะเครื่องออกไปเพื่อให้อ่านง่าย ของจริงบนเครื่องหนึ่ง ๆ มักมีมากกว่านี้อีกหลายรายการ จากโปรแกรมอื่น ๆ ที่ติดตั้งไว้)

ค่าของ PATH คือรายชื่อโฟลเดอร์ที่คั่นด้วย : เรียงกันเป็นเส้นตรง เวลาพิมพ์ชื่อคำสั่งใด ๆ shell จะเดินไล่ค้นหาไฟล์ที่ชื่อนั้นทีละโฟลเดอร์ จากซ้ายไปขวา แล้วรันไฟล์แรกที่เจอ ตัวอย่างข้างบนถ้าพิมพ์ node shell จะเจอไฟล์ node ในโฟลเดอร์แรกสุดคือ /Users/varis/.nvm/versions/node/v22.23.2/bin ก่อน แล้วหยุดค้นหาทันที ไม่สนใจว่าโฟลเดอร์ถัดไปในรายการ จะมีไฟล์ชื่อ node อยู่ด้วยหรือไม่ ลำดับก่อนหลังในรายการนี้จึงมีผลจริง ถ้ามีโปรแกรมชื่อเดียวกันติดตั้งไว้ หลายที่ โฟลเดอร์ที่มาก่อนใน PATH จะชนะเสมอ

หาว่าคำสั่งมาจากไหนด้วย which

เมื่อสงสัยว่าคำสั่งที่พิมพ์ไปนั้นจริง ๆ แล้วรันมาจากไฟล์ไหนในบรรดาโฟลเดอร์ทั้งหมดใน PATH ใช้คำสั่ง which ตามด้วยชื่อคำสั่งนั้นเพื่อดูคำตอบตรง ๆ 

$ which node
/Users/varis/.nvm/versions/node/v22.23.2/bin/node

$ which npm
/Users/varis/.nvm/versions/node/v22.23.2/bin/npm

which เดินหา PATH ตามลำดับเดียวกับที่ shell ใช้จริง แล้วรายงานแค่ path ของไฟล์แรกที่เจอ ประโยชน์คือถ้าเครื่องมีโปรแกรมชื่อเดียวกันติดตั้งไว้มากกว่าหนึ่งที่ (เช่นมี Node ทั้งจาก nvm และจาก installer อื่น) which จะบอกได้ทันทีว่าเวอร์ชันไหนกำลังถูกใช้งานอยู่จริง

which ไม่ได้มีอยู่ใน shell ทุกตัวเหมือนกันหมด ทางเลือกที่พกพาได้กว้างกว่าคือ command -v ซึ่งทำหน้าที่เดียวกันและมีอยู่ใน shell มาตรฐานเกือบทุกตัว 

$ command -v node
/Users/varis/.nvm/versions/node/v22.23.2/bin/node

ทำไมถึงเจอ command not found

command not found เป็น error ที่เจอบ่อยที่สุดอันหนึ่งในการใช้ terminal สาเหตุมีอยู่สามแบบ เรียงตามลำดับที่มักเจอจริง ดังนี้

  1. พิมพ์ชื่อคำสั่งผิด เช่นพิมพ์ nod แทน node หรือพิมพ์ตัวใหญ่เล็กผิด วิธีแก้คือตรวจตัวสะกดให้ตรงเป๊ะ แล้วลองใช้ Tab ช่วยเติมให้ตามที่เรียนไปในบทที่แล้ว
  2. ยังไม่ได้ติดตั้งโปรแกรมนั้นเลย เช่นพิมพ์ node ทั้งที่เครื่องยังไม่มี Node.js อยู่จริง ๆ วิธีแก้คือติดตั้งโปรแกรมนั้นก่อน (บทถัดไปจะสอนติดตั้ง Node.js โดยเฉพาะ)
  3. ติดตั้งแล้ว แต่โฟลเดอร์ของมันไม่อยู่ใน PATH สาเหตุที่พบบ่อยที่สุดของข้อนี้คือ เปิด terminal ค้างไว้ตั้งแต่ก่อนติดตั้ง แล้วติดตั้งเสร็จก็ลองรันในหน้าต่างเดิมทันที วิธีแก้คือปิดแล้วเปิด terminal ใหม่ ตามที่จะอธิบายเพิ่มด้านล่าง

ตั้งค่าตัวแปรชั่วคราว

บางครั้งจำเป็นต้องตั้งค่า environment variable ของตัวเองชั่วคราว เช่นเก็บ API key ไว้ให้โปรแกรมอ่าน โดยไม่ต้องเขียนค่านั้นลงในโค้ดตรง ๆ ใช้ export เพื่อประกาศตัวแปรให้มีผลตลอดทั้งเซสชันของ terminal บานนั้น 

$ export API_KEY=abc123
$ echo $API_KEY
abc123

ถ้าต้องการตั้งค่าแค่ครั้งเดียวสำหรับคำสั่งเดียวเท่านั้น ไม่ต้องคงอยู่ตลอดเซสชัน วางชื่อตัวแปรกับค่าไว้หน้าคำสั่งได้เลย โดยไม่ต้องมี export 

$ API_KEY=abc123 node app.js

รูปแบบนี้ตั้งค่า API_KEY ให้เห็นเฉพาะตอนรัน node app.js คำสั่งเดียวเท่านั้น คำสั่งถัดไปจะไม่เห็นค่านี้อีกแล้ว ทั้งสองแบบมีจุดร่วมกันคือค่าที่ตั้งจะหายไปทันทีที่ปิด terminal ถ้าต้องการให้ตัวแปรคงอยู่ถาวรทุกครั้งที่เปิด terminal ใหม่ ต้องเขียนค่านั้นลงในไฟล์ตั้งค่าของ shell เช่น .zshrc หรือ .bashrc ซึ่งเป็นเรื่องที่อยู่นอกเหนือขอบเขตของคอร์สนี้

ข้อผิดพลาดที่พบบ่อย: ติดตั้งโปรแกรมใหม่เสร็จแล้วรีบพิมพ์ชื่อคำสั่งทดสอบใน terminal บานเดิมที่เปิดค้างไว้ตั้งแต่ก่อนติดตั้ง แล้วเจอ command not found ทันทีจนคิดว่าติดตั้งไม่สำเร็จ ทั้งที่จริง ๆ แล้วติดตั้งสำเร็จดี สาเหตุคือ shell จะอ่านค่า PATH แค่ตอนเริ่มต้นเซสชันเท่านั้น ไฟล์ตั้งค่าที่ตัวติดตั้งเขียนเพิ่มเข้าไปจะยังไม่มีผลกับ shell ที่เปิดค้างอยู่ก่อนหน้า วิธีแก้คือปิด terminal บานนั้นแล้วเปิดใหม่ เพื่อให้ shell อ่านค่า PATH ที่อัปเดตแล้วเข้ามา

แบบฝึกหัด

รันคำสั่ง echo $PATH และ which node บนเครื่องของคุณเอง ถ้ายังไม่ได้ติดตั้ง Node.js ให้บอกว่าผลลัพธ์ของ which node จะเป็นอย่างไร แล้วตอบคำถามนี้: โฟลเดอร์ไหนใน PATH ของคุณที่มีแนวโน้มจะเป็นที่มาของคำสั่ง node มากที่สุด (เมื่อติดตั้งแล้ว)

ดูเฉลย

which node พิมพ์ path เต็มของไฟล์ที่จะถูกรันจริงเมื่อพิมพ์ node บนเครื่องที่ติดตั้ง Node.js ผ่าน nvm ไฟล์นั้นจะอยู่ใต้ ~/.nvm/versions/node/<เวอร์ชัน>/bin ส่วนเครื่องที่ติดตั้งผ่านตัวติดตั้งแบบ .pkg จาก nodejs.org มักจะอยู่ที่ /usr/local/bin แทน สองแบบนี้ให้ path ที่หน้าตาต่างกันโดยสิ้นเชิง แต่ทั้งคู่ถูกต้องเท่ากัน ขึ้นอยู่กับว่าติดตั้งด้วยวิธีไหน

ถ้ายังไม่ได้ติดตั้ง Node.js เลย which node จะไม่พิมพ์อะไรออกมา (หรือพิมพ์ว่าไม่พบคำสั่ง ขึ้นอยู่กับ shell) และจบด้วย exit code ที่ไม่ใช่ศูนย์ ซึ่งก็คือสถานการณ์ command not found ที่อธิบายไปข้างต้นนั่นเอง บทถัดไปจะแก้ปัญหานี้ด้วยการติดตั้ง Node.js ให้เรียบร้อย
