เดินทางในระบบไฟล์

ต่อไปเราจะลองเดินไปมาระหว่างโฟลเดอร์ด้วยสามคำสั่งที่ใช้บ่อยมาก ได้แก่ pwd, ls และ cd ลองนึกภาพว่าเรากำลังเปิดโฟลเดอร์ ใน Finder หรือ Explorer เพียงแต่เปลี่ยนจากการคลิกมาเป็นการพิมพ์คำสั่ง

ระบบไฟล์คือต้นไม้

ไฟล์และโฟลเดอร์ในเครื่องจัดเรียงเป็นโครงสร้างคล้ายต้นไม้ (tree) จุดบนสุดเรียกว่า root และเขียนแทนด้วย / ไฟล์ทุกไฟล์จะแตกแขนงออกมาจากจุดนี้

/ ├── Users │ └── mint │ ├── Desktop │ ├── Downloads │ └── projects │ └── coffee-master │ ├── index.html │ └── style.css └── Applications

จากภาพนี้ coffee-master เป็นลูกของ projects ซึ่งเป็นลูกของ mint ซึ่งเป็นลูกของ Users ซึ่งเป็นลูกของ root การ “เดินทาง” ในระบบไฟล์ก็คือการย้ายตำแหน่งขึ้นลงบนต้นไม้นี้นั่นเอง

อยู่ที่ไหน: pwd

ก่อนจะไปที่อื่น เราควรรู้ก่อนว่าตอนนี้อยู่ตรงไหน คำสั่ง pwd (print working directory) ใช้ดูตำแหน่งปัจจุบัน 

$ pwd
/Users/mint/projects/coffee-master

ผลลัพธ์ที่ได้คือ absolute path เต็ม ๆ นับจาก root มาเรื่อย ๆ จนถึงตำแหน่งปัจจุบัน (บทถัดไปจะพูดถึง absolute path โดยละเอียด)

มีอะไรอยู่ตรงนี้: ls

คำสั่ง ls (list) แสดงรายการไฟล์และโฟลเดอร์ในตำแหน่งปัจจุบัน

$ ls
index.html	style.css

แบบเปล่า ๆ ls บอกแค่ชื่อ ถ้าอยากรู้รายละเอียดเพิ่ม ให้เติม flag -l (long format) 

$ ls -l
total 16
-rw-r--r--  1 mint  staff    14 Aug 14 10:20 index.html
-rw-r--r--  1 mint  staff     7 Aug 14 10:20 style.css

คอลัมน์ที่ต้องรู้ตอนนี้มีสี่คอลัมน์ ไล่จากซ้ายไปขวาได้ดังนี้

  • -rw-r--r-- คือ permission บอกว่าใครอ่าน/เขียน/รันไฟล์นี้ได้บ้าง (รายละเอียดเรื่อง permission เป็นหัวข้อของบทเรียนอื่น ตอนนี้รู้แค่ว่านี่คือคอลัมน์นี้ก็พอ)
  • 14 คือขนาดไฟล์ หน่วยเป็น byte
  • Aug 14 10:20 คือวันเวลาที่แก้ไขไฟล์ล่าสุด
  • index.html คือชื่อไฟล์

ระหว่าง permission กับขนาดไฟล์ยังมี link count, เจ้าของไฟล์ (owner) และกลุ่ม (group) อยู่ด้วย ตอนนี้ยังไม่ต้องจำรายละเอียดเหล่านี้

และถ้าอยากเห็นไฟล์ที่ซ่อนอยู่ด้วย ให้เติม flag -a (all) 

$ ls -a
.		..		.git		.gitignore	index.html	style.css

ไฟล์หรือโฟลเดอร์ที่ชื่อขึ้นต้นด้วยจุด เช่น .git หรือ .gitignore คือ “dot-file” ระบบซ่อนไฟล์เหล่านี้จาก ls แบบธรรมดาโดยอัตโนมัติ เพราะส่วนใหญ่เป็นไฟล์ config หรือข้อมูลภายในของเครื่องมือต่าง ๆ ที่ไม่ได้ใช้งานตรง ๆ ทุกวัน ไม่ใช่ไฟล์ที่มี permission พิเศษอะไร แค่ตั้งชื่อให้ ls ข้ามไปเฉย ๆ ส่วน . กับ .. ที่เห็นอยู่เสมอคือทางลัดไปยังโฟลเดอร์ปัจจุบันและโฟลเดอร์แม่ ซึ่งจะอธิบายต่อในหัวข้อถัดไป

ย้ายไปที่อื่น: cd

คำสั่ง cd (change directory) ใช้เปลี่ยนโฟลเดอร์ปัจจุบัน โดยใส่ชื่อโฟลเดอร์ ปลายทางเป็น argument ลองดูทีละขั้น โดยเริ่มจาก home directory 

$ pwd
/Users/mint

$ cd projects
$ pwd
/Users/mint/projects

$ cd coffee-master
$ pwd
/Users/mint/projects/coffee-master

$ cd ..
$ pwd
/Users/mint/projects

$ cd ..
$ pwd
/Users/mint

$ cd -
/Users/mint/projects
$ pwd
/Users/mint/projects

รูปแบบของ argument ที่ cd รับมีความหมายพิเศษอยู่สี่แบบ

  • cd projects — ย้ายลงไปในโฟลเดอร์ลูกชื่อ projects
  • cd .. — ขึ้นหนึ่งชั้น ไปยังโฟลเดอร์แม่ของโฟลเดอร์ปัจจุบัน
  • cd ~ — กลับบ้าน คือกลับไปที่ home directory ของผู้ใช้ปัจจุบันทันที ไม่ว่าจะอยู่ลึกแค่ไหน
  • cd - — กลับไปที่โฟลเดอร์เดิมก่อนหน้าการ cd ครั้งล่าสุด สลับไปมาระหว่างสองโฟลเดอร์ได้สะดวกโดยไม่ต้องพิมพ์ path เต็ม (สังเกตว่า cd - จะพิมพ์ path ปลายทางออกมาให้ดูด้วย ต่างจาก cd แบบอื่นที่เงียบเมื่อสำเร็จ)

บน Windows: ใน Git Bash ใช้คำสั่งเดียวกับ macOS ทุกอย่าง แต่ถ้าจำเป็นต้องใช้ PowerShell คำสั่ง ls จะเป็น Get-ChildItem (มีชื่อย่อว่า dir) ส่วน pwd คือ Get-Location และ cd ใช้ได้เหมือนกัน

ข้อผิดพลาดที่พบบ่อย: ใช้ cd กับไฟล์แทนที่จะเป็นโฟลเดอร์ เช่น รันคำสั่ง cd index.html ทั้งที่ index.html เป็นไฟล์ ไม่ใช่โฟลเดอร์ terminal จะแจ้ง error ประมาณ not a directory: index.html ทันที วิธีแก้คือเช็กด้วย ls ก่อนว่าสิ่งที่จะ cd เข้าไปเป็นโฟลเดอร์จริงหรือเปล่า

อีกเรื่องที่ทำให้งงคือเรื่องตัวพิมพ์เล็กใหญ่ของชื่อโฟลเดอร์ ดิสก์ macOS ส่วนใหญ่ (APFS แบบ default) เป็น case-insensitive แต่ case-preserving แปลว่าต่อให้สร้างโฟลเดอร์ชื่อ Projects ไว้ คำสั่ง cd projects ตัวพิมพ์เล็กก็ยังพาไปถึงได้เหมือนเดิม แต่บน Linux (และบน macOS ที่จงใจฟอร์แมตดิสก์เป็นแบบ case-sensitive) ระบบไฟล์จะมองว่า Projects กับ projects เป็นคนละชื่อกันเลย cd projects จะได้ error No such file or directory ถ้าโฟลเดอร์จริงชื่อ Projects ด้วยตัว P ใหญ่ ทางที่ปลอดภัยที่สุดคือพิมพ์ชื่อให้ตรงตัวพิมพ์เสมอ ไม่พึ่งพฤติกรรมที่ต่างกันไปตามระบบ

แบบฝึกหัด

เปิด terminal จริง ย้ายไปที่โฟลเดอร์โปรเจกต์ของคอร์สนี้ด้วย cd แล้วรัน ls -la จากนั้นตอบว่า

  1. มี entry ไหนบ้างที่เป็นไฟล์หรือโฟลเดอร์ที่ซ่อนอยู่ (ขึ้นต้นด้วยจุด)
  2. ถ้ารัน cd .. จากตำแหน่งนี้ จะไปถึงโฟลเดอร์ไหน
ดูเฉลย

entry ที่ซ่อนอยู่คือทุกตัวที่ชื่อขึ้นต้นด้วยจุด ซึ่งในโปรเจกต์ทั่วไปมักเจอ .git (ข้อมูลของ Git repository), .gitignore (รายชื่อไฟล์ที่ไม่ต้องการให้ Git ติดตาม), .DS_Store (ไฟล์ที่ macOS สร้างเก็บข้อมูลการแสดงผลของ Finder เฉพาะบน macOS) และ .vscode (การตั้งค่าเฉพาะโปรเจกต์ของ VS Code) entry เหล่านี้ ถูกซ่อนโดย “ข้อตกลง” ของ ls เท่านั้น ไม่ได้ถูกจำกัดสิทธิ์การเข้าถึงแต่อย่างใด การเติม -a จึงทำให้เห็นได้ตามปกติ

จากในโฟลเดอร์โปรเจกต์ การรัน cd .. จะพาไปยังโฟลเดอร์ที่ครอบโปรเจกต์นี้อยู่ เช่นถ้าโปรเจกต์อยู่ที่ /Users/mint/projects/coffee-master การ cd .. หนึ่งครั้งจะพาไปที่ /Users/mint/projects ซึ่งเป็นโฟลเดอร์แม่ ที่เก็บโปรเจกต์อื่น ๆ ไว้ด้วยเช่นกัน
