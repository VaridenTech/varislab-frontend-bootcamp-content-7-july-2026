ติดตั้ง Node.js และ npm

ถึงเวลานำพื้นฐานจากบทก่อน ๆ มาใช้ติดตั้งเครื่องมือจริงแล้ว บทนี้เราจะติดตั้ง Node.js และ npm จากนั้นตรวจสอบด้วยตัวเองว่าทั้งสองคำสั่งพร้อมใช้งาน

Node.js คืออะไรในหนึ่งย่อหน้า

Node.js คือ JavaScript runtime ที่ทำให้เรารัน JavaScript นอกเบราว์เซอร์ได้ จึงนำภาษาเดียวกับ ที่ใช้ทำหน้าเว็บมาเขียนเครื่องมือ สร้าง server หรือรันงานอัตโนมัติบนเครื่องได้ ส่วนรายละเอียด การทำงานของ Node.js จะเรียนต่อในคอร์สถัดไป บทนี้ขอเน้นที่การติดตั้งให้พร้อมก่อน

ติดตั้งด้วย nvm ดีกว่าอย่างไร

Node.js ติดตั้งได้หลายวิธี วิธีที่คอร์สนี้แนะนำคือ nvm (Node Version Manager) แทนที่จะโหลด installer แบบ .pkg จาก nodejs.org ตรง ๆ เหตุผลคือ nvm ติดตั้ง Node.js ได้หลายเวอร์ชันพร้อมกันบนเครื่องเดียว แล้วสลับใช้เวอร์ชันไหนก็ได้ตามต้องการ ซึ่งสำคัญมากในทางปฏิบัติ เพราะแต่ละโปรเจกต์อาจล็อกเวอร์ชัน Node.js ไว้ไม่ตรงกัน ถ้าติดตั้งแบบ .pkg จะได้ Node.js แค่เวอร์ชันเดียวตายตัว จะเปลี่ยนเวอร์ชันทีต้องถอนของเก่าแล้วติดตั้งใหม่ และการติดตั้งหรือถอนแบบนั้นมักต้องใส่รหัสผ่าน admin ของเครื่องด้วย ต่างจาก nvm ที่ติดตั้งอยู่ในสิทธิ์ของผู้ใช้ทั่วไป สลับเวอร์ชันได้ด้วยคำสั่งเดียวโดยไม่ต้องใส่รหัสผ่านเลย

ติดตั้ง nvm บน macOS และ Linux

รันคำสั่งนี้ใน terminal เพื่อดาวน์โหลดและติดตั้ง nvm (ใช้ได้ทั้ง macOS และ Linux)

$ curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash

คำสั่งนี้ดาวน์โหลดสคริปต์ติดตั้งจาก GitHub แล้วส่งต่อให้ bash รันทันที สคริปต์จะสร้างโฟลเดอร์ ~/.nvm แล้วเพิ่มบรรทัดตั้งค่าไม่กี่บรรทัดต่อท้ายไฟล์ตั้งค่าของ shell (เช่น .zshrc) ให้อัตโนมัติ ขั้นตอนสำคัญที่พลาดกันบ่อยที่สุดคือหลังติดตั้งเสร็จ ต้องปิด terminal บานนี้แล้วเปิดใหม่ ก่อนจะใช้คำสั่ง nvm ได้ เหตุผลตรงกับที่เรียนไปในบทที่แล้วเป๊ะ ๆ คือ shell อ่านค่าจากไฟล์ตั้งค่าแค่ตอน เริ่มเซสชันเท่านั้น บรรทัดที่ตัวติดตั้งเพิ่งเพิ่มเข้าไปจะยังไม่มีผลกับ shell บานเดิมที่เปิดค้างอยู่ก่อนติดตั้ง

ติดตั้ง Node เวอร์ชัน LTS

เปิด terminal ใหม่แล้วให้ nvm ติดตั้ง Node.js เวอร์ชันล่าสุดฝั่ง LTS

$ nvm install --lts
$ nvm use --lts

LTS ย่อจาก “Long Term Support” คือสาย Node.js ที่ได้รับการดูแลและแพตช์ความปลอดภัยระยะยาว เหมาะกับงานจริงมากที่สุด ต่างจากสาย “Current” ที่ได้ฟีเจอร์ใหม่เร็วกว่าแต่เปลี่ยนแปลงบ่อยและมีโอกาส breaking change สูงกว่า คอร์สนี้และคอร์ส Node.js ถัดไปแนะนำให้ใช้ LTS เป็นค่าเริ่มต้นเสมอ ยกเว้นมีโปรเจกต์ใดระบุเวอร์ชันอื่นไว้ชัดเจน

ตรวจสอบว่าติดตั้งสำเร็จ

ใช้ flag -v เพื่อดูเลขเวอร์ชันของทั้ง node และ npm

$ node -v
v22.23.2

$ npm -v
10.9.8

(ผลลัพธ์ข้างต้นคือค่าจริงที่รันได้จากเครื่องที่ใช้เขียนบทเรียนนี้ เลขเวอร์ชันบนเครื่องของคุณจะไม่ตรงกันเป๊ะ ๆ เพราะ Node.js ออกเวอร์ชันใหม่อยู่เรื่อย ๆ ไม่ใช่เรื่องผิดปกติ ขอแค่รันแล้วได้เลขเวอร์ชันออกมาก็ถือว่าติดตั้งสำเร็จ) สังเกตว่าไม่มีขั้นตอนติดตั้ง npm แยกต่างหากเลย เพราะ npm ถูกรวมมาให้พร้อมกับ Node.js อยู่แล้วตั้งแต่ต้น ติดตั้ง Node.js เสร็จก็ได้ npm มาด้วยในตัว

npx คืออะไร

npx เป็นอีกคำสั่งที่ติดมากับ Node.js ใช้รันคำสั่งจากแพ็กเกจใดแพ็กเกจหนึ่งได้ทันที โดยไม่ต้องติดตั้งแพ็กเกจนั้นแบบ global ไว้ก่อน จริง ๆ แล้วคำสั่งนี้ไม่ใช่เรื่องใหม่สำหรับคุณเลย เพราะคอร์ส SCSS ที่ผ่านมาให้รัน npx sass --watch เพื่อคอย compile ไฟล์ SCSS เป็น CSS อัตโนมัติ ตอนนั้น npx เป็นตัวไปดึงแพ็กเกจ sass มารันให้ชั่วคราวโดยไม่ต้องติดตั้งแบบถาวรไว้ในเครื่อง ทีนี้พอเข้าใจแล้วว่า Node.js กับ npm มาจากไหน ก็เข้าใจแล้วว่า npx นั้นทำงานอย่างไรเบื้องหลัง

รัน JavaScript บรรทัดเดียวเพื่อทดสอบ

ใช้ flag -e เพื่อสั่งให้ node รันโค้ด JavaScript สั้น ๆ บรรทัดเดียวโดยไม่ต้องสร้างไฟล์

$ node -e "console.log('hello from node')"
hello from node

วิธีนี้สะดวกมากเวลาต้องการทดสอบเร็ว ๆ ว่า Node.js รันโค้ด JavaScript ได้จริงหรือไม่ โดยไม่ต้องเปิด editor สร้างไฟล์ แล้วค่อยรันแยก

บน Windows: nvm ตัวนี้ใช้กับ Git Bash ไม่ได้ ให้ติดตั้ง nvm-windows แทน หรือจะดาวน์โหลด installer เวอร์ชัน LTS จาก nodejs.org ก็ได้ ถ้าใช้ WSL ให้ทำตามขั้นตอนของ Linux ได้เลย และไม่ว่าจะวิธีไหน ต้องปิดแล้วเปิด terminal ใหม่หลังติดตั้งเสมอ

ข้อผิดพลาดที่พบบ่อย: รัน node -v ใน terminal บานเดิมที่เปิดค้างไว้ตั้งแต่ก่อน ติดตั้ง แล้วเจอ command not found จนสรุปไปเองว่าติดตั้งไม่สำเร็จ ทั้งที่จริง ๆ ติดตั้งผ่านเรียบร้อยดี สาเหตุเดียวกับเรื่อง PATH ที่อธิบายไปแล้วในบทที่ 10 ให้ปิด terminal บานนั้นแล้วเปิดใหม่ก่อนเสมอ

แบบฝึกหัด

ติดตั้ง Node.js เวอร์ชัน LTS บนเครื่องของคุณให้เรียบร้อย จากนั้นรันคำสั่งทั้งสี่นี้ตามลำดับ แล้วบันทึกผลลัพธ์ที่ได้ จากแต่ละคำสั่งไว้: node -v, npm -v, which node และ node -e "console.log(2 + 2)"

ดูเฉลย

แต่ละคำสั่งพิสูจน์คนละเรื่องกัน node -v และ npm -v ยืนยันว่าทั้งสองโปรแกรมติดตั้งแล้ว และ shell หาเจอผ่าน PATH จริง (ถ้าหาไม่เจอจะได้ command not found แทนที่จะได้เลข เวอร์ชัน) which node บอกว่าไฟล์ node ที่กำลังถูกใช้งานอยู่จริงมาจากที่ไหน ซึ่งมีประโยชน์ มากเวลามีการติดตั้ง Node.js ไว้มากกว่าหนึ่งวิธีบนเครื่องเดียวแล้วสับสนว่าเวอร์ชันไหนกำลังทำงานอยู่ ส่วน node -e พิสูจน์ว่า runtime รันโค้ด JavaScript จริงได้ ไม่ใช่แค่รายงานเลขเวอร์ชันเฉย ๆ 

$ node -v
v22.23.2
$ npm -v
10.9.8
$ which node
/Users/mint/.nvm/versions/node/v22.23.2/bin/node
$ node -e "console.log(2 + 2)"
4

เลขเวอร์ชันและ path ที่ได้บนเครื่องของคุณจะไม่ตรงกับตัวอย่างนี้เป๊ะ ๆ ซึ่งไม่ใช่ปัญหา ขอแค่ทั้งสี่คำสั่งคืนค่า ออกมาแทนที่จะขึ้น command not found ก็ถือว่าติดตั้งสำเร็จ ถ้าเจอ command not found ที่คำสั่งไหนก็ตาม ให้กลับไปอ่านบทที่แล้วเรื่อง PATH อีกครั้ง
