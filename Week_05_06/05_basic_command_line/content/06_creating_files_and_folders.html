สร้างไฟล์และโฟลเดอร์

สองบทที่แล้วเราเดินไปมาในระบบไฟล์ที่มีอยู่แล้วเท่านั้น บทนี้จะพาคุณสร้างโฟลเดอร์และไฟล์ขึ้นมาเอง ด้วยคำสั่ง mkdir และ touch แล้วประกอบเป็นโปรเจกต์ฝึกมือหนึ่งชุดที่จะใช้ต่อ ในบทเรียนถัดไปอีกหลายบท

สร้างโฟลเดอร์ด้วย mkdir

mkdir ย่อจาก “make directory” รับชื่อโฟลเดอร์ที่ต้องการสร้างเป็น argument 

$ mkdir my-cli-lab
$ ls
my-cli-lab

คำสั่งนี้สร้างโฟลเดอร์เปล่าชื่อ my-cli-lab ขึ้นในตำแหน่งปัจจุบัน แล้ว ls ยืนยันว่าโฟลเดอร์นี้มีอยู่จริงแล้ว

สร้างหลายชั้นพร้อมกันด้วย -p

ถ้าอยากสร้างโฟลเดอร์ที่มีโฟลเดอร์ลูกซ้อนอยู่ข้างในทันที เช่น src/components โดยที่ src ยังไม่มีอยู่เลย mkdir แบบธรรมดาจะทำไม่ได้ 

$ mkdir src/components
mkdir: src: No such file or directory

error นี้บอกตรง ๆ ว่าไม่พบ src ซึ่งเป็นโฟลเดอร์แม่ที่ต้องมีอยู่ก่อน mkdir ปกติสร้างได้แค่ชั้นเดียวต่อครั้งเท่านั้น ทางแก้คือเติม flag -p (parents) เพื่อสั่งให้สร้างทุกชั้นที่ยังไม่มีให้ครบในคำสั่งเดียว 

$ mkdir -p src/components
$ ls src
components

คราวนี้ mkdir สร้างทั้ง src และ components ที่อยู่ข้างในให้พร้อมกัน ไม่ฟ้อง error แม้ src จะยังไม่เคยมีมาก่อนเลยก็ตาม

สร้างไฟล์เปล่าด้วย touch

touch สร้างไฟล์เปล่าขึ้นมาใหม่ ถ้าไฟล์นั้นยังไม่มีอยู่ รับชื่อไฟล์ได้หลายตัวพร้อมกันในคำสั่งเดียว 

$ touch index.js README.md
$ ls
README.md	index.js	src

แต่ถ้าไฟล์นั้นมีอยู่แล้ว touch จะไม่ลบหรือแก้เนื้อหาข้างในเลย มันแค่อัปเดตเวลาที่แก้ไขล่าสุด (modified time) ของไฟล์ให้เป็นตอนนี้เท่านั้น 

$ ls -l README.md
-rw-r--r--  1 mint  staff  0 Aug 14 19:46 README.md

$ touch README.md
$ ls -l README.md
-rw-r--r--  1 mint  staff  0 Aug 14 19:46 README.md

สังเกตว่าขนาดไฟล์ยังเป็น 0 byte เท่าเดิม (เพราะไฟล์นี้ว่างเปล่าอยู่แล้วตั้งแต่แรก) สิ่งที่เปลี่ยน คือเวลาที่แก้ไขล่าสุดเท่านั้น คุณสมบัตินี้ทำให้ touch ปลอดภัยที่จะรันซ้ำกับไฟล์เดิมได้เสมอ โดยไม่ต้องกลัวข้อมูลหาย

สร้างโครงโปรเจกต์ฝึกมือ

ลองรวมทุกคำสั่งที่เรียนมาสร้างโปรเจกต์ฝึกมือขึ้นจริง ๆ สักหนึ่งโฟลเดอร์ เริ่มจาก home directory 

$ cd ~
$ mkdir my-cli-lab
$ cd my-cli-lab
$ mkdir -p src notes
$ touch README.md src/index.js
$ ls -R
notes		README.md	src

./notes:

./src:
index.js

ls -R (recursive) แสดงรายการไฟล์ของทุกโฟลเดอร์แบบไล่ลึกลงไปในคำสั่งเดียว แต่ละโฟลเดอร์ลูกจะขึ้นหัวข้อของตัวเองตามด้วยรายการไฟล์ข้างใน สังเกตว่าลำดับที่แสดงเป็น notes ก่อน README.md ไม่ใช่เรียงตามตัวพิมพ์ใหญ่เล็กแบบ ASCII ตรง ๆ (ซึ่งจะให้ README.md ขึ้นก่อนเพราะ R ตัวใหญ่มาก่อน n ตัวเล็ก) เพราะ macOS เรียงชื่อไฟล์ตาม locale ที่ตั้งไว้ (ในที่นี้คือ en_US.UTF-8) ซึ่งเทียบตัวอักษรแบบไม่สนตัวพิมพ์ใหญ่เล็ก ถ้าเปลี่ยน locale หรือไปรันบน Linux ที่ใช้ locale C ลำดับที่เห็นอาจสลับกันได้ อย่าแปลกใจถ้าลำดับบนเครื่องคุณไม่ตรงกับตัวอย่างนี้เป๊ะ ๆ

เก็บโฟลเดอร์ my-cli-lab นี้ไว้ในเครื่อง อย่าเพิ่งลบทิ้ง เพราะบทเรียนที่ 7 ถึง 9 จะใช้โฟลเดอร์นี้ต่อในการฝึกคัดลอก ย้าย ลบ และดูเนื้อหาไฟล์

เปิดโฟลเดอร์ใน VS Code ด้วย code .

หลังสร้างโครงโปรเจกต์เสร็จ ขั้นตอนถัดไปที่ทำบ่อยที่สุดคือเปิดโฟลเดอร์นี้ใน VS Code ทันที โดยไม่ต้องสลับไปเปิดผ่านเมนู File อีกที 

$ code .

code คือคำสั่งเปิด VS Code จาก terminal ส่วน . คือ relative path ที่หมายถึง “โฟลเดอร์ปัจจุบัน” ตามที่เรียนไปในบทที่แล้ว รวมกันแล้ว code . จึงแปลว่า “เปิด VS Code โดยให้โฟลเดอร์ปัจจุบันเป็น workspace” ซึ่งเร็วกว่า เปิด VS Code แล้วค่อยไปกด File → Open Folder มาก

คำสั่ง code ไม่ได้ติดตั้งมาให้อัตโนมัติ ต้องเปิด VS Code ขึ้นมาก่อนครั้งหนึ่ง กด Cmd + Shift + P (macOS) หรือ Ctrl + Shift + P (Windows/Linux) เพื่อเปิด Command Palette แล้วพิมพ์หา Shell Command: Install 'code' command in PATH กด Enter หนึ่งครั้ง จากนั้น code จะใช้งานได้จาก terminal ทุกครั้งไป (เรื่อง PATH คืออะไรจะอธิบายละเอียดในบทเรียนถัดไปเรื่อง environment variables)

บน Windows: ใน Git Bash คำสั่ง mkdir และ touch ใช้ได้ตามปกติ แต่ใน PowerShell ไม่มี touch ให้ใช้ New-Item README.md แทน ส่วน code . ใช้ได้เหมือนกันถ้าตอนติดตั้ง VS Code เลือก “Add to PATH” ไว้

ข้อผิดพลาดที่พบบ่อย: รัน mkdir สร้างโฟลเดอร์ซ้อนกันโดยลืมเติม -p เช่น mkdir src/components ทั้งที่ src ยังไม่มีอยู่ แล้วงงว่าทำไม error บอกว่าไม่พบ src ทั้งที่เพิ่งจะสั่งสร้างมันไป (จริง ๆ แล้วคำสั่งนี้ พยายามสร้างแค่ components ข้างใน src เท่านั้น ไม่ได้สร้าง src ให้ด้วย)

อีกเรื่องที่พบบ่อยไม่แพ้กันคือสร้างโฟลเดอร์ฝึกมือไว้ผิดที่ เพราะไม่ได้เช็ก pwd ก่อนรัน mkdir ทำให้ my-cli-lab ไปโผล่อยู่ในโฟลเดอร์โปรเจกต์อื่นแทนที่ จะอยู่ที่ home directory ตามตั้งใจ นิสัยที่ดีคือรัน pwd เช็กตำแหน่งก่อนสร้างโฟลเดอร์ใหม่เสมอ เหมือนที่เน้นย้ำไปแล้วในบทก่อนหน้า

แบบฝึกหัด

สร้างโครงสร้างต่อไปนี้ให้ครบ โดยใช้จำนวนคำสั่งให้น้อยที่สุด แล้วพิสูจน์ด้วย ls -R

my-cli-lab/ ├── README.md ├── notes/ └── src/ ├── index.js └── utils/ └── format.js
ดูเฉลย

ใช้แค่สี่คำสั่งก็พอ เพราะ mkdir -p สร้างโฟลเดอร์ซ้อนกันหลายชั้นได้ในครั้งเดียว (สั่ง src/utils กับ notes พร้อมกันในบรรทัดเดียวได้ เพราะ mkdir รับหลาย argument) และ touch ก็สร้างไฟล์ได้หลายไฟล์พร้อมกัน เช่นกัน ไม่จำเป็นต้องรันทีละไฟล์ทีละโฟลเดอร์ 

$ cd ~/my-cli-lab
$ mkdir -p src/utils notes
$ touch README.md src/index.js src/utils/format.js
$ ls -R
notes		README.md	src

./notes:

./src:
index.js	utils

./src/utils:
format.js
