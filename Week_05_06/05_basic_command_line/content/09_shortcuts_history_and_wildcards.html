ทางลัด ประวัติคำสั่ง และ Wildcard

บทที่ผ่านมาเน้นว่าคำสั่งไหนทำอะไร บทนี้เปลี่ยนมุมมาที่ความเร็วในการพิมพ์แทน เพราะยิ่งใช้ terminal บ่อยเท่าไร ทางลัดพวกนี้ยิ่งประหยัดเวลาและลดโอกาสพิมพ์ผิดได้มากเท่านั้น

กด Tab ให้ shell พิมพ์ให้

ไม่ต้องพิมพ์ชื่อไฟล์หรือโฟลเดอร์ให้ครบทุกตัวอักษรเอง shell เดาให้ได้ถ้าพิมพ์แค่บางส่วนแล้วกด Tab เช่นอยู่ใน home directory แล้วมีโฟลเดอร์ my-cli-lab อยู่ 

$ cd my-c[กด Tab]
$ cd my-cli-lab/

(ตัวอย่างข้างต้นจำลองให้เห็นภาพ เพราะการกด Tab เป็นการโต้ตอบกับ shell โดยตรง ไม่มีทางบันทึกเป็นข้อความนิ่ง ๆ ได้) พิมพ์แค่ my-c แล้วกด Tab หนึ่งครั้ง shell จะเติมส่วนที่เหลือให้ครบเป็น my-cli-lab/ ทันที เพราะในโฟลเดอร์ปัจจุบันมีชื่อที่ขึ้นต้นด้วย my-c อยู่แบบเดียว ไม่กำกวม

ถ้ามีหลายชื่อที่ขึ้นต้นเหมือนกัน เช่นมีทั้ง my-cli-lab และ my-cli-notes shell จะเติมให้ได้แค่ส่วนที่ตรงกันทั้งหมด (my-cli-) แล้วหยุดรอ กด Tab ซ้ำอีกครั้งเพื่อให้แสดงรายชื่อทั้งหมดที่เป็นไปได้ให้เลือกพิมพ์ต่อเอง

นิสัยกด Tab แทนการพิมพ์ชื่อยาว ๆ เองทุกตัวอักษรคือทางลัดเดียวที่ลดพิมพ์ผิดชื่อไฟล์หรือ พิมพ์ path ผิดได้มากที่สุด เพราะถ้าพิมพ์ผิดตั้งแต่ต้น Tab จะไม่เติมอะไรให้เลย ซึ่งเป็นสัญญาณเตือนทันทีว่าพิมพ์ชื่อผิดตั้งแต่แรก

เรียกคำสั่งเดิมด้วยลูกศรขึ้น

shell จำคำสั่งที่เคยพิมพ์ไปแล้วทั้งหมดไว้เป็นประวัติ กดลูกศรขึ้น ↑ เพื่อดึงคำสั่งก่อนหน้ากลับมา ที่ prompt โดยไม่ต้องพิมพ์ใหม่ กดซ้ำหลายครั้งเพื่อย้อนกลับไปไกลขึ้นเรื่อย ๆ และกดลูกศรลง ↓ เพื่อเลื่อนมาทางคำสั่งที่ใหม่กว่า สะดวกมากเวลาต้องรันคำสั่งเดิมซ้ำ หรือรันคำสั่งที่คล้ายของเดิมแต่แก้นิดหน่อย

ถ้าอยากเห็นรายการคำสั่งทั้งหมดที่เคยรันมาในเซสชันนี้ ใช้คำสั่ง history 

$ history
  501  cd ~/my-cli-lab
  502  ls
  503  cp README.md README.backup.md
  504  mv notes docs
  505  history

(ตัวเลขและคำสั่งในตัวอย่างข้างต้นจำลองขึ้นเพื่อให้เห็นรูปแบบ เพราะประวัติจริงขึ้นกับคำสั่งที่แต่ละคนเคยพิมพ์มาก่อน) ตัวเลขด้านหน้าคือลำดับในประวัติ ใช้เรียกคำสั่งนั้นซ้ำแบบเจาะจงได้ด้วย ! ตามด้วยเลข เช่น !503 จะรันคำสั่งลำดับที่ 503 ซ้ำทันที

ปุ่มลัดที่ต้องรู้

นอกจาก Tab กับลูกศร ยังมีปุ่มลัดอีกชุดที่ใช้บ่อยจนควรจำขึ้นใจ

ปุ่ม ทำอะไร
Ctrl + C หยุด process ที่กำลังรันอยู่
Ctrl + L ล้างหน้าจอ (เท่ากับคำสั่ง clear)
Ctrl + D จบ input หรือออกจาก shell
Ctrl + A / Ctrl + E ย้ายเคอร์เซอร์ไปต้น / ท้ายบรรทัด

ปุ่มที่ใช้บ่อยที่สุดในสี่ปุ่มนี้คือ Ctrl + C เพราะเป็นวิธีหยุดคำสั่งที่ค้างอยู่หรือรันไม่รู้จบ เช่น tail -f ที่เพิ่งเห็นในบทที่แล้ว, dev server ที่รันด้วย npm run dev, หรือ sass --watch ที่คอย compile SCSS ใหม่ทุกครั้งที่ไฟล์เปลี่ยน คำสั่งพวกนี้ถูกออกแบบมาให้ค้าง รันต่อเนื่องอยู่แล้วโดยตั้งใจ ไม่ใช่ค้างเพราะพัง การกด Ctrl + C คือวิธีปกติที่ใช้หยุดมัน ไม่ใช่การปิดหน้าต่าง terminal ทิ้ง

Wildcard: จัดการหลายไฟล์พร้อมกัน

Wildcard คือสัญลักษณ์พิเศษที่ shell ขยายเป็นชื่อไฟล์จริงก่อนส่งให้คำสั่งทำงาน ใช้ได้กับแทบทุกคำสั่งที่รับชื่อไฟล์ เป็น argument ตัวที่ใช้บ่อยที่สุดมีสองตัวคือ * ซึ่งแทนตัวอักษรกี่ตัวก็ได้ (รวมถึงศูนย์ตัว) และ ? ซึ่งแทนตัวอักษรตัวเดียวเท่านั้น 

$ ls *.md
README.md

*.md ขยายเป็นชื่อไฟล์ทุกไฟล์ในโฟลเดอร์ปัจจุบันที่ลงท้ายด้วย .md ก่อนที่ ls จะเห็นด้วยซ้ำ ใช้ในโฟลเดอร์ย่อยได้เช่นกัน 

$ ls src/*.js
src/index.js

ส่วน ? แทนตัวอักษรได้แค่ตัวเดียว ต่างจาก * ที่แทนได้กี่ตัวก็ได้ 

$ ls file?.txt
file1.txt	file2.txt

กรณีนี้ file?.txt จับ file1.txt และ file2.txt ได้ แต่จะไม่จับ file10.txt เพราะมีตัวอักษรหลัง file สองตัวไม่ใช่ตัวเดียว

จุดที่มีประโยชน์มากคือใช้ wildcard ร่วมกับคำสั่งที่จัดการหลายไฟล์ได้ เช่นลบไฟล์ log ทั้งหมดในคำสั่งเดียว 

$ rm *.log

คำสั่งนี้ลบทุกไฟล์ที่ลงท้ายด้วย .log ในโฟลเดอร์ปัจจุบันพร้อมกันหมด โดยไม่แตะไฟล์ที่ลงท้ายแบบอื่นเลย

บน Windows: ปุ่มลัดเหล่านี้ใช้ได้ใน Git Bash ทั้งหมด ส่วนใน PowerShell Ctrl + C ทำงานเหมือนกัน แต่ Ctrl + D อาจไม่ทำงาน ให้พิมพ์ exit แทน

ข้อผิดพลาดที่พบบ่อย: ปิดหน้าต่าง terminal ทิ้งตรง ๆ แทนที่จะกด Ctrl + C เพื่อหยุด process ที่รันอยู่ บางครั้งจะทำให้ dev server ยังจับ port นั้นค้างไว้อยู่เบื้องหลัง พอเปิดใหม่แล้วสั่งรันอีกครั้งก็จะเจอ error ว่า port ถูกใช้งานอยู่แล้ว ทั้งที่มองไม่เห็นโปรแกรมไหนรันอยู่เลยจากหน้าจอ

อีกกรณีที่อันตรายกว่านั้นคือรัน rm * ทั้งที่ยืนอยู่ผิดโฟลเดอร์ เพราะ * เพียงตัวเดียวขยายเป็น “ทุกไฟล์ในโฟลเดอร์ปัจจุบัน” โดยไม่เจาะจงนามสกุลเลย ถ้าไม่ได้เช็ก pwd ก่อน อาจลบไฟล์ผิดโฟลเดอร์ไปทั้งหมดโดยไม่รู้ตัว รัน ls * ดูก่อนเสมอ เพื่อยืนยันว่า wildcard นั้นจับไฟล์ที่ตั้งใจไว้จริง ๆ ก่อนจะรัน rm ตามหลังไป เสียเวลาแค่สองสามวินาที แต่กันความเสียหายที่แก้คืนไม่ได้

แบบฝึกหัด

ใน ~/my-cli-lab สร้างไฟล์เปล่าสามไฟล์คือ a.log, b.log และ notes.txt จากนั้นใช้ wildcard หนึ่งคำสั่งแสดงเฉพาะไฟล์ .log แล้วใช้ wildcard อีกหนึ่งคำสั่งลบไฟล์ .log ทั้งหมดทิ้ง โดยที่ notes.txt ต้องไม่ถูกแตะต้องเลย

ดูเฉลย

*.log ถูก shell ขยายเป็นรายชื่อไฟล์จริงทุกไฟล์ที่ลงท้ายด้วย .log ก่อนที่คำสั่งจะเริ่มทำงานด้วยซ้ำ ในกรณีนี้คือ a.log กับ b.log ดังนั้น rm *.log จึงเทียบเท่ากับพิมพ์ rm a.log b.log ตรง ๆ rm เห็นแค่สองชื่อไฟล์นี้เท่านั้น ไม่มีทางเห็น notes.txt เลยเพราะชื่อนั้น ไม่ตรงกับ pattern การรัน ls *.log ก่อนเป็นวิธียืนยันว่า pattern จับไฟล์ที่ต้องการจริง ๆ ก่อนจะสั่งลบตามหลัง 

$ cd ~/my-cli-lab
$ touch a.log b.log notes.txt
$ ls *.log
a.log	b.log
$ rm *.log
$ ls
README.md	docs		notes.txt	src
