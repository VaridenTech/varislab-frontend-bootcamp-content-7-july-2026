Mixins และ @include

พอเราเริ่มแยกไฟล์เป็น module แล้ว คำถามถัดไปคือ “ถ้ามีกลุ่ม declaration เดิมที่ต้องใช้ซ้ำหลายจุด ควรเก็บยังไง” คำตอบที่ตรงที่สุดใน SCSS คือ @mixin และ @include ซึ่งให้เราตั้งชื่อชุด style แล้วเรียกใช้ซ้ำได้เหมือน helper ขนาดเล็ก

@mixin คือชุด declaration ที่ตั้งชื่อไว้

ให้คิดว่า mixin คือ “สูตร” ของ CSS หลายบรรทัดที่เราตั้งชื่อไว้ก่อน แล้วเวลาต้องใช้ก็สั่ง @include เพื่อให้ Sass คัดลอก declaration เหล่านั้นไปวางในตำแหน่งที่เรียกใช้ 

@mixin visually-hidden {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0 0 0 0);
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}

.skip-label {
  @include visually-hidden;
}

CSS ที่คอมไพล์แล้วจะเป็น:

.skip-label {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0 0 0 0);
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}

จุดสำคัญคือ mixin ไม่ได้สร้าง class ใหม่ให้อัตโนมัติ แต่จะ “ปล่อย declaration ออกมา” ตรง selector ที่เรา include มันเข้าไป

ใช้ร่วมกับ module namespace ได้เหมือนบทก่อนหน้า

ถ้า helper นี้มีไว้ใช้ทั้งโปรเจกต์ เรามักเก็บไว้ในไฟล์เช่น abstracts/_mixins.scss แล้วเรียกผ่าน namespace ของ module เพื่อให้รู้ทันทีว่ามาจากไฟล์ไหน 

/* abstracts/_mixins.scss */
@mixin flex-center($gap: 0.75rem) {
  display: flex;
  align-items: center;
  justify-content: center;
  gap: $gap;
}

/* components/_hero.scss */
@use "../abstracts/mixins";

.hero-actions {
  @include mixins.flex-center(1rem);
}

เมื่อคอมไพล์แล้ว Sass จะเอา namespace ออกและเหลือ CSS ปกติ:

.hero-actions {
  display: flex;
  align-items: center;
  justify-content: center;
  gap: 1rem;
}
อ่านโค้ดแบบนี้แล้วเรารู้ทั้งสองอย่างพร้อมกัน: flex-center เป็น helper ที่ใช้ซ้ำได้ และมันถูกนำเข้ามาจาก module mixins ไม่ใช่โค้ดลอย ๆ ในไฟล์ปัจจุบัน

ตัวแปร, mixin และ CSS class ต่างกันยังไง

มือใหม่มักสับสนว่าของทั้งสามอย่างนี้ต่างกันตรงไหน ลองมองว่ามันแก้คนละปัญหา:

เครื่องมือ เก็บอะไร เหมาะเมื่อไร
ตัวแปร ค่าเดียว เช่น สี, spacing หรือ radius เมื่ออยากเปลี่ยนค่าจากจุดเดียวแล้วให้ที่อ้างถึงอัปเดตตาม
Mixin หลาย declaration ที่จะถูกปล่อยออกมาตอนคอมไพล์ เมื่อ style ชุดหนึ่งต้องใช้ซ้ำในหลาย selector
CSS class selector ที่มีอยู่จริงใน CSS ปลายทาง เมื่อ HTML สามารถใส่ class เดิมเพื่อ reuse style ได้โดยตรง 
$card-radius: 18px;

@mixin card-surface {
  padding: 1.5rem;
  border-radius: $card-radius;
  background-color: #fff;
}

.card-surface {
  padding: 1.5rem;
  border-radius: $card-radius;
  background-color: #fff;
}

ในตัวอย่างนี้ ตัวแปรเก็บแค่ค่า 18px, mixin เก็บ “สูตรหลายบรรทัด” และ class .card-surface คือ selector ที่ถูกปล่อยออกไปให้ HTML ใช้งานได้จริง

ข้อควรระวัง: include ซ้ำ = declaration ซ้ำ

นี่คือเรื่องสำคัญที่สุดของบทนี้ ทุกครั้งที่เรา @include mixin Sass จะคัดลอก declaration ไปวางตรงนั้นอีกครั้ง ไม่ได้ merge ให้เองอัตโนมัติ 

@mixin card-surface {
  padding: 1.5rem;
  border-radius: 18px;
  background-color: #fff;
  box-shadow: 0 12px 30px rgba(53, 18, 110, 0.12);
}

.profile-card {
  @include card-surface;
}

.pricing-card {
  @include card-surface;
}

CSS ที่คอมไพล์แล้วจะมี declaration เดิมซ้ำอยู่ทั้งสอง selector:

.profile-card {
  padding: 1.5rem;
  border-radius: 18px;
  background-color: #fff;
  box-shadow: 0 12px 30px rgba(53, 18, 110, 0.12);
}

.pricing-card {
  padding: 1.5rem;
  border-radius: 18px;
  background-color: #fff;
  box-shadow: 0 12px 30px rgba(53, 18, 110, 0.12);
}

ถ้า style ชุดนี้สั้นและอ่านง่าย การซ้ำอาจรับได้ แต่ถ้า include helper ใหญ่มากในหลายสิบจุด CSS ปลายทางจะยาวขึ้นทันที เพราะ mixin ทำหน้าที่ “คัดลอก” ไม่ใช่ “อ้างอิง”

ข้อผิดพลาดที่พบบ่อย

  • ลืม @include แล้วเขียนแค่ชื่อ mixin ทำให้ Sass มองเป็นโค้ดผิดไวยากรณ์
  • ใช้ mixin เพื่อเก็บค่าเดียว ทั้งที่ตัวแปรเหมาะกว่าและอ่านง่ายกว่า
  • สร้าง mixin ขนาดใหญ่เกินไปจน include ซ้ำแล้วได้ CSS ซ้ำเป็นก้อนโต
  • ลืม namespace ของ module เช่นควรเขียน mixins.flex-center ไม่ใช่เรียกตรง ๆ

แบบฝึกหัด

ให้สมมติว่ามีไฟล์ abstracts/_mixins.scss และต้องการ helper ชื่อ card-surface ที่มี padding: 1.25rem;, border-radius: 16px;, background-color: #fff; และ border: 1px solid #e9defa; ให้ include helper นี้ใน .profile-card และ .feature-card จากนั้นอธิบายว่า CSS ที่คอมไพล์แล้วจะซ้ำตรงไหน

ดูเฉลย 
/* abstracts/_mixins.scss */
@mixin card-surface {
  padding: 1.25rem;
  border-radius: 16px;
  background-color: #fff;
  border: 1px solid #e9defa;
}

/* components/_cards.scss */
@use "../abstracts/mixins";

.profile-card {
  @include mixins.card-surface;
}

.feature-card {
  @include mixins.card-surface;
}
/* CSS ที่คอมไพล์แล้ว */
.profile-card {
  padding: 1.25rem;
  border-radius: 16px;
  background-color: #fff;
  border: 1px solid #e9defa;
}

.feature-card {
  padding: 1.25rem;
  border-radius: 16px;
  background-color: #fff;
  border: 1px solid #e9defa;
}

Declaration ทั้งสี่บรรทัดถูกคัดลอกออกมาซ้ำในทั้ง .profile-card และ .feature-card เพราะ mixin จะปล่อย CSS ใหม่ทุกครั้งที่ include
