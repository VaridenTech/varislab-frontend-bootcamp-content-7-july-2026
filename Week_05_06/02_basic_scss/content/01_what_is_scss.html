SCSS คืออะไร?

SCSS คือรูปแบบไวยากรณ์ยอดนิยมของ Sass ที่ออกแบบมาให้หน้าตาคล้าย CSS มากที่สุด จึงเหมาะมากสำหรับคนที่เขียน CSS อยู่แล้วและอยากเพิ่มความสามารถอย่างตัวแปร การซ้อน selector และการแยกไฟล์ให้เป็นระบบมากขึ้น

Sass กับ SCSS ต่างกันอย่างไร?

คำว่า Sass มักใช้เรียกทั้ง ecosystem ของภาษาและ compiler ส่วน SCSS คือ syntax แบบหนึ่งของ Sass ที่ยังคงใช้วงเล็บปีกกา {} และเครื่องหมาย ; เหมือน CSS ปกติ

คำ หมายถึงอะไร เหมาะกับมือใหม่ไหม
Sass ชื่อภาษา/ตัวแปลงที่เพิ่มพลังให้ CSS ควรรู้ชื่อไว้ เพราะใช้เรียก package และคำสั่ง
.scss ไฟล์ที่ใช้ syntax แบบ CSS-compatible เหมาะมาก เพราะเริ่มจาก CSS เดิมแล้วค่อยเพิ่ม feature

SCSS ทำงานร่วมกับเบราว์เซอร์อย่างไร

เบราว์เซอร์อ่าน SCSS ไม่ออกโดยตรง สิ่งที่เบราว์เซอร์แสดงผลได้จริงยังคงเป็น CSS ดังนั้น workflow พื้นฐานคือ: 

SCSS → compiler → CSS → browser

ให้คิดว่า SCSS คือ “ภาษาที่ช่วยเราเขียนสไตล์ให้ฉลาดขึ้น” ส่วน compiler คือเครื่องมือที่แปล SCSS ให้กลับมาเป็น CSS ธรรมดาก่อนส่งต่อให้หน้าเว็บ

ตัวอย่าง SCSS เทียบกับ CSS ที่ถูกคอมไพล์แล้ว

SCSS ต้นฉบับ

$brand-color: #6f3cc3;

.button {
  background-color: $brand-color;
  color: white;
}

CSS หลังคอมไพล์

.button {
  background-color: #6f3cc3;
  color: white;
}

จุดสำคัญคือเครื่องหมาย $ ไม่มีอยู่ใน CSS ปกติ มันเป็น feature ของ SCSS เท่านั้น พอคอมไพล์เสร็จ compiler จะเอาค่าจริงมาแทนที่ตัวแปรให้

ไฟล์ .scss มีไว้ทำอะไร

  • เก็บ logic ฝั่งสไตล์ เช่น ตัวแปร การซ้อน selector และการแบ่งโมดูล
  • ช่วยลดการคัดลอกซ้ำ เพราะค่าที่ใช้บ่อยประกาศครั้งเดียวแล้วเรียกใช้ซ้ำได้
  • ทำให้โค้ดอ่านเป็นระบบขึ้น โดยเฉพาะโปรเจกต์ที่มีหลายหน้า หลาย component

ประโยชน์หลักของ SCSS

  • Reusable — เก็บค่าซ้ำ ๆ เช่นสี ระยะห่าง และขนาดตัวอักษรไว้เป็นตัวแปร
  • อ่านง่ายขึ้น — ความสัมพันธ์ของ component กับสถานะย่อยเห็นชัดขึ้นผ่าน nesting ที่พอดี
  • ดูแลง่ายขึ้น — เปลี่ยนโทนสีหรือ spacing ที่จุดเดียวแล้วทั้งโปรเจกต์อัปเดตตาม

เมื่อไหร่ที่ CSS ธรรมดาก็เพียงพอ

ถ้าโปรเจกต์มีไฟล์สไตล์เล็กมาก มีหน้าเดียว หรือแทบไม่มีค่าที่ใช้ซ้ำกันเลย การใช้ CSS ปกติก็อาจเพียงพอและลดขั้นตอน build ได้ SCSS ไม่ใช่สิ่งที่ “ต้องใช้เสมอ” แต่เป็นเครื่องมือที่ช่วยมากเมื่อสไตล์เริ่มโต

เริ่มจากโจทย์จริงก่อน: ถ้าโปรเจกต์เริ่มมีสีหลักหลายจุด มี component ซ้ำ หรือแก้สไตล์ทีหนึ่งต้องไล่หลายไฟล์ นั่นคือสัญญาณว่า SCSS เริ่มคุ้มค่า

ข้อควรระวังสำหรับผู้เริ่มต้น

  • อย่าคิดว่า SCSS จะรันในเบราว์เซอร์ได้ตรง ๆ — ต้องแปลงเป็น CSS ก่อนเสมอ
  • อย่าสับสนระหว่าง “Sass” ที่เป็นชื่อระบบ กับ “SCSS” ที่เป็น syntax ที่เราเขียนในไฟล์
  • อย่าใช้ feature เพิ่มเติมเพียงเพราะทำได้ ถ้า CSS ธรรมดาอ่านง่ายกว่า ให้ใช้แบบง่ายก่อน

แบบฝึกหัด

จากสอง snippet นี้ ข้อไหนคือโค้ดที่ต้องผ่านการคอมไพล์ก่อนใช้งานในเบราว์เซอร์?

/* Snippet A */
.card {
  border-radius: 12px;
}

/* Snippet B */
$brand-color: #6f3cc3;

.card {
  border-color: $brand-color;
}
ดูเฉลย

Snippet B ต้องคอมไพล์ก่อน เพราะมีตัวแปร $brand-color ซึ่งเป็นไวยากรณ์ของ SCSS ไม่ใช่ CSS ที่เบราว์เซอร์อ่านได้โดยตรง
