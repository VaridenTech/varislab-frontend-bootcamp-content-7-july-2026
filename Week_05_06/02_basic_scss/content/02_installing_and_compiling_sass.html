ติดตั้งและคอมไพล์ Sass

หลังจากรู้แล้วว่า SCSS ต้องถูกแปลงเป็น CSS ก่อน ขั้นต่อไปคือเตรียมโปรเจกต์ให้มีทั้งไฟล์ต้นฉบับ และไฟล์ผลลัพธ์อย่างชัดเจน เพื่อให้เรารู้ว่าไฟล์ไหนเขียนเอง และไฟล์ไหนถูกสร้างโดย compiler

โครงสร้างโปรเจกต์พื้นฐาน

โครงสร้างเริ่มต้นที่เข้าใจง่ายสำหรับผู้เริ่มต้นมีหน้าตาแบบนี้:

scss-course/ ├── index.html ├── package.json ├── scss/main.scss └── css/main.css
  • index.html คือหน้าเว็บที่ link ไฟล์ CSS ที่คอมไพล์แล้ว
  • package.json เก็บข้อมูลโปรเจกต์และ dependency
  • scss/main.scss คือไฟล์ต้นฉบับที่เราแก้ไข
  • css/main.css คือไฟล์ผลลัพธ์ที่เบราว์เซอร์โหลดไปใช้

ติดตั้ง Sass ด้วย npm

ลำดับคำสั่งพื้นฐานมีดังนี้:

npm init -y
npm install --save-dev sass
npx sass --version
npx sass scss/main.scss css/main.css
npx sass --watch scss/main.scss:css/main.css

คำสั่งแรกสร้าง package.json อัตโนมัติ คำสั่งที่สองติดตั้ง Sass เป็น dev dependency ส่วน npx sass --version ใช้เช็กว่า CLI พร้อมใช้งานแล้วจริง

คำสั่ง compile แบบครั้งเดียว

npx sass scss/main.scss css/main.css

คำสั่งนี้หมายถึง “อ่านไฟล์ต้นฉบับจาก scss/main.scss แล้วเขียนผลลัพธ์ไปที่ css/main.css” เหมาะเวลาต้องการคอมไพล์เป็นรอบ ๆ เช่นก่อนเปิดไฟล์ HTML ในเบราว์เซอร์

คำสั่ง watch สำหรับทำงานต่อเนื่อง

npx sass --watch scss/main.scss:css/main.css

โหมด watch จะคอยเฝ้าดูการเปลี่ยนแปลงของไฟล์ SCSS และคอมไพล์ใหม่ให้อัตโนมัติทุกครั้งที่บันทึกไฟล์ ทำให้ workflow ระหว่างเรียนหรือพัฒนา UI เร็วขึ้นมาก

หยุด watch mode อย่างไร

ถ้ารันใน terminal ปกติ ให้กด Ctrl + C เพื่อหยุด process ที่กำลังเฝ้าดูไฟล์อยู่

อย่าลืม link ไฟล์ CSS ที่ถูกสร้างแล้ว

แม้เราจะเขียน SCSS อยู่ในโฟลเดอร์ scss/ แต่ใน HTML ต้อง link ไปที่ไฟล์ CSS ที่ถูกคอมไพล์ออกมาเท่านั้น 

<link rel='stylesheet' href='css/main.css' />

ถ้าไป link scss/main.scss โดยตรง เบราว์เซอร์จะไม่เข้าใจและจะไม่แสดงผลสไตล์ตามที่คาดหวัง

ทำไมเบราว์เซอร์ถึงโหลด SCSS ไม่ได้

เบราว์เซอร์รู้จักมาตรฐาน CSS เท่านั้น มันไม่รู้ว่า $variable, nesting หรือ feature อื่นของ Sass ควรถูกแปลงอย่างไร งานของ compiler คือแปลง feature เหล่านี้ให้กลายเป็น CSS ที่เป็นมาตรฐานก่อน

ข้อผิดพลาดที่เจอบ่อย

  • สั่งจาก directory ผิด — ถ้า terminal ไม่ได้อยู่ที่ root ของโปรเจกต์ path อย่าง scss/main.scss อาจหาไม่เจอ
  • path ปลายทางไม่พร้อมใช้งาน — Dart Sass มักสร้างโฟลเดอร์ปลายทางอย่าง css/ ให้ได้เอง แต่ถ้าสะกด path ผิด, สั่งจากโฟลเดอร์ผิด, มีส่วนหนึ่งของ path เป็นไฟล์แทนที่จะเป็นโฟลเดอร์ หรือสิทธิ์เขียนไม่พอ คำสั่งก็ยังล้มเหลวได้
  • แก้ไฟล์ผิดตัว — ผู้เริ่มต้นมักเผลอไปแก้ css/main.css โดยตรง ทั้งที่ไฟล์นั้นควรถูก generate จาก SCSS
ถ้าเจอ error ประเภท no such file or directory ให้เช็กสองอย่างก่อน: ตอนนี้ terminal อยู่โฟลเดอร์ไหน และ path ต้นทาง/ปลายทางสะกดตรงกับโครงสร้างไฟล์จริงหรือไม่ โดยจำไว้ว่า Dart Sass รุ่นใหม่มักสร้างโฟลเดอร์ปลายทางที่ยังไม่มีให้ได้เอง

แบบฝึกหัด

สมมติว่าคุณมีไฟล์ต้นฉบับอยู่ที่ styles/app.scss และต้องการได้ไฟล์ผลลัพธ์เป็น public/app.css ให้เขียนทั้งคำสั่ง compile ครั้งเดียว และคำสั่ง watch

ดูเฉลย 
npx sass styles/app.scss public/app.css
npx sass --watch styles/app.scss:public/app.css

ถ้าต้องหยุด watch mode ให้กด Ctrl + C ใน terminal เดียวกัน
