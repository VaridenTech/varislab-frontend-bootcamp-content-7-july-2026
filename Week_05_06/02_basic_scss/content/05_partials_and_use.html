Partial และ @use

พอโปรเจกต์เริ่มมีตัวแปรและ component หลายตัว เราไม่อยากกองทุกอย่างไว้ในไฟล์เดียวอีกต่อไป SCSS จึงมีแนวคิดเรื่อง partial และ module เพื่อแยกของที่ใช้ซ้ำออกเป็นไฟล์ย่อย แล้วค่อยดึงกลับมาใช้แบบชัดเจนผ่าน @use

Partial คืออะไร

Partial คือไฟล์ SCSS ที่ตั้งใจให้ไฟล์อื่นนำเข้าไปใช้ ไม่ได้คอมไพล์เป็นไฟล์ CSS ปลายทางโดยตรง ตามธรรมเนียมเราจะขึ้นต้นชื่อไฟล์ด้วยเครื่องหมาย underscore เช่น _tokens.scss หรือ _colors.scss 

scss/
├── _tokens.scss
└── main.scss

ไฟล์แบบนี้มักเก็บ design tokens, reset, helper หรือ component ย่อย แล้วให้ไฟล์ entry point เช่น main.scss เป็นตัวเรียกใช้

เวลาเรียกใช้ ไม่ต้องพิมพ์ underscore หรือ .scss

ถึงไฟล์จริงจะชื่อ _tokens.scss แต่เวลาใช้กับ @use เราอ้างแค่ชื่อ module แบบสั้น ๆ ได้เลย 

@use "tokens";

Sass จะหาไฟล์ _tokens.scss ให้เองโดยอัตโนมัติ นี่เป็นเหตุผลที่ชื่อไฟล์ควรสั้น ชัด และสื่อความหมายตั้งแต่แรก

ค่าใน module จะมากับ namespace

จุดสำคัญของ @use คือมันไม่เททุกอย่างเข้ามาใน global scope แต่จะบังคับให้เราอ้างชื่อผ่าน namespace ของไฟล์นั้นก่อน ทำให้รู้ทันทีว่าค่านี้มาจากที่ไหน 

/* _tokens.scss */
$brand-color: #6f3cc3;
$space-md: 1rem;

/* main.scss */
@use "tokens";

.button {
  padding: tokens.$space-md;
  background-color: tokens.$brand-color;
}

CSS ที่คอมไพล์แล้วจะเป็น:

.button {
  padding: 1rem;
  background-color: #6f3cc3;
}

ถ้าชื่อยาวเกินไป ใช้ alias ได้

บางครั้งชื่อไฟล์หรือชื่อโฟลเดอร์อาจยาวเกินความจำเป็น เราสามารถตั้งชื่อ alias ให้ namespace สั้นลงได้ด้วย as 

@use "tokens" as t;

.card {
  border-color: t.$brand-color;
  padding: t.$space-md;
}

Alias ช่วยให้เขียนสั้นลง แต่ยังรักษาความชัดเจนว่าค่านี้มาจาก module ไหน เหมาะเมื่อชื่อจริงยาวหรือมีหลาย module อยู่ในไฟล์เดียว

Module เดียวกันจะถูกโหลดครั้งเดียว

ถ้าหลายไฟล์ในโปรเจกต์ @use "tokens" เหมือนกัน Sass จะจัดการให้ module นั้นถูกโหลดเพียงครั้งเดียวในระบบโมดูล เราจึงไม่ต้องกังวลเรื่องการนำเข้าไฟล์เดิมซ้ำแล้วเกิด CSS ซ้ำแบบเดิม ๆ

  • โค้ดอ่านง่ายขึ้น เพราะ dependency ชัดเจนในแต่ละไฟล์
  • ลดความเสี่ยงจากตัวแปรชื่อชนกันโดยไม่ตั้งใจ
  • ทำให้การแยกไฟล์เป็นระบบมากขึ้นเมื่อโปรเจกต์โตขึ้น

@use ต้องอยู่ top level

คำสั่ง @use ควรอยู่ด้านบนของไฟล์ในระดับ top level ไม่ควรวางไว้ข้างใน selector, media query หรือเงื่อนไขอื่น เพราะ Sass ต้องรู้ dependency ของไฟล์ตั้งแต่เริ่มคอมไพล์ 

@use "tokens";

.profile-card {
  padding: tokens.$space-md;
}
ให้จำง่าย ๆ ว่าเปิดไฟล์ SCSS มา สิ่งแรก ๆ ที่ควรเห็นคือรายการ @use ของไฟล์นั้น จากนั้นค่อยเป็นตัวแปร local หรือ selector ของ component

แล้ว @import ล่ะ

@import เป็น syntax แบบ legacy ที่ deprecated แล้ว และไม่แนะนำสำหรับโค้ดใหม่ ให้ใช้ @use แทน เพราะ @use จัดการ namespace และ dependency ได้ชัดกว่า

แนวคิดที่ควรจำจากบทนี้

แนวคิด สิ่งที่ควรทำ เหตุผล
Partial ตั้งชื่อไฟล์ขึ้นต้นด้วย _ สื่อว่าเป็นไฟล์ย่อยสำหรับนำไปใช้ ไม่ใช่ entry point
การอ้างอิง ใช้ @use "tokens"; ไม่ต้องพิมพ์ underscore หรือ .scss
Namespace เรียกผ่าน tokens.$brand-color รู้ที่มาของค่าและลดชื่อชนกัน
Alias ใช้ as t เมื่อต้องการชื่อสั้น เขียนสะดวกขึ้นโดยยังมีความชัดเจน
Placement วาง @use ไว้ด้านบนของไฟล์ ประกาศ dependency ก่อนเขียน style

แบบฝึกหัด

สมมติว่ามีไฟล์ _colors.scss ที่เก็บตัวแปร $profile-bg: #f5f0ff; และ $profile-padding: 1.5rem; ให้เขียนไฟล์ profile.scss ที่ใช้ module นี้ด้วยชื่อ namespace colors และสร้าง class .profile-card จากนั้นดูว่า CSS ที่คอมไพล์แล้วควรออกมาเป็นอย่างไร

ดูเฉลย

@use "colors" โหลด partial แบบมี namespace ทำให้รู้ชัดว่า $profile-padding และ $profile-bg มาจากไฟล์สี 

/* profile.scss */
@use "colors";

.profile-card {
  padding: colors.$profile-padding;
  background-color: colors.$profile-bg;
  border-radius: 16px;
}
/* CSS ที่คอมไพล์แล้ว */
.profile-card {
  padding: 1.5rem;
  background-color: #f5f0ff;
  border-radius: 16px;
}
