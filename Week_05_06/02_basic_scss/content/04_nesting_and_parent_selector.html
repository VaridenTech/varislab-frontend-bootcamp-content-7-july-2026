Nesting และ Parent Selector

Nesting คือการเขียน selector ซ้อนกันเพื่อสื่อความสัมพันธ์ของ component กับส่วนย่อยหรือสถานะของมัน ส่วน & หรือ parent selector คือเครื่องมือที่อ้างถึง selector ปัจจุบัน เพื่อสร้าง pseudo-class, modifier และชื่อแบบ BEM ได้สะดวกขึ้น

Nesting แบบตื้นคือเพื่อนที่ดีที่สุด

การซ้อนแบบพอดีช่วยให้อ่านง่าย เพราะเราเห็นทันทีว่า style นี้เป็นของใคร เช่น ชื่อเรื่องอยู่ใน card เดียวกัน แต่ถ้าซ้อนลึกเกินไป โค้ดจะยาว อ่านยาก และผูกติดกับ HTML มากเกินจำเป็น 

.card {
  padding: 1rem;

  .card__title {
    margin: 0;
  }
}

คอมไพล์แล้วจะได้:

.card {
  padding: 1rem;
}

.card .card__title {
  margin: 0;
}

ใช้กับ pseudo-classes ได้อย่างเป็นธรรมชาติ

.button {
  background: #6f3cc3;
  color: white;

  &:hover {
    background: #54279b;
  }
}

ผลลัพธ์หลังคอมไพล์:

.button {
  background: #6f3cc3;
  color: white;
}

.button:hover {
  background: #54279b;
}

สังเกตว่า &:hover ไม่ได้หมายถึงลูกของ .button แต่มันแปลว่า “เอา selector ปัจจุบันมาต่อกับ :hover”

Parent selector (&) กับ BEM suffixes

ถ้าเขียนชื่อ class แบบ BEM เรามักใช้ & เพื่อสร้าง element และ modifier โดยไม่ต้องพิมพ์ชื่อ block ซ้ำหลายครั้ง 

.card {
  padding: 1rem;
  border: 1px solid #d9c8f0;

  &__title {
    margin-bottom: 0.75rem;
    font-weight: 700;
  }

  &--featured {
    border-color: #6f3cc3;
    box-shadow: 0 0 0 3px rgb(111 60 195 / 15%);
  }
}

คอมไพล์แล้วจะได้:

.card {
  padding: 1rem;
  border: 1px solid #d9c8f0;
}

.card__title {
  margin-bottom: 0.75rem;
  font-weight: 700;
}

.card--featured {
  border-color: #6f3cc3;
  box-shadow: 0 0 0 3px rgb(111 60 195 / 15%);
}

ตรงนี้สำคัญมาก: &__title กลายเป็น .card__title ไม่ใช่ .card .card__title เพราะเราเอาชื่อ parent มาต่อคำโดยตรง

Nested media queries

อีกจุดที่สะดวกมากคือการเขียน media query ไว้ใกล้ component ที่เกี่ยวข้อง ทำให้เราเห็น style ปกติและ style responsive อยู่ด้วยกัน 

.card {
  padding: 1.5rem;

  @media (max-width: 640px) {
    padding: 1rem;
  }
}

คอมไพล์แล้วจะได้:

.card {
  padding: 1.5rem;
}

@media (max-width: 640px) {
  .card {
    padding: 1rem;
  }
}

อย่าซ้อนตามต้นไม้ HTML ทั้งหมด

กับ SCSS มือใหม่มักเผลอ mirror โครงสร้าง HTML ลงมาแบบทุกชั้น เช่น .page .layout .sidebar .menu .item a ซึ่งทำให้ selector ยาว เปราะ และแก้ยาก

แนวทางที่ปลอดภัยสำหรับบทเริ่มต้นคือพยายามไม่ให้เกินประมาณ 3 ระดับของ selector ถ้าลึกกว่านี้ให้หยุดคิดก่อนว่าเราควรตั้ง class ที่ชัดขึ้นแทนหรือไม่

ข้อควรระวังที่พบบ่อย

  • ใช้ nesting ลึกเกินไปจน CSS ที่คอมไพล์ออกมาซับซ้อนโดยไม่จำเป็น
  • สับสนระหว่าง .card .card__title กับ .card__title ที่เกิดจาก &__title
  • ใช้ & ทุกที่โดยไม่จำเป็น ทั้งที่บางครั้งเขียน selector ธรรมดาอ่านง่ายกว่า

แบบฝึกหัด

ลองเขียน navigation block ที่มี class หลักเป็น .nav และต้องมี .nav__link, สถานะ hover และ modifier .nav__link--active จากนั้นดู CSS ที่ควรถูกคอมไพล์ออกมา

ดูเฉลย

เครื่องหมาย & แทน selector แม่ปัจจุบัน จึงต่อเป็นชื่อแบบ BEM และ pseudo-class โดยไม่ต้องพิมพ์ .nav__link ซ้ำ 

/* SCSS */
.nav {
  &__link {
    color: #54279b;
    text-decoration: none;

    &:hover {
      color: #6f3cc3;
    }

    &--active {
      font-weight: 700;
      text-decoration: underline;
    }
  }
}
/* CSS ที่คอมไพล์แล้ว */
.nav__link {
  color: #54279b;
  text-decoration: none;
}

.nav__link:hover {
  color: #6f3cc3;
}

.nav__link--active {
  font-weight: 700;
  text-decoration: underline;
}
