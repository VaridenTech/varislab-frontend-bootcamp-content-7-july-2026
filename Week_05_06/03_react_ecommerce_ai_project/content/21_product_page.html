Product Detail Page

หน้าสุดท้ายของ chapter นี้คือหน้าที่ผู้ใช้ตัดสินใจซื้อ: หน้า Product detail ที่เปิดจากการคลิกการ์ดสินค้าใน Home หรือ Category (path /products/:id) หน้านี้มีของให้ดูเยอะที่สุดในแอป — แกลเลอรีรูปพร้อม thumbnail ที่คลิกสลับได้, ข้อมูลราคา/ส่วนลด/สต็อก, ปุ่ม Add to Cart, กราฟแท่งสรุปคะแนนรีวิว และรายการรีวิวจากผู้ซื้อ เราจะสร้างมันจากคอมโพเนนต์ย่อย 5 ตัวแล้วประกอบร่างในไฟล์หน้าเพจตอนท้าย

ข้อสังเกตหนึ่งก่อนเริ่ม และเป็นข้อที่ต้องจำให้แม่น: ปุ่ม Add to Cart ในบทนี้จะวาดออกมาบนหน้าจอจริง กดได้จริง แต่กดแล้วไม่เกิดอะไรขึ้น — ตะกร้าสินค้ายังไม่มีอยู่ในแอปเลย (นั่นคือ chapter ถัดไปทั้ง chapter) หน้าที่เราสร้างวันนี้คือ Product.tsx เวอร์ชันแรก ที่จบในตัว โดย onAddToCart เป็นฟังก์ชันว่างที่มีแค่ comment เราจะสร้าง cart store ในบทเรียน 22 แล้วกลับมาต่อสายปุ่มนี้เข้ากับตะกร้าจริงในบทเรียน 23 ตอนนั้นจะบอกชัด ๆ อีกทีว่าต้องแก้บรรทัดไหนบ้าง ถ้าตอนทดสอบท้ายบทคุณกดปุ่มแล้วไม่มีอะไรเกิดขึ้น นั่นคือผลลัพธ์ที่ถูกต้อง ไม่ใช่บั๊ก

ติดตั้ง dayjs

รีวิวจาก dummyjson มีวันที่ติดมาเป็น ISO string เช่น 2025-04-30T09:41:02.053Z — เอาไปแสดงตรง ๆ ไม่ได้แน่ ๆ เราอยากได้รูปแบบอ่านง่ายอย่าง 30 April 2025 การ format วันที่ด้วย Date ดิบ ๆ ของ JavaScript ทำได้แต่เขียนยาวและพลาดง่าย เราจึงใช้ dayjs — library จัดการวันที่ตัวจิ๋วที่ API เหมือน Moment.js แต่เบากว่ามาก และเป็นตัวที่เจอบ่อยที่สุดตัวหนึ่งในโปรเจกต์ React ปัจจุบัน ตามกติกาเดิม เราติดตั้งเอง:

npm install dayjs
git add -A && git commit -m "chore: install dayjs"

นี่คือ dependency ตัวสุดท้ายของ chapter หน้าเพจ เราจะได้ใช้มันครั้งแรกใน ReviewCard — เรียก dayjs(isoString).format("DD MMMM YYYY") จบในบรรทัดเดียว

แบ่งสองรอบอีกครั้ง — คราวนี้ตัดตามเส้นสถาปัตยกรรม

บทเรียน 19 ให้เกณฑ์ไว้ว่า: ถ้า prompt เดียวทำให้เกิดของที่ต้องตรวจเกินหนึ่งหน้าจอ และของนั้นแบ่งเป็นก้อนที่ทดสอบแยกกันได้ ให้แบ่ง บทนี้เข้าเกณฑ์ข้อแรกเต็ม ๆ (เจ็ดไฟล์ใหม่ในรอบเดียว) แต่ไม่เข้าเกณฑ์ข้อสอง — คอมโพเนนต์ทั้งห้าตัวยังไม่มีใครเรียกใช้จนกว่าหน้าเพจจะเสร็จ จบรอบแรกไปก็ยังไม่มีอะไรให้เปิดดูในเบราว์เซอร์

เราจึงใช้เส้นตัดคนละเส้น: ทิศทางการพึ่งพา ซึ่งบังเอิญตรงกับเส้นสถาปัตยกรรมของบทเรียน 05 พอดี

  • รอบที่ 2 — สองไฟล์ใน pages/Product/: ReviewSection กับ Product.tsx ทั้งคู่บริโภคของจากรอบที่ 1 การให้มันมาทีหลังแปลว่าตอนส่ง prompt รอบสอง คุณ @-mention คอมโพเนนต์ที่มีอยู่จริงแล้วได้ Agent จึงเห็น props signature ของจริง ไม่ใช่ signature ที่มันเพิ่งเดาไว้เองในย่อหน้าก่อนหน้า

ผลพลอยได้ที่สำคัญกว่าเรื่องขนาด diff: ถ้ารอบที่ 2 typecheck ไม่ผ่านเพราะ props ไม่ตรง คุณรู้ทันทีว่าปัญหาอยู่ที่ไฟล์ไหน — ไฟล์ที่เพิ่งเขียนใหม่สองไฟล์ ไม่ใช่ในกองเก้าไฟล์ที่ทุกอย่างเกิดพร้อมกัน

ProductImageGallery: แกลเลอรีรูปพร้อม thumbnail

สินค้าแต่ละตัวมีรูปหลายรูป (field images: string[] ใน type Product) แกลเลอรีของเราแสดงรูปใหญ่หนึ่งรูป และแถว thumbnail ด้านล่างให้คลิกสลับ แนวคิดหลักของคอมโพเนนต์นี้:

  • state สองตัวทำงานคู่กัน — selectedImage จำว่ารูปไหนถูกเลือก (เริ่มจาก defaultImage หรือรูปแรก) และ isImageLoaded คุม skeleton แบบเดียวกับ ProductCard ในบทเรียน 18 จุดที่ต้องอ่านช้า ๆ คือ handleImageClick: มัน setIsImageLoaded(false) ก่อนเปลี่ยนรูปเสมอ เพราะรูปใหม่ยังไม่เคยโหลด ถ้าลืมบรรทัดนี้ ผู้ใช้จะเห็นรูปเก่าค้างอยู่ (state ยัง true) ทั้งที่ src เปลี่ยนไปแล้ว จนกว่ารูปใหม่จะโหลดเสร็จ — แทนที่จะเห็น skeleton ที่สื่อว่ากำลังโหลดอยู่ พอรูปใหม่มาถึง onLoad ยิงและทุกอย่างกลับเข้าที่
  • ไฮไลต์ thumbnail ที่เลือก — เทียบ selectedImage === image แล้วเติมคลาส styles.active ซึ่งใน SCSS เขียนเป็น &.active (ตัวเดียวกับที่มีทั้ง .thumbnail และ .active) ให้กรอบดำ ส่วน &:hover ให้กรอบเทาตอนชี้
  • key={index} ยอมรับได้ที่นี่ — ต่างจากรายการสินค้าที่สลับชุดได้ตลอด รายการรูปของสินค้าหนึ่งตัวนิ่งตลอดอายุของหน้า ไม่มีการเพิ่ม ลบ หรือสลับลำดับ index จึงเสถียรพอ (และรูปก็ไม่มี id ให้ใช้อยู่แล้ว)

ProductDetailInfo: ข้อมูลฝั่งขวาและปุ่ม Add to Cart

ฝั่งขวาของหน้าคือบล็อกข้อมูล: ชื่อ แบรนด์ ดาว ราคา ส่วนลด คำอธิบาย ปุ่ม และรายละเอียดสต็อก/การจัดส่ง ทั้งหมดเป็นการแสดงผลล้วน ๆ props เยอะแต่ไม่มีตัวไหนซับซ้อน — ทุกตัวเป็นค่าพร้อมแสดงที่หน้าเพจเตรียมมาให้ (รวมถึง originalPrice ที่ผ่าน calculateOriginalPrice มาแล้ว)

จุดเดียวที่เป็น "พฤติกรรม" คือ onButtonClick: () => void — callback prop แบบเดียวกับ onProductClick ของ ProductCard: คอมโพเนนต์นี้ไม่รู้และไม่ควรรู้ว่ากดปุ่มแล้วเกิดอะไร มันแค่รายงานว่า "ปุ่มถูกกดแล้วนะ" การออกแบบแบบนี้กำลังจะพิสูจน์คุณค่าในอีกสองบท: ตอนตะกร้ามาถึงในบทเรียน 23 เราจะเปลี่ยนพฤติกรรมปุ่มได้โดยไม่ต้องแตะไฟล์นี้เลยแม้แต่บรรทัดเดียว ส่วนตัวปุ่มเองคือ Button จากบทเรียน 12 พร้อมไอคอน faCartPlus

RatingBreakdown: กราฟแท่งสรุปคะแนน

ต่อไปคือกราฟแบบที่เห็นในเว็บรีวิวทุกเจ้า: แถบ 5★ ถึง 1★ พร้อมแท่งบอกสัดส่วนว่าคะแนนไหนมีกี่รีวิว มาแกะคณิตศาสตร์ของแท่งกัน เพราะนี่คือหัวใจของคอมโพเนนต์ และเป็นจุดที่ต้องตรวจหนักที่สุดของบท:

  • Array(5).fill(0).map(…) — ท่าสร้าง array 5 ช่องเพื่อวนลูป 5 รอบ (ต้อง .fill(0) ก่อนเพราะ Array(5) เปล่า ๆ ให้ array โหว่ที่ .map ข้ามไม่ยอมวน) ในแต่ละรอบ stars = 5 - index ทำให้ไล่จาก 5★ ลงไป 1★ ตามลำดับที่เว็บรีวิวนิยมแสดง
  • Math.round(review.rating / 2) === stars — convention เดิมของแอปเรา: คะแนนดิบเป็นสเกลเต็ม 10 การหารสองแล้วปัดเศษแปลงเป็นสเกลดาว 1–5 แบบเดียวกับที่ StarReview ทำเป๊ะ (บทเรียน 14) — สองคอมโพเนนต์นี้ต้องใช้สูตรเดียวกัน ไม่งั้นดาวที่การ์ดกับกราฟจะเล่าคนละเรื่อง จากนั้น filter(…).length นับจำนวนรีวิวที่ตกอยู่ในดาวระดับนั้น (บรรทัดนี้คือบรรทัดที่กล่อง 💡 ท้ายบทจะกลับมาคุยด้วย — อ่านต่อไปก่อน)
  • percentage — สัดส่วนของระดับนั้นเทียบรีวิวทั้งหมด ถูกส่งเข้า inline style width: `${percentage}%` ของ .fill — แท่งนอก (.bar) กว้างเต็มพื้นที่ด้วย flex-grow: 1 ส่วนแท่งใน (.fill) กว้างตามเปอร์เซ็นต์ นี่คือกราฟแท่งที่สร้างจาก div สองชั้นล้วน ๆ ไม่ต้องพึ่ง chart library เลย สังเกต guard totalReviews ? … : 0 กันหารด้วยศูนย์เมื่อไม่มีรีวิว
  • สีตามอารมณ์คะแนน — getBarStyleClass จับคู่ 4–5★ เป็นเขียว, 3★ ส้ม, 1–2★ แดง เป็น mapping ฝั่งการแสดงผลเฉย ๆ แยกอยู่ใน helper function ให้อ่านง่าย
  • reviews: { rating: number }[] — type ของ prop ขอแค่ field rating เท่านั้น ไม่ใช่ ProductReview[] เต็ม ๆ เพราะ structural typing ของ TypeScript ยอมให้ส่ง ProductReview[] เข้ามาได้อยู่แล้ว (มี field ครบเกินขอ) — การประกาศขอเท่าที่ใช้ทำให้คอมโพเนนต์ผูกกับ type ของ feature น้อยลง และเป็น type ที่บอกด้วยว่าจำนวนแท่งต้องมาจาก array ของรีวิว ไม่ใช่จากคะแนนเฉลี่ยตัวเดียว

ReviewCard และ ReviewSection

ไฮไลต์ของการ์ดรีวิวคือบรรทัด dayjs(date).format("DD MMMM YYYY") — รับ ISO string มาแปลงเป็น 30 April 2025 โดย pattern ในเครื่องหมายคำพูดอ่านตรงตัว: DD วันที่สองหลัก, MMMM ชื่อเดือนเต็ม, YYYY ปีสี่หลัก ส่วน avatar ใช้ทริคยอดนิยม: ไม่มีรูปโปรไฟล์ก็แสดงอักษรตัวแรกของชื่อ (name[0]) ในกล่องสี่เหลี่ยมแทน

ส่วน ReviewSection คือ section รีวิวที่แบ่งครึ่ง — ซ้ายเป็นสรุปคะแนนรวม + RatingBreakdown, ขวาเป็นรายการ ReviewCard ตัวนี้เป็นของหน้า Product โดยเฉพาะจึงอยู่ใต้โฟลเดอร์ของหน้า ไม่มีลอจิกใหม่ — เป็นคอมโพเนนต์ประกอบร่างล้วน ๆ ที่ map field ของ ProductReview (reviewerName, comment, …) เข้า props ของ ReviewCard (name, review, …) เหมือนที่ ProductsList ทำให้ ProductCard ในบทเรียน 18 และ key={index} ก็ยอมรับได้ด้วยเหตุผลเดียวกับ thumbnail: รายการรีวิวของสินค้าหนึ่งตัวนิ่ง ไม่มีเพิ่ม/ลบ/สลับ (และ dummyjson ไม่ได้ให้ id ของรีวิวมา)

Product.tsx: early return แบบทั้งหน้า

สุดท้ายคือไฟล์หน้าเพจ ซึ่งมีจุดที่ต่างจากสองหน้าก่อนหน้าอย่างชัดเจน: หน้า Home กับ Category ใช้ error/loading แบบ inline รายส่วน เพราะหน้าเหล่านั้นมีหลาย section ที่เป็นอิสระต่อกัน แต่หน้านี้ทุกอย่างมาจาก query ก้อนเดียว จึง return ทั้งหน้าเป็น spinner หรือ ErrorMessage ไปเลยได้

สังเกตเงื่อนไข isError || !productDetail — เช็ค !productDetail ควบไปด้วยเพื่อให้ TypeScript รู้ว่าโค้ดหลังจากบรรทัดนี้ productDetail เป็น Product แน่นอน จึง destructure ได้โดยไม่ต้องใส่ ? อีก — เป็นท่า narrowing ที่ทำงานสองหน้าที่พร้อมกัน: กันเคสจริง (query สำเร็จแต่ไม่มีข้อมูล) และปลดล็อก type ให้โค้ดที่เหลือทั้งไฟล์

ส่วน useParams<{ id: string }>() ดึงค่า :id จาก URL ที่ router จับคู่ route /products/:id ไว้ตั้งแต่บทเรียน 09 generic บอก TypeScript ว่า params มี key อะไรบ้าง แต่ค่าที่ได้ยังเป็น string | undefined เสมอ (ผู้ใช้อาจพิมพ์ URL แปลก ๆ มาเองได้) เราเลยกันสองชั้น: id ?? "" ให้ queryKey ไม่พัง และ enabled: !!id ไม่ยิง API เลยถ้าไม่มี id — และนี่คือจานสุดท้ายของ factory จากบทเรียน 17 ที่ได้ออกใช้งานจริง พร้อมกับ String(id) ที่คุณพิมพ์เองในบทนั้นทำงานเงียบ ๆ อยู่เบื้องหลัง

import React, { useState } from "react";
import Skeleton from "react-loading-skeleton";
import styles from "./ProductImageGallery.module.scss";

interface ProductImageGalleryProps {
  images: string[];
  defaultImage?: string;
}

const ProductImageGallery: React.FC<ProductImageGalleryProps> = ({
  images,
  defaultImage,
}) => {
  const [selectedImage, setSelectedImage] = useState<string>(
    defaultImage || images[0],
  );
  const [isImageLoaded, setIsImageLoaded] = useState(false);

  const handleImageClick = (image: string) => {
    setIsImageLoaded(false);
    setSelectedImage(image);
  };

  return (
    <div className={styles.productImageGallery}>
      {/* Large Displayed Image */}
      <div className="width-full text-center">
        {!isImageLoaded && (
          <div className="mb-30">
            <Skeleton height={400} />
          </div>
        )}
        <img
          src={selectedImage}
          alt="Selected image"
          style={{
            display: isImageLoaded ? "inline-block" : "none",
          }}
          onLoad={() => setIsImageLoaded(true)}
        />
      </div>

      {/* Image Thumbnails */}
      <div className={styles.thumbnailList}>
        {images.map((image, index) => (
          <div
            key={index}
            className={`${styles.thumbnail} ${
              selectedImage === image ? styles.active : ""
            }`}
            onClick={() => handleImageClick(image)}
          >
            <img src={image} alt={`Thumbnail ${index + 1}`} />
          </div>
        ))}
      </div>
    </div>
  );
};

export default ProductImageGallery;

        (review) => Math.round(review.rating / 2) === stars,
      ).length;

      const percentage = totalReviews ? (count / totalReviews) * 100 : 0;
      return { stars, count, percentage };
    });

  // Helper function to determine bar style class based on stars
  const getBarStyleClass = (stars: number) => {
    switch (stars) {
      case 5:
      case 4:
        return styles.greenBar; // Class for green
      case 3:
        return styles.orangeBar; // Class for orange
      case 2:
      case 1:
        return styles.redBar; // Class for red
      default:
        return styles.defaultBar; // Default class
    }
  };

  return (
    <div>
      {ratingCounts.map(({ stars, count, percentage }) => (
        <div key={stars} className="flex align-item-center gap-15 mb-10">
          <div className="fw-bold flex align-item-center gap-5">
            <span>{stars}</span>
            <FontAwesomeIcon icon={faStar} className={styles.starIcon} />
          </div>
          <div className={styles.bar}>
            <div
              className={`${styles.fill} ${getBarStyleClass(stars)}`}
              style={{ width: `${percentage}%` }}
            />
          </div>
          <div className="text-muted">{count}</div>
        </div>
      ))}
    </div>
  );
};

export default RatingBreakdown;
