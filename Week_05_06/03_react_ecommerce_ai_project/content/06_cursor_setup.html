บทเรียน 06 · ตั้งวงกับ Cursor (Setting Up Cursor)

ติดตั้งและรู้จัก Cursor

Cursor Setup

สี่บทที่ผ่านมาคุณพิมพ์เองทุกบรรทัดเพื่อให้มีของให้ AI อ้างอิง และตอนนี้ของนั้นครบแล้ว: โปรเจกต์ที่รันได้ เครื่องมือคุณภาพที่ทำงานอยู่ ผัง SCSS และโครงสร้างโฟลเดอร์ที่ตกลงกันไว้ บทนี้เราจะติดตั้งเครื่องมือที่จะพิมพ์โค้ดให้เราตลอด 27 บทที่เหลือ และที่สำคัญกว่าการติดตั้ง คือทำความเข้าใจว่ามันมีกี่โหมด แต่ละโหมดแตะไฟล์ของเราได้แค่ไหน และถ้ามันทำพัง เราถอยกลับอย่างไร

บทนี้ไม่มีโค้ดของแอปเลยสักบรรทัด — เป็นการตั้งวงล้วน ๆ ถ้าคุณไม่เคยเปิด Cursor มาก่อนก็ไม่มีปัญหา เราเริ่มจากศูนย์

Cursor คืออะไร และต่างจาก VS Code ตรงไหน

Cursor คือ code editor ที่สร้างต่อยอดจาก VS Code โดยตรง หน้าตา แถบเมนู keyboard shortcut และ extension ส่วนใหญ่จึงเหมือนเดิมทั้งหมด สิ่งที่เพิ่มเข้ามาคือชั้น AI ที่ฝังอยู่ใน editor แทนที่จะเป็นเว็บแชทแยกอีกหน้าต่างหนึ่ง

ความต่างที่สำคัญจริง ๆ ไม่ใช่ "มี AI ในตัว" แต่คือ AI ตัวนี้เห็นทั้งโปรเจกต์ ไม่ใช่แค่ข้อความที่เราพิมพ์ให้มัน ลองเทียบสองสถานการณ์กับโปรเจกต์ที่เราเพิ่งสร้างเสร็จ:

  • แชทในเบราว์เซอร์ — คุณสั่งว่า "สร้าง component ProductCard" มันไม่รู้ว่าโปรเจกต์คุณมี alias @/, ไม่รู้ว่าคุณใช้ SCSS Modules ไม่ใช่ Tailwind, ไม่รู้ว่า component ต้องไปอยู่ใน features/products/components/ คุณต้องพิมพ์ทุกอย่างนี้ลงไปเองทุกครั้ง แล้วเอาผลลัพธ์ไปวางในไฟล์เอง
  • Cursor — มันเปิดอ่านไฟล์ในโปรเจกต์ได้ อ้างอิงไฟล์ที่มีอยู่จริงได้ สร้างไฟล์ใหม่ในตำแหน่งที่ถูกต้องได้ และรับกติกาประจำโปรเจกต์ที่เราเขียนไว้ล่วงหน้า (บทเรียน 07) มาใช้ทุกคำสั่งโดยไม่ต้องพิมพ์ซ้ำ

เครื่องมือประเภทนี้มีมากกว่าหนึ่งตัว คอร์สนี้เลือก Cursor เพราะสามอย่างที่เราจะใช้หนักตลอดคอร์ส — การอ้างไฟล์ด้วย @, ไฟล์กติกาประจำโปรเจกต์ และโหมด Agent ที่แก้หลายไฟล์ในคำสั่งเดียว — อยู่ครบในตัวเดียวและตั้งค่าง่าย ถ้าคุณใช้เครื่องมืออื่นที่มีสามอย่างนี้ แนวคิดทั้งหมดในบทเรียน 07–08 ย้ายไปใช้ได้ตรง ๆ เปลี่ยนแค่ชื่อเมนู

ติดตั้งและเปิดโปรเจกต์

สี่ขั้น ใช้เวลาไม่เกินสิบนาที:

  1. ดาวน์โหลด — ไปที่ cursor.com กดปุ่มดาวน์โหลด เว็บจะเลือกไฟล์ให้ตรงกับระบบปฏิบัติการของคุณเอง (macOS / Windows / Linux) ติดตั้งเหมือนโปรแกรมทั่วไป
  2. เปิดครั้งแรกแล้ว import ของเดิม — หน้าจอต้อนรับจะถามว่าจะดึง settings, keybindings และ extensions จาก VS Code มาด้วยไหม ตอบว่าเอา — extension ESLint กับ Prettier ที่เราตั้งไว้ในบทเรียน 03 จะย้ายตามมาให้ครบ ไม่ต้องติดตั้งใหม่ และ Format On Save จะทำงานเหมือนเดิม
  3. Sign in — ต้องมีบัญชี (สมัครด้วย GitHub หรืออีเมลได้) บัญชีฟรีมีโควตาการเรียกใช้ AI ต่อเดือนจำกัด ซึ่งพอสำหรับคอร์สนี้ถ้าไม่ยิง prompt ทิ้งขว้าง — อีกเหตุผลหนึ่งที่เราจะฝึกเขียน prompt ให้ได้ของตั้งแต่ครั้งแรก
  4. เปิดโปรเจกต์ — File → Open Folder แล้วเลือกโฟลเดอร์ react-ecommerce-app ที่สร้างไว้ตั้งแต่บทเรียน 02

ข้อสี่มีรายละเอียดที่คนพลาดกันบ่อย: ต้องเปิดโฟลเดอร์รากของโปรเจกต์ ไม่ใช่ดับเบิลคลิกเปิดไฟล์ .tsx เดี่ยว ๆ Cursor สร้างดัชนีของโค้ดจากโฟลเดอร์ที่เปิดอยู่ ถ้าคุณเปิดผิดชั้น (เช่นเปิด src/ อย่างเดียว) มันจะมองไม่เห็น package.json, vite.config.ts, tsconfig.app.json และไฟล์กติกาที่เราจะสร้างในบทหน้า — แล้วผลลัพธ์จะเริ่มเพี้ยนโดยที่คุณหาสาเหตุไม่เจอ

เช็กว่าทุกอย่างยังปกติ: เปิด terminal ใน Cursor (Terminal → New Terminal) แล้วรัน npm run dev ต้องได้หน้าเว็บเดิมกับที่เห็นตอนจบบทเรียน 04 และ npm run lint ต้องยังผ่าน — Cursor ไม่ได้เปลี่ยนอะไรในโปรเจกต์ มันแค่เป็น editor อีกตัวที่เปิดโฟลเดอร์เดียวกัน

สามโหมดที่ต้องแยกให้ออก

ความสับสนที่เจอบ่อยของคนเพิ่งเริ่มใช้คือแยกไม่ออกว่าตอนนี้กำลังคุยกับโหมดไหน ซึ่งเป็นเรื่องใหญ่ เพราะมีโหมดเดียวเท่านั้นที่แก้ไฟล์ให้จริง:

โหมดใช้ตอนไหนแก้ไฟล์ให้เลยไหม
Tabเติมโค้ดที่กำลังพิมพ์อยู่ไม่ — คุณกด Tab เอง
Askถามเพื่อทำความเข้าใจโค้ดไม่
Agentสั่งให้สร้าง/แก้หลายไฟล์ใช่

รายละเอียดที่ต้องรู้ของแต่ละตัว:

  • Tab ทำงานอยู่ตลอดเวลาระหว่างที่คุณพิมพ์ในไฟล์ มันเดาส่วนที่เหลือของบรรทัด (หรือหลายบรรทัด) แล้วขึ้นเป็นตัวอักษรจาง ๆ กด Tab เพื่อรับ กด Esc เพื่อปฏิเสธ มันไม่ถามอะไรและไม่รอคำสั่ง — คุณเป็นคนกดรับทุกครั้ง
  • Ask กับ Agent อยู่ในแผงแชทเดียวกัน (เปิดด้วย Cmd+I บน macOS หรือ Ctrl+I บน Windows/Linux) และสลับกันด้วย dropdown เล็ก ๆ ที่มุมล่างของช่องพิมพ์ ดู dropdown นั้นก่อนกดส่งทุกครั้ง — คำสั่งที่ตั้งใจให้ Agent ทำ แต่ส่งไปตอนอยู่โหมด Ask จะได้คำตอบยาวเหยียดที่อธิบายว่า "ควรทำแบบนี้" โดยไม่มีไฟล์ไหนเปลี่ยนเลย ส่วนคำถามที่ตั้งใจแค่ถาม แต่ส่งไปตอนอยู่โหมด Agent อาจได้ diff กลับมาโดยไม่ตั้งใจ

พูดให้ชัด: Agent เป็นโหมดหลักของคอร์สนี้ — ทุกกล่อง 🤖 ในบทสร้างฟีเจอร์คือ prompt ที่ส่งเข้าโหมด Agent แต่ Ask คือโหมดที่ทำให้คุณ "อธิบายให้ได้" ตามกติกาข้อเดียวของคอร์ส เวลาที่โค้ดกลับมาแล้วมีบรรทัดที่คุณอ่านไม่ออก คุณไม่ควรสั่ง Agent ให้แก้มัน คุณควรเปิด Ask แล้วถามจนเข้าใจก่อน สองโหมดนี้จึงไม่ได้แข่งกัน มันเป็นคนละครึ่งของงานเดียวกัน

เลือก model อย่างไร

เหนือช่องพิมพ์มี dropdown เลือก model ให้อีกตัวหนึ่ง หลักการง่าย ๆ: model ที่ฉลาดกว่าใช้เวลาคิดนานกว่าและกินโควตามากกว่าอย่างมีนัยสำคัญ ส่วนงานเกือบทั้งหมดในคอร์สนี้เป็นงานทำตามแบบที่เราวางไว้แล้ว — โครงสร้างเราตัดสินใจไว้ในบทเรียน 05 กติกาเราเขียนไว้ในบทเรียน 07 และ prompt ทุกอันบอกชื่อไฟล์ที่ต้องการไว้ครบ งานลักษณะนี้ model มาตรฐานที่ Cursor ตั้งมาให้ก็พอ ถ้าเจอบทที่ผลลัพธ์ออกมาไม่เข้าที่สองสามรอบติด ค่อยสลับไป model ที่แรงกว่าเฉพาะบทนั้น ไม่ต้องเปิดค้างไว้ทั้งคอร์ส

ให้บริบทด้วย @

พิมพ์ @ ในช่องแชท แล้วรายการให้เลือกจะเด้งขึ้นมา สามแบบที่เราจะใช้จริง:

  • @ ตามด้วยชื่อไฟล์ — แนบไฟล์เดียว เช่น @vite.config.ts ใช้บ่อยที่สุด
  • @ ตามด้วยชื่อโฟลเดอร์ — แนบทั้งโฟลเดอร์ เช่น @src/features/products เหมาะกับตอนสั่งงานที่ต้องรู้จักไฟล์หลายไฟล์ในฟีเจอร์เดียวกัน
  • @Codebase — ให้มันค้นทั้งโปรเจกต์เอง ใช้ตอนที่คุณเองยังไม่รู้ว่าไฟล์ที่เกี่ยวข้องอยู่ตรงไหน เช่น "ตอนนี้มีที่ไหนบ้างที่คำนวณราคาหลังส่วนลด" ข้อแลกเปลี่ยนคือมันเดาเอาว่าไฟล์ไหนเกี่ยว ซึ่งเดาพลาดได้ ถ้าคุณรู้ชื่อไฟล์อยู่แล้ว ระบุตรง ๆ แม่นกว่าเสมอ

คำถามที่ตามมาคือ ทำไมต้อง @ ในเมื่อ copy โค้ดไปวางในแชทก็ได้เหมือนกัน สมมติว่าอีกสิบบทข้างหน้าคุณมีไฟล์ src/features/products/api.ts อยู่แล้ว และอยากให้ Cursor เพิ่มฟังก์ชันดึงสินค้าตามหมวดหมู่ลงไป การพิมพ์ @src/features/products/api.ts ชนะการวางโค้ดด้วยเหตุผลสามข้อ:

  • มันอ่านของจริง ไม่ใช่สำเนา — ถ้าคุณแก้ไฟล์นั้นเมื่อสองนาทีที่แล้ว @ เห็นเวอร์ชันล่าสุดเสมอ ส่วนโค้ดที่วางไว้ในแชทคือภาพนิ่งของนาทีที่คุณ copy มา
  • มันรู้ path — Agent ที่รู้ว่าไฟล์นี้อยู่ที่ src/features/products/api.ts จะแก้ไฟล์นั้นให้ตรงจุด ส่วน Agent ที่ได้แต่เนื้อโค้ดลอย ๆ ต้องเดาว่าจะเอาไปวางที่ไหน — และมันเดาผิดได้ เช่นสร้างไฟล์ใหม่ทับซ้อนขึ้นมาอีกตัว
  • มันตามต่อเองได้ — จาก api.ts มันเปิดดู types.ts ที่ถูก import เข้ามาต่อได้เอง สิ่งที่คุณ copy ไปวางมีแค่เท่าที่คุณเลือกมา

Checkpoint และการย้อนกลับ

Agent เก็บ checkpoint ให้อัตโนมัติทุกครั้งที่มันลงมือแก้โค้ด ในแผงแชทจะมีปุ่มย้อนกลับ (restore) ที่พาโปรเจกต์กลับไปสู่สภาพก่อนคำสั่งนั้น ใช้ได้และสะดวก แต่มันมีข้อจำกัดที่ต้องรู้: มันผูกกับ session ของแชท ถ้าคุณปิดโปรแกรม เปิดแชทใหม่ หรือแก้ไฟล์เองสลับไปมาระหว่างนั้น สิ่งที่ปุ่มนั้นจะย้อนให้ ก็เริ่มไม่ตรงกับที่คุณคิดไว้

เพราะแบบนี้ คอร์สนี้จึงไม่ฝากชีวิตไว้กับปุ่มของ editor แต่ใช้เครื่องมือที่คุณควบคุมได้เต็มร้อยแทน:

🚨 commit ก่อน prompt ทุกครั้ง — ก่อนกดส่งคำสั่งให้ Agent ให้ git add -A && git commit ให้ working tree สะอาดก่อนเสมอ พอ Agent ทำงานเสร็จ git diff จะแสดงสิ่งที่ AI เปลี่ยนทั้งหมดอย่างชัดเจน และถ้าผลลัพธ์ไม่เอาไหน git restore . คือปุ่ม undo ที่เชื่อถือได้กว่าปุ่มไหน ๆ ใน editor

กติกานี้ให้ผลพลอยได้ที่สำคัญกว่าการกู้คืนเสียอีก: เมื่อ working tree สะอาดก่อนส่งคำสั่ง สิ่งที่ git diff แสดงหลังจากนั้นคือผลงานของ AI ล้วน ๆ ไม่มีการแก้ของคุณเองปนอยู่ นั่นทำให้ขั้นตอนตรวจงานในบทเรียน 08 ทำได้จริง — คุณกำลังอ่านสิ่งที่มันทำ ไม่ใช่พยายามแยกแยะว่าบรรทัดไหนใครเขียน

ทำให้เป็นนิสัยตั้งแต่วันนี้ สองคำสั่งนี้จะวนซ้ำอีกหลายสิบรอบตลอดคอร์ส:

git status          # ต้องเห็น "nothing to commit, working tree clean"
# ...ส่ง prompt ให้ Agent...
git diff            # อ่านทุกบรรทัดที่ AI เปลี่ยน

แบบฝึกสั้น ๆ: ใช้ Ask เป็นเครื่องมืออ่านโค้ด

ก่อนจบบท ลองใช้ Ask กับของจริงหนึ่งรอบ เลือกโจทย์ที่คุณรู้คำตอบอยู่แล้ว เพราะนี่ไม่ใช่การหาความรู้ใหม่ แต่เป็นการดูว่าเครื่องมือนี้ตอบได้แม่นแค่ไหน

  1. เปิดแผงแชท แล้วสลับ dropdown เป็น Ask (ย้ำอีกครั้ง: ดูให้แน่ใจว่าไม่ใช่ Agent)
  2. พิมพ์คำสั่งนี้ แล้วกดส่ง:
@vite.config.ts @tsconfig.app.json
อธิบายว่า alias @/ ในโปรเจกต์นี้ทำงานอย่างไร ทำไมต้องตั้งค่าสองที่
และถ้าตั้งแค่ที่เดียวจะเกิดอะไรขึ้น
  1. อ่านคำตอบ แล้วเทียบกับบทเรียน 03 ทีละข้อ: มันบอกถูกไหมว่า Vite ใช้ตอน bundle และ TypeScript ใช้ตอนตรวจ type กับตอน autocomplete มันอ้างค่าที่อยู่ในไฟล์คุณจริง ๆ หรืออ้างค่าที่ "โปรเจกต์ทั่วไปมักตั้ง"
  2. เช็ก git status — ต้องยังสะอาดอยู่ ไม่มีไฟล์ไหนเปลี่ยน นั่นคือหลักฐานว่า Ask ไม่แตะโค้ดจริง ๆ

ประเด็นของแบบฝึกนี้ไม่ใช่ "AI ตอบถูกไหม" แต่คือการติดตั้งนิสัยว่า Ask เป็นเครื่องมืออ่าน ไม่ใช่เครื่องมือเขียน ตลอดคอร์สนี้ ทุกครั้งที่คุณเจอบรรทัดที่อธิบายไม่ได้ ทางแก้คือเปิด Ask ถามไฟล์นั้นตรง ๆ แล้วกลับไปยืนยันกับโค้ดจริงว่าคำตอบตรงกัน ไม่ใช่กด Accept แล้วเดินหน้าต่อ (พอถึงบทเรียน 09 คุณจะมี src/app/router.tsx ของจริงแล้ว ลองทำแบบเดิมกับไฟล์นั้นอีกรอบ — คราวนั้นคำตอบที่คุณใช้เทียบคือเนื้อหาของบทเรียน 09 เอง)

ตอนนี้ Cursor พร้อมใช้แล้ว แต่มันยังไม่รู้อะไรเกี่ยวกับกติกาของโปรเจกต์เราเลย — มันไม่รู้ว่าเราใช้ SCSS Modules ไม่รู้ว่า component ควรไปอยู่ชั้นไหน และไม่รู้ว่าเราห้าม any ถ้าสั่งงานตอนนี้ คุณจะต้องพิมพ์เรื่องพวกนี้ซ้ำในทุก prompt บทหน้าเราจะเขียนมันลงไฟล์ครั้งเดียวให้จบ

💡 Checkpoint: เปิดโปรเจกต์ react-ecommerce-app อยู่ใน Cursor และรัน npm run dev จาก terminal ของ Cursor ได้ผลเหมือนเดิม, แผงแชทเปิดได้ด้วย Cmd+I และคุณชี้ได้ว่า dropdown สลับ Ask/Agent อยู่ตรงไหน, ทำแบบฝึก Ask ข้างบนแล้วอย่างน้อยหนึ่งรอบโดยที่ git status ยังสะอาด และตอบได้ว่าทำไมต้อง commit ก่อนส่ง prompt ทุกครั้ง ถ้าตอบข้อสุดท้ายไม่ได้ ให้ย้อนกลับไปอ่านหัวข้อ Checkpoint และการย้อนกลับอีกรอบก่อนไปต่อ
