หน้า Product Detail: รายละเอียดสินค้าครบทุกมุม

Product Detail Page

หน้าสุดท้ายของ chapter นี้คือหน้าที่ผู้ใช้ตัดสินใจซื้อ: หน้า Product detail ที่เปิดจากการคลิกการ์ดสินค้าใน Home หรือ Category (path /products/:id) หน้านี้มีของให้ดูเยอะที่สุดในแอป — แกลเลอรีรูปพร้อม thumbnail ที่คลิกสลับได้, ข้อมูลราคา/ส่วนลด/สต็อก, ปุ่ม Add to Cart, กราฟแท่งสรุปคะแนนรีวิว และรายการรีวิวจากผู้ซื้อ เราจะสร้างมันจากคอมโพเนนต์ย่อย 5 ตัวแล้วประกอบร่างในไฟล์หน้าเพจตอนท้าย

ข้อสังเกตหนึ่งก่อนเริ่ม: ปุ่ม Add to Cart ในบทนี้จะยังกดแล้วไม่เกิดอะไรขึ้น — ตะกร้าสินค้ายังไม่มีอยู่ในแอปเลย (นั่นคือ chapter ถัดไปทั้ง chapter) เราจะสร้างหน้านี้เป็นเวอร์ชันแรกที่จบในตัว แล้วกลับมาต่อสายปุ่มนี้เข้ากับตะกร้าจริงในบทเรียน 20 เดี๋ยวถึงตรงนั้นจะบอกชัด ๆ อีกทีว่าต้องแก้บรรทัดไหนบ้าง

ติดตั้ง dayjs

รีวิวจาก dummyjson มีวันที่ติดมาเป็น ISO string เช่น 2025-04-30T09:41:02.053Z — เอาไปแสดงตรง ๆ ไม่ได้แน่ ๆ เราอยากได้รูปแบบอ่านง่ายอย่าง 30 April 2025 การ format วันที่ด้วย Date ดิบ ๆ ของ JavaScript ทำได้แต่เขียนยาวและพลาดง่าย เราจึงใช้ dayjs — library จัดการวันที่ตัวจิ๋ว (~2KB) ที่ API เหมือน Moment.js แต่เบากว่ามาก และเป็นตัวที่เจอบ่อยที่สุดตัวหนึ่งในโปรเจกต์ React ปัจจุบัน:

npm i dayjs

เราจะได้ใช้มันครั้งแรกใน ReviewCard ด้านล่าง — เรียก dayjs(isoString).format("DD MMMM YYYY") จบในบรรทัดเดียว

ProductImageGallery: แกลเลอรีรูปพร้อม thumbnail

สินค้าแต่ละตัวมีรูปหลายรูป (field images: string[] ใน type Product) แกลเลอรีของเราแสดงรูปใหญ่หนึ่งรูป และแถว thumbnail ด้านล่างให้คลิกสลับ สร้างไฟล์ src/features/products/components/ProductImageGallery/ProductImageGallery.tsx:

import React, { useState } from "react";
import Skeleton from "react-loading-skeleton";
import styles from "./ProductImageGallery.module.scss";

interface ProductImageGalleryProps {
  images: string[];
  defaultImage?: string;
}

const ProductImageGallery: React.FC<ProductImageGalleryProps> = ({
  images,
  defaultImage,
}) => {
  const [selectedImage, setSelectedImage] = useState<string>(
    defaultImage || images[0],
  );
  const [isImageLoaded, setIsImageLoaded] = useState(false);

  const handleImageClick = (image: string) => {
    setIsImageLoaded(false);
    setSelectedImage(image);
  };

  return (
    <div className={styles.productImageGallery}>
      {/* Large Displayed Image */}
      <div className="width-full text-center">
        {!isImageLoaded && (
          <div className="mb-30">
            <Skeleton height={400} />
          </div>
        )}
        <img
          src={selectedImage}
          alt="Selected image"
          style={{
            display: isImageLoaded ? "inline-block" : "none",
          }}
          onLoad={() => setIsImageLoaded(true)}
        />
      </div>

      {/* Image Thumbnails */}
      <div className={styles.thumbnailList}>
        {images.map((image, index) => (
          <div
            key={index}
            className={`${styles.thumbnail} ${
              selectedImage === image ? styles.active : ""
            }`}
            onClick={() => handleImageClick(image)}
          >
            <img src={image} alt={`Thumbnail ${index + 1}`} />
          </div>
        ))}
      </div>
    </div>
  );
};

export default ProductImageGallery;

แนวคิดหลักของคอมโพเนนต์นี้:

  • state สองตัวทำงานคู่กัน — selectedImage จำว่ารูปไหนถูกเลือก (เริ่มจาก defaultImage หรือรูปแรก) และ isImageLoaded คุม skeleton แบบเดียวกับ ProductCard ในบทเรียน 15 จุดที่ต้องอ่านช้า ๆ คือ handleImageClick: มัน setIsImageLoaded(false) ก่อนเปลี่ยนรูปเสมอ เพราะรูปใหม่ยังไม่เคยโหลด ถ้าลืมบรรทัดนี้ ผู้ใช้จะเห็นรูปเก่าค้างอยู่ (state ยัง true) ทั้งที่ src เปลี่ยนไปแล้ว จนกว่ารูปใหม่จะโหลดเสร็จ — แทนที่จะเห็น skeleton ที่สื่อว่ากำลังโหลดอยู่ พอรูปใหม่มาถึง onLoad ยิงและทุกอย่างกลับเข้าที่
  • ไฮไลต์ thumbnail ที่เลือก — เทียบ selectedImage === image แล้วเติมคลาส styles.active ซึ่งใน SCSS เขียนเป็น &.active (ตัวเดียวกับที่มีทั้ง .thumbnail และ .active) ให้กรอบดำ ส่วน &:hover ให้กรอบเทาตอนชี้
  • key={index} ยอมรับได้ที่นี่ — ต่างจากรายการสินค้าที่สลับชุดได้ตลอด รายการรูปของสินค้าหนึ่งตัวนิ่งตลอดอายุของหน้า ไม่มีการเพิ่ม ลบ หรือสลับลำดับ index จึงเสถียรพอ (และรูปก็ไม่มี id ให้ใช้อยู่แล้ว)

RatingBreakdown: กราฟแท่งสรุปคะแนน

ต่อไปคือกราฟแบบที่เห็นในเว็บรีวิวทุกเจ้า: แถบ 5★ ถึง 1★ พร้อมแท่งบอกสัดส่วนว่าคะแนนไหนมีกี่รีวิว สร้างไฟล์ src/features/products/components/RatingBreakdown/RatingBreakdown.tsx:

import React from "react";
import { FontAwesomeIcon } from "@fortawesome/react-fontawesome";
import { faStar } from "@fortawesome/free-solid-svg-icons";
import styles from "./RatingBreakdown.module.scss";

interface RatingBreakdownProps {
  reviews: { rating: number }[]; // Only need the `rating` property
}

const RatingBreakdown: React.FC<RatingBreakdownProps> = ({ reviews }) => {
  const totalReviews = reviews.length;

  // Compute counts for each rating (1-5 stars)
  const ratingCounts = Array(5)
    .fill(0)
    .map((_, index) => {
      const stars = 5 - index; // Descending from 5 to 1
      const count = reviews.filter(
        (review) => Math.round(review.rating / 2) === stars,
      ).length;

      const percentage = totalReviews ? (count / totalReviews) * 100 : 0;
      return { stars, count, percentage };
    });

  // Helper function to determine bar style class based on stars
  const getBarStyleClass = (stars: number) => {
    switch (stars) {
      case 5:
      case 4:
        return styles.greenBar; // Class for green
      case 3:
        return styles.orangeBar; // Class for orange
      case 2:
      case 1:
        return styles.redBar; // Class for red
      default:
        return styles.defaultBar; // Default class
    }
  };

  return (
    <div>
      {ratingCounts.map(({ stars, count, percentage }) => (
        <div key={stars} className="flex align-item-center gap-15 mb-10">
          <div className="fw-bold flex align-item-center gap-5">
            <span>{stars}</span>
            <FontAwesomeIcon icon={faStar} className={styles.starIcon} />
          </div>
          <div className={styles.bar}>
            <div
              className={`${styles.fill} ${getBarStyleClass(stars)}`}
              style={{ width: `${percentage}%` }}
            />
          </div>
          <div className="text-muted">{count}</div>
        </div>
      ))}
    </div>
  );
};

export default RatingBreakdown;

มาแกะคณิตศาสตร์ของแท่งกัน เพราะนี่คือหัวใจของคอมโพเนนต์:

  • Array(5).fill(0).map(…) — ท่าสร้าง array 5 ช่องเพื่อวนลูป 5 รอบ (ต้อง .fill(0) ก่อนเพราะ Array(5) เปล่า ๆ ให้ array โหว่ที่ .map ข้ามไม่ยอมวน) ในแต่ละรอบ stars = 5 - index ทำให้ไล่จาก 5★ ลงไป 1★ ตามลำดับที่เว็บรีวิวนิยมแสดง
  • Math.round(review.rating / 2) === stars — convention เดิมของแอปเรา: คะแนนดิบเป็นสเกลเต็ม 10 การหารสองแล้วปัดเศษแปลงเป็นสเกลดาว 1–5 แบบเดียวกับที่ StarReview ทำเป๊ะ (บทเรียน 11) — สองคอมโพเนนต์นี้ต้องใช้สูตรเดียวกัน ไม่งั้นดาวที่การ์ดกับกราฟจะเล่าคนละเรื่อง จากนั้น filter(…).length นับจำนวนรีวิวที่ตกอยู่ในดาวระดับนั้น
  • percentage — สัดส่วนของระดับนั้นเทียบรีวิวทั้งหมด ถูกส่งเข้า inline style width: `${percentage}%` ของ .fill — แท่งนอก (.bar) กว้างเต็มพื้นที่ด้วย flex-grow: 1 ส่วนแท่งใน (.fill) กว้างตามเปอร์เซ็นต์ นี่คือกราฟแท่งที่สร้างจาก div สองชั้นล้วน ๆ ไม่ต้องพึ่ง chart library เลย สังเกต guard totalReviews ? … : 0 กันหารด้วยศูนย์เมื่อไม่มีรีวิว
  • สีตามอารมณ์คะแนน — getBarStyleClass จับคู่ 4–5★ เป็นเขียว, 3★ ส้ม, 1–2★ แดง เป็น mapping ฝั่งการแสดงผลเฉย ๆ แยกอยู่ใน helper function ให้อ่านง่าย
  • reviews: { rating: number }[] — type ของ prop ขอแค่ field rating เท่านั้น ไม่ใช่ ProductReview[] เต็ม ๆ เพราะ structural typing ของ TypeScript ยอมให้ส่ง ProductReview[] เข้ามาได้อยู่แล้ว (มี field ครบเกินขอ) — การประกาศขอเท่าที่ใช้ทำให้คอมโพเนนต์ผูกกับ type ของ feature น้อยลง

ReviewSection: ประกอบฝั่งรีวิวทั้งแถบ

ไม่มีลอจิกใหม่ — เป็นคอมโพเนนต์ประกอบร่างล้วน ๆ ที่ map field ของ ProductReview (reviewerName, comment, …) เข้า props ของ ReviewCard (name, review, …) เหมือนที่ ProductsList ทำให้ ProductCard ในบทเรียน 15 และ key={index} ก็ยอมรับได้ด้วยเหตุผลเดียวกับ thumbnail: รายการรีวิวของสินค้าหนึ่งตัวนิ่ง ไม่มีเพิ่ม/ลบ/สลับ (และ dummyjson ไม่ได้ให้ id ของรีวิวมา)

Product.tsx: ประกอบหน้า (เวอร์ชันแรก)

ถึงเวลาแทนที่ stub ตัวสุดท้ายของ chapter นี้ แทนที่เนื้อหา src/pages/Product/Product.tsx ทั้งไฟล์ด้วยโค้ดนี้:

import React from "react";
import ClipLoader from "react-spinners/ClipLoader";
import { useParams } from "react-router";
import { useQuery } from "@tanstack/react-query";
import ReviewSection from "./components/ReviewSection";
import CategoryBanner from "@/pages/Category/components/CategoryBanner/CategoryBanner";
import ProductImageGallery from "@/features/products/components/ProductImageGallery/ProductImageGallery";
import { calculateOriginalPrice } from "@/shared/utils/price.utils";
import ProductDetailInfo from "@/features/products/components/ProductDetailInfo/ProductDetailInfo";
import { productQueries } from "@/features/products/queries";
import ErrorMessage from "@/shared/components/ErrorMessage/ErrorMessage";

const Product: React.FC = () => {
  const { id } = useParams<{ id: string }>();
  const {
    data: productDetail,
    isLoading,
    isError,
  } = useQuery({
    ...productQueries.detail(id ?? ""),
    enabled: !!id,
  });

  const onAddToCart = () => {
    // TODO: the cart doesn't exist yet — we wire this up in lesson 20
  };

  if (isLoading) {
    return (
      <div className="text-center mb-30">
        <ClipLoader
          size={40}
          aria-label="Loading Spinner"
          data-testid="loader"
        />
      </div>
    );
  }

  if (isError || !productDetail) {
    return (
      <div className="container">
        <ErrorMessage message="We couldn't load this product. Please try again." />
      </div>
    );
  }

  const {
    title,
    images,
    description,
    brand,
    reviews,
    rating,
    price,
    discountPercentage,
    sku,
    stock,
    availabilityStatus,
    shippingInformation,
    warrantyInformation,
  } = productDetail;
  const originalPrice = calculateOriginalPrice(price, discountPercentage);

  return (
    <div>
      <CategoryBanner name={title} />
      <section className="pt-60">
        <div className="container">
          <div className="flex mb-35">
            <div className="width-50">
              <div className="pr-10">
                <ProductImageGallery images={images} />
              </div>
            </div>
            <div className="width-50">
              <div className="pl-10">
                <ProductDetailInfo
                  title={title}
                  brand={brand}
                  rating={rating}
                  reviewsCount={reviews.length}
                  price={price}
                  originalPrice={originalPrice}
                  discountPercentage={discountPercentage}
                  description={description}
                  sku={sku}
                  stock={stock}
                  availabilityStatus={availabilityStatus}
                  shippingInfo={shippingInformation}
                  warrantyInfo={warrantyInformation}
                  onButtonClick={onAddToCart}
                />
              </div>
            </div>
          </div>
          <div className="pb-30">
            <h3 className="fs-24">Reviews</h3>
            <ReviewSection rating={rating} reviews={reviews} />
          </div>
        </div>
      </section>
    </div>
  );
};

export default Product;

เดินดูทีละท่อน:

  • useParams<{ id: string }>() — ดึงค่า :id จาก URL ที่ router จับคู่ route /products/:id ไว้ตั้งแต่บทเรียน 06 generic บอก TypeScript ว่า params มี key อะไรบ้าง แต่ค่าที่ได้ยังเป็น string | undefined เสมอ (ผู้ใช้อาจพิมพ์ URL แปลก ๆ มาเองได้) เราเลยกันสองชั้น: id ?? "" ให้ queryKey ไม่พัง และ enabled: !!id ไม่ยิง API เลยถ้าไม่มี id
  • productQueries.detail(id ?? "") — query ตัวสุดท้ายของ factory จากบทเรียน 14 ได้ออกใช้งานจริงแล้ว เปิดสินค้าตัวที่เคยเปิดซ้ำภายในหนึ่งนาที (staleTime ของเรา) จะได้ข้อมูลจาก cache ทันที
  • early return แบบทั้งหน้า — หน้า Home/Category ใช้ error/loading แบบ inline รายส่วน เพราะหน้าเหล่านั้นมีหลาย section ที่เป็นอิสระต่อกัน แต่หน้านี้ทุกอย่างมาจาก query ก้อนเดียว จึง return ทั้งหน้าเป็น spinner หรือ ErrorMessage ไปเลยได้ สังเกตเงื่อนไข isError || !productDetail — เช็ค !productDetail ควบไปด้วยเพื่อให้ TypeScript รู้ว่าโค้ดหลังจากบรรทัดนี้ productDetail เป็น Product แน่นอน จึง destructure ได้โดยไม่ต้องใส่ ? อีก
  • ประกอบร่าง — CategoryBanner จากบทที่แล้วรับ name={title} กลายเป็นแถบชื่อสินค้า, ครึ่งซ้ายเป็น ProductImageGallery, ครึ่งขวาเป็น ProductDetailInfo ที่รับค่าพร้อมแสดงทั้งชุด (รวม originalPrice ที่คำนวณด้วย calculateOriginalPrice ระดับหน้าเพจ) ปิดท้ายด้วย ReviewSection — ตัวไฟล์หน้าเพจแทบไม่มี markup ของตัวเอง มีแต่การส่งข้อมูลเข้าคอมโพเนนต์ที่เราสร้างมาทั้งบท
🚨 ไฟล์นี้ยังไม่ใช่เวอร์ชันสุดท้าย — และนี่คือความตั้งใจ ถ้าคุณเปิดเทียบกับ repo ต้นฉบับตอนนี้จะเห็นส่วนต่างอยู่สามจุด ซึ่งทั้งหมดเกี่ยวกับตะกร้าสินค้าที่ยังไม่มีในแอปเรา: (1) ต้นฉบับ import AddToCartModalContent กับ useCart จาก feature cart — ของเรายังไม่มี feature นั้น (2) ต้นฉบับมี modal state (isModalOpen + ฟังก์ชันเปิด/ปิด) และ JSX <AddToCartModalContent /> ท้ายไฟล์ (3) ต้นฉบับ onAddToCart เรียก addToCart(…) ใส่ของลงตะกร้าจริงแล้วเปิด modal — ของเราเป็น TODO เปล่า ๆ ไปก่อน ที่เหลือทุกบรรทัดตรงกับต้นฉบับเป๊ะแล้ว เราจะสร้าง cart store ในบทเรียน 19 แล้วกลับมาเติมสามจุดนี้ในบทเรียน 20 — ตอนนั้นปุ่ม Add To Cart จะมีชีวิตขึ้นมาจริง ๆ

Checkpoint

💡 รัน npm run dev แล้วคลิกการ์ดสินค้าจากหน้า Home หรือ Category (หรือเปิด http://localhost:5173/products/3 ตรง ๆ) — ระหว่างโหลดเห็น ClipLoader แวบหนึ่ง แล้วหน้าเต็มต้องปรากฏ: แถบชื่อสินค้าด้านบน, แกลเลอรีรูปฝั่งซ้ายที่คลิก thumbnail แล้วรูปใหญ่สลับตาม (มี skeleton คั่นระหว่างรอ และ thumbnail ที่เลือกมีกรอบดำ), ข้อมูลราคา/ส่วนลด/สต็อกฝั่งขวา และ section Reviews ด้านล่างที่กราฟแท่งมีสีเขียว/ส้ม/แดงตามระดับดาว พร้อมการ์ดรีวิวที่วันที่อ่านง่ายแบบ 30 April 2025 ลองเปิด /products/999999 ด้วย — ต้องเห็นข้อความ error ไม่ใช่จอขาวหรือ spinner ค้าง ส่วนปุ่ม Add To Cart กดแล้วไม่มีอะไรเกิดขึ้น — ถูกต้องแล้ว รอบทเรียน 20
