บทเรียน 04 · ติดตั้งโปรเจกต์ (Project Setup)

โครงสร้าง SCSS

SCSS Foundation

บทที่แล้วเราลบ CSS ทิ้งหมดจนหน้าเว็บโล่ง วันนี้ได้เวลาสร้างระบบ style ของเราเองขึ้นมาแทน แอปนี้ใช้ style สองชั้น: ชั้น global ที่สร้างในบทนี้ (design tokens, กฎพื้นฐาน และ utility classes ที่ทุกหน้าหยิบใช้ได้) กับชั้น SCSS Modules รายคอมโพเนนต์ที่จะเริ่มใช้ตั้งแต่ช่วงบทคอมโพเนนต์เป็นต้นไป หัวใจของชั้น global คือแนวคิด design token — ค่าการออกแบบทั้งหมด (สี ฟอนต์ ระยะห่าง) ประกาศเป็นตัวแปรไว้ที่เดียว ทั้งแอปอ้างจากตัวแปรนั้น จะเปลี่ยนโทนสีทั้งเว็บก็แก้บรรทัดเดียว

ติดตั้ง sass และ normalize.css

npm i normalize.css
npm i -D sass

สังเกตว่าสองตัวนี้ติดตั้งคนละแบบ: sass เป็น devDependency เพราะมันคือตัวแปลงไฟล์ .scss เป็น CSS ตอน build — โค้ดของมันไม่ได้ติดไปกับแอป ส่วน normalize.css เป็น dependency ปกติเพราะเนื้อ CSS ของมันถูก bundle เข้าแอปจริง หน้าที่ของ normalize คือลบความต่างของ style ตั้งต้นระหว่างเบราว์เซอร์ (margin ของ heading, ขนาดฟอนต์ใน form ฯลฯ) ให้เราเริ่มจากพื้นเรียบเสมอกันทุกเบราว์เซอร์

แค่ติดตั้ง sass ไว้ Vite ก็รู้จักไฟล์ .scss ทันทีโดยไม่ต้องตั้งค่าอะไรเพิ่ม

สร้างโฟลเดอร์ src/styles

ไฟล์ style ทั้งเจ็ดของบทนี้อยู่ใน src/styles/ สังเกตว่าหกไฟล์แรกขึ้นต้นด้วย underscore (_variables.scss) — ธรรมเนียมของ Sass เรียกไฟล์แบบนี้ว่า partial หมายถึงไฟล์ชิ้นส่วนที่มีไว้ให้ไฟล์อื่นดึงไปใช้ ไม่ได้ตั้งใจให้ถูกแปลงเป็น CSS เดี่ยว ๆ ของตัวเอง มีเพียง main.scss ตัวเดียวที่เป็นทางเข้า

สร้างไฟล์ src/styles/_spacing.scss — ไฟล์นี้สนุกที่สุด เพราะเราไม่ได้เขียน class เอง แต่เขียนโค้ดที่สร้าง class:

// Margin Utilities
@mixin generate-margin($property, $size) {
  @if $property == "t" {
    margin-top: #{$size}px;
  } @else if $property == "r" {
    margin-right: #{$size}px;
  } @else if $property == "b" {
    margin-bottom: #{$size}px;
  } @else if $property == "l" {
    margin-left: #{$size}px;
  } @else if $property == "x" {
    margin-left: #{$size}px;
    margin-right: #{$size}px;
  } @else if $property == "y" {
    margin-top: #{$size}px;
    margin-bottom: #{$size}px;
  } @else {
    margin: #{$size}px;
  }
}

@mixin generate-padding($property, $size) {
  @if $property == "t" {
    padding-top: #{$size}px;
  } @else if $property == "r" {
    padding-right: #{$size}px;
  } @else if $property == "b" {
    padding-bottom: #{$size}px;
  } @else if $property == "l" {
    padding-left: #{$size}px;
  } @else if $property == "x" {
    padding-left: #{$size}px;
    padding-right: #{$size}px;
  } @else if $property == "y" {
    padding-top: #{$size}px;
    padding-bottom: #{$size}px;
  } @else {
    padding: #{$size}px;
  }
}

// Generate classes for common pixel values
@each $size in 0, 3, 5, 10, 15, 20, 25, 30, 35, 40, 45, 50, 55, 60, 65, 70, 80,
  90, 100
{
  // Margin classes
  .mt-#{$size} {
    @include generate-margin(t, $size);
  }
  .mr-#{$size} {
    @include generate-margin(r, $size);
  }
  .mb-#{$size} {
    @include generate-margin(b, $size);
  }
  .ml-#{$size} {
    @include generate-margin(l, $size);
  }
  .mx-#{$size} {
    @include generate-margin(x, $size);
  }
  .my-#{$size} {
    @include generate-margin(y, $size);
  }
  .m-#{$size} {
    @include generate-margin("", $size);
  }

  // Padding classes
  .pt-#{$size} {
    @include generate-padding(t, $size);
  }
  .pr-#{$size} {
    @include generate-padding(r, $size);
  }
  .pb-#{$size} {
    @include generate-padding(b, $size);
  }
  .pl-#{$size} {
    @include generate-padding(l, $size);
  }
  .px-#{$size} {
    @include generate-padding(x, $size);
  }
  .py-#{$size} {
    @include generate-padding(y, $size);
  }
  .p-#{$size} {
    @include generate-padding("", $size);
  }

  .gap-#{$size} {
    gap: #{$size}px;
  }
}

อ่านจากล่างขึ้นบน: ลูป @each วนขนาด 19 ค่า (0 ถึง 100) แต่ละรอบสร้าง class 15 ตัว (.mt-20, .px-10, .gap-15 ฯลฯ) โดยเรียก @mixin ด้านบนซึ่งเลือกว่าตัวอักษรย่อไหนแปลว่า margin/padding ด้านไหน (top, right, x = ซ้ายขวา, y = บนล่าง) ส่วน #{$size} คือ interpolation — การฝังค่าตัวแปรลงในชื่อ class หรือค่า CSS โค้ดไม่ถึงร้อยบรรทัดนี้ generate class ให้เราเกือบ 300 ตัว และถ้าอยากได้ขนาดใหม่ก็เติมเลขในลูปตัวเดียวจบ ถ้าคุณเคยใช้ Tailwind มาก่อน จะรู้สึกคุ้น ๆ — นี่คือแนวคิดเดียวกันในเวอร์ชันทำมือขนาดจิ๋ว

ต่อสายเข้าแอป

แก้ src/main.tsx เพิ่มการ import main.scss — บรรทัดที่เว้นที่ไว้ตั้งแต่บทที่ 02:

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "./styles/main.scss";
import App from "./App";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);

นี่คือการ import แบบ side effect — ไม่มีการรับค่าอะไรมาใส่ตัวแปร แค่บอก Vite ว่า "เอา style ชุดนี้เข้า bundle ด้วย" แต่พอ save ปุ๊บ มีเรื่อง: TypeScript ขีดเส้นแดงใต้บรรทัดนั้นพร้อมข้อความทำนอง Cannot find module './styles/main.scss'

สอน TypeScript ให้รู้จัก .scss

ที่ฟ้องแบบนั้นเพราะ TypeScript รู้จักแต่ไฟล์ .ts/.tsx — มันไม่มีทางรู้เองว่า import ไฟล์ .scss แล้วจะได้อะไรกลับมา และ template ของ Vite เปิดตัวเลือก noUncheckedSideEffectImports ไว้ ซึ่งสั่งให้ตรวจแม้แต่ import แบบ side effect ว่าชี้ไปยัง module ที่มีอยู่จริง ทางแก้คือเขียนไฟล์ declaration (.d.ts) ประกาศให้ระบบ type รู้ สร้างไฟล์ src/shared/types/global.d.ts (สร้างโฟลเดอร์ซ้อนตามนี้ด้วย — mkdir -p src/shared/types — ตำแหน่งนี้คือบ้านของ type กลางทั้งแอป จะเห็นภาพรวมในบทหน้า):

declare module "*.css" {
  const content: { [className: string]: string };
  export default content;
}

declare module "*.scss" {
  const content: { [className: string]: string };
  export default content;
}

อ่านว่า: "ไฟล์อะไรก็ตามที่ลงท้ายด้วย .css หรือ .scss ให้ถือว่าเป็น module ที่มี default export เป็น object จับคู่ชื่อ class ไปยัง string" นิยามนี้ทำงานสองหน้าที่พร้อมกัน หน้าที่แรกคือปลดล็อกบรรทัด import "./styles/main.scss" ของเราตอนนี้ หน้าที่ที่สองสำคัญกว่า: อีกไม่กี่บทเราจะเขียน import styles from "./Button.module.scss" แล้วใช้ styles.button ใน JSX — object ที่ CSS Modules คืนมามีรูปร่างตรงตามนิยามนี้เป๊ะ (ชื่อ class ต้นฉบับ → ชื่อ class ที่ถูกแปลงให้ unique) ถ้าไม่มี declaration นี้ ทุก import แบบนั้นจะเป็น type error หมด

เหลือขั้นสุดท้าย: บอก TypeScript ว่าไฟล์ declaration ของเราอยู่ที่ไหน เปิด tsconfig.app.json แล้วเพิ่ม typeRoots ต่อท้าย compilerOptions:

{
  "compilerOptions": {
    // ...ค่าเดิมทั้งหมด รวมถึง "paths" จากบทที่แล้ว คงไว้...

    "typeRoots": ["./node_modules/@types", "./src/shared/types"]
  },
  "include": ["src"]
}

typeRoots คือรายชื่อโฟลเดอร์ที่ TypeScript โหลด type declaration เข้ามาให้เองโดยไม่ต้อง import — เราเพิ่ม ./src/shared/types ของเราเข้าไป แต่มีกับดักหนึ่งที่ต้องรู้: การประกาศ typeRoots คือการแทนที่ค่า default ไม่ใช่ต่อท้าย ถ้าเราใส่แค่โฟลเดอร์ของเรา TypeScript จะเลิกมองหา type จากแพ็กเกจ @types/* ทั้งหมด (เช่น @types/react) แล้วโปรเจกต์จะแดงทั้งกระดาน — จึงต้องใส่ ./node_modules/@types กลับเข้าไปด้วยเสมอ

💡 Checkpoint: รัน npm run typecheck ต้องผ่านไม่มี error (เส้นแดงใต้ import scss ต้องหายไปด้วย — ถ้ายังค้างใน editor ลองสั่ง Restart TS Server) จากนั้น npm run dev — หน้า React E-commerce App จะหน้าตาต่างจากเดิมแบบสังเกตได้: หัวข้อชิดขอบซ้ายบนเป๊ะ (margin ถูกล้างหมด) และฟอนต์เปลี่ยนจาก serif ของเบราว์เซอร์เป็น system font สะอาดตา อยากพิสูจน์ว่า utility ทำงานจริง ลองแก้ h1 ใน App.tsx เป็น <h1 className="text-primary mt-20"> ชั่วคราว — ตัวหนังสือต้องกลายเป็นสีน้ำเงินและขยับลงมา 20px แล้วอย่าลืมเอาออกให้เหมือนเดิมก่อนไปบทถัดไป
