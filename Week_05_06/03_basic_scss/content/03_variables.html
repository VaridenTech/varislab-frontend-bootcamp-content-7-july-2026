ตัวแปรใน SCSS

หนึ่งใน feature ที่ทำให้ SCSS คุ้มค่ามากคือ ตัวแปร เพราะมันช่วยเก็บค่าที่ใช้ซ้ำบ่อยไว้ในชื่อที่สื่อความหมาย เช่น สีหลัก ระยะห่าง มุมโค้ง หรือขนาดตัวอักษร ทำให้ทั้งโปรเจกต์เปลี่ยนค่าได้จากจุดเดียว

ไวยากรณ์พื้นฐาน

$name: value;

ทุกตัวแปรของ SCSS จะขึ้นต้นด้วย $ ตามด้วยชื่อที่เราเลือก และลงท้ายด้วย ; เหมือนการประกาศ property ใน CSS 

$brand-color: #6f3cc3;
$space-md: 1rem;
$radius-md: 12px;

ทำไมตัวแปรถึงช่วยมาก

  • เปลี่ยนค่าทีเดียว แล้วทุกจุดที่อ้างอิงถึงค่าดังกล่าวอัปเดตตาม
  • ลดการพิมพ์ค่าซ้ำ เช่นรหัสสีเดิมหลายบรรทัด หรือ spacing ขนาดเดียวกันทั้งหน้า
  • ทำให้ชื่อสื่อความหมาย เช่น $brand-color อ่านแล้วรู้ว่าเป็นสีประจำแบรนด์ ไม่ใช่แค่รหัสสีลอย ๆ

เริ่มต้นตั้งชื่อแบบ purpose-based token

สำหรับมือใหม่ ควรตั้งชื่อตาม “หน้าที่” มากกว่าตามค่าจริง เพราะจะช่วยให้โค้ดทนต่อการเปลี่ยนดีไซน์ในอนาคต

หมวด ตัวอย่างชื่อตัวแปร เอาไว้ใช้กับอะไร
สี $brand-color, $text-muted สีแบรนด์ สีข้อความหลัก สีข้อความรอง
ระยะห่าง $space-sm, $space-md padding, margin, gap
ตัวอักษร $font-base, $font-size-lg font-family, font-size, line-height
มุมโค้ง $radius-sm, $radius-md border-radius ของ card, button, badge

ตัวอย่างการนำกลับมาใช้ซ้ำ

$brand-color: #6f3cc3;
$space-md: 1rem;
$radius-md: 12px;

.button {
  padding: $space-md;
  border-radius: $radius-md;
  background-color: $brand-color;
}

.card {
  padding: $space-md;
  border: 2px solid $brand-color;
  border-radius: $radius-md;
}

จะเห็นว่าค่าเดียวกันถูกใช้ได้หลาย selector โดยไม่ต้องคัดลอกตัวเลขหรือรหัสสีซ้ำหลายจุด

เรื่อง scope แบบเริ่มต้นที่ควรรู้

ในบทเริ่มต้น ให้จำแบบง่ายก่อนว่า ตัวแปรที่ประกาศไว้ด้านบนของไฟล์มักถูกใช้ซ้ำได้ในส่วนล่างของไฟล์เดียวกัน นี่เป็นเหตุผลที่โปรเจกต์จำนวนมากเก็บ token พื้นฐานไว้ส่วนบนของไฟล์หรือแยกเป็นไฟล์เฉพาะในบทถัดไป

เมื่อเรียนลึกขึ้น เราจะเจอแนวคิดเรื่อง scope ของ module และการจัดการตัวแปรข้ามไฟล์ แต่ตอนนี้ขอให้โฟกัสก่อนว่าตัวแปรช่วยลดความซ้ำซ้อนและทำให้ชื่อของค่าต่าง ๆ ชัดขึ้น

Sass variables ต่างจาก CSS custom properties อย่างไร

หัวข้อ Sass variables CSS custom properties
ช่วงเวลาที่ทำงาน ตอนคอมไพล์ ตอน runtime ในเบราว์เซอร์
หน้าตา syntax $brand-color --brand-color และ var(--brand-color)
เบราว์เซอร์เห็นชื่อเดิมไหม ไม่เห็น ชื่อถูกแทนด้วยค่าจริงใน CSS ที่คอมไพล์แล้ว เห็น เพราะ custom property ยังอยู่ใน CSS ที่ส่งไปยังเบราว์เซอร์ 
/* Sass variable */
$brand-color: #6f3cc3;

.banner {
  color: $brand-color;
}

/* CSS custom property */
:root {
  --brand-color: #6f3cc3;
}

.banner {
  color: var(--brand-color);
}

ถ้าต้องการค่าที่เปลี่ยนตาม runtime เช่น theme สว่าง/มืดในเบราว์เซอร์ CSS custom properties มักตอบโจทย์กว่า แต่ถ้าต้องการลดความซ้ำซ้อนตอนเขียนโค้ดและจัดระบบ token SCSS variables ก็มีประโยชน์มาก

ข้อผิดพลาดที่พบบ่อย

  • ลืมใส่ $ ตอนเรียกใช้ ทำให้ compiler มองเป็นข้อความธรรมดาหรือ property ผิดรูปแบบ
  • ตั้งชื่อตามค่าจริงเกินไป เช่น $purple-1 จนอ่านไม่ออกว่าใช้เชิงหน้าที่อะไร
  • คัดลอกค่าลงไปตรง ๆ แทนใช้ตัวแปร ทำให้พอจะแก้ดีไซน์ต้องไล่หลายจุดอีกครั้ง

แบบฝึกหัด

ลองสร้าง component แจ้งเตือนชื่อ .alert โดยใช้ตัวแปร $brand-color, $space-md และ $radius-md จากนั้นดูว่า CSS ที่คอมไพล์แล้วควรมีหน้าตาอย่างไร

ดูเฉลย 
/* SCSS */
$brand-color: #6f3cc3;
$space-md: 1rem;
$radius-md: 12px;

.alert {
  padding: $space-md;
  border: 1px solid $brand-color;
  border-radius: $radius-md;
  color: $brand-color;
}
/* CSS ที่คอมไพล์แล้ว */
.alert {
  padding: 1rem;
  border: 1px solid #6f3cc3;
  border-radius: 12px;
  color: #6f3cc3;
}
