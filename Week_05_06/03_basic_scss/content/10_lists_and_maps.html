Lists และ Maps

พอโปรเจกต์เริ่มมีค่าที่เกี่ยวข้องกันหลายตัว เรามักไม่อยากประกาศตัวแปรแยกทีละชื่อ ตลอดเวลา เช่นระดับ spacing หลายขนาด หรือชุดสีของสถานะต่าง ๆ SCSS จึงมีโครงสร้างข้อมูลพื้นฐานอย่าง list และ map ให้เก็บค่าที่สัมพันธ์กันไว้ด้วยกัน

List คือค่าหลายตัวที่เรียงตามลำดับ

list เหมาะเมื่อ “ตำแหน่ง” ของข้อมูลสำคัญ เช่น ชุดค่าของ shadow, font stack หรือรายการขนาดที่ต้องอ้างตามลำดับ เราเรียกสมาชิกออกมาด้วย helper จาก sass:list 

@use "sass:list";

$card-shadow: 0 12px 30px rgba(53, 18, 110, 0.14);

.card {
  box-shadow:
    list.nth($card-shadow, 1)
    list.nth($card-shadow, 2)
    list.nth($card-shadow, 3)
    list.nth($card-shadow, 4);
}

สิ่งที่ต้องจำคือ index ของ Sass เริ่มที่ 1 ไม่ใช่ 0 แบบหลายภาษาโปรแกรม 

.card {
  box-shadow: 0 12px 30px rgba(53, 18, 110, 0.14);
}

Map คือคู่ key-value ที่อ่านความหมายได้ชัดกว่า

ถ้าข้อมูลไม่ได้เด่นที่ลำดับ แต่เด่นที่ “ชื่อ” เช่น sm, md, lg หรือ success, warning, danger map จะอ่านง่ายกว่า list มาก เพราะเราอ้างค่าด้วย key ที่มีความหมาย 

@use "sass:map";

$spacing: (
  sm: 0.5rem,
  md: 1rem,
  lg: 1.5rem,
);

.stack {
  display: flex;
  flex-direction: column;
  gap: map.get($spacing, md);
}

CSS ที่คอมไพล์แล้วจะเป็น:

.stack {
  display: flex;
  flex-direction: column;
  gap: 1rem;
}

ในงานจริง map ช่วยลดการเดาว่า “สมาชิกตัวที่ 2 หมายถึงอะไร” เพราะชื่อ key บอกความหมายไว้อยู่แล้ว

ถ้า key ไม่มีอยู่จริง map.get() จะคืนค่า null

จุดนี้สำคัญมาก เพราะ Sass ไม่ได้ throw error ให้อัตโนมัติทุกครั้ง ถ้าเราเขียน map.get($spacing, xl) แล้วไม่มี key xl ผลลัพธ์จะเป็น null และถ้า null ถูกใช้เป็นค่าของ property Sass มักจะตัด declaration นั้นทิ้งจาก CSS ปลายทาง 

@use "sass:map";

$spacing: (
  sm: 0.5rem,
  md: 1rem,
  lg: 1.5rem,
);

.stack-loose {
  gap: map.get($spacing, xl);
  padding: map.get($spacing, lg);
}

CSS ที่คอมไพล์แล้วจะเป็น:

.stack-loose {
  padding: 1.5rem;
}
นี่คือเหตุผลที่ควรตั้งชื่อ key ให้สื่อความหมายและใช้ชุดชื่อเดิมซ้ำทั้งโปรเจกต์ เพราะ key สะกดผิดหรือคนละมาตรฐานอาจทำให้ declaration หายไปแบบเงียบ ๆ ได้

เลือก list หรือ map ดี?

สถานการณ์ เครื่องมือที่เหมาะกว่า เหตุผล
ข้อมูลขึ้นกับลำดับ เช่น offset ของ shadow List เรียกตำแหน่งตาม index ได้ตรงไปตรงมา
ข้อมูลมีชื่อบอกบทบาท เช่น spacing scale Map อ่านโค้ดแล้วรู้ทันทีว่ากำลังเลือกค่าระดับไหน
ต้องให้ทีมใช้ token ชุดเดียวกันซ้ำ ๆ Map กำหนด key มาตรฐานได้ชัดกว่า list

ข้อผิดพลาดที่พบบ่อย

  • ลืมว่า list.nth() เริ่มนับจาก 1 ทำให้ดึงสมาชิกผิดตัว
  • ใช้ list กับข้อมูลที่ควรมีชื่อกำกับ จนสุดท้ายจำไม่ได้ว่าสมาชิกแต่ละตำแหน่งคืออะไร
  • สะกด key ของ map ไม่ตรงกัน แล้วได้ null กลับมาโดยไม่ทันสังเกต
  • เก็บข้อมูลหลายแบบปนกันใน map เดียว จนชื่อ key และความหมายเริ่มสับสน

แบบฝึกหัด

ให้สร้าง map ชื่อ $spacing ที่มีค่า sm: 0.5rem, md: 1rem และ lg: 1.5rem จากนั้นใช้กับคลาส .stack โดยกำหนด display: flex;, flex-direction: column;, gap: map.get($spacing, md); และ padding: map.get($spacing, lg); แล้วดูว่า CSS ที่คอมไพล์แล้วเป็นอย่างไร

ดูเฉลย 
@use "sass:map";

$spacing: (
  sm: 0.5rem,
  md: 1rem,
  lg: 1.5rem,
);

.stack {
  display: flex;
  flex-direction: column;
  gap: map.get($spacing, md);
  padding: map.get($spacing, lg);
}
/* CSS ที่คอมไพล์แล้ว */
.stack {
  display: flex;
  flex-direction: column;
  gap: 1rem;
  padding: 1.5rem;
}
