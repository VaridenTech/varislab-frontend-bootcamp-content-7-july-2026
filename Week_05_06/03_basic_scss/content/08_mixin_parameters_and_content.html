พารามิเตอร์ของ Mixin และ @content

บทก่อนหน้าเราสร้าง mixin แบบค่าตายตัวไปแล้ว แต่ของจริงมักต้องยืดหยุ่นกว่านั้น เช่น ปุ่มแต่ละแบบอาจใช้สีไม่เหมือนกัน หรือ media query ควรรับขนาดหน้าจอที่เปลี่ยนได้ นี่คือจุดที่พารามิเตอร์ของ mixin และ @content เข้ามาช่วย

Mixin รับค่าเข้าได้เหมือนฟังก์ชันตัวเล็ก ๆ

เราสามารถประกาศตัวแปรไว้ในวงเล็บของ mixin แล้วส่งค่าตอน include ได้ทันที ทำให้ helper เดิมนำไปใช้ได้หลายสถานการณ์โดยไม่ต้องคัดลอกโค้ดใหม่ 

/* abstracts/_mixins.scss */
@mixin button-variant($background, $foreground: #fff) {
  background-color: $background;
  color: $foreground;
  border: 1px solid transparent;
  border-radius: 999px;
  padding: 0.75rem 1rem;
  font-weight: 700;
}

/* components/_button.scss */
@use "../abstracts/mixins";

.button-primary {
  @include mixins.button-variant(#6f3cc3);
}

.button-secondary {
  @include mixins.button-variant(#efe7fb, #2d114f);
}

CSS ที่คอมไพล์แล้วจะเป็น:

.button-primary {
  background-color: #6f3cc3;
  color: #fff;
  border: 1px solid transparent;
  border-radius: 999px;
  padding: 0.75rem 1rem;
  font-weight: 700;
}

.button-secondary {
  background-color: #efe7fb;
  color: #2d114f;
  border: 1px solid transparent;
  border-radius: 999px;
  padding: 0.75rem 1rem;
  font-weight: 700;
}

$background เป็นพารามิเตอร์ที่จำเป็น ส่วน $foreground: #fff คือค่า default ถ้าเราไม่ส่งค่าสีตัวอักษรเข้ามา Sass จะใช้ #fff ให้อัตโนมัติ

Positional arguments กับ named arguments

ตอน include เราส่งค่าได้สองแบบ แบบแรกคือ positional arguments ที่อาศัยลำดับของค่า และอีกแบบคือ named arguments ที่ระบุชื่อพารามิเตอร์ชัดเจน 

.button-primary {
  @include mixins.button-variant(#6f3cc3);
}

.button-soft {
  @include mixins.button-variant(
    $background: #f3ecff,
    $foreground: #3d1766
  );
}
  • แบบ positional เขียนสั้น เหมาะเมื่อพารามิเตอร์มีน้อยและลำดับจำง่าย
  • แบบ named อ่านชัด เหมาะเมื่อมีค่า optional หรืออยากกันการสลับลำดับผิด
  • ถ้ามี default value เราส่งเฉพาะค่าที่ต้องเปลี่ยนก็พอ

@content ใช้รับ block จากตอน include

บาง mixin ไม่ได้แค่คัดลอก declaration เดิม แต่ต้อง “ห่อ” โค้ดข้างในด้วย wrapper บางอย่าง เช่น media query แบบนี้เราจะใช้ @content เป็นตำแหน่งที่ Sass เอา block จากตอน include มาวาง 

/* abstracts/_mixins.scss */
@mixin respond-above($width) {
  @media (min-width: $width) {
    @content;
  }
}

/* components/_feature-grid.scss */
@use "../abstracts/mixins";

.feature-grid {
  display: grid;
  gap: 1rem;

  @include mixins.respond-above(48rem) {
    grid-template-columns: repeat(2, minmax(0, 1fr));
    align-items: start;
  }
}

เมื่อคอมไพล์แล้ว nested block จะถูกย้ายเข้า media query ปกติ:

.feature-grid {
  display: grid;
  gap: 1rem;
}

@media (min-width: 48rem) {
  .feature-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
    align-items: start;
  }
}

มุมที่ควรจำคือ @content ไม่ได้คืนค่าเหมือน function แต่มันเปิดช่องให้ selector ที่เรียกใช้ ส่ง block CSS เข้ามาแทรกในโครงสร้างที่ mixin กำหนดไว้

ค่า default ช่วยลดการส่งค่าซ้ำ

ถ้าหลาย variant ใช้กติกาเดิมแทบทั้งหมด เราควรให้ mixin ตั้งค่าเริ่มต้นที่ปลอดภัยไว้ก่อน แล้ว override เฉพาะกรณีที่ต่างจริง ๆ

สถานการณ์ สิ่งที่ควรใช้ เหตุผล
ต้องเปลี่ยนค่าตามลำดับง่าย ๆ Positional arguments โค้ดสั้นและอ่านเร็ว
ต้องข้ามไปแก้แค่บางพารามิเตอร์ Named arguments ลดความเสี่ยงจากการสลับลำดับผิด
ค่าส่วนใหญ่เหมือนเดิมเกือบตลอด Default values เขียน include ให้น้อยลงและสื่อค่าเริ่มต้นชัด
ต้องห่อ nested rules เช่น media query @content ยืดหยุ่นกว่า mixin ที่ปล่อย declaration ตายตัว

ข้อผิดพลาดที่พบบ่อย

  • ส่ง positional arguments สลับลำดับ ทำให้สีพื้นหลังและสีตัวอักษรผิดคู่กัน
  • คิดว่า default value ทำให้พารามิเตอร์แรกไม่จำเป็น ทั้งที่ $background ยังต้องส่งอยู่
  • ใช้ named arguments แต่สะกดชื่อพารามิเตอร์ไม่ตรงกับตอนประกาศ mixin
  • เขียน mixin ที่ใช้ @content แต่ส่ง block ที่ไม่เกี่ยวกับ wrapper นั้น ทำให้โค้ดอ่านยาก

แบบฝึกหัด

ให้สร้าง mixin ชื่อ badge($background, $foreground: #fff) ในไฟล์ abstracts/_mixins.scss โดยกำหนด display: inline-flex;, align-items: center;, gap: 0.35rem;, padding: 0.25rem 0.75rem;, border-radius: 999px;, background-color และ color จากพารามิเตอร์ จากนั้นใช้กับ .badge-success และ .badge-neutral โดยอย่างน้อยหนึ่งครั้งต้องใช้ named argument แล้วดูว่า CSS ที่คอมไพล์แล้วเป็นอย่างไร

ดูเฉลย 
/* abstracts/_mixins.scss */
@mixin badge($background, $foreground: #fff) {
  display: inline-flex;
  align-items: center;
  gap: 0.35rem;
  padding: 0.25rem 0.75rem;
  border-radius: 999px;
  background-color: $background;
  color: $foreground;
  font-size: 0.875rem;
  font-weight: 700;
}

/* components/_badge.scss */
@use "../abstracts/mixins";

.badge-success {
  @include mixins.badge(#1f9d55);
}

.badge-neutral {
  @include mixins.badge(
    $background: #eef2ff,
    $foreground: #312e81
  );
}
/* CSS ที่คอมไพล์แล้ว */
.badge-success {
  display: inline-flex;
  align-items: center;
  gap: 0.35rem;
  padding: 0.25rem 0.75rem;
  border-radius: 999px;
  background-color: #1f9d55;
  color: #fff;
  font-size: 0.875rem;
  font-weight: 700;
}

.badge-neutral {
  display: inline-flex;
  align-items: center;
  gap: 0.35rem;
  padding: 0.25rem 0.75rem;
  border-radius: 999px;
  background-color: #eef2ff;
  color: #312e81;
  font-size: 0.875rem;
  font-weight: 700;
}
