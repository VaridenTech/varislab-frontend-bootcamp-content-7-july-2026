จัดระเบียบไฟล์และโมดูล

เมื่อเริ่มรู้จัก partial และ @use แล้ว คำถามถัดไปคือ “ควรวางไฟล์ไว้ตรงไหนดี” บทนี้ไม่ได้พยายามบังคับสถาปัตยกรรมใหญ่โต แต่จะสอนหลักเริ่มต้นที่ใช้ได้จริงกับโปรเจกต์เล็กถึงกลาง: แยกไฟล์ตามหน้าที่ ตั้งชื่อให้สม่ำเสมอ และคอมไพล์เฉพาะไฟล์ทางเข้าเท่านั้น

ตัวอย่างโครงสร้างที่เข้าใจง่าย

สำหรับคอร์สเริ่มต้น โครงสร้างประมาณนี้อ่านง่ายและขยายต่อได้โดยไม่งง:

scss/ ├── abstracts/ │ └── _tokens.scss ├── base/ │ └── _reset.scss ├── components/ │ └── _button.scss └── main.scss
  • abstracts/_tokens.scss เก็บ design tokens เช่น สี spacing หรือ radius
  • base/_reset.scss เก็บกติกาพื้นฐานของทั้งหน้า เช่น box-sizing หรือ margin เริ่มต้น
  • components/_button.scss เก็บ style ของ component เดียวให้ครบในที่เดียว
  • main.scss เป็น entry point ที่รวม module ที่หน้าเว็บนี้ต้องใช้

หลักคิดคือ single responsibility

พยายามให้แต่ละไฟล์มีหน้าที่หลักเพียงอย่างเดียว ถ้าไฟล์หนึ่งทั้งเก็บ token ทั้ง reset ทั้ง component หลายแบบพร้อมกัน เราจะหาของยากขึ้นและแก้ไขยากขึ้นเมื่อโปรเจกต์โต

ไฟล์ ควรเก็บอะไร ไม่ควรปนอะไร
_tokens.scss สี, spacing, radius, font tokens selector ของ component
_reset.scss style พื้นฐานของ element ทั่วไป สีเฉพาะของปุ่มหรือ card
_button.scss style ของปุ่มและสถานะที่เกี่ยวข้อง layout ของทั้งหน้า

Dependency ต้อง explicit

ไฟล์ใดต้องใช้ token หรือ helper จากไฟล์ไหน ให้ประกาศ @use ไว้ในไฟล์นั้นอย่างตรงไปตรงมา อย่าหวังพึ่งว่ามีไฟล์อื่นโหลดไว้ให้แล้ว เพราะการพึ่งพาแบบซ่อนเร้นทำให้ย้ายไฟล์หรือ reuse ยาก 

/* components/_button.scss */
@use "../abstracts/tokens";

.button {
  padding: tokens.$space-md;
  background-color: tokens.$brand-color;
  border-radius: tokens.$radius-md;
}

เมื่อเห็นไฟล์นี้เพียงไฟล์เดียว เราก็รู้ทันทีว่าปุ่มพึ่งพา token จากโฟลเดอร์ abstracts โดยไม่ต้องเดา

ตั้งชื่อไฟล์ให้อ่านง่ายและสม่ำเสมอ

สำหรับผู้เริ่มต้น แนวทางที่ปลอดภัยคือใช้ lowercase kebab-case กับชื่อไฟล์และโฟลเดอร์ เช่น main.scss, _button-group.scss, abstracts และ components

  • ตัวพิมพ์เล็กทั้งหมดช่วยลดความสับสนระหว่างระบบปฏิบัติการ
  • kebab-case อ่านง่ายเมื่อชื่อมีหลายคำ
  • partial ยังคงขึ้นต้นด้วย _ เพื่อสื่อบทบาทของไฟล์

คอมไพล์เฉพาะ entry point

โดยทั่วไปเราไม่สั่งคอมไพล์ไฟล์อย่าง _tokens.scss หรือ _button.scss แยกทีละไฟล์ แต่จะคอมไพล์ main.scss ซึ่งเป็นตัวรวมทุกอย่างแทน เพราะเบราว์เซอร์ควรได้ CSS ปลายทางเพียงชุดที่จัดเรียงครบแล้ว 

npx sass scss/main.scss css/main.css

ถ้าวันหนึ่งโปรเจกต์มีหลายหน้า ก็อาจมีหลาย entry point ได้ เช่น admin.scss และ marketing.scss แต่หลักคิดยังเหมือนเดิม: partial มีไว้ประกอบ entry point ไม่ใช่คอมไพล์เดี่ยว ๆ

ไม่จำเป็นต้องเริ่มด้วยสถาปัตยกรรม 7–1

บางบทความพูดถึงโครงสร้างใหญ่แบบ 7–1 ซึ่งมีหลายโฟลเดอร์ย่อยมาก แต่มือใหม่ไม่จำเป็นต้องเริ่มตรงนั้น ถ้าโปรเจกต์ยังเล็ก โครงสร้างที่มีเพียง abstracts, base, components และ main.scss ก็เพียงพอและเข้าใจง่ายกว่า

เป้าหมายของการจัดไฟล์ไม่ใช่ให้ดู advanced แต่คือทำให้เราและเพื่อนร่วมทีม หาไฟล์เจอ แก้ไขถูกจุด และเห็น dependency ได้ชัด

ตัวอย่างไฟล์ main.scss

ไฟล์ทางเข้ามักมีหน้าที่หลักคือรวบรวม module ตามลำดับที่อ่านแล้วเข้าใจง่าย เช่น ของพื้นฐานก่อน แล้วค่อย component 

@use "abstracts/tokens";
@use "base/reset";
@use "components/button";

แม้บาง module จะไม่ได้ปล่อย selector ออกมามากนัก แต่การเขียนรวมไว้ที่ entry point ช่วยให้เห็นภาพรวมของชุด style ที่หน้านั้นต้องใช้

ข้อผิดพลาดที่พบบ่อย

  • ตั้งชื่อไฟล์ปนกันหลายแบบ เช่น Button.scss, button_group.scss, _button.scss
  • โยนทุกอย่างลง main.scss จนไฟล์ยาวและใช้ซ้ำลำบาก
  • คอมไพล์ partial โดยตรง ทั้งที่มันควรถูกนำไปใช้ผ่าน entry point
  • ซ่อน dependency ไว้ ทำให้เปิดไฟล์ component มาแล้วไม่รู้ว่าพึ่ง token จากไหน

แบบฝึกหัด

ให้จัดไฟล์ทั้งหกชิ้นนี้ลงในโครงสร้างโฟลเดอร์ที่เหมาะสม: _tokens.scss, _reset.scss, _button.scss, main.scss, _card.scss และ _typography.scss จากนั้นเขียนตัวอย่าง main.scss ที่เรียกใช้ module ที่จำเป็นทั้งหมด

ดูเฉลย

โครงสร้างนี้แยก token, base style และ component ออกจากกัน ส่วน main.scss ทำหน้าที่รวมโมดูลตามลำดับที่อ่านง่าย 

scss/
├── abstracts/
│   └── _tokens.scss
├── base/
│   ├── _reset.scss
│   └── _typography.scss
├── components/
│   ├── _button.scss
│   └── _card.scss
└── main.scss
/* main.scss */
@use "abstracts/tokens";
@use "base/reset";
@use "base/typography";
@use "components/button";
@use "components/card";
