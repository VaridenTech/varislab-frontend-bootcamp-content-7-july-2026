Add to Cart & Mini Cart

บทที่แล้วเราสร้างเครื่องยนต์ของตะกร้าเสร็จแล้ว แต่ยังไม่มีใครได้ใช้มันเลย บทนี้เราจะต่อสายให้ครบวงจรแรก: กดปุ่ม Add To Cart บนหน้า Product → สินค้าเข้า store → modal เด้งยืนยัน → ตัวเลขบนไอคอนตะกร้าที่ Header ขยับตาม งานแบ่งเป็นสามชิ้น: modal ยืนยัน, การอัปเดตหน้า Product และ mini cart (badge) บน Header

และบทนี้ต่างจากทุกบทที่ผ่านมาในข้อเดียวที่สำคัญมาก: เป็นบทแรกที่ prompt ต้องสั่งให้ Agent แก้ไฟล์ที่มีเนื้อหาอยู่แล้ว ตั้งแต่บทเรียน 09 มาถึงตอนนี้ เราสั่งสร้างไฟล์ใหม่แทบทั้งหมด (มีแค่ providers.tsx บทที่แล้วที่แก้ของเดิม และเป็นการแก้แค่สองบรรทัด) วันนี้เรามีไฟล์เดิมสองไฟล์ที่ต้องแก้ ไฟล์ละหลายจุด — และการคุมขอบเขตของ prompt แบบนั้นมีท่าเฉพาะของมัน

ทำไม prompt ที่แก้ไฟล์เดิมถึงอันตรายกว่า prompt ที่สร้างไฟล์ใหม่

ตอนสั่งสร้างไฟล์ใหม่ การตรวจงานง่ายมาก: git status บอกชื่อไฟล์ที่โผล่มา ถ้าจำนวนไม่ตรงกับที่สั่ง คุณเห็นทันทีในหนึ่งวินาที และถ้าเนื้อในผิดก็ลบทั้งโฟลเดอร์แล้วสั่งใหม่ ไม่มีอะไรเสียหาย

แต่พอสั่งแก้ไฟล์เดิม โจทย์กลับด้าน: ไฟล์ที่ขึ้นสถานะ modified อาจถูกแก้หนึ่งบรรทัดหรือถูกเขียนใหม่ทั้งไฟล์ก็ได้ git status บอกเหมือนกันเป๊ะ คุณต้องอ่าน git diff จริง ๆ เท่านั้นถึงจะรู้ และสิ่งที่ Agent ชอบทำที่สุดเวลาเปิดไฟล์เดิมขึ้นมาแก้คือ"จัดระเบียบ" ของที่มันไม่ได้ถูกสั่งให้แตะ — เรียงลำดับ import ใหม่ เปลี่ยน React.FC เป็น function declaration แตกฟังก์ชันเป็นตัวย่อย หรือ "ปรับปรุง" ชื่อตัวแปรให้สื่อความหมายกว่าเดิม ทุกข้อนี้อาจถูกในสุญญากาศ แต่มันทำให้ diff ที่ควรอ่านจบใน 20 วินาทีกลายเป็น 200 บรรทัดที่คุณจะอ่านไม่ไหวแล้วกด accept ทิ้ง

เครื่องมือสามอย่างที่เราจะใช้คุมมันในบทนี้ และจะใช้ซ้ำในทุกบทที่แก้ไฟล์เดิมหลังจากนี้:

  • @-mention ไฟล์ที่จะแก้ตรง ๆ — ให้ Agent อ่านของเดิมก่อนแก้ ไม่ใช่เดาว่าไฟล์เดิมหน้าตาอย่างไรแล้วเขียนใหม่ทั้งก้อน นี่คือเหตุผลเดียวกับบทเรียน 12 แค่คนละทิศ: คราวนั้นไฟล์ที่ mention เป็นแม่แบบ คราวนี้มันคือของเดิมที่ห้ามเสียหาย
  • สั่งจำนวนจุดที่แก้ให้ชัดเป็นตัวเลข — ไม่ใช่ "อัปเดตหน้า Product ให้เพิ่มของลงตะกร้าได้" แต่เป็น "แก้สามจุดตามนี้ นอกนั้นห้ามแตะแม้แต่บรรทัดเดียว" ตัวเลขนั้นกลายเป็นสิ่งที่คุณเอาไปนับใน git diff ได้ตอนตรวจ
  • ระบุชื่อไฟล์ที่แก้ได้ในบรรทัด โครงสร้าง: แล้วปิดที่เหลือทั้งหมดใน ขอบเขต: — โดยเฉพาะไฟล์ที่เกี่ยวข้องแต่ห้ามแตะ เช่น ProductDetailInfo ที่เป็นเจ้าของปุ่มจริง ๆ

ข้อสุดท้ายนั้นมีเรื่องน่าสนใจซ่อนอยู่ ลองคิดดู: ปุ่ม Add To Cart อยู่ใน ProductDetailInfo แต่บทนี้เราไม่แตะไฟล์นั้นเลยแม้แต่ตัวอักษรเดียว เพราะบทเรียน 21 ออกแบบมันเป็น onButtonClick: () => void ไว้แล้ว — component ที่วาดปุ่มไม่รู้และไม่ต้องรู้ว่ากดแล้วเกิดอะไร นี่คือคำทำนายจากบทเรียน 21 ที่ถึงกำหนดวันนี้พอดี และเป็นเหตุผลว่าทำไม callback prop ถึงคุ้มค่าที่จะออกแบบตั้งแต่แรก

AddToCartModalContent — modal ยืนยันการเพิ่มสินค้า

เวลาผู้ใช้กดเพิ่มสินค้า ต้องมี feedback ทันทีว่า "สำเร็จแล้วนะ" ไม่อย่างนั้นเขาจะกดซ้ำอีกสามรอบเพราะไม่แน่ใจ (แล้วได้ของ 4 ชิ้นโดยไม่ตั้งใจ) เราจะทำ modal ยืนยันโดยไม่เขียน modal ใหม่ — component Modal กลางที่สร้างไว้ตั้งแต่บทเรียน 13 กับ Button จากบทเรียน 12 รอเราหยิบมาประกอบอยู่แล้ว

จุดที่น่าสังเกตของไฟล์นี้มีสามข้อ:

  • เป็นการ compose ล้วน ๆ — ไฟล์นี้ไม่รู้จัก react-modal เลยด้วยซ้ำ มันรับ isOpen/onClose แล้วส่งต่อให้ Modal กลาง (prop ฝั่ง Modal ชื่อ onRequestClose ตามธรรมเนียมของ react-modal) — เนื้อในเป็นแค่ข้อความกับปุ่ม Close นี่คือผลตอบแทนของการลงทุนสร้าง shared components ไว้ก่อนในบทเรียน 12–13: feature ใหม่ประกอบเสร็จใน 20 กว่าบรรทัด
  • ไม่มี logic ตะกร้าอยู่ในนี้ — component นี้ไม่เรียก useCart ไม่รู้ว่าสินค้าอะไรถูกเพิ่ม มันเป็น "หน้าตา" เพียว ๆ ที่ถูกควบคุมจากพ่อ (หน้า Product) ผ่าน props สองตัว ทำให้ทดสอบง่ายและเอาไปใช้ที่อื่นได้ถ้าต้องการ
  • class ที่ใช้คือ utility กลางทั้งหมด — text-center, fs-20, mb-20 จาก _utilities.scss และ _typography.scss บทเรียน 04 ไม่ต้องมี .module.scss ของตัวเอง

CartSummary — mini cart บน Header

ผู้ใช้เพิ่มของแล้วก็จริง แต่พอปิด modal ไปก็ไม่เหลือร่องรอยอะไรบนจอว่าตะกร้ามีของ ธรรมเนียมของเว็บขายของคือไอคอนตะกร้ามุมขวาบนพร้อมตัวเลขจำนวนชิ้น ตัวนี้เป็น component ตัวแรกของคอร์สที่อ่านจาก store จริง ๆ:

  • นับ "จำนวนชิ้น" ไม่ใช่ "จำนวนแถว" — reduce บวก quantity ของทุกแถวรวมกัน ถ้าตะกร้ามีสินค้าตัวเดียวจำนวน 3 ชิ้น badge ต้องโชว์ 3 ไม่ใช่ 1 (cart.items.length จะให้คำตอบผิดทันทีที่มีการกดซ้ำ)
  • useMemo กับ dependency [cart.items] — คำนวณผลรวมใหม่เฉพาะตอน items เปลี่ยนจริง และเพราะ reducer ของเรา immutable ทุกการแก้ไขจะได้ array reference ใหม่เสมอ useMemo จึงจับการเปลี่ยนแปลงได้แม่นยำ — วินัยจากบทที่แล้วมาส่งผลตรงนี้
  • badge โผล่เฉพาะตอนมีของ — {totalItems > 0 && ...} ตะกร้าว่าง = ไอคอนเกลี้ยง ๆ ไม่มีเลข 0 แปะให้รก
  • การจัดตำแหน่ง badge — ตัวเลขใช้ position: absolute เกาะมุมขวาบนของกล่องที่มี class relative (utility จากบทเรียน 04) ดันขึ้น-ออกไป 12px ให้ลอยเหนือไอคอน สีพื้นดึงจาก variables.$red01 ผ่าน @use ตามแพตเทิร์น SCSS module ที่ใช้กันมาทั้งโปรเจกต์
  • onIconClick เป็น prop — component นี้ไม่ตัดสินใจเองว่าคลิกแล้วไปไหน คนใช้ (Header) เป็นคนบอก การแยกแบบนี้ทำให้ CartSummary ไม่ต้องรู้จัก router เลย ท่าเดียวกับ onButtonClick ของ ProductDetailInfo เป๊ะ

สี่จุดที่หายไปจาก Product.tsx

ย้อนไปบทเรียน 21 เราจงใจปล่อยให้ onAddToCart เป็นฟังก์ชันว่างที่มีแต่ comment TODO เพราะตอนนั้นยังไม่มี store ให้เรียก และกล่อง 🚨 ท้ายบทนั้นระบุไว้ล่วงหน้าเลยว่าไฟล์นี้ต่างจากต้นฉบับอยู่สี่จุด ซึ่งเขียนรวมไว้เป็นสามข้อ วันนี้เราจะเติมให้ครบ และ diff ของบทนี้ต้องมีแค่นั้นพอดี:

  1. บรรทัด import — import React from "react"; กลายเป็น import React, { useState } from "react"; และมี import ใหม่สองบรรทัดแทรกเข้ามาระหว่างบรรทัดของ ProductDetailInfo กับบรรทัดของ productQueries: ตัว modal และ hook useCart
  2. state ของ modal และฟังก์ชันเปิด/ปิด — const [isModalOpen, setIsModalOpen] = useState(false); กลายเป็นบรรทัดแรกสุดในตัว component (เหนือ useParams) ตามด้วย onOpenModal/onCloseModal แบบบรรทัดเดียวสองตัว และ JSX <AddToCartModalContent /> ต่อท้ายก่อนปิด </div> นอกสุด
  3. ไส้ในของ onAddToCart — comment TODO ถูกแทนที่ด้วยการแปลงข้อมูลสินค้าเป็น CartItem แล้วส่งเข้า store ก่อนเปิด modal

จุดที่สี่คือหนึ่งบรรทัดที่กล่อง 🚨 ของบทเรียน 21 พ่วงไว้ท้ายข้อ (3) เพราะมันคือสิ่งที่ทำให้ข้อ 3 ทำงานได้: const { addToCart } = useCart(); ซึ่งวางต่อท้ายบล็อก useQuery พอดี — ที่มันไม่ได้อยู่คือแถวบรรทัดแรก ๆ ของคอมโพเนนต์คู่กับ useState ซึ่งเป็นที่ที่หลายคน (และ Agent) เดาว่ามันควรอยู่ รวมแล้วบรรทัดโค้ดที่เพิ่มเข้ามานอกตัวฟังก์ชัน onAddToCart มีเจ็ดบรรทัดพอดี (บวกบรรทัดว่างอีกสองบรรทัด ซึ่ง git diff นับด้วย) แล้วที่เหลือคือการแก้บรรทัด import React กับการเขียนไส้ในของฟังก์ชันเดียว ถ้า git diff ของคุณยาวกว่านี้ แปลว่ามีของแถมมาด้วย

เรื่องที่ควรหยุดคิดสักนิดใน handler ตัวใหม่:

  • การแปลงร่างข้อมูลเกิดที่นี่ — API ให้ Product ก้อนใหญ่ แต่ store ต้องการ CartItem ที่เราออกแบบไว้บทที่แล้ว หน้า Product คือคนแปลง: thumbnail กลายเป็น image, quantity ตั้งเป็น 1 เสมอ (กดหนึ่งครั้ง = หนึ่งชิ้น และถ้ากดซ้ำ reducer จะรวมเข้าแถวเดิมให้เอง — เราจ่ายค่ากติกานี้ไว้แล้วใน ADD_TO_CART)
  • originalPrice คำนวณแล้วเก็บติดไปเลย — เราใช้ calculateOriginalPrice ตัวเดียวกับที่หน้านี้ใช้แสดงราคาก่อนลดอยู่แล้ว (import อยู่ในไฟล์ตั้งแต่บทเรียน 21 ไม่ต้องเพิ่มบรรทัดใหม่) เก็บผลลัพธ์ลงตะกร้าไปด้วย เพื่อให้หน้า Cart โชว์ราคาเต็มกับยอด "You Save" ได้ในบทหน้าโดยไม่ต้องยิง API ถามราคาสินค้าซ้ำทีละตัว
  • ลำดับใน handler สื่อความหมาย — addToCart(...) ก่อน แล้วค่อย onOpenModal(): ยืนยันหลังจากของเข้าตะกร้าแล้วจริง ๆ ส่วน if (productDetail) กันกรณีที่ type บอกว่า data อาจยังไม่มา (ในทางปฏิบัติปุ่มยังไม่ render ถ้าข้อมูลไม่มา เพราะ early return สองก้อนกันไว้แล้ว แต่ TypeScript ไม่รู้เรื่องนั้น — closure ตัวนี้ถูกประกาศก่อน early return จึงยังเห็น productDetail เป็น Product | undefined อยู่)
  • useCart ใช้ได้เพราะบทที่แล้วเราเสียบ provider ไว้แล้ว — หน้า Product render อยู่ใต้ AppProviders ผ่าน router ดังนั้น CartContext หาเจอแน่นอน ถ้าคุณลืมแก้ providers.tsx ในบทเรียน 22 บรรทัดนี้จะโยน error "useCart must be used within a CartProvider" ใส่หน้าคุณทันที — ยามที่เราตั้งไว้ทำงานแล้ว

Header — เติมของที่ค้างไว้ตั้งแต่บทเรียน 10

Header เวอร์ชันบทเรียน 10 ของเรามีโลโก้กับเมนู แต่มุมขวายังโล่ง และบทนั้นบอกเหตุผลไว้ตรง ๆ ว่าทำไมถึงไม่เขียนบรรทัด useProductRoute() ค้างไว้ล่วงหน้า: ตัวแปรที่ประกาศแล้วไม่ได้ใช้จะโดน ESLint ฟ้องทันที ตอนนี้ได้เวลาเติมของที่ค้างไว้แล้ว จุดที่เพิ่มมีสามจุด — import CartSummary, import useProductRoute, ดึง goToCartSummary ออกมา แล้ววาง <CartSummary /> ปิดท้ายแถว flex

และตรงนี้คือจุดที่การตัดสินใจเชิงสถาปัตยกรรมของบทเรียน 10 เก็บดอกครั้งแรก บทนั้นเราสร้าง useProductRoute ขึ้นมาเพื่อรวม URL ของทั้งแอปไว้ที่เดียว แล้วจบบทโดยที่ไม่มีใครเรียกใช้มันเลยสักที่ — เพราะในบทนั้นไม่มีจุดไหนที่ต้อง navigate จริง ๆ hook ที่ไม่มีคนใช้คือ hook ที่ยังพิสูจน์อะไรไม่ได้ วันนี้ Header เป็นคนแรกที่เรียกมัน และนั่นแปลว่าวันนี้เป็นวันแรกที่ Agent มีโอกาสไม่ใช้มันด้วย

ลองคิดแบบ Agent ดู: มันได้โจทย์ว่า "คลิกไอคอนตะกร้าแล้วไปหน้า /cart" ทางที่สั้นที่สุดและพบบ่อยที่สุดในโค้ดทั่วโลกคือ const navigate = useNavigate(); แล้ว onClick={() => navigate("/cart")} จบในสองบรรทัด ใช้งานได้ถูกต้อง 100% lint ผ่าน typecheck ผ่าน หน้าเว็บทำงานเป๊ะ — และมันทำลายเหตุผลทั้งหมดที่ useProductRoute มีอยู่ เพราะ URL string "/cart" เพิ่งหลุดออกจากที่รวมของมันไปนั่งอยู่ในไฟล์ที่สอง วันที่เปลี่ยน URL scheme คุณจะแก้ hook แล้วคิดว่าจบ ทั้งที่ยังมีอีกที่ที่ตกหล่น

นี่คือรูปแบบของข้อผิดพลาดที่ไม่มีเครื่องมือตัวไหนจับได้ และเป็นข้อที่ต้องอยู่ใน checklist เป็นข้อต้น ๆ ของบทนี้ — วิธีจับใช้เวลาสองวินาที: grep -rn "useNavigate\|navigate(" src/shared/components/Header/ ต้องว่างเปล่า

src/features/cart/components/CartSummary/CartSummary.tsx:

import React, { useMemo } from "react";
import { FontAwesomeIcon } from "@fortawesome/react-fontawesome";
import { faCartShopping } from "@fortawesome/free-solid-svg-icons";
import styles from "./CartSummary.module.scss";
import { useCart } from "@/features/cart/useCart";

interface CartSummaryProps {
  onIconClick: () => void;
}

const CartSummary: React.FC<CartSummaryProps> = ({ onIconClick }) => {
  const { cart } = useCart();

  const totalItems = useMemo(
    () => cart.items.reduce((sum, item) => sum + item.quantity, 0),
    [cart.items],
  );

  return (
    <div className="relative" onClick={onIconClick}>
      <FontAwesomeIcon className="pointer fs-20" icon={faCartShopping} />
      {totalItems > 0 && (
        <span
          className={`${styles.cartCount} fs-12 fw-bold text-center`}
          aria-label="Cart item count"
        >
          {totalItems}
        </span>
      )}
    </div>
  );
};

export default CartSummary;
💡 ของที่ควรถูกทักในรีวิว: ตัวที่รับคลิกในไฟล์นี้คือ <div onClick={onIconClick}> — ไม่ใช่ <button> ไม่มี role ไม่มี tabIndex และไม่มี handler ของคีย์บอร์ด ผลคือผู้ใช้ที่กด Tab ไล่ไปตาม Header จะข้ามไอคอนตะกร้าไปเลย และกด Enter ตรงนั้นไม่ได้ ที่น่าสังเกตเป็นพิเศษคือบทเรียน 10 เขียนเตือนเรื่องนี้ไว้เองด้วยคำเกือบตรงตัว: บรรทัด AI มักพลาดตรงนี้ ของบทนั้นบอกว่าอย่าใช้ <div onClick={() => navigate("/cart")}> เพราะกดด้วยคีย์บอร์ดไม่ได้ — แล้วต้นฉบับก็ทำแบบนั้นพอดีในบทนี้ ทางแก้คือเปลี่ยน <div> เป็น <button type="button"> แล้วย้าย relative ไปไว้บนปุ่ม ซึ่งเป็นการแก้บรรทัดเดียว เราสั่งตามต้นฉบับเพราะโค้ดอ้างอิงของคอร์สนี้คือแอปจริง แต่ในรีวิวจริงข้อนี้ควรถูกทัก และข้อพ่วงที่ควรถกด้วยคือ aria-label="Cart item count" ที่แปะบน <span> ซึ่งมีตัวเลขอยู่ข้างในอยู่แล้ว — ชื่อที่เราตั้งเองจะไปทับข้อความจริง แทนที่จะเสริมมัน สิ่งที่ต้องการจริง ๆ คือให้ผู้ใช้ได้ยินทั้งจำนวนและความหมาย

src/pages/Product/Product.tsx — เวอร์ชันสมบูรณ์ ไฟล์นี้จะไม่เปลี่ยนอีกแล้วตลอดคอร์ส:

import React, { useState } from "react";
import ClipLoader from "react-spinners/ClipLoader";
import { useParams } from "react-router";
import { useQuery } from "@tanstack/react-query";
import ReviewSection from "./components/ReviewSection";
import CategoryBanner from "@/pages/Category/components/CategoryBanner/CategoryBanner";
import ProductImageGallery from "@/features/products/components/ProductImageGallery/ProductImageGallery";
import { calculateOriginalPrice } from "@/shared/utils/price.utils";
import ProductDetailInfo from "@/features/products/components/ProductDetailInfo/ProductDetailInfo";
import AddToCartModalContent from "@/features/cart/components/AddToCartModalContent/AddToCartModalContent";
import { useCart } from "@/features/cart/useCart";
import { productQueries } from "@/features/products/queries";
import ErrorMessage from "@/shared/components/ErrorMessage/ErrorMessage";

const Product: React.FC = () => {
  const [isModalOpen, setIsModalOpen] = useState(false);
  const { id } = useParams<{ id: string }>();
  const {
    data: productDetail,
    isLoading,
    isError,
  } = useQuery({
    ...productQueries.detail(id ?? ""),
    enabled: !!id,
  });
  const { addToCart } = useCart();

  const onOpenModal = () => setIsModalOpen(true);
  const onCloseModal = () => setIsModalOpen(false);

  const onAddToCart = () => {
    if (productDetail) {
      addToCart({
        id: productDetail.id,
        title: productDetail.title,
        price: productDetail.price,
        quantity: 1,
        image: productDetail.thumbnail,
        originalPrice: calculateOriginalPrice(
          productDetail.price,
          productDetail.discountPercentage,
        ),
      });
      onOpenModal();
    }
  };

  if (isLoading) {
    return (
      <div className="text-center mb-30">
        <ClipLoader
          size={40}
          aria-label="Loading Spinner"
          data-testid="loader"
        />
      </div>
    );
  }

  if (isError || !productDetail) {
    return (
      <div className="container">
        <ErrorMessage message="We couldn't load this product. Please try again." />
      </div>
    );
  }

  const {
    title,
    images,
    description,
    brand,
    reviews,
    rating,
    price,
    discountPercentage,
    sku,
    stock,
    availabilityStatus,
    shippingInformation,
    warrantyInformation,
  } = productDetail;
  const originalPrice = calculateOriginalPrice(price, discountPercentage);

  return (
    <div>
      <CategoryBanner name={title} />
      <section className="pt-60">
        <div className="container">
          <div className="flex mb-35">
            <div className="width-50">
              <div className="pr-10">
                <ProductImageGallery images={images} />
              </div>
            </div>
            <div className="width-50">
              <div className="pl-10">
                <ProductDetailInfo
                  title={title}
                  brand={brand}
                  rating={rating}
                  reviewsCount={reviews.length}
                  price={price}
                  originalPrice={originalPrice}
                  discountPercentage={discountPercentage}
                  description={description}
                  sku={sku}
                  stock={stock}
                  availabilityStatus={availabilityStatus}
                  shippingInfo={shippingInformation}
                  warrantyInfo={warrantyInformation}
                  onButtonClick={onAddToCart}
                />
              </div>
            </div>
          </div>
          <div className="pb-30">
            <h3 className="fs-24">Reviews</h3>
            <ReviewSection rating={rating} reviews={reviews} />
          </div>
        </div>
      </section>

      <AddToCartModalContent isOpen={isModalOpen} onClose={onCloseModal} />
    </div>
  );
};

export default Product;

เอาไฟล์นี้วางคู่กับเวอร์ชันในบทเรียน 21 แล้วไล่ดูสิ่งที่ไม่เปลี่ยน จะเห็นภาพชัดกว่าดูสิ่งที่เปลี่ยน: useQuery เหมือนเดิมทุกตัวอักษร, early return สองก้อนเหมือนเดิม, การ destructure สิบสามฟิลด์เหมือนเดิม, props สิบสี่ตัวที่ส่งให้ ProductDetailInfo เหมือนเดิม และ ProductDetailInfo.tsx เองไม่ถูกแตะเลยแม้แต่ตัวอักษรเดียว ทั้งที่ปุ่มที่พฤติกรรมเปลี่ยนไปทั้งหมดอยู่ในไฟล์นั้น — นี่คือของจริงที่ callback prop ซื้อให้เรา และเป็นคำตอบว่าทำไมบทเรียน 21 ถึงยอมออกแบบ onButtonClick ทั้งที่วันนั้นมันยังไม่ทำอะไรเลย

สังเกตว่าเมนูสองรายการยังใช้ <Link to> ส่วนไอคอนตะกร้าใช้ useProductRoute — สองท่าในไฟล์เดียวกัน และทั้งคู่ถูกด้วยเหตุผลคนละข้อ: <Link> เหมาะกับ "ลิงก์" ที่ผู้ใช้ควรคลิกขวาเปิดแท็บใหม่ได้ ส่วน navigate ผ่าน hook เหมาะกับ "การกระทำ" ที่เกิดหลังเหตุการณ์บางอย่าง เส้นแบ่งนี้จะกลับมาอีกครั้งในบทเรียน 28 ตอนที่การสั่งซื้อสำเร็จแล้วต้องพาผู้ใช้ไปหน้า order success เอง

อีกจุดคือ Header render อยู่ใน MainLayout ซึ่งอยู่ใต้ AppProviders — ดังนั้น useCart ใน CartSummary ทำงานได้จากทุกหน้า และเพราะทุกคนอ่านจาก context ใบเดียวกัน การกดปุ่มบนหน้า Product จะทำให้ badge บน Header ขยับทันทีโดยที่สอง component นี้ไม่รู้จักกันเลย — นี่แหละพลังของการยก state ขึ้นไปไว้บน Context

💡 ของที่ควรถูกทักในรีวิว: Header อยู่ใน src/shared/components/ แต่ import ของจาก src/features/cart/ — ซึ่งเป็นการชี้ทวนทิศทางที่บทเรียน 05 วางไว้ (shared คือของที่ทุก feature ใช้ได้ จึงไม่ควรรู้จัก feature ไหนเป็นพิเศษ) เหตุผลที่ต้นฉบับยอมรับได้คือ Header เป็นจุดประกอบของทั้งแอปอยู่แล้ว ส่วน CartSummary เองอยู่ใน features/cart/components ถูกที่แล้วเพราะมันรู้จัก useCart แต่การอ่านแบบเข้มกว่านั้นบอกว่าจุดประกอบตัวจริงคือ MainLayout ใน src/app/ ต่างหาก — ถ้าย้าย <CartSummary /> ไปไว้ที่นั่นหรือให้ Header รับเป็น children/prop ทิศทางการพึ่งพาจะสะอาดทันทีโดยหน้าจอไม่เปลี่ยนเลย ในโปรเจกต์ขนาดนี้เรื่องนี้ไม่ทำให้อะไรพัง แต่ในโปรเจกต์ที่มีสิบ feature มันคือจุดเริ่มของ shared ที่ค่อย ๆ รู้จักทุกอย่างในแอปจนย้ายไปใช้ที่อื่นไม่ได้อีก

🤔 อธิบายให้ได้

  1. เปิด ProductDetailInfo.tsx ขึ้นมาดู แล้วตอบว่าไฟล์นี้ต้องแก้กี่บรรทัดในบทนี้ และทำไม จากนั้นสมมติว่าบทเรียน 21 เขียนมันเป็น onButtonClick ที่รับ productId: number แล้วเรียก useCart เองข้างใน — บอกให้ได้ว่าวันนี้จะต้องแก้กี่ไฟล์แทน
  2. ลองแก้ Header.tsx ให้ใช้ useNavigate กับ navigate("/cart") ตรง ๆ แทน useProductRoute — รัน npm run lint และ npm run typecheck ทั้งคู่ผ่าน หน้าเว็บทำงานเหมือนเดิมทุกประการ อธิบายว่าอะไรที่แย่ลง และบอกให้ได้ว่าคุณจะรู้ตัวเมื่อไหร่ถ้าไม่มีใครทักในรีวิว (เสร็จแล้วแก้กลับ)
  3. เปลี่ยน dependency array ของ useMemo ใน CartSummary จาก [cart.items] เป็น [] แล้วกด Add To Cart — อธิบายว่าทำไม badge ถึงไม่ขยับ ทั้งที่ cart.items เปลี่ยนไปแล้วจริง ๆ และตอบว่าถ้า reducer ของบทเรียน 22 เขียนแบบ mutate อาการจะเหมือนหรือต่างจากนี้ (เสร็จแล้วแก้กลับ)
