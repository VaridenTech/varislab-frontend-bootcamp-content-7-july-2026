แยกเป็น Reusable Components

Extracting Components

หลักการออกแบบ props

ก่อนแยก component ใดก็ตาม ถามสามคำถาม

  1. ใช้ที่ไหนบ้าง — ถ้าคำตอบมีที่เดียวและไม่มีทีท่าจะเพิ่ม อย่าเพิ่งแยก (YAGNI)
  2. อะไรต่างกันในแต่ละที่ — นั่นคือ props
  3. อะไรคงที่ทุกที่ — นั่นคือโค้ดข้างใน component

หลักที่ช่วยให้ props สะอาด: component ที่ดีรับ "ข้อมูล" ไม่ใช่ "คลาส" — <StatCard label="Today's Money" value="$53,000" /> อ่านออกทันทีว่าคืออะไร ส่วน <Card className="flex items-center..."> คือการย้ายปัญหาเดิมไปอีกที่

Button — variant map pattern

เริ่มจาก component ที่ใช้ซ้ำหลายจุด ปุ่มในดีไซน์นี้มีสามแบบ ได้แก่ SIGN UP สีเขียวทึบ DOCUMENTATION สีขาว และ VIEW ALL แบบขอบเส้น เราจะรวมเป็นปุ่มเดียวที่มี 3 variant

// src/components/Button.tsx
import { ButtonHTMLAttributes } from "react";

type Variant = "primary" | "outline" | "ghost";

const variantClasses: Record<Variant, string> = {
  primary: "bg-primary text-white hover:bg-primary-dark",
  outline: "border border-ink text-ink hover:bg-ink hover:text-white",
  ghost: "text-muted hover:bg-gray-100",
};

interface ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: Variant;
}

export default function Button({
  variant = "primary",
  className = "",
  ...rest
}: ButtonProps) {
  return (
    <button
      className={`inline-flex items-center justify-center rounded-xl px-4 py-2 text-xs font-bold tracking-wide uppercase transition-colors focus-visible:ring-2 focus-visible:ring-primary/50 focus-visible:outline-none disabled:pointer-events-none disabled:opacity-50 ${variantClasses[variant]} ${className}`}
      {...rest}
    />
  );
}

สี่เทคนิคในไฟล์เดียว แกะทีละตัว

  • Variant map — object Record<Variant, string> แทน ternary ซ้อน: เพิ่ม variant ใหม่ = เพิ่มหนึ่งบรรทัดใน map แล้ว TypeScript บังคับให้ครบทุกตัวเอง (ลบตัวหนึ่งออกจาก map ดู — error ทันที)
  • extends ButtonHTMLAttributes + spread ...rest — onClick, type, disabled, aria-* ทุกตัวของปุ่ม HTML ผ่านเข้ามาได้ฟรี ไม่ต้องประกาศ prop เอง
  • className escape hatch — ที่ไหนต้องการเสริม (เช่น className="w-full" ให้ปุ่ม SIGN UP เต็มกว้าง) ทำได้โดยไม่ต้องเพิ่ม prop ใหม่ ปุ่ม DOCUMENTATION สีขาวบนการ์ดเขียวก็ใช้ทางนี้: variant="ghost" className="bg-white text-ink"
  • พฤติกรรมพื้นฐานอยู่ใน component — เขียน focus-visible ring และ disabled style เพียงครั้งเดียว แล้วทุกปุ่มในแอปจะใช้กติกาเดียวกันตามที่ตรวจไว้ในบทเรียน 13

StatCard

ต่อไปแก้โค้ดซ้ำชุดใหญ่ในหน้า Dashboard สิ่งที่ต่างกันระหว่างการ์ดทั้ง 4 ใบคือป้าย ตัวเลข delta ทิศทางของ delta และไอคอน ซึ่งทั้งหมดนี้จะเป็น props

// src/components/StatCard.tsx
import { ReactNode } from "react";

interface StatCardProps {
  label: string;
  value: string;
  delta?: string;
  deltaTone?: "up" | "down";
  icon: ReactNode;
}

export default function StatCard({
  label,
  value,
  delta,
  deltaTone = "up",
  icon,
}: StatCardProps) {
  return (
    <div className="flex items-center justify-between rounded-2xl bg-white p-4 shadow-sm">
      <div>
        <p className="text-sm font-medium text-muted">{label}</p>
        <p className="text-xl font-bold text-ink">
          {value}{" "}
          {delta && (
            <span
              className={`text-sm font-bold ${
                deltaTone === "up" ? "text-success" : "text-danger"
              }`}
            >
              {delta}
            </span>
          )}
        </p>
      </div>
      <div className="flex size-12 items-center justify-center rounded-xl bg-primary text-white">
        {icon}
      </div>
    </div>
  );
}

ข้อสังเกต: icon เป็น ReactNode — ยัด SVG อะไรมาก็ได้, delta เป็น optional เผื่อการ์ดที่ไม่มีเปอร์เซ็นต์, และ ternary ที่เหลืออยู่ (deltaTone) เป็นเงื่อนไขเดียวชั้นเดียว — แบบนี้โอเค กติกาต้าน "ternary ซ้อน" ไม่ใช่ "ternary ทุกตัว" ฝั่งการใช้งานในหน้า Dashboard ยุบเหลือ

import { stats } from "../data/stats";

<div className="grid grid-cols-1 gap-6 md:grid-cols-2 xl:grid-cols-4">
  {stats.map((s) => (
    <StatCard key={s.label} {...s} />
  ))}
</div>

จาก ~120 บรรทัดเหลือ 5 — และข้อมูลอยู่ใน data/stats.ts ที่มันควรอยู่มาตลอด

StatusBadge และ ProgressBar

Component ขนาดเล็กสองตัวนี้ช่วยแยก style ออกจาก ternary ในบทเรียน 11 และลดโค้ดซ้ำข้ามหน้า

// src/components/StatusBadge.tsx
import { ReactNode } from "react";

type Tone = "success" | "muted";

const toneClasses: Record<Tone, string> = {
  success: "bg-success text-white",
  muted: "bg-gray-100 text-muted",
};

export default function StatusBadge({
  tone,
  children,
}: {
  tone: Tone;
  children: ReactNode;
}) {
  return (
    <span className={`rounded-lg px-3 py-1 text-xs font-bold ${toneClasses[tone]}`}>
      {children}
    </span>
  );
}

ใช้: <StatusBadge tone={author.online ? "success" : "muted"}>{author.online ? "Online" : "Offline"}</StatusBadge> — ternary เหลือแค่ตรงข้อมูล ไม่แตะสไตล์ อีกแล้ว และสังเกตว่า tone ตั้งชื่อตามความหมาย (success/muted) ไม่ใช่ตามหน้า (online/offline) — หน้า Tables ใช้กับ Working/Done/Canceled ต่อได้เลย

// src/components/ProgressBar.tsx
export default function ProgressBar({ value }: { value: number }) {
  return (
    <div>
      <p className="text-sm font-bold text-primary">{value}%</p>
      <div
        role="progressbar"
        aria-valuenow={value}
        aria-valuemin={0}
        aria-valuemax={100}
        className="mt-1 h-1 w-full rounded-full bg-gray-200"
      >
        <div
          className="h-1 rounded-full bg-primary"
          style={{ width: `${value}%` }}
        />
      </div>
    </div>
  );
}

สังเกต role="progressbar" และ aria-value* เดิมที screen reader ไม่ทราบว่า div ที่แสดง 60% หมายถึงอะไร เมื่อใส่ semantics ไว้ใน ProgressBar ทุกจุดที่เรียกใช้ก็จะได้ข้อมูล accessibility ชุดเดียวกัน ประโยชน์ของการ refactor จึงมีทั้งโค้ดที่สั้นลงและพฤติกรรมที่สม่ำเสมอ

NavItem

ก้อน NavLink จากบทเรียน 13 วนใช้สองที่ (เมนูหลัก + ACCOUNT PAGES) — แยกปิดท้าย

// src/components/NavItem.tsx
import { ReactNode } from "react";
import { NavLink } from "react-router";

interface NavItemProps {
  to: string;
  icon: ReactNode;
  label: string;
  onNavigate?: () => void;
}

export default function NavItem({ to, icon, label, onNavigate }: NavItemProps) {
  return (
    <NavLink
      to={to}
      onClick={onNavigate}
      className={({ isActive }) =>
        `flex items-center gap-3 rounded-2xl px-4 py-3 text-sm font-bold transition-colors
         focus-visible:ring-2 focus-visible:ring-primary/50 focus-visible:outline-none ` +
        (isActive ? "bg-white text-ink shadow-sm" : "text-muted hover:bg-white")
      }
    >
      <span className="flex size-8 items-center justify-center rounded-xl bg-white text-primary">
        {icon}
      </span>
      {label}
    </NavLink>
  );
}

Sidebar ทั้งสองหมวดเหลือ menu.map((m) => <NavItem key={m.to} {...m} onNavigate={onClose} />)

สั่ง refactor ผ่าน Agent อย่างมีกำกับ

เราสามารถให้ Agent ช่วยลงมือ refactor ได้ แต่เราควรออกแบบ interface และ props ให้ชัดเจนก่อน แทนการให้ Agent ตัดสินใจจากโค้ดเพียงอย่างเดียว

แยก stat card ที่ซ้ำ 4 ที่ใน src/pages/DashboardPage.tsx ออกเป็น
src/components/StatCard.tsx ตาม interface นี้เป๊ะ ๆ:

interface StatCardProps {
  label: string;
  value: string;
  delta?: string;
  deltaTone?: "up" | "down";
  icon: ReactNode;
}

ย้ายข้อมูลการ์ดทั้ง 4 ไปไว้ src/data/stats.ts แล้วให้หน้า map จาก data
ห้ามเปลี่ยนหน้าตา UI แม้แต่ pixel เดียว

หลัง Agent แก้เสร็จ ให้ตรวจสามขั้น: (1) อ่าน diffว่า interface ตรงตามที่กำหนด (2) รัน dev แล้วเทียบกับ screenshotเพื่อดูว่า UI ไม่เปลี่ยนโดยไม่ตั้งใจ และ (3) ทำทีละ componentเพื่อให้แต่ละ prompt และ diff มีขนาดที่ตรวจได้สะดวก

เมื่อแยก Button, StatCard, StatusBadge, ProgressBar และ NavItem ครบแล้ว ส่วน Toggle เก็บไว้ทำพร้อมหน้า Profile ให้ตรวจ checklist บทเรียน 14 อีกรอบ ถ้าทุกข้อผ่านจึง commit การ refactor ชุดนี้

git add .
git commit -m "refactor: extract Button, StatCard, StatusBadge, ProgressBar, NavItem"

ลูปครบทั้งสี่จังหวะเป็นครั้งแรก: prompt → generate → review → refactor — เหลือแค่สรุปและโจทย์ปิดท้าย

ก่อนหน้า: ตรวจ Maintainability สารบัญบทเรียน ถัดไป: สรุปและก้าวต่อไป
