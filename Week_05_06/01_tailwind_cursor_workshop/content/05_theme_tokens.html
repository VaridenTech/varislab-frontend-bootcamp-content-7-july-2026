Design Tokens

ทำไมต้องมี token

สีเขียวมิ้นต์ของ Purity โผล่อยู่ทุกหน้า: กล่องไอคอน, ปุ่ม, progress bar, hero ของหน้า Sign Up ถ้าเราพิมพ์ bg-teal-400 กระจายไปทั่ว แล้ววันหนึ่ง brand เปลี่ยนสี (เรื่องปกติมากในชีวิตจริง) ต้องไล่แก้ทุกไฟล์ และถ้า Agent เกิดใช้ teal-300 บ้าง teal-400 บ้างในแต่ละรอบ generate สีจะเพี้ยนกันเองโดยไม่มีใครสังเกต

ทางแก้คือ design token: ตั้งชื่อค่าที่เป็น "ระบบ" ของดีไซน์ไว้ที่เดียว แล้วอ้างชื่อแทนค่า

อ่านค่าจาก Figma

เปิดไฟล์ Figma ของ Purity แล้วลองคลิกเลือกของทีละชิ้น: กล่องไอคอนของ stat card → ดู Fill ในแผง Design ด้านขวา, ตัวหนังสือหัวการ์ด → ดูสีข้อความ, ป้ายรองสีเทา → ดูอีกค่า เมื่อไล่ดูหลาย ๆ ชิ้นจะพบว่าดีไซน์ทั้งดีไซน์ใช้สีหลักอยู่ไม่กี่ตัว นี่คือชุดที่เราจะใช้ตลอด workshop (ค่าอ่านจากไฟล์ Figma โดยประมาณ — ปัดให้จำง่ายเล็กน้อย ไม่ผิดบาป)

เขียนลง src/index.css ด้วย @theme — ฟีเจอร์ของ Tailwind v4 ที่ทำให้ config เป็น CSS

/* src/index.css */
@import "tailwindcss";

@theme {
  --color-primary: #4fd1c5;
  --color-primary-dark: #38b2ac;
  --color-ink: #2d3748;
  --color-muted: #a0aec0;
  --color-surface: #f8f9fa;
  --color-success: #48bb78;
  --color-danger: #e53e3e;
}
  • primary / primary-dark — เขียวมิ้นต์ประจำแบรนด์ กับเวอร์ชันเข้มไว้ทำ hover
  • ink — น้ำเงินเทาเข้ม สีตัวหนังสือหลักของดีไซน์นี้ (ไม่ใช่ดำสนิท)
  • muted — เทาอ่อนของป้ายรองและเมนูที่ไม่ active
  • surface — เทาจาง ๆ ของพื้นหลังทั้งหน้า
  • success / danger — เขียวของ +55% และแดงของ -14%

แค่นี้ Tailwind จะสร้าง utility ให้อัตโนมัติทุกตัว: bg-primary, text-ink, border-muted, ring-primary/50 — ใช้ได้เหมือนสีในตัวทุกประการ รวมถึง opacity modifier

<button class="rounded-xl bg-primary px-4 py-2 font-bold text-white hover:bg-primary-dark">
  SIGN UP
</button>

ลองกลับไปแปลง stat card จากบทเรียน 03 ให้ใช้ token — เปลี่ยนแค่ 4 class

- <p class="text-sm font-medium text-gray-400">          + text-muted
- <p class="text-xl font-bold text-gray-700">            + text-ink
- <span class="text-sm font-bold text-green-500">        + text-success
- <div class="... rounded-xl bg-teal-400">               + bg-primary

หน้าตาเหมือนเดิมทุกประการ แต่ตอนนี้การ์ดพูดภาษาดีไซน์ ("นี่คือสี primary") ไม่ใช่ภาษาค่าดิบ ("นี่คือ teal-400") — และที่สำคัญสำหรับ workflow ของเรา: token ที่ตั้งไว้จะไปอยู่ใน prompt และ rules ให้ Agent ใช้ตาม ทำให้ทุกรอบ generate ได้สีชุดเดียวกัน

จัดระเบียบ class ยาว ๆ

Class ที่เรียงมั่ว ๆ อ่านยากและ review ยาก แนะนำลำดับนี้ (ไม่ต้องเป๊ะ แต่ให้มีระบบ): layout → sizing → spacing → typography → สี → border/เงา → states เช่น flex items-center gap-3 w-full px-4 py-2 text-sm font-bold text-ink bg-white rounded-xl shadow-sm hover:bg-surface

ข่าวดีคือไม่ต้องจัดเอง — ติดตั้ง plugin ของ Prettier แล้วให้มันเรียงให้ทุกครั้งที่ save

npm install -D prettier prettier-plugin-tailwindcss

// .prettierrc
{
  "plugins": ["prettier-plugin-tailwindcss"]
}

ประโยชน์แฝงที่จะเห็นชัดในบทที่ 5: เมื่อ class เรียงเป็นมาตรฐานเดียวกันหมด การเทียบว่าสองที่ "ใช้ class ชุดเดียวกันไหม" (สัญญาณของโค้ดซ้ำ) ทำได้ด้วยตาเปล่า

ทำไมไม่ใช้ @apply ทุกที่

Tailwind มี @apply ให้ยุบ class ชุดยาวเป็น class ใหม่ใน CSS ได้ เช่น .btn { @apply rounded-xl bg-primary px-4 py-2; } — เห็นครั้งแรกเหมือนทางออกของ class ยาว แต่ถ้าใช้ทั่วไปหมด เราจะกลับไปสู่โลกเดิมเป๊ะ: ตั้งชื่อ class, สลับไฟล์ไปดูความหมาย, CSS ผีที่ไม่มีใครกล้าลบ — สิ่งที่หนีมาตั้งแต่บทเรียน 03

คำตอบเรื่อง reuse ของโลก React + Tailwind คือ React component — ปุ่มที่ใช้ซ้ำไม่ใช่ .btn แต่คือ <Button> ที่ห่อ class ไว้ข้างในหนึ่งเดียว บทเรียน 15 จะทำเรื่องนี้เต็ม ๆ

แบบฝึกท้ายบท

การ์ด "Active Users" ในหน้า Dashboard มีพื้นหลังน้ำเงินเข้มไล่เฉด ซึ่งเข้มกว่า ink อีกขั้น — ลองเพิ่ม token --color-ink-dark: #1a202c เข้าไปใน @theme เตรียมไว้ แล้วคิดดูว่า gradient จาก ink ไป ink-dark เขียนด้วย utility ว่าอะไร (ใบ้: ขึ้นต้นด้วย bg-gradient-to-b) — เฉลยอยู่ในบทเรียน 10 ตอนที่ Agent สร้างการ์ดใบนี้จริง

พื้นฐาน Tailwind ครบแล้ว: utilities, responsive, states, tokens — พอสำหรับอ่านและตรวจโค้ดที่ AI เขียนได้อย่างมั่นใจ ต่อไปคือทักษะที่สอง: แปลงดีไซน์เป็นคำสั่งที่ชัดเจน
