บทเรียน 06 · จาก Screenshot สู่ Prompt (Screenshot to Prompt)

อ่านโครงสร้าง UI จาก Screenshot

Reading a UI

ก่อน prompt ต้องอ่านให้ออก

หลักสูตรของ workshop นี้เขียนว่า "ใช้ Cursor Agent สร้าง UI ฉบับแรก หลังเข้าใจโครงสร้างแล้ว" — ครึ่งหลังของประโยคคือหัวใจ เราสั่งงานสิ่งที่ตัวเองยังไม่เข้าใจไม่ได้ ผลลัพธ์ที่ได้จะเป็นการเดาของ AI ไม่ใช่ดีไซน์ของเรา

เป้าหมายของบทนี้: ฝึกมองภาพ UI แล้วเห็นเป็น "โครงสร้าง + pattern" ไม่ใช่ pixel — ทักษะเดียวกับที่นักพัฒนาใช้ตอนรับงานจากดีไซเนอร์มาแตกเป็นงานย่อย

ขั้นที่ 1 — แบ่งเป็น region

มองหา "ก้อนใหญ่" ก่อน แล้วค่อยเจาะลง — หน้า Dashboard แตกเป็นชั้น ๆ ได้แบบนี้

  • ราก: สองคอลัมน์ — sidebar ซ้าย (คงที่) + คอลัมน์ขวา (เนื้อหา)
    • Sidebar: โลโก้ → เมนูหลัก 4 รายการ → หัวข้อ "ACCOUNT PAGES" → เมนูบัญชี 3 รายการ → การ์ด "Need help?" ล่างสุด
    • คอลัมน์ขวา: navbar (breadcrumb + ค้นหา + ไอคอน) → เนื้อหา 4 แถว
      • แถว 1: การ์ดสถิติ ×4
      • แถว 2: การ์ดโปรโมท ×2 (ข้อความ+โลโก้ / รูปภาพ)
      • แถว 3: กราฟ ×2 (Active Users แท่ง / Sales overview เส้น)
      • แถว 4: ตาราง Projects (กว้าง ~2/3) + timeline Orders (แคบ ~1/3)

แต่ละแถวให้ถามต่อว่า "กี่คอลัมน์ และบนมือถือยุบเหลือเท่าไหร่" — อย่าลืมว่าดีไซน์ให้มาแค่ desktop การตัดสินใจ responsive เป็นของเรา และต้องเขียนลง prompt เสมอ (แถว 1: 4→2→1, แถว 3: 2→1, แถว 4: 3 ส่วนที่กลายเป็นซ้อนกัน — คาดเดาอย่างมีหลักการจากบทเรียน 04)

ขั้นที่ 2 — หา pattern ที่ซ้ำ

มองอีกรอบด้วยคำถาม "อะไรหน้าตาเหมือนกันบ้าง"

  • การ์ดขาว (rounded-2xl bg-white shadow-sm) คือหน่วยพื้นฐานของทั้งดีไซน์ — ทุกอย่างอยู่ในการ์ดแบบนี้หมด
  • Stat card ×4 — ต่างกันแค่ข้อมูล (ป้าย, ตัวเลข, %, ไอคอน) โครงเหมือนกันเป๊ะ
  • ตาราง — Projects ในหน้านี้กับ 2 ตารางในหน้า Tables ใช้สูตรเดียวกัน: หัวคอลัมน์เทาตัวเล็ก แถวคั่นเส้นบาง
  • Progress bar — โผล่ทั้งตาราง Projects หน้านี้และหน้า Tables
  • Badge สถานะ — Online/Offline ในหน้า Tables

สังเกตไว้ตั้งแต่ตอนอ่าน — ชื่อ pattern พวกนี้ (StatCard, ProgressBar, StatusBadge) จะกลายเป็นชื่อ component ตอน refactor ในบทเรียน 15 การอ่าน UI ที่ดีคือการเริ่ม refactor ตั้งแต่ยังไม่มีโค้ด

ขั้นที่ 3 — อ่านระบบ spacing / typography / สี

  • ช่องไฟ — ระยะห่างระหว่างการ์ดคงที่ตลอดทั้งหน้า ราว 24px → gap-6 เดียวใช้ทั้งหน้า
  • Typography — หัวการ์ดตัวหนาสี ink, ป้ายรอง text-sm text-muted, ตัวเลขใหญ่ตัวหนา — มีอยู่ 3-4 ระดับเท่านั้น ไม่ใช่ 20 แบบ
  • สี — เขียวมิ้นต์ = token primary ของเรา, เขียว/แดงของเปอร์เซ็นต์ = success/danger, พื้นหลัง = surface — ดีไซน์ทั้งหน้าใช้สีที่เราตั้ง token ไว้แล้วครบ

ผลของการอ่านสามขั้น: เราได้ bullet list ที่พร้อมกลายเป็นส่วน "โครงสร้าง" ของ prompt ในบทถัดไปแทบจะคำต่อคำ

แบบฝึก — decompose หน้า Tables

ก่อนดูเฉลย ลองทำสามขั้นกับหน้า Tables ด้วยตัวเอง เขียนเป็น bullet list ในไฟล์โน้ต — เก็บไว้ด้วย เพราะบทเรียน 11 จะให้ใช้มันเขียน prompt จริง

เฉลยย่อ (อ่านหลังลองเองแล้ว): โครงหน้า = shell เดิม (sidebar + navbar ใช้ร่วมทุกหน้า — ไม่ต้องคิดใหม่) + เนื้อหา 2 แถว: การ์ด "Authors Table" (คอลัมน์ AUTHOR รูป+ชื่อ+อีเมล / FUNCTION สองบรรทัด / STATUS badge เขียวหรือเทา / EMPLOYED วันที่ / ลิงก์ Edit — 6 แถว) และการ์ด "Projects" (COMPANIES ไอคอน+ชื่อ / BUDGET / STATUS ข้อความ / COMPLETION ตัวเลข % + progress bar / ปุ่ม kebab) pattern ที่ซ้ำ: การ์ดขาว, สูตรตาราง, badge, progress bar — ตรงกับที่เจอในหน้า Dashboard เกือบทั้งหมด

อ่านออกแล้ว ขั้นต่อไปคือเปลี่ยนสิ่งที่อ่านได้เป็นคำสั่งที่ AI ตีความผิดไม่ได้ — กายวิภาคของ prompt ที่ดี ในบทถัดไป
