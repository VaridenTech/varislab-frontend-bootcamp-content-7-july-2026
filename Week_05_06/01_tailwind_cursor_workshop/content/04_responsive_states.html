Responsive & States

Mobile-first

หลักการ responsive ของ Tailwind มีประโยคเดียว: class ที่ไม่มี prefix ใช้กับทุกขนาดจอ ส่วน class ที่มี prefix ใช้ตั้งแต่ breakpoint นั้น "ขึ้นไป"

<div class="grid grid-cols-1 gap-6 md:grid-cols-2 xl:grid-cols-4">
  <!-- stat cards ทั้ง 4 ใบ -->
</div>

อ่านว่า: เริ่มจาก 1 คอลัมน์ (มือถือ) พอจอกว้างถึง md ขยายเป็น 2 พอถึง xl ขยายเป็น 4 — เขียนจากจอเล็กขึ้นไปหาจอใหญ่เสมอ นี่คือความหมายของคำว่า mobile-first

กับดักที่คนพลาดกันมากที่สุด: sm: ไม่ได้แปลว่า "บนจอเล็ก" แต่แปลว่า "ตั้งแต่ 640px ขึ้นไป" ถ้าอยากให้มือถือเป็นแบบหนึ่ง ให้เขียนแบบนั้นโดยไม่ใส่ prefix แล้วใช้ prefix เขียนทับสำหรับจอที่ใหญ่ขึ้น

Prefixมีผลตั้งแต่นึกถึง
sm:640pxมือถือแนวนอน
md:768pxแท็บเล็ต
lg:1024pxโน้ตบุ๊ก
xl:1280pxจอเดสก์ท็อป
2xl:1536pxจอใหญ่

Patterns จากหน้า Dashboard

ดีไซน์ Purity ให้ภาพมาแค่ desktop — การตัดสินใจว่าจอเล็กยุบยังไงเป็นของเรา (และต้องเขียนลง prompt ในบทที่ 3) นี่คือ 4 pattern ที่เราจะใช้กับ dashboard นี้จริง

  • แถว stat cards — grid grid-cols-1 gap-6 md:grid-cols-2 xl:grid-cols-4 มือถือเรียงลง แท็บเล็ตจับคู่ เดสก์ท็อปเรียง 4
  • แถวกราฟสองใบ — grid gap-6 lg:grid-cols-2 มือถือซ้อนกัน โน้ตบุ๊กขึ้นไปแบ่งครึ่ง
  • Sidebar — hidden lg:flex จอเล็กซ่อนไว้ก่อน จอใหญ่แสดง — จำ pattern นี้ให้แม่น: ของที่ซ่อนบนมือถือต้องมีทางเข้าถึงอื่นเสมอ ตอนนี้เรายังไม่มี (เดี๋ยวบทเรียน 12 จะทำ drawer + ปุ่ม hamburger ให้ครบ)
  • กรอบเนื้อหา — mx-auto w-full max-w-[1440px] px-4 md:px-6 จำกัดกว้างสุด จัดกลาง และมี padding ขอบจอ — สังเกต max-w-[1440px]: วงเล็บเหลี่ยมคือ "arbitrary value" ใช้ค่านอก scale ได้เมื่อจงใจ

States — hover, focus และเพื่อนร่วมแก๊ง

Prefix แบบเดียวกันนี้ใช้กับ "สถานะ" ของ element ได้ด้วย

  • hover:bg-teal-500 — เมื่อเมาส์ชี้
  • focus-visible:ring-2 focus-visible:ring-teal-400/50 — วงแหวนรอบปุ่มเมื่อโฟกัสด้วยคีย์บอร์ด — ทำไมไม่ใช้ focus: เฉย ๆ? เพราะ focus: ติดตอนคลิกเมาส์ด้วย (เกิดวงแหวนวูบวาบน่ารำคาญ) ส่วน focus-visible: ฉลาดพอจะโชว์เฉพาะตอนผู้ใช้นำทางด้วยคีย์บอร์ด — ข้อยกเว้นเดียวคือช่อง input ที่ใช้ focus: ได้ เพราะการพิมพ์คือการโฟกัสโดยตั้งใจเสมอ
  • active:scale-95 — ตอนกดค้าง
  • disabled:opacity-50 — ตอนปุ่มถูกปิดใช้งาน

ท่าพิเศษที่ดีไซน์นี้ต้องใช้: group — เมื่ออยากให้ "ลูก" เปลี่ยนตอน hover "แม่" เช่นการ์ดโปรโมท "Work with the Rockets" ที่อยากให้รูปข้างในซูมเมื่อชี้ทั้งการ์ด

<a href="#" class="group block overflow-hidden rounded-2xl">
  <img
    src="/images/rockets.png"
    alt="ทีมงานกำลังทำงานร่วมกัน"
    class="transition-transform duration-300 group-hover:scale-105"
  />
</a>

ติด group ที่แม่ แล้วลูกใช้ group-hover: อ้างถึงสถานะของแม่ได้ (แถม transition-transform ให้ซูมแบบนุ่ม ๆ ไม่กระตุก)

วิธีทดสอบ

  • เปิด DevTools แล้วกดไอคอน device toolbar (Cmd+Shift+M) — เลือกขนาดมือถือมาตรฐาน เช่น 390×844
  • หรือลากขอบหน้าต่างช้า ๆ จากแคบสุดไปกว้างสุด แล้วดูว่า layout เปลี่ยนที่จุดไหนบ้าง — ทุกจุดที่เปลี่ยนคือ breakpoint ที่เราเขียนไว้ ถ้ามีช่วงไหนพัง (ของล้น, ช่องว่างประหลาด) นั่นคือช่วงที่ลืมคิด

กฎนิ้วโป้ง: ออกแบบมือถือก่อน แล้วค่อยเติม prefix ขยายขึ้น — เขียน grid-cols-1 ก่อน แล้วถามตัวเองว่า "จอกว้างขึ้นควรได้อะไรเพิ่ม" ง่ายกว่าเขียน desktop แล้วพยายามยัดลงจอเล็กเสมอ AI มักทำกลับด้าน (เพราะเราแนบภาพ desktop ให้มัน) — และนั่นจะเป็นประเด็นใหญ่ของบทเรียน 12

เหลือชิ้นสุดท้ายของพื้นฐาน Tailwind: ทำยังไงให้ "สีแบรนด์" ของ Purity เป็นระบบ ไม่ใช่ตัวเลขสีกระจายทั่วโค้ด — ไปบทถัดไป
