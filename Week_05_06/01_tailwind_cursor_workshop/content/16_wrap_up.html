บทเรียน 16 · Refactor เป็น Component (Refactor to Components)

สรุปและก้าวต่อไป

Wrap Up

ยินดีด้วย 🎉

สิ่งที่อยู่ในมือคุณตอนนี้: Purity Dashboard เวอร์ชัน Tailwind ที่สร้างโดย Cursor Agent ภายใต้การกำกับของคุณ — ผ่านการตรวจสามเลนส์และ refactor จนสะอาด

Routeหน้าสถานะ
/Dashboardเสร็จ — stat cards, promo, กราฟ placeholder, ตาราง, timeline
/tablesTablesเสร็จ — Authors + Projects พร้อม badge และ progress bar
/signupSign Upเสร็จ — layout แยกนอก shell, ฟอร์มพร้อม toggle จริง
/profileProfileโจทย์ของคุณ — ด้านล่าง

บวกชุด component ที่ใช้ซ้ำได้: Button, StatCard, NavItem, StatusBadge, ProgressBar — และที่มีค่ากว่าโค้ดคือกระบวนการที่ได้ฝึกจนครบลูป

ทักษะทั้งสี่ ↔ บทเรียน

  • ถอด screenshot/wireframe/requirement เป็น prompt ที่ชัดเจน → บทเรียน 06 (อ่าน UI), 07 (กายวิภาคสี่ส่วน), 08 (Figma)
  • ใช้ Cursor Agent สร้าง UI ฉบับแรก → บทเรียน 09–11 (shell, Dashboard, Tables + Sign Up)
  • ตรวจโค้ด Tailwind ที่ AI สร้าง → บทเรียน 12 (responsive), 13 (accessibility), 14 (maintainability)
  • Refactor เป็น component ที่ใช้ซ้ำได้ → บทเรียน 15

ย้ำอีกครั้งเพราะสำคัญ: ลูป prompt → generate → review → refactor ไม่ใช่ของเฉพาะ workshop นี้ — มันคือวิธีทำงานกับ AI ที่ใช้กับ UI ทุกงาน ทุก framework ทุกดีไซน์ หลังจากนี้

โจทย์ใหญ่: หน้า Profile

ถึงตาคุณวิ่งลูปเองทั้งรอบ โดยไม่มีบทเรียนจูงมือ

  1. Decompose (วิชาบทเรียน 06) — แบ่ง region: hero, การ์ดโปรไฟล์ที่ลอยทับ, สามคอลัมน์ (Platform Settings / Profile Information / Conversations), grid การ์ดโปรเจกต์
  2. เขียน prompt สี่ส่วน (07) — อ่านค่าประกอบจาก Figma (08); อย่าลืมระบุว่า route /profile อยู่ใน DashboardLayout และให้ใช้ component ที่มีอยู่ (Button, toggle pattern จากบทเรียน 13)
  3. Generate (09) — แนบภาพ อ่าน diff ก่อน Accept
  4. Review สามเลนส์ (12–14) — จด TODO แล้วเคลียร์
  5. Refactor (15) — อย่างน้อยหนึ่ง component ใหม่ควรเกิดจากหน้านี้

จุดยากที่เฉลยล่วงหน้าให้นิดเดียว

  • การ์ดลอยทับ hero — margin ติดลบ (-mt-16) + relative/z-10
  • Platform Settings — toggle 6 ตัว: ถึงเวลาแยก toggle จากบทเรียน 13 เป็น component Toggle ที่รับ label กับ defaultChecked
  • แท็บ OVERVIEW / TEAMS / PROJECTS — โอกาสสร้าง component ใหม่ (ตั้งชื่อเองตาม domain — ไม่ใช่ Card2 นะ)
  • สามคอลัมน์ — คิดเรื่องการยุบบนมือถือเองตั้งแต่ตอนเขียน prompt ไม่ใช่ตอนตรวจ

ไอเดียต่อยอด

  • หน้า Billing และ RTL — มีในไฟล์ Figma ครบ วิ่งลูปเพิ่มอีกสองรอบ
  • Dark mode — Tailwind มี dark: variant ให้ทุก utility ลองเริ่มจาก token
  • กราฟจริง — แทน placeholder ด้วย chart library แล้วฝึกสั่ง Agent ให้ต่อ data ให้
  • ข้อมูลจริง — เอาวิชา TanStack Query จากคอร์ส e-commerce มาต่อ API เข้าตารางกับ stat cards
  • Deploy — วิธีเดียวกับที่เรียนในคอร์ส React (บทเรียน 35 ของคอร์สนั้น) ใช้ได้เลย

ส่งท้าย

AI generate โค้ดได้เร็วขึ้นทุกเดือน และจะเร็วขึ้นไปอีก — สิ่งที่แพงขึ้นสวนทางกันคือทักษะสามอย่างที่คุณเพิ่งฝึกมาทั้ง workshop: อ่านดีไซน์ให้แตก เขียนความต้องการให้ชัด และ review ให้เป็น คนที่มีสามอย่างนี้ใช้ AI เป็นทีมงานได้ทั้งทีม คนที่ไม่มีได้แค่กดปุ่มแล้วภาวนา

อย่ากลัวที่จะให้ AI ทำงานเยอะ ๆ — แต่อย่า ship สิ่งที่ตัวเองอ่านไม่เข้าใจ นั่นแหละเส้นแบ่งที่ทำให้คุณเป็น engineer ไม่ใช่ผู้ชม

เจอกันในโปรเจกต์ถัดไป 🚀
