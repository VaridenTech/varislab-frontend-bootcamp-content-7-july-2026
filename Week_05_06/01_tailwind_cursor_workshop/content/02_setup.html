Project & Cursor Setup

สร้างโปรเจกต์

เราจะตั้งโครงโปรเจกต์เอง เพื่อให้ Agent ทำงานอยู่ในกรอบที่ชัดเจน หลักการนี้จะใช้ตลอด workshop: เราตัดสินใจเรื่องโครงสร้าง แล้วให้ AI ช่วยทำงานภายในโครงนั้น เริ่มด้วยการรันคำสั่งต่อไปนี้ใน terminal

npm create vite@latest purity-dashboard -- --template react-ts
cd purity-dashboard
npm install
npm install tailwindcss @tailwindcss/vite react-router

เราจะได้โปรเจกต์ React + TypeScript บน Vite แบบเดียวกับคอร์ส React พร้อมแพ็กเกจที่เพิ่มเข้ามาอีกสองส่วน: tailwindcss กับปลั๊กอิน Vite และ react-router สำหรับสลับหน้า workshop นี้ไม่มี data loading ที่ซับซ้อน

ต่อ Tailwind v4 เข้า Vite

เปิดโปรเจกต์แล้วแก้ 2 ไฟล์ ไฟล์แรกคือ vite.config.ts — เพิ่มปลั๊กอิน Tailwind

// vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
});

ไฟล์ที่สองคือ src/index.css — ลบเนื้อหาเดิมของ Vite ทิ้งทั้งหมด เหลือบรรทัดเดียว

/* src/index.css */
@import "tailwindcss";
Tailwind v4 ตั้งค่าเป็น CSS ล้วน (เดี๋ยวเจอ @theme ในบทเรียน 05) — ไม่มี tailwind.config.js และไม่ต้องรัน npx tailwindcss init ถ้าคุณเจอบทความหรือวิดีโอสอนแบบนั้น แปลว่าเป็น v3 ของเก่า วิธีสังเกตอีกอย่าง: v3 ใช้ @tailwind base; สามบรรทัดแทน @import "tailwindcss"; บรรทัดเดียว

พิสูจน์ว่าใช้งานได้: แก้ src/App.tsx ให้เหลือแค่นี้ แล้วรัน npm run dev

export default function App() {
  return (
    <h1 className="p-8 text-3xl font-bold text-teal-500">Purity Dashboard</h1>
  );
}

ถ้าเห็นข้อความตัวหนาสีเขียวมิ้นต์ใหญ่ ๆ แปลว่า Tailwind ทำงานแล้ว (ยังไม่ต้องเข้าใจ class พวกนี้ — บทที่ 2 ทั้งบทมีไว้เพื่อการนี้)

โครงโฟลเดอร์

สร้างโฟลเดอร์ว่าง 4 ตัวใน src/ ตามนี้ (ลบ assets/ ของ Vite ทิ้งได้)

src/
  app/         # router, layouts — โครงของแอป
  pages/       # component หนึ่งไฟล์ต่อหนึ่ง route
  components/  # UI ที่ใช้ซ้ำได้ (Sidebar, Navbar และที่จะเกิดจากการ refactor)
  data/        # mock data แยกไว้ ไม่ปนกับ component

โครงนี้เล็กกว่าคอร์ส e-commerce (ที่มี features/) เพราะ workshop นี้เป็นงาน UI ล้วน — หลักการเดิม: โครงเรียบที่สุดที่พองาน อย่าสร้างชั้นที่ยังไม่ได้ใช้

รู้จัก Cursor

Cursor พัฒนาต่อยอดมาจาก VS Code และเพิ่มเครื่องมือ AI เข้ามาใน editor ตอนเปิดครั้งแรก โปรแกรมจะให้ import settings, keybindings และ extensions จาก VS Code ได้ ความรู้และวิธีใช้ VS Code เดิมจึงนำมาใช้ต่อได้ทันที

วิธีใช้ AI ใน Cursor มี 3 ระดับ ใช้ให้ถูกงาน

  • Tab — autocomplete อัจฉริยะระหว่างพิมพ์ เดาบรรทัดถัดไปให้ กด Tab เพื่อรับ เหมาะกับตอนเราเป็นคนเขียนเอง
  • Inline Edit (Cmd+K) — เลือกโค้ดจุดเดียวแล้วสั่งแก้ตรงนั้น เช่น "เปลี่ยนปุ่มนี้เป็นสีแดง" เหมาะกับการแก้เฉพาะจุด
  • Agent panel (Cmd+I) — เครื่องมือหลักของ workshop นี้ ใช้คุยผ่านแชท สั่งงานข้ามหลายไฟล์ สร้างไฟล์ใหม่ รันคำสั่ง และอ่านโปรเจกต์ของเราได้ เหมาะกับงานชิ้นใหญ่อย่าง "สร้างหน้านี้ตาม screenshot"

ในแชทของ Agent มีตัวเลือกโหมด Agent กับ Ask — ต่างกันสำคัญ: Ask ตอบและอธิบายอย่างเดียว ไม่แตะไฟล์ ส่วน Agent ลงมือแก้จริง เวลาอยากปรึกษา ("โครงสร้างนี้โอเคไหม") ใช้ Ask เวลาสั่งงานใช้ Agent

การให้บริบท (context) เป็นส่วนสำคัญของการสั่งงาน พิมพ์ @ ในแชทเพื่อแนบ @Files หรือ @Folders ให้ AI อ่านไฟล์ที่เกี่ยวข้องได้ และเรายังแนบรูปด้วยการลาก screenshot ลงช่องแชทได้โดยตรง ในบทที่ 3 เราจะฝึกแนบภาพพร้อมเขียนคำอธิบายให้ Agent เข้าใจดีไซน์ตรงกับเรา

Project rules — สอน Agent ครั้งเดียว ใช้ได้ทุก prompt

เพื่อไม่ต้องพิมพ์ข้อกำหนดเดิม เช่น "ใช้ TypeScript ใช้ Tailwind และไม่สร้างไฟล์ CSS" ซ้ำทุกครั้ง Cursor ให้เราเขียนกติกาประจำโปรเจกต์ไว้ในโฟลเดอร์ .cursor/rules/ Agent จะอ่านกติกาเหล่านี้โดยอัตโนมัติเมื่อทำงานในโปรเจกต์

สร้างไฟล์ .cursor/rules/project.mdc (นามสกุล .mdc คือ markdown ที่มี frontmatter บอกว่ากติกานี้ใช้เมื่อไหร่ — alwaysApply: true คือใช้เสมอ)

---
description: Purity Dashboard — React + Tailwind conventions
alwaysApply: true
---

- React 19 + TypeScript + Vite; styling ด้วย Tailwind CSS v4 utilities เท่านั้น ห้ามสร้างไฟล์ .css/.scss เพิ่ม
- โครงสร้าง: src/app (router, layouts), src/pages (component ต่อ route), src/components (UI ที่ใช้ซ้ำ), src/data (mock data)
- Component เป็น function component + TypeScript, ไฟล์ละหนึ่ง component, ตั้งชื่อ PascalCase.tsx
- Mobile-first: class ไม่มี prefix คือมือถือ แล้วขยายด้วย md:/lg:/xl:
- ใช้ semantic HTML (aside, nav, header, main, table) และ SVG inline สำหรับไอคอน
- รูปทุกรูปมี alt; ปุ่ม/ลิงก์เป็น <button>/<a> จริง และมี focus-visible state

สังเกตกติกาสองข้อสุดท้ายไว้ แม้จะมี rules แล้ว Agent ก็อาจสร้างโค้ดที่ไม่ตรงตามกติกาได้ rules ช่วยลดความผิดพลาด แต่ไม่ได้แทนการ review ซึ่งเราจะฝึกกันในบทที่ 5

วินัยการใช้ Agent

  • อ่าน diff ทุกไฟล์ก่อนกด Accept — Agent แสดงการแก้ไขเป็น diff ให้ดูเสมอ อ่านให้เข้าใจว่าเปลี่ยนอะไรและตรงกับที่สั่งหรือไม่ก่อนกดรับ
  • ใช้ checkpoint — Cursor เก็บ checkpoint ทุกครั้งที่ Agent แก้โค้ด ถ้าผลลัพธ์เริ่มออกนอกทาง ให้กด restore แล้วย้อนกลับมาลองใหม่ได้
  • งานเล็ก ๆ ทีละงาน — สั่ง "สร้าง sidebar" แล้วตรวจ ดีกว่าสั่ง "สร้างทั้งเว็บ" แล้วได้ diff 30 ไฟล์ที่ตรวจไม่ไหว
หน้าตา UI ของ Cursor เปลี่ยนค่อนข้างเร็ว ชื่อปุ่ม แถบ หรือ shortcut ในบทเรียนอาจต่างจากเวอร์ชันที่คุณใช้ แต่แนวคิดหลักอย่าง agent, context, rules และการ review diff ยังเหมือนเดิม ถ้าหาปุ่มไม่เจอ ให้ดูจากหน้าที่ของเครื่องมือนั้นแทนการจำตำแหน่ง

Commit เก็บไว้

นิสัยจากคอร์ส React: commit เล็ก ๆ บ่อย ๆ ตั้งแต่ตอนนี้

git init
git add .
git commit -m "scaffold: vite + react + ts + tailwind v4 + cursor rules"

ตอนนี้เครื่องมือพร้อมแล้ว ก่อนให้ Agent สร้าง UI เราจะทำความเข้าใจโค้ด Tailwind ให้พออ่านและตรวจงานได้ในบทถัดไป
