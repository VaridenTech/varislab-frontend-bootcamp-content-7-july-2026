ทำไมต้อง pin @faker-js/faker@10.6.0 ให้แน่น

เราพิน Prisma ไว้ที่ 7.10.0 และพิน image postgres:17 มาตั้งแต่บทที่ 5 ด้วยเหตุผลเดียวกันทุกครั้ง: เวอร์ชันถัดไปอาจเปลี่ยนพฤติกรรมโดยไม่ประกาศว่าเป็น breaking change faker ก็เหมือนกัน — รายการคำในแต่ละ locale (ชื่อสินค้า, ชื่อบริษัท, ชื่อวัตถุดิบอาหาร) แก้ไขได้ระหว่าง minor version เสมอ และเพราะเราเรียก faker.seed(20260913) แล้วอ่านผลลัพธ์ที่ได้แบบ deterministic ค่าที่สุ่มออกมาจึงผูกกับเวอร์ชันที่ติดตั้งจริง ไม่ใช่แค่กับตัวเลข seed

สังเกตว่า buildProducts (หัวข้อถัดไป) จะเช็ค id === 1 แล้วเรียกฟังก์ชันนี้แทนการสุ่ม พร้อมเติมชื่อ 'Velvet Matte Lipstick' เข้า usedTitles ของหมวด beauty ไว้ด้วย เพื่อไม่ให้สินค้าชิ้นที่สุ่มถัดไปในหมวดเดียวกันบังเอิญได้ชื่อซ้ำ

สุ่มชื่อไม่ให้ซ้ำ: groceryName และ productName

สินค้าที่เหลือ 207 ชิ้นเรียก generatedProduct ซึ่งเริ่มด้วยการตั้งชื่อผ่านหนึ่งในสองฟังก์ชันนี้ ทั้งคู่ทำงานแบบเดียวกัน: สุ่มคำ แปลงเป็น title case ด้วย titleCase แล้ววนสุ่มใหม่ถ้าชื่อนั้นซ้ำกับชื่อที่ใช้ไปแล้วในหมวดเดียวกัน (usedTitles เป็น Set แยกต่อหมวด ไม่ใช่ตัวเดียวทั้งไฟล์) หมวด groceries ใช้ groceryName ที่สุ่มจากคำศัพท์อาหารสามชนิด (ingredient / fruit / vegetable) ส่วนหมวดอื่นทั้งหมดใช้ productName ที่สุ่มชื่อสินค้าทั่วไปจาก faker

function titleCase(value: string): string {
  return value.replace(/\b\w/g, (letter) => letter.toUpperCase());
}

function groceryName(usedTitles: Set<string>): string {
  let candidate: string;
  do {
    const pick = faker.number.int({ min: 0, max: 2 });
    const word =
      pick === 0 ? faker.food.ingredient() : pick === 1 ? faker.food.fruit() : faker.food.vegetable();
    candidate = titleCase(word);
  } while (usedTitles.has(candidate));
  return candidate;
}

function productName(usedTitles: Set<string>): string {
  let candidate: string;
  do {
    candidate = titleCase(faker.commerce.productName());
  } while (usedTitles.has(candidate));
  return candidate;
}

generatedProduct: สุ่มทุก field ที่ไม่ใช่ id 1

ฟังก์ชันนี้คือที่มาของ 207 ชิ้นที่เหลือ ประเด็นที่ควรสังเกตสามจุด

  • ส่วนลดมีโอกาส 2 ใน 3 — faker.number.int({ min: 0, max: 2 }) !== 0 สุ่มได้ 0, 1 หรือ 2 เท่า ๆ กัน ดังนั้น 1 ใน 3 ของสินค้าจะไม่มีส่วนลด (discountPercentage เป็น null ตรงกับ Float? ในบทที่ 1) ส่วนอีก 2 ใน 3 จะได้ตัวเลข 1–25
  • ตัวเลขทศนิยมรอบสองชั้น — faker.number.float({ fractionDigits: 3 }) ให้ทศนิยมได้เอง แต่การคูณ 100 แล้ว Math.round แล้วหารกลับด้วย 100 คือการล็อกไม่ให้ค่าลอยไปเป็นอะไรแบบ 12.340000000000002 จาก floating-point — ใช้แบบเดียวกันทั้ง rating, width, height, depth และส่วนลด
  • รีวิวสามรายการต่อสินค้าเสมอ — Array.from({ length: 3 }, () => ...) สุ่ม rating 1–5, ประโยคคอมเมนต์สั้น ๆ แบบสุ่มจาก faker, วันที่ในช่วง 180 วันที่ผ่านมา, ชื่อและอีเมลผู้รีวิว — สอดคล้องกับ 3 รีวิวต่อชิ้นที่ตารางเก่าเคยมีตอนดึงจาก dummyjson
function generatedProduct(id: number, slug: string, usedTitles: Set<string>): GeneratedProduct {
  const title = slug === 'groceries' ? groceryName(usedTitles) : productName(usedTitles);
  usedTitles.add(title);
  const hasDiscount = faker.number.int({ min: 0, max: 2 }) !== 0;
  const discountPercentage = hasDiscount
    ? Math.round(faker.number.float({ min: 1, max: 25, fractionDigits: 4 }) * 100) / 100
    : null;
  return {
    id,
    slug,
    title,
    description: faker.commerce.productDescription(),
    price: Number(faker.commerce.price({ min: 4, max: 1999, dec: 2 })),
    discountPercentage,
    rating: Math.round(faker.number.float({ min: 2.5, max: 5, fractionDigits: 3 }) * 100) / 100,
    stock: faker.number.int({ min: 0, max: 100 }),
    tags: [slug, faker.word.noun().toLowerCase()],
    brand: titleCase(faker.company.name()),
    sku: faker.string.alphanumeric({ length: 8, casing: 'upper' }),
    weight: faker.number.int({ min: 1, max: 10 }),
    width: Math.round(faker.number.float({ min: 5, max: 100, fractionDigits: 3 }) * 100) / 100,
    height: Math.round(faker.number.float({ min: 5, max: 100, fractionDigits: 3 }) * 100) / 100,
    depth: Math.round(faker.number.float({ min: 5, max: 100, fractionDigits: 3 }) * 100) / 100,
    warrantyInformation: faker.helpers.arrayElement(WARRANTY),
    shippingInformation: faker.helpers.arrayElement(SHIPPING),
    availabilityStatus: faker.helpers.arrayElement(AVAILABILITY),
    returnPolicy: faker.helpers.arrayElement(RETURN_POLICY),
    minimumOrderQuantity: faker.number.int({ min: 1, max: 50 }),
    barcode: faker.string.numeric(13),
    qrCode: `https://picsum.photos/seed/product-${id}-qr/200/200`,
    images: Array.from(
      { length: faker.number.int({ min: 1, max: 4 }) },
      (_, index) => `https://picsum.photos/seed/product-${id}-${index}/600/600`,
    ),
    thumbnail: `https://picsum.photos/seed/product-${id}-thumb/300/300`,
    createdAt: faker.date.past({ years: 2 }),
    updatedAt: faker.date.recent({ days: 120 }),
    reviews: Array.from({ length: 3 }, () => ({
      rating: faker.number.int({ min: 1, max: 5 }),
      // comment: ประโยคสุ่มสั้น ๆ จาก faker (ดูคำอธิบายด้านบน)
      date: faker.date.recent({ days: 180 }),
      reviewerName: faker.person.fullName(),
      reviewerEmail: faker.internet.email().toLowerCase(),
    })),
  };
}

buildProducts: ที่มาของความ deterministic ทั้งหมด

faker.seed(20260913) ถูกเรียกครั้งเดียวตอนต้นฟังก์ชันนี้ ก่อนวน loop ผ่าน CATEGORIES ทีละหมวดตามลำดับ array แล้ววนสร้างสินค้าตาม count ของหมวดนั้น (จาก COUNT_OVERRIDES หรือ DEFAULT_COUNT) นี่คือเหตุผลที่ลำดับของ CATEGORIES, ค่าใน COUNT_OVERRIDES, และลำดับ field ข้างในทุกฟังก์ชันที่เรียก faker ต้องตรงกับที่พิมพ์ไว้ในบทนี้เป๊ะ — สลับสองหมวดใน CATEGORIES หรือเพิ่มการเรียก faker.xxx() อีกครั้งในฟังก์ชันไหนก็ตาม จะทำให้ทุกอย่างหลังจุดนั้นสุ่มออกมาคนละค่าทันที (คนละ “draw sequence” ของ RNG เดียวกัน)

function buildProducts(): GeneratedProduct[] {
  faker.seed(20260913);
  const products: GeneratedProduct[] = [];
  let nextId = 1;
  for (const [slug] of CATEGORIES) {
    const count = COUNT_OVERRIDES[slug] ?? DEFAULT_COUNT;
    const usedTitles = new Set<string>();
    for (let index = 0; index < count; index++) {
      const id = nextId++;
      if (id === 1) {
        products.push(handAuthoredProductOne(slug));
        usedTitles.add('Velvet Matte Lipstick');
        continue;
      }
      products.push(generatedProduct(id, slug, usedTitles));
    }
  }
  return products;
}

$transaction: ลบ–เติมใหม่ทั้งชุดใน statement เดียว

โครงเดิมจากบทที่ 9 ก่อนหน้ายังอยู่ครบ: ลบตามลำดับ review → product → category (ลูกก่อนแม่), แทรกใหม่ตามลำดับ category → product → review (แม่ก่อนลูก), อ่าน Category กลับมาทำ Map จาก slug ไป id, และห่อทั้งหมดไว้ใน prisma.$transaction(async (tx) => { ... }) เพื่อให้ล้มทั้งชุดหรือสำเร็จทั้งชุด สิ่งที่เปลี่ยนไปมีอย่างเดียว: ไม่มี fetch อีกแล้ว เพราะ products มาจาก buildProducts() ที่รันในหน่วยความจำล้วน ๆ ก่อนเปิด transaction ด้วยซ้ำ

  await prisma.$transaction(async (tx) => {
    await tx.review.deleteMany();
    await tx.product.deleteMany();
    await tx.category.deleteMany();

    await tx.category.createMany({
      data: CATEGORIES.map(([slug, name]) => ({ slug, name })),
    });
    const categoryIdBySlug = new Map(
      (await tx.category.findMany()).map((category) => [category.slug, category.id]),
    );
    const categoryId = (slug: string): number => {
      const id = categoryIdBySlug.get(slug);
      if (id === undefined) {
        throw new Error(`Unknown category slug: ${slug}`);
      }
      return id;
    };

    await tx.product.createMany({
      data: products.map((product) => ({
        id: product.id,
        title: product.title,
        // ...ฟิลด์ที่เหลือส่งตรงจาก product แบนเข้า columns ทั้งหมด
        categoryId: categoryId(product.slug),
      })),
    });

    await tx.review.createMany({
      data: products.flatMap((product) =>
        product.reviews.map((review) => ({
          productId: product.id,
          rating: review.rating,
          comment: review.comment,
          date: review.date,
          reviewerName: review.reviewerName,
          reviewerEmail: review.reviewerEmail,
        })),
      ),
    });
  });

  const reviewCount = products.reduce((count, product) => count + product.reviews.length, 0);
  console.log(`Seeded ${CATEGORIES.length} categories, ${products.length} products, ${reviewCount} reviews`);
}

try {
  await main();
} finally {
  await prisma.$disconnect();
}

ตรวจโค้ดที่ AI สร้าง

  • CATEGORIES มี 24 คู่ เรียงลำดับตรงกับที่ระบุในบทนี้เป๊ะ (สลับลำดับแม้สองหมวดก็ทำให้ค่าที่สุ่มได้เปลี่ยนไปทั้งหมดตามหลังจุดนั้น)
  • faker.seed(20260913) ถูกเรียกครั้งเดียวใน buildProducts ก่อนวน loop — ไม่มีการเรียก faker.seed() ซ้ำที่อื่น
  • product id 1 เป็นค่าคงที่ ไม่มี faker. ปนอยู่ในฟังก์ชันที่สร้างมันเลยสักบรรทัด
  • มี createMany สามครั้งพอดี (category, product, review) ไม่มี upsert และไม่มี for/map ที่เรียก create ทีละชิ้น
  • ลำดับ deleteMany คือ review → product → category และทุกคำสั่งข้างในเรียกผ่าน tx ไม่ใช่ prisma
  • warranty/shipping/availability/returnPolicy สุ่มจาก faker.helpers.arrayElement บน array ตัวเลือกคงที่ ไม่ใช่ข้อความอิสระจาก faker
  • ไม่มี any และไม่มี non-null assertion (!) — หา categoryId จาก slug ด้วยฟังก์ชันที่ throw Error เมื่อไม่พบ
  • package.json มี @faker-js/faker ใน devDependencies และ "db:seed": "tsx prisma/seed.ts" ใน scripts

AI มักพลาดตรงนี้: ปล่อยให้สินค้า id 1 สุ่มไปด้วยแทนที่จะเขียนด้วยมือ (ได้ผลรันแต่ค่าจะไม่ตรงกับที่บทถัดไปพิมพ์ไว้เลย) หรือสุ่มข้อความอิสระให้ warrantyInformation/returnPolicy แทนการสุ่มจาก array ตัวเลือกที่กำหนด (ทำให้ค่าไม่อยู่ในเซตที่คาดไว้)
