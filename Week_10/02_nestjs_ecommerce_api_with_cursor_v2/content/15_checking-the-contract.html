ทำสัญญาให้รันได้จริงด้วย zod

เมื่อจบบทนี้ คุณจะสามารถ

  • ยกระดับ contract:check ที่เขียนเองไว้ตั้งแต่บทที่ 12 ให้ตรวจ โครงสร้างทั้งก้อน ของ response ด้วย zod ไม่ใช่แค่ field ที่เราอุตส่าห์นึกออกและเขียนเช็คไว้เอง
  • อธิบายว่า .strict() ให้อะไรเพิ่มจาก z.object({...}) เฉย ๆ — มันปฏิเสธ field ที่เกินมาหรือถูกเปลี่ยนชื่อ ไม่ใช่แค่ field ที่หายไป
  • อ่าน error ที่ zod โยนออกมาตอน .parse() ล้มเหลว (ZodError) เพื่อหาว่า field ไหนพังและพังเพราะอะไร โดยไม่ต้องเขียนตัวหา diff เอง

check ที่เขียนเอง จับได้แค่สิ่งที่เรานึกถึง

npm run contract:check มีอยู่แล้วตั้งแต่บทที่ 12 และโตมาเป็นเก้า check ในบทที่ 13–14 — มันแก้ปัญหา "ไล่ยิง curl ใหม่ทุกครั้ง" ไปแล้วเรียบร้อย แต่มันมีช่องโหว่ที่ใหญ่กว่าเดิมซ่อนอยู่: มันตรวจเฉพาะสิ่งที่เราเขียนสั่งให้มันตรวจ ตอนนี้มันดู status, จำนวน category, จำนวนคีย์ของสินค้าชิ้นที่ 1, และข้อความ 404 — เท่านั้น

แปลว่าถ้า mapper เปลี่ยน thumbnail เป็น thumbnailUrl เงียบ ๆ จำนวนคีย์ยังเป็น 22 เท่าเดิม ทุกบรรทัดยังขึ้น ✅ และสัญญาพังไปแล้วโดยไม่มีใครรู้ การไล่เขียน assert ให้ครบทั้ง 22 คีย์ของทุก endpoint ด้วยมือเป็นงานที่ไม่มีใครเขียนจบและไม่มีใครอยากดูแล

สิ่งที่เราต้องการคือ regression test ของสัญญา ที่ตรวจ body ทั้งก้อน: คำสั่งเดิมที่ยิง request ชุดเดิมไปที่ API ของเรา แต่คราวนี้เทียบ response ทั้งอันกับ schema ที่เขียนจาก docs/api-spec.md ไม่ใช่เทียบทีละ field ที่เรานึกออก — และยังคืน exit code ที่ไม่ใช่ศูนย์เมื่อพังเหมือนเดิม เพื่อให้เอาไปแขวนใน CI ได้ในอนาคต

จุดที่ทำให้ script นี้ต่างจาก unit test ทั่วไปคือมันยิงAPI ของเราเองที่กำลังรันอยู่จริง ไม่ได้ mock อะไรเลย มันจึงตรวจสิ่งที่ TypeScript ตรวจให้ไม่ได้: TypeScript เช็คว่า ProductResponseDto ที่คุณ ประกาศไว้ ถูกต้องตอน compile แต่ไม่รู้ว่า JSON ที่ออกไปจริงทาง HTTP ตรงกับที่ประกาศไว้หรือเปล่า ถ้า mapper คืนค่าผิดชนิด หรือมีใคร (หรือ AI) เปลี่ยนชื่อ field ไปเงียบ ๆ แต่ยังพอ compile ผ่านได้ด้วยเหตุผลบางอย่าง TypeScript จะไม่รู้เรื่องเลยจนกว่าจะมีคนอ่าน response จริง — นี่คือช่องว่างที่ zod ปิดให้ที่ขอบเขต JSON

ทำไม npm run contract:check ต้องใช้ tsx ไม่ใช่ node ตรง ๆ

schema ทั้งหมดแยกไว้ในไฟล์ scripts/contract-schemas.ts ต่างหาก ไม่ได้เขียนปนอยู่ใน contract-check.ts เพราะบทที่ 19 จะ import schema ชุดเดียวกันนี้ไปใช้ซ้ำ (สำหรับ check ที่ 10 ของ POST /carts/add) และเพราะไฟล์ schema ล้วน ๆ อ่านและรีวิวแยกจากตัว script ที่รันจริงได้ง่ายกว่า

scripts/contract-check.ts จึงมีบรรทัด import { ... } from './contract-schemas.js' อยู่บนสุด — ต่างจากฉบับที่คุณเขียนเองในบทที่ 12 ที่ไม่มี import เลยสักบรรทัด จึงสั่ง node ตรง ๆ ได้ การลบ type ออกอย่างเดียว (type stripping) ที่ Node ทำได้เองตอนรันไฟล์ .ts เดี่ยว ๆ ไม่พอสำหรับกรณีนี้ เพราะตอนนี้มีการ import ข้ามไฟล์ .ts สองไฟล์ ซึ่งต้องมีตัว resolve module ที่รู้จักรูปแบบของ TypeScript จริง ๆ (แม้ path ที่ import จะเขียนด้วยนามสกุล .js ตามธรรมเนียม ESM+TypeScript แต่ไฟล์จริงบนดิสก์คือ .ts) เราจึงใช้ tsx ตัวเดียวกับที่ db:seed ใช้อยู่แล้วมารันแทน node ตรง ๆ

fetch และ top-level await ในลูปของ script นี้เป็นของที่มีใน Node อยู่แล้ว ไม่ต้องติดตั้ง node-fetch หรืออะไรเพิ่ม

เป้าหมายของบทนี้

รายการด้านล่างคือไฟล์ที่เปลี่ยนในโค้ดอ้างอิงของคอร์ส — ใช้เป็นแผนที่ตอนเทียบงาน ไม่ใช่ข้อบังคับ Cursor ของคุณอาจวางไฟล์หรือตั้งชื่อต่างไปได้ ขอแค่ผ่านผลลัพธ์ที่ต้องได้ใน prompt

  • package.json — ในโค้ดอ้างอิง: "contract:check": "tsx scripts/contract-check.ts" / ไม่แก้ script อื่นและไม่เพิ่ม dependency นอกจาก zod

ไม่มีไฟล์ใน src/ ถูกแตะในบทนี้เลย — สิ่งที่เราสร้างคือเครื่องมือตรวจ ไม่ใช่ฟีเจอร์ และ schema พวกนี้ไม่ได้มาแทนที่ ProductResponseDto ที่มีอยู่แล้ว: ProductResponseDto ยังเป็น type ตอน compile ที่ Swagger CLI plugin อ่านในบทที่ 21–22 อยู่เหมือนเดิม ส่วน zod schema ในบทนี้เป็นการตรวจแยกอีกชั้นหนึ่งตอนruntime ว่า response จริงที่ออกไปทาง HTTP ยังตรงกับสัญญาอยู่หรือเปล่า — ไม่ใช่รูปทรงที่สามอันดับที่มาแข่งกัน แต่เป็นเครื่องมือคนละงาน: DTO บอก compiler, zod บอกตอนรันจริง

สั่ง Cursor เขียน schema และ script ตรวจสัญญา

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: before contract check") ปล่อยให้ API รันอยู่ที่ http://localhost:3000 ไว้ เพราะเราจะรันตรวจทันทีหลังได้โค้ด

ตรวจโค้ดที่ AI สร้าง

  • ทุก object schema เต็มรูป (product, category, envelope, error) ปฏิเสธ field ที่ไม่รู้จัก — ทดสอบได้จริงด้วยการเปลี่ยนชื่อ field ในส่วนตรวจว่าใช้งานได้จริงด้านล่าง ถ้าตรวจแล้วยังขึ้น ✅ แปลว่า schema ปล่อยผ่านเงียบ ๆ
  • รัน npm run contract:check ได้เก้าบรรทัดตามลำดับในผลลัพธ์ที่ต้องได้ และไม่มี check ของ POST /carts/add ปนมา เพราะ endpoint นั้นยังไม่มีอยู่จริงในบทนี้
  • บรรทัด ❌ บอกได้ว่า field ไหนพังและพังเพราะอะไร (มี path) — ไม่ใช่ข้อความคงที่อย่าง "invalid response"
  • import ข้ามไฟล์ในโปรเจกต์ลงท้าย .js ตามกติกาใน .cursor/rules (แม้ไฟล์จริงคือ .ts — ไม่ใช่พิมพ์ผิด)
  • URL ที่ยิงมีแค่ API ของเราเอง (เปลี่ยนได้ด้วย LOCAL_URL) ไม่มี URL ของ server ตัวที่สองหลงเหลือในไฟล์
  • มี ❌ แล้ว echo $? ไม่ใช่ 0
  • git status ไม่มีไฟล์ใน src/ และไม่มีไฟล์ที่ไม่เกี่ยวกับ script ตรวจสัญญาถูกแก้, dependency ที่เพิ่มมีแค่ zod และไม่มี any, as หรือ !

AI มักพลาดตรงนี้: เขียน schema เป็น z.object({...}) เฉย ๆ โดยไม่ปิดท้ายด้วย .strict() — โค้ดยัง compile ผ่านและดูทำงานถูกในตอนแรก แต่ zod โหมดปกติ (ที่เรียกว่า "strip") จะเงียบ ๆ ตัดทุก field ที่ไม่รู้จักทิ้งไปโดยไม่ error เลย ถ้าวันหนึ่งมีใคร (หรือ AI ตัวอื่น) เปลี่ยนชื่อ field ใน mapper หรือเผลอเพิ่ม field แปลกปลอมเข้ามา check จะยังขึ้น ✅ เหมือนไม่มีอะไรเกิดขึ้น ทั้งที่ response จริงเปลี่ยนไปแล้ว อีกจุดที่พลาดได้คือใช้ .safeParse() แล้วเช็คแค่ result.success โดยไม่พิมพ์ result.error.issues ออกมา — script ยังรายงาน ❌ ถูกต้องอยู่ แต่บรรทัด error จะไม่บอกว่า field ไหนพังเพราะอะไร ทำให้ debug ช้าลงกลับไปเหมือนสมัยที่ยังไม่มี schema เลย

โค้ดอ้างอิงของบทนี้ — เป็นหนึ่งในวิธีที่ถูก ของคุณไม่จำเป็นต้องเหมือนทุกบรรทัด ขอแค่ผ่านผลลัพธ์ที่ต้องได้ (แต่บทที่ 19 จะอ้างชื่อ cartProductSchema/orderResponseSchema และ array checks ถ้าของคุณตั้งชื่อต่างไปก็ไม่เป็นไร Cursor ในบทนั้นจะอ่านจากโค้ดของคุณเอง):

scripts/contract-schemas.ts

import { z } from 'zod';

export const dimensionsSchema = z.object({
  width: z.number(),
  height: z.number(),
  depth: z.number(),
});

export const reviewSchema = z.object({
  rating: z.number().int().min(1).max(5),
  comment: z.string(),
  date: z.iso.datetime(),
  reviewerName: z.string(),
  reviewerEmail: z.email(),
});

export const metaSchema = z.object({
  createdAt: z.iso.datetime(),
  updatedAt: z.iso.datetime(),
  barcode: z.string(),
  qrCode: z.url(),
});

export const productSchema = z
  .object({
    id: z.number().int(),
    title: z.string(),
    description: z.string(),
    category: z.string(),
    price: z.number(),
    discountPercentage: z.number().optional(),
    rating: z.number(),
    stock: z.number().int(),
    tags: z.array(z.string()),
    brand: z.string(),
    sku: z.string(),
    weight: z.number(),
    dimensions: dimensionsSchema,
    warrantyInformation: z.string(),
    shippingInformation: z.string(),
    availabilityStatus: z.string(),
    reviews: z.array(reviewSchema),
    returnPolicy: z.string(),
    minimumOrderQuantity: z.number().int(),
    meta: metaSchema,
    images: z.array(z.url()),
    thumbnail: z.url(),
  })
  .strict();

export const categorySchema = z
  .object({ slug: z.string(), name: z.string(), url: z.url() })
  .strict();

export const listEnvelopeSchema = z
  .object({
    products: z.array(productSchema),
    total: z.number().int(),
    skip: z.number().int(),
    limit: z.number().int(),
  })
  .strict();

export const errorSchema = z
  .object({
    message: z.union([z.string(), z.array(z.string())]),
    error: z.string(),
    statusCode: z.number(),
  })
  .strict();

export const cartProductSchema = z
  .object({
    id: z.number().int(),
    title: z.string(),
    price: z.number(),
    quantity: z.number().int(),
    total: z.number(),
    discountPercentage: z.number().optional(),
    discountedPrice: z.number(),
    thumbnail: z.url(),
  })
  .strict();

export const orderResponseSchema = z
  .object({
    id: z.number().int(),
    userId: z.number().int(),
    products: z.array(cartProductSchema),
    total: z.number(),
    discountedTotal: z.number(),
    totalProducts: z.number().int(),
    totalQuantity: z.number().int(),
  })
  .strict();

scripts/contract-check.ts

import {
  categorySchema,
  errorSchema,
  listEnvelopeSchema,
  productSchema,
} from './contract-schemas.js';

const BASE = process.env.LOCAL_URL ?? 'http://localhost:3000';

interface Check {
  name: string;
  run: () => Promise<void>;
}

async function getJson(path: string, init?: RequestInit) {
  const response = await fetch(`${BASE}${path}`, init);
  const body = await response.json();
  return { status: response.status, body };
}

      if (status !== 200) throw new Error(`status ${status}`);
      const categories = categorySchema.array().parse(body);
      if (categories.length !== 24) throw new Error(`expected 24 categories, got ${categories.length}`);
    },
  },
  {
    name: 'GET /products?limit=5&skip=0 → limit and skip echo the request',
    run: async () => {
      const { status, body } = await getJson('/products?limit=5&skip=0');
      if (status !== 200) throw new Error(`status ${status}`);
      const envelope = listEnvelopeSchema.parse(body);
      if (envelope.limit !== 5 || envelope.products.length !== 5) {
        throw new Error('limit did not echo the request');
      }
    },
  },
  {
    name: 'GET /products?limit=0 → 400 (out of range)',
    run: async () => {
      const { status, body } = await getJson('/products?limit=0');
      if (status !== 400) throw new Error(`expected 400, got ${status}`);
      errorSchema.parse(body);
    },
  },
  {
    name: 'GET /products?limit=101 → 400 (out of range)',
    run: async () => {
      const { status, body } = await getJson('/products?limit=101');
      if (status !== 400) throw new Error(`expected 400, got ${status}`);
      errorSchema.parse(body);
    },
  },
  {
    name: 'GET /products/1 → validated product',
    run: async () => {
      const { status, body } = await getJson('/products/1');
      if (status !== 200) throw new Error(`status ${status}`);
      productSchema.parse(body);
    },
  },
  {
    name: 'GET /products/9999 → 404 with message',
    run: async () => {
      const { status, body } = await getJson('/products/9999');
      if (status !== 404) throw new Error(`expected 404, got ${status}`);
      errorSchema.parse(body);
    },
  },
  {
    name: 'GET /products/abc → 400 with message',
    run: async () => {
      const { status, body } = await getJson('/products/abc');
      if (status !== 400) throw new Error(`expected 400, got ${status}`);
      errorSchema.parse(body);
    },
  },
  {
    name: 'GET /products/category/groceries?limit=20&skip=0 → total 27',
    run: async () => {
      const { status, body } = await getJson('/products/category/groceries?limit=20&skip=0');
      if (status !== 200) throw new Error(`status ${status}`);
      const envelope = listEnvelopeSchema.parse(body);
      if (envelope.total !== 27) throw new Error(`expected total 27, got ${envelope.total}`);
    },
  },
  {
    name: 'GET /products/category/nope?limit=5&skip=0 → 200, empty envelope',
    run: async () => {
      const { status, body } = await getJson('/products/category/nope?limit=5&skip=0');
      if (status !== 200) throw new Error(`status ${status}`);
      const envelope = listEnvelopeSchema.parse(body);
      if (envelope.products.length !== 0 || envelope.total !== 0) {
        throw new Error('unknown category should be empty, not an error');
      }
    },
  },
];
// Task 14 (lesson 19) appends a tenth check here — POST /carts/add → 201 —
// once that endpoint exists. Do not add it in this task: a student running
// this script at lesson 15 doesn't have /carts/add yet (it arrives at
// lesson 19), and a check that can never pass at the point it's introduced
// is worse than not having it yet.

let failures = 0;
for (const check of checks) {
  try {
    await check.run();
    console.log(`✅ ${check.name}`);
  } catch (error) {
    failures += 1;
    console.log(`❌ ${check.name}`);
    console.log(`   ${error instanceof Error ? error.message : String(error)}`);
  }
}
process.exit(failures === 0 ? 0 : 1);
