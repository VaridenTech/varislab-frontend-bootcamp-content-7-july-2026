คำสั่ง SQL ที่ซับซ้อน

ต่อไปเราจะเพิ่ม Table boards และ comments ให้ระบบกระดานข้อความ ทุก Comment ต้องรู้ว่าใครเป็นคนเขียนและอยู่บน Board ไหน จึงต้องเชื่อมไปยัง Table users และ boards นี่คือความสัมพันธ์ที่ Relational Database จัดการได้ดี

Foreign Key

มาดู Schema ของ users, boards และ comments ทั้งหมดพร้อมกัน

คุณไม่จำเป็นต้องเรียกใช้สิ่งเหล่านี้หากคุณรันคำสั่ง SQL ตัวอย่างก่อนหน้านี้ นี่เป็นเพียงเพื่อให้คุณดูสคีมา


CREATE TABLE users (
  user_id INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  username VARCHAR ( 25 ) UNIQUE NOT NULL,
  email VARCHAR ( 50 ) UNIQUE NOT NULL,
  full_name VARCHAR ( 100 ) NOT NULL,
  last_login TIMESTAMP,
  created_on TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE boards (
  board_id INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  board_name VARCHAR ( 50 ) UNIQUE NOT NULL,
  board_description TEXT NOT NULL
);

CREATE TABLE comments (
  comment_id INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  user_id INT REFERENCES users(user_id) ON DELETE CASCADE,
  board_id INT REFERENCES boards(board_id) ON DELETE CASCADE,
  comment TEXT NOT NULL,
  time TIMESTAMP
);
  • Data Type ใหม่คือ TEXT ซึ่งใช้เก็บข้อความโดยไม่ต้องกำหนดความยาวสูงสุดแบบ VARCHAR
  • user_id INT REFERENCES users(user_id) สร้าง Foreign Key ชนิด Integer ที่อ้างถึง Primary Key user_id ใน Table users ชื่อ Field ฝั่งนี้กับฝั่งที่อ้างถึงไม่จำเป็นต้องเหมือนกัน ขอเพียงระบุ Table และ Field ปลายทางให้ถูกต้อง
  • ON DELETE CASCADE บอก PostgreSQL ว่าเมื่อลบผู้ใช้ ให้ลบ Comment ของผู้ใช้นั้นตามไปด้วย ถ้าไม่ระบุจะมีพฤติกรรมเหมือน ON DELETE NO ACTION คือไม่ยอมลบผู้ใช้ที่ยังมี Comment อ้างถึง อีกทางเลือกคือ ON DELETE SET NULL ซึ่งเก็บ Comment ไว้แต่เปลี่ยน user_id เป็น NULL
  • board_id ใช้หลักการเดียวกัน แต่อ้างถึง Table boards

ถ้ายังไม่มีข้อมูลตัวอย่าง ให้วาง SQL ชุดนี้ ลงใน psql แล้วรอให้ Script ทำงานจนเสร็จ

JOIN

สมมติว่าเราต้องแสดงรายการ Comment พร้อมข้อความตัวอย่างบนหน้า Board เริ่มจาก Query ข้อมูลใน Table comments ก่อน

SELECT comment_id, user_id, LEFT(comment, 20) AS preview FROM comments WHERE board_id = 39;
  • ฟังก์ชัน LEFT คืนตัวอักษรจำนวนที่กำหนดจากด้านซ้ายของ String เราใช้เพื่อให้ข้อความตัวอย่างสั้นและอ่านง่าย ส่วน RIGHT ทำงานแบบเดียวกันจากด้านขวา
  • AS ใช้ตั้งชื่อ Column ในผลลัพธ์ ถ้าไม่ตั้งชื่อ ค่านี้จะอยู่ใต้ชื่อ left ซึ่งสื่อความหมายไม่ชัด

ข้อมูลนี้ยังไม่พอสำหรับหน้าเว็บ เพราะผู้ใช้ต้องการเห็น Username ไม่ใช่แค่ user_id แต่ Username อยู่ใน Table users เราจึงต้อง JOIN สอง Table เข้าด้วยกัน

SELECT
  comment_id, comments.user_id, users.username, time, LEFT(comment, 20) AS preview
FROM
  comments
INNER JOIN
  users
ON
  comments.user_id = users.user_id
WHERE
  board_id = 39;

INNER JOIN จับคู่ Row จากสอง Table ตามเงื่อนไขใน ON ตัวอย่างนี้รวม Comment กับ User เมื่อ user_id ตรงกัน จึงดึง Username มาแสดงร่วมกับ Comment ได้

INNER JOIN คืนเฉพาะ Row ที่จับคู่กันได้ทั้งสองฝั่ง ถ้า Comment ไม่มี User ที่ตรงกัน Comment นั้นจะไม่อยู่ในผลลัพธ์ แต่ใน Schema นี้ Foreign Key ช่วยรับประกันว่า user_id ทุกค่าต้องมีอยู่ใน Table users

LEFT JOIN เก็บทุก Row จาก Table ฝั่งซ้ายไว้ แม้ไม่มีข้อมูลตรงกันฝั่งขวา ส่วน RIGHT JOIN ทำตรงกันข้าม เช่น เก็บ User ไว้แม้ยังไม่มี Comment

FULL OUTER JOIN เก็บทุก Row จากทั้งสอง Table ไม่ว่าจะจับคู่กันได้หรือไม่

CROSS JOIN จับทุก Row ฝั่งหนึ่งเข้ากับทุก Row อีกฝั่ง หรือที่เรียกว่า Cartesian product ถ้า Table ละ 1,000 Row ผลลัพธ์จะมี 1,000,000 Row จึงต้องใช้ด้วยความระมัดระวัง

Table ยัง JOIN กับตัวเองได้ เรียกว่า Self Join เช่น Table พนักงานที่มี Field อ้างถึงหัวหน้าหรือผู้ใต้บังคับบัญชาซึ่งอยู่ใน Table เดียวกัน

งานส่วนใหญ่ใช้ INNER JOIN และ LEFT JOIN เป็นหลัก

อีกทางเลือกคือ NATURAL JOIN ซึ่งให้ Database หา Column ชื่อเดียวกันมาจับคู่ให้อัตโนมัติ

SELECT
  comment_id, comments.user_id, users.username, time, LEFT(comment, 20) AS preview
FROM
  comments
NATURAL INNER JOIN
  users
WHERE
  board_id = 39;

คำสั่งนี้ให้ผลเหมือนตัวอย่างด้านบน โดย NATURAL JOIN เป็นการบอก PostgreSQL ว่า "คอลัมน์ในสองตารางนี้ใช้ชื่อเดียวกัน ให้จับคู่คอลัมน์เหล่านั้นเข้าด้วยกันได้เลย" วิธีนี้สะดวกเมื่อชื่อคอลัมน์ตรงกัน แต่โดยทั่วไปการระบุเงื่อนไข JOIN ให้ชัดเจนจะสื่อเจตนาได้ดีกว่า จึงควรใช้ NATURAL JOIN อย่างระมัดระวัง

Subquery

ถ้าต้องการหา Comment ทั้งหมดของ Maynord Simonich เราอาจ Query หา user_id ก่อนแล้วค่อย Query Comment อีกครั้ง หรือรวมสองขั้นตอนเป็น Query เดียวด้วย Subquery

SELECT comment_id, user_id, LEFT(comment, 20) FROM comments WHERE user_id = (SELECT user_id FROM users WHERE full_name = 'Maynord Simonich');

Subquery ด้านในหา ID ของ Maynord แล้วส่งค่าให้ Query ด้านนอกทันที ตัวอย่างนี้คาดว่า Subquery ต้องคืนมาเพียงหนึ่ง Row ไม่เช่นนั้น Query จะล้มเหลว โดยทั่วไปเราครอบ Subquery ไว้ด้วย () และยังซ้อน Subquery หลายชั้นได้เมื่อจำเป็น

GROUP BY

ถ้าต้องทำรายงานสิบ Board ที่มี Comment มากที่สุด เราต้องจัดกลุ่ม Comment ตามชื่อ Board แล้วนับจำนวนในแต่ละกลุ่ม

SELECT
  boards.board_name, COUNT(*) AS comment_count
FROM
  comments
INNER JOIN
  boards
ON
  boards.board_id = comments.board_id
GROUP BY
  boards.board_name
ORDER BY
  comment_count DESC
LIMIT 10;

GROUP BY รวม Row ที่มี board_name เดียวกันเป็นกลุ่ม แล้ว COUNT(*) นับจำนวน Comment ในแต่ละกลุ่ม จากนั้นเรียงจากมากไปน้อยและเลือกสิบอันดับแรก

ถ้าต้องการ Board ที่มี Comment น้อยที่สุด เราเปลี่ยนเป็น ASC ได้ แต่ยังมีกรณีสำคัญ: Board ที่ไม่มี Comment เลยจะไม่อยู่ในผลลัพธ์ของ INNER JOIN

SELECT
  boards.board_name, COUNT(*) AS comment_count
FROM
  comments
INNER JOIN
  boards
ON
  boards.board_id = comments.board_id
GROUP BY
  boards.board_name
ORDER BY
  comment_count ASC
LIMIT 10;

เพื่อให้ Board ว่างแสดงด้วย เราใช้ RIGHT JOIN เพื่อเก็บทุก Board ไว้ และเปลี่ยนจาก COUNT(*) เป็น COUNT(comment_id) เพราะ * จะนับ Row ของ Board ว่างเป็น 1 แต่ comment_id ของ Row นั้นเป็น NULL จึงได้จำนวน Comment ที่ถูกต้องคือ 0

SELECT
  boards.board_name, COUNT(comment_id) AS comment_count
FROM
  comments
RIGHT JOIN
  boards
ON
  boards.board_id = comments.board_id
GROUP BY
  boards.board_name
ORDER BY
  comment_count;

กรณีนี้เตือนให้เรารู้โครงสร้างข้อมูล เข้าใจผลลัพธ์ที่คาดหวัง และตรวจข้อจำกัดของ Query เสมอ เพราะ Query ที่รันผ่านไม่ได้แปลว่าผลลัพธ์ถูกต้องทุกกรณี
