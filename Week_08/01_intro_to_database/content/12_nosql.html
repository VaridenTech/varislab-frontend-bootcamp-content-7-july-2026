รู้จักฐานข้อมูล NoSQL

มาดูกระบวนทัศน์ที่สองของฐานข้อมูล ฐานข้อมูล NoSQL กัน คำว่า "NoSQL" เป็นคำศัพท์ที่แพร่หลายและจริงๆ แล้วไม่ได้มีความหมายมากนัก เมื่อคุณพูดว่า NoSQL คุณกำลังบอกว่ามันไม่ใช่แค่ฐานข้อมูลเชิงสัมพันธ์ สิ่งนี้อาจคลุมเครือมากยิ่งขึ้นเมื่อคุณตระหนักว่าฐานข้อมูล NoSQL บางตัวสามารถจัดการกับคำสั่ง SQL ได้ โดยรวมแล้ว มันเป็นคำศัพท์ทางการตลาดที่ไม่มีประโยชน์ที่ฉันใส่ไว้ที่นี่เพียงเพราะว่าคุณจะเห็นมันทุกที่ โดยพื้นฐานแล้วคุณสามารถหมายถึง "ไม่ใช่ Postgres/MySQL/SQL Server/etc"

การแยกแยะว่าฐานข้อมูล NoSQL ประเภทใดที่เราจะพูดถึงจะมีประโยชน์มากกว่า ในส่วนนี้ เราจะพูดถึงฐานข้อมูล ตามเอกสาร กับ MongoDB มีฐานข้อมูล NoSQL อื่นๆ มากมาย และหลายฐานข้อมูลมีความแตกต่างกันค่อนข้างมาก แต่ยังคงรวมเป็นฐานข้อมูล "NoSQL"

เหตุใดจึงเลือกฐานข้อมูลตามเอกสาร

มีเหตุผลหลายประการในการเลือกแต่ละฐานข้อมูลเหล่านี้ และมีหลายเหตุผลที่ทับซ้อนกัน สิ่งที่ฉันจะแสดงให้คุณดูส่วนใหญ่ในวันนี้คือสิ่งที่ฉันเรียกว่าฐานข้อมูล "workhorse": พวกเขาสามารถจัดการงานที่มีจุดประสงค์ทั่วไปได้มากมาย และคุณไม่จำเป็นต้องมีข้อได้เปรียบเฉพาะเจาะจงที่คุณต้องการใช้ คุณเพียงแค่ต้องมีฐานข้อมูล

ด้วยฐานข้อมูลตามเอกสาร ข้อดีที่ชัดเจนและสำคัญที่สุดประการหนึ่งก็คือข้อมูลของคุณไม่มีโครงสร้างโดยสิ้นเชิงและก็ไม่เป็นไร ด้วยฐานข้อมูลเชิงสัมพันธ์ คุณจะต้องกำหนดรูปร่างของข้อมูลล่วงหน้า คุณจะพูดประมาณว่าตารางฐานข้อมูลนี้มีสามคอลัมน์ ชื่อเป็นสตริง อายุเป็นจำนวนเต็ม ด้วยฐานข้อมูลแบบเอกสาร คุณเพียงแค่เริ่มเขียนออบเจ็กต์ลงในฐานข้อมูลและมันจะรองรับสิ่งนั้น เอกสารบางฉบับอาจมีช่องบางช่องและบางช่องก็มีช่องอื่นๆ ได้ มันขึ้นอยู่กับคุณทั้งหมด อาจเป็นปัญหาเล็กน้อยเมื่อคุณสะกดชื่อฟิลด์ผิด เนื่องจากฐานข้อมูลจะยินดียอมรับชื่อฟิลด์ที่สะกดผิดเป็นฟิลด์ใหม่ ไม่ใช่ว่าฉันเคยทำอย่างนั้นมาก่อน 😅

ฐานข้อมูลตามเอกสารเช่น MongoDB รู้สึกคุ้นเคยกับนักพัฒนา JavaScript มาก มันเหมือนกับการนำอ็อบเจ็กต์ JavaScript ปกติมาโยนลงในฐานข้อมูลเพื่อเรียกค้นในภายหลัง

ฐานข้อมูล NoSQL อื่นๆ ที่ควรรู้

มีฐานข้อมูล NoSQL ประเภทอื่นๆ อีกมากมายที่มีการเขียนใหม่ค่อนข้างบ่อย วันนี้เราจะเน้นไปที่ MongoDB แต่คุณควรลองดูฐานข้อมูล NoSQL ที่ยอดเยี่ยมอื่นๆ เช่น Cassandra, Couchbase, Firebase Firestore และอื่นๆ
