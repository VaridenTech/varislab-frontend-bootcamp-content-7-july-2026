รู้จักฐานข้อมูล NoSQL

ต่อไปมาดู Database อีกกลุ่มที่เรียกรวม ๆ ว่า NoSQL คำนี้กว้างมากและบอกเราเพียงว่า “ไม่ใช่ Relational Database แบบ PostgreSQL, MySQL หรือ SQL Server” เท่านั้น ที่ชวนสับสนคือ NoSQL บางตัวยังรองรับ SQL ด้วย ถึงคำนี้จะไม่แม่นนัก แต่เราจะเจอบ่อยในเอกสารและบทสนทนาทั่วไป

การแยกแยะว่าฐานข้อมูล NoSQL ประเภทใดที่เราจะพูดถึงจะมีประโยชน์มากกว่า ในส่วนนี้ เราจะพูดถึงฐานข้อมูล ตามเอกสาร กับ MongoDB มีฐานข้อมูล NoSQL อื่นๆ มากมาย และหลายฐานข้อมูลมีความแตกต่างกันค่อนข้างมาก แต่ยังคงรวมเป็นฐานข้อมูล "NoSQL"

เหตุใดจึงเลือกฐานข้อมูลตามเอกสาร

Database แต่ละแบบมีจุดเด่นต่างกันและหลายกรณีก็ใช้แทนกันได้ ตัวที่เราจะเรียนเป็น Database แบบ Workhorse คือรองรับงานทั่วไปได้กว้าง ไม่จำเป็นต้องมี Use Case เฉพาะทางมากจึงจะคุ้มค่า

จุดเด่นของ Document Database คือข้อมูลไม่จำเป็นต้องมีโครงสร้างเหมือนกันทุก Document ต่างจาก Relational Database ที่ต้องกำหนด Column และ Data Type ล่วงหน้า เราสามารถเขียน Object ลงไปได้เลย และแต่ละ Document มี Field ต่างกันได้ ความยืดหยุ่นนี้มี Trade-off เช่น ถ้าสะกดชื่อ Field ผิด Database อาจยอมรับเป็น Field ใหม่โดยไม่แจ้ง Error

Document Database อย่าง MongoDB มักคุ้นมือสำหรับนักพัฒนา JavaScript เพราะข้อมูลมีหน้าตาคล้าย Object ที่เราใช้ในโค้ด สามารถเก็บแล้ว Query กลับมาได้โดยไม่ต้องแปลงเป็น Row และ Column ก่อน

ฐานข้อมูล NoSQL อื่นๆ ที่ควรรู้

มีฐานข้อมูล NoSQL ประเภทอื่นๆ อีกมากมายที่มีการเขียนใหม่ค่อนข้างบ่อย วันนี้เราจะเน้นไปที่ MongoDB แต่คุณควรลองดูฐานข้อมูล NoSQL ที่ยอดเยี่ยมอื่นๆ เช่น Cassandra, Couchbase, Firebase Firestore และอื่นๆ
