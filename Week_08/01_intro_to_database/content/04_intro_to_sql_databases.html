รู้จักฐานข้อมูล SQL

สิ่งแรกอันดับแรก: เมื่อฉันพูดว่าฐานข้อมูล SQL ฉันหมายถึงฐานข้อมูลเชิงสัมพันธ์ (หรือเรียกโดยย่อว่า RDBMS หรือระบบจัดการฐานข้อมูลเชิงสัมพันธ์) สิ่งสำคัญที่ควรทราบคือฐานข้อมูลเชิงสัมพันธ์บางฐานข้อมูลเท่านั้นที่ใช้ SQL และฐานข้อมูลที่ไม่ใช่เชิงสัมพันธ์ทั้งหมดไม่ได้ใช้ SQL (เช่น ฐานข้อมูล NoSQL บางตัวใช้ SQL) อย่างไรก็ตาม ฉันใช้คำศัพท์ทั่วไปในที่นี้เพื่อช่วยให้คุณบูรณาการกับข้อมูลที่เผยแพร่อยู่แล้วบนอินเทอร์เน็ต นี่เป็นกรณี (เช่น ไร้เซิร์ฟเวอร์) ที่การตลาดชนะและเราลงเอยด้วยคำศัพท์แปลกๆ

ฐานข้อมูลเชิงสัมพันธ์คืออะไร

วิธีที่ดีที่สุดที่ฉันนึกถึงในการอธิบายฐานข้อมูลเชิงสัมพันธ์คือการนึกถึงสเปรดชีต เช่น Excel, Numbers หรือชีต เป็นตารางขนาดใหญ่ที่มีหลายคอลัมน์และแถว แต่ละแถวแสดงถึงหนึ่งรายการในฐานข้อมูล และแต่ละคอลัมน์แสดงถึงหนึ่งฟิลด์ (หรือประเภทของข้อมูล) ในฐานข้อมูล

ฐานข้อมูลเชิงสัมพันธ์ส่วนใหญ่มีโครงสร้างสคีมา คุณไม่สามารถสร้างสิ่งต่าง ๆ ได้ทันทีเช่น MongoDB หรือฐานข้อมูล NoSQL อื่น ๆ คุณต้องปฏิบัติตามสคีมาที่สร้างไว้ล่วงหน้าเมื่อคุณแทรกลงในฐานข้อมูล ตัวอย่างเช่น เมื่อคุณสร้างฐานข้อมูลที่อยู่ของคุณ ก็จะมีที่อยู่ เมือง และรัฐอยู่ในนั้น หากมีใครพยายามแทรกคอลัมน์ "ความคิดเห็น" ลงในคอลัมน์นั้น จะไม่อนุญาตให้บุคคลนั้นเข้าไปเนื่องจากอยู่นอกสคีมาที่คุณกำหนดไว้ล่วงหน้า สิ่งนี้อาจเป็นประโยชน์เพราะมันบังคับใช้ระเบียบวินัยบางอย่างในแอปของคุณ แต่ก็อาจไม่ยืดหยุ่นเช่นกัน

พลังลับของฐานข้อมูลเชิงสัมพันธ์อยู่ในชื่อ: คุณสามารถมีหลายฐานข้อมูลและ/หรือตารางที่เกี่ยวข้องกัน ฉันเดาว่าถ้ามันอยู่ในชื่อมันก็ไม่ได้เป็นความลับขนาดนั้น ในขณะที่ใน MongoDB เป็นความคิดที่ดีที่จะลองเข้าร่วมเอกสารต่างๆ ในคอลเลกชันต่างๆ กัน เป็นความคิดที่ดีสำหรับหลายตารางในฐานข้อมูลเชิงสัมพันธ์ที่จะเข้าร่วมร่วมกัน

SQL คืออะไร

SQL ย่อมาจากภาษาคิวรีที่มีโครงสร้าง โดยพื้นฐานแล้วเป็นวิธีการสร้างคำถามและคำสั่งเพื่อส่งไปยังฐานข้อมูลเพื่อสร้าง อ่าน อัปเดต และลบบันทึก ฐานข้อมูลเชิงสัมพันธ์แต่ละฐานข้อมูลมีรสชาติของตัวเองว่าต้องการให้ SQL มีลักษณะอย่างไร แต่โดยทั่วไปแล้วฐานข้อมูลส่วนใหญ่จะอยู่ห่างกัน ในขณะที่ MongoDB เรากำลังส่งออบเจ็กต์การสืบค้น JSON ที่นี่เราจะส่งสตริงการสืบค้นที่ฐานข้อมูลจะอ่านและดำเนินการให้เรา มันเป็นภาษาที่ทรงพลังและยืดหยุ่นมาก แต่นี่คือมหาสมุทรลึก ในทางเทคนิคแล้ว SQL กำลังทัวริงเสร็จสมบูรณ์ ฉันจำงานแรกของฉันได้ จริงๆ แล้วคือการฝึกงาน ฉันใช้เวลาทั้งวันเขียนคำถามจำนวนมหาศาล (หลายสิบบรรทัด) เราจะไม่ไปลึกขนาดนั้น เราจะกล่าวถึงข้อมูลพื้นฐานที่นี่ จากนั้นคุณสามารถเจาะลึกลงไปได้เมื่อจำเป็น

สิ่งสำคัญที่นี่คือคุณต้องเข้าใจวิธีการทำงานของฐานข้อมูลเชิงสัมพันธ์ สามารถแบ่งสถาปัตยกรรมข้อมูลออกเป็นความสัมพันธ์ และรู้วิธีเขียนแบบสอบถามที่เหมาะสมไปยังฐานข้อมูลเชิงสัมพันธ์

ภูมิทัศน์ SQL

วันนี้เราจะมาพูดถึง PostgreSQL และฉันต้องการให้คุณพิสูจน์เหตุผลในการตัดสินใจนั้น มีให้เลือกมากมายที่นี่ (ในขณะที่ MongoDB เป็นตัวเลือกที่ชัดเจนจริงๆ ในพื้นที่ NoSQL) ก่อนที่ฉันจะยกย่องคุณธรรมของ PostgreSQL ให้กับคุณ เรามาสำรวจสิ่งที่เราสามารถเลือกได้กันดีกว่า

MySQL / มาเรียดีบี

ตัวเลือกอื่นที่ "ชัดเจน" ก็คือ MySQL และจริงๆ แล้วเป็นตัวเลือกที่ฉันใช้เป็นการส่วนตัวมากที่สุดนอกเหนือจาก Postgres ในอาชีพของฉัน นอกจากนี้ยังสนับสนุน WordPress ที่ได้รับความนิยมอย่างล้นหลามและได้รับความนิยมอย่างมากโดยทั่วไปกับบริษัทต่างๆ เช่น Facebook, Google และ Netflix ซึ่งเป็นที่รู้จักว่าเป็นผู้ใช้รายใหญ่ เป็นทางเลือกที่ถูกต้องอย่างแน่นอนที่จะใช้มันในปัจจุบัน สามารถปรับขนาดได้สูง เป็นโค้ดเบสที่เข้าใจได้ดีและมีความเป็นผู้ใหญ่ และมีคุณสมบัติมากมายที่จะทำให้คุณมีความสุข เป็นของ Oracle ซึ่งเสนอให้ผู้ใช้บางรายหยุดชั่วคราว (พวกเขาได้มาจากการได้มาของ Sun)

ผู้สร้าง MySQL ดั้งเดิมบางรายทำการแยกมันหลังจากการเข้าซื้อกิจการของ Oracle เพื่อสร้าง MariaDB ซึ่งส่วนใหญ่เป็นการแทนที่ MySQL แบบดรอปอิน นอกจากนี้ยังเป็นทางเลือกที่ดีมากและใช้กันอย่างแพร่หลายในปัจจุบัน

SQLite

อีกฐานข้อมูลหนึ่งที่ใช้กันทั่วไปมาก SQLite เป็นฐานข้อมูลขนาดเล็กมากและมีประสิทธิภาพมาก จริงๆ แล้วมีไว้เพื่อจัดส่งกับเซิร์ฟเวอร์ใดก็ตามที่ใช้งานอยู่ มันไม่ได้หมายถึงการเป็นเซิร์ฟเวอร์ของตัวเอง แทนที่จะมีวิธีจัดเก็บข้อมูลที่ซับซ้อน กลับกลายเป็นเพียงการเขียนลงในไฟล์! การแยกโค้ดเครือข่ายและโค้ดการจำลองที่จำเป็นทั้งหมดออกทำให้เป็นฐานข้อมูลขนาดเล็กที่ง่ายต่อการจัดส่งพร้อมกับอุปกรณ์ IoT บนระบบปฏิบัติการ คอนโซลเกม (ทั้ง PlayStation และ Xbox ใช้งาน!) ตู้เย็น และทุกที่รอบตัวคุณ

บริษัทต่างๆ เช่น Turso และ Cloudflare กำลังเปลี่ยน SQLite ให้เป็นฐานข้อมูลที่ใช้งานบนคลาวด์ และตอนนี้ก็ใช้ได้กับเว็บแอปแล้ว โดยเฉพาะอย่างยิ่งในสถานการณ์ที่มีการกระจายตัวสูงหรือในกรณีที่คุณมีฐานข้อมูลขนาดเล็กนับล้านเทียบกับฐานข้อมูลขนาดใหญ่เพียงแห่งเดียว

ฉันสอนชั้นเรียนเกี่ยวกับ SQLite ที่นี่

ไมโครซอฟต์ SQL เซิร์ฟเวอร์ / ออราเคิล / DB2

ทั้งหมดนี้เป็นผลิตภัณฑ์เชิงพาณิชย์ ทั้งหมดเป็นผลิตภัณฑ์ที่ค่อนข้างเก่า (พ่อของฉันทำงานกับ DB2 ที่ IBM จริงๆ!) ซึ่งทำงานได้ดีในสเกลขนาดใหญ่ แต่ป้ายราคาก็อาจแพงมาก และเนื่องจากฉันไม่เคยใช้มันและจะไม่ใช้เลย เนื่องจากมีฐานข้อมูลโอเพ่นซอร์สที่ยอดเยี่ยม ฉันจะปล่อยให้คุณสำรวจมันตามเวลาของคุณ

PostgreSQL

สิ่งนี้นำเราไปสู่ ​​PostgreSQL (เรียกว่า "post-gress") PostgreSQL เป็นอีกหนึ่งฐานข้อมูลโอเพ่นซอร์สที่ยอดเยี่ยมที่ยังคงได้รับส่วนแบ่งการตลาดจำนวนมาก และมีคุณสมบัติที่โดดเด่นบางอย่างของมันอย่างไร เราจะพูดถึงสิ่งเหล่านั้นในขณะที่เราดำเนินการ แต่รู้ว่ามันปรับขนาดได้ เข้าถึงได้พร้อมคุณสมบัติที่ยอดเยี่ยม และเป็นที่นิยมอย่างมาก มีผู้ใช้ที่มีชื่อเสียงเช่น Apple, Microsoft, Etsy และอื่นๆ อีกมากมาย

จริงๆ แล้ว ฉันจะบอกได้เลยว่า Postgres "ชนะ" แล้ว มันคือสถานที่ทำงาน ฐานข้อมูลที่ทำทุกอย่าง Postgres ควรเป็นการตัดสินใจเริ่มต้นของคุณ และคุณควรเปลี่ยนทิศทางเมื่อคุณมีเหตุผลเท่านั้น

ฉันจะแสดงให้คุณเห็นว่า Postgres (ผ่านฟีเจอร์และส่วนขยาย) สามารถทำสิ่งที่ฐานข้อมูลอื่นๆ เหล่านี้สามารถทำได้ค่อนข้างดีจริงๆ ดังนั้นหากคุณมีความต้องการ NoSQL หรือกราฟเพียงเล็กน้อย Postgres ก็สามารถทำได้ค่อนข้างดี หากแอปของคุณอาศัยการมีกราฟและขอบโดยสิ้นเชิง ใช่แล้ว บางอย่างเช่น Neo4J จะมีความสำคัญ มันคือการแลกเปลี่ยนทั้งหมด และอคติของฉันผิดพลาดอย่างมากจากความเรียบง่าย / มีเครื่องมือน้อยลง นั่นคืออคติของฉัน และฉันอยากจะเปิดเผยเรื่องนี้ล่วงหน้า!
