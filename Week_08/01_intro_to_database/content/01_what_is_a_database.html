ฐานข้อมูลคืออะไร

ทุกครั้งที่เราสมัครสมาชิก เพิ่มสินค้าลงตะกร้า หรือโพสต์ข้อความ แอปจะมีข้อมูลใหม่ที่ต้องจำไว้ ข้อมูลเหล่านี้อาจเป็นชื่อผู้ใช้ รายการสินค้า ยอดเงิน หรือแม้แต่เวลาที่เราเปิดอ่านข้อความล่าสุด ถ้าแอปจำข้อมูลไม่ได้ ทุกอย่างก็จะกลับไปเริ่มต้นใหม่เมื่อเราปิดหน้าเว็บหรือ Server หยุดทำงาน

Database หรือฐานข้อมูล คือชุดข้อมูลที่จัดเก็บไว้อย่างเป็นระบบ เพื่อให้แอปนำกลับมาใช้ได้ในภายหลัง แทนที่แต่ละส่วนของแอปจะต้องหาวิธีเก็บข้อมูลเอง เราสามารถใช้ Database ช่วยบันทึก ค้นหา แก้ไข และลบข้อมูลได้อย่างเป็นระบบ

ข้อมูลกับสถานะของแอป

ข้อมูลที่แอปต้องจำในช่วงเวลาหนึ่งเรียกว่า State หรือสถานะ เช่น ตะกร้าสินค้าของลูกค้าคนหนึ่งอาจมีสินค้าอยู่สามชิ้น ยอดคงเหลือของบัญชีหนึ่งอาจเป็น 2,500 บาท และบทความหนึ่งอาจมีสถานะเป็นฉบับร่าง State เปลี่ยนไปตามสิ่งที่ผู้ใช้และระบบทำ

เราสามารถเก็บ State ไว้ในตัวแปรได้ระหว่างที่โปรแกรมกำลังทำงาน แต่วิธีนี้เหมาะกับข้อมูลชั่วคราวเท่านั้น เมื่อ Process ถูกปิด เครื่อง Restart หรือเรา Deploy แอปเวอร์ชันใหม่ ข้อมูลใน Memory ก็หายไป ถ้าข้อมูลนั้นต้องอยู่ต่อ เราต้องเก็บแบบ Persistent หรือบันทึกไว้ในที่ที่ไม่หายตาม Process

Database และ DBMS

คำว่า Database หมายถึงชุดข้อมูลที่จัดเก็บไว้ ส่วน Database Management System หรือ DBMS คือ Software ที่ใช้ดูแลข้อมูลนั้น เช่น PostgreSQL, MongoDB และ Redis ในการสนทนาทั่วไปเรามักใช้คำว่า Database เรียกทั้งข้อมูลและตัว Software เพราะบริบทช่วยให้รู้ว่ากำลังหมายถึงส่วนไหน

DBMS ทำหน้าที่เป็นตัวกลางระหว่างแอปกับข้อมูล แอปส่งคำสั่งไปว่าอยากอ่านหรือเปลี่ยนอะไร จากนั้น DBMS จะตรวจสอบคำสั่ง หาข้อมูลที่เกี่ยวข้อง และตอบผลลัพธ์กลับมา เราจึงไม่จำเป็นต้องเปิดไฟล์บน Disk แล้วจัดการตำแหน่งของข้อมูลทุกชิ้นด้วยตัวเอง

ฐานข้อมูลไม่ได้มีแค่ตาราง

หลายคนนึกถึงตารางที่มีแถวและคอลัมน์เมื่อพูดถึง Database ซึ่งเป็นภาพของ Relational Database อย่าง PostgreSQL แต่ข้อมูลสามารถจัดเก็บได้หลายรูปแบบ MongoDB เก็บข้อมูลเป็น Document ที่มีหน้าตาคล้าย Object ใน JavaScript ส่วน Redis เก็บข้อมูลโดยใช้ Key สำหรับเรียก Value กลับมา

ไม่มีรูปแบบใดดีที่สุดสำหรับทุกงาน ตารางเหมาะกับข้อมูลที่มีโครงสร้างและความสัมพันธ์ชัดเจน Document เหมาะกับข้อมูลที่ต้องการความยืดหยุ่น ส่วน Key-Value เหมาะกับการเข้าถึงข้อมูลอย่างรวดเร็ว คอร์สนี้จะพาเราเรียนทั้งสามรูปแบบเพื่อให้เห็นข้อดีและข้อจำกัดของแต่ละแบบ

สิ่งที่เราทำกับข้อมูล

งานพื้นฐานกับข้อมูลมักสรุปด้วยคำว่า CRUD ซึ่งมาจาก Create, Read, Update และ Delete ลองนึกถึงระบบร้านค้าออนไลน์:

  • Create สร้างบัญชีลูกค้าหรือเพิ่มคำสั่งซื้อใหม่
  • Read อ่านรายละเอียดสินค้าและดูประวัติคำสั่งซื้อ
  • Update เปลี่ยนที่อยู่จัดส่งหรือแก้ไขจำนวนสินค้า
  • Delete ลบสินค้าที่เลิกขายหรือข้อมูลที่ไม่ต้องการแล้ว

Database แต่ละตัวใช้ภาษาและรูปแบบคำสั่งต่างกัน แต่แนวคิด CRUD ยังเหมือนเดิม เมื่อเข้าใจว่าข้อมูลอะไรต้องเก็บและแอปต้องทำอะไรกับข้อมูล เราจะเลือกโครงสร้างและ Database ได้ง่ายขึ้น

Database ไม่ได้แก้ทุกอย่างให้อัตโนมัติ

การใช้ Database ไม่ได้แปลว่าข้อมูลจะปลอดภัยหรือถูกต้องเสมอไป เรายังต้องออกแบบโครงสร้าง กำหนดสิทธิ์ สำรองข้อมูล และรับมือกับความผิดพลาดให้เหมาะสม Database เป็นเครื่องมือที่ช่วยให้งานเหล่านี้เป็นระบบขึ้น แต่คุณภาพของระบบยังขึ้นอยู่กับวิธีที่เราออกแบบและใช้งานมัน

ในบทถัดไปเราจะดูให้ชัดขึ้นว่า Database ช่วยแก้ปัญหาอะไร และเมื่อใดที่ไฟล์หรือ Spreadsheet เริ่มไม่เพียงพอสำหรับแอปของเรา
