คำสั่ง Neo4j ที่ซับซ้อน

ส่วนนี้จะถือว่าคุณได้แทรกบุคคลและภาพยนตร์ทั้งหมดจากส่วนก่อนหน้าแล้ว ถ้าไม่ ให้ เรียกใช้แบบสอบถามนี้ เพื่อรับข้อมูลทั้งหมด

ลองทำแบบสอบถามเพื่อทำความคุ้นเคยกับข้อมูลกัน

MATCH (n) RETURN distinct labels(n), count(*);

การดำเนินการนี้จะสืบค้นฐานข้อมูลสำหรับโหนดทั้งหมด (ซึ่งเป็นส่วน (n) สังเกตว่าไม่มีป้ายกำกับ) จากนั้นจะใช้ฟังก์ชัน labels() ในตัวเพื่อรับป้ายกำกับทั้งหมด จากนั้นนับจำนวนที่มีฟังก์ชัน count(*)

MATCH (n)-[r]->() RETURN type(r), count(*);

เช่นเดียวกับข้างต้น ขณะนี้เรากำลังนับจำนวนความสัมพันธ์ที่เรามีในฐานข้อมูล

เอาล่ะ เรามาเลือกนักแสดงแล้วดูว่าคนอื่นๆ ที่เคยแสดงภาพยนตร์ด้วยเป็นใครบ้าง ฉันจะเลือกคีอานู รีฟส์ที่นี่

MATCH (Keanu:Person)-[:ACTED_IN]->(m:Movie)<-[:ACTED_IN]-(Costar:Person)
WHERE Keanu.name = "Keanu Reeves"
RETURN DISTINCT Costar.name, count(*)
ORDER BY count(*) DESC, Costar.name;
  • เราเคยเห็นคำถามที่คล้ายกันมาก่อนเท่าที่ MATCH ดำเนินไป
  • คล้ายกับด้านบน เราใช้ประโยค DISTINCT จากนั้นใช้ count(*) เพื่อรวมจำนวนภาพยนตร์ที่ Keanu ปรากฏในภาพยนตร์เหล่านี้ร่วมกับบุคคลเหล่านี้
  • ORDER BY ควรดูคุ้นเคยเนื่องจากทำงานคล้ายกับ PostgreSQL มาก ฉันให้ช่องสั่งซื้อไว้สองช่อง โดยจะเรียงตามจำนวนภาพยนตร์ที่อยู่รวมกันก่อน แล้วจึงเรียงตามตัวอักษรตามชื่อ

หากคุณใช้เบราว์เซอร์และต้องการดูกราฟสวยๆ ให้ลองทำดังนี้:

MATCH (Keanu:Person)-[:ACTED_IN]->(m:Movie)<-[r:ACTED_IN]-(Costar:Person)
WHERE Keanu.name = "Keanu Reeves"
RETURN Costar, m, Keanu, r;

หากคุณต้องการกราฟิกที่สวยงาม คุณจะต้องส่งคืนโหนดทั้งหมด ไม่ใช่แค่ฟิลด์เท่านั้น

องศาของเควินเบคอน

ดังนั้น จุดรวมของชุดข้อมูลนี้คือการแก้ปัญหา Six Degrees of Kevin Bacon นั่นคือนักแสดงและนักแสดงทุกคนในฮอลลีวูดสามารถเชื่อมโยง Kevin Bacon เข้าด้วยกันผ่านการแสดงในภาพยนตร์ที่แสดงร่วมกับเขาโดยตรง กับคนที่แสดงภาพยนตร์กับ Kevin Bacon หรือกับคนที่แสดงในภาพยนตร์ร่วมกับคนที่อยู่ในภาพยนตร์กับ Kevin Bacon และอื่นๆ ขึ้นไปถึงหกองศา ของการแยก

มาดูกันว่าคุณจะแก้ปัญหานั้นด้วยชุดข้อมูลของเราได้อย่างไร มาดูกันว่า Keanu ใกล้แค่ไหน (เรียกใช้สิ่งนี้ในเบราว์เซอร์)

MATCH path = shortestPath(
  (Bacon:Person {name:"Kevin Bacon"})-[*]-(Keanu:Person {name:"Keanu Reeves"})
)
RETURN path;
  • shortestPath เป็นฟังก์ชันที่จะค้นหาเส้นทางที่สั้นที่สุดระหว่างสองโหนดโดยพิจารณาจากความสัมพันธ์ของโหนดเหล่านั้น
  • ตัวแปร path กลายเป็นประเภทพาธ มันมีข้อมูลทั้งหมดสำหรับเส้นทางทั้งหมดที่อยู่ในมือคุณ
  • คุณสามารถเรียกใช้สิ่งนี้ใน cypher-shell แต่มันจะให้ข้อมูลกลับมากมายแก่คุณ

หากต้องการดูเป็นมิตรมากขึ้นใน Cypher-shell เพียงแค่ดูที่ความยาว

MATCH path = shortestPath(
  (Bacon:Person {name:"Kevin Bacon"})-[*]-(Keanu:Person {name:"Keanu Reeves"})
)
RETURN length(path);

คุณอาจเห็นมันบ่นว่าไม่มีขอบเขต ตามทฤษฎีแล้ว หากเส้นทางยาวมาก อาจใช้เวลานานในการวิ่งขณะที่สำรวจกราฟของคุณ มันต้องการให้คุณเพิ่มจำนวนโหนดสูงสุดที่จะกระโดด เพื่อที่ว่าถ้ามันไม่พบมันในระดับ X มันก็จะยอมแพ้ ซึ่งจะมีลักษณะดังนี้: (Bacon:Person {name:"Kevin Bacon"})-[*..5]-(Keanu:Person {name:"Keanu Reeves"}) โดยที่ *..5 เป็นส่วนสำคัญ สิ่งนี้บอกให้ยอมแพ้หากไม่ถึง 5 โหนด

หากต้องการผ่อนคลายสิ่งนี้ในลักษณะที่สามารถอ่านได้ใน Cypher-Shell กับภาพยนตร์และนักแสดง/นักแสดงทั้งหมด คุณสามารถทำได้ดังนี้:

MATCH path = shortestPath(
    (First:Person {name:"Kevin Bacon"})-[*..5]-(Second:Person {name:"Keanu Reeves"})
)
UNWIND nodes(path) AS node
RETURN coalesce(node.name, node.title) AS text;
  • UNWIND นำบางสิ่งที่เป็นรายการและขยายออกเป็นแต่ละโหนด ด้วย nodes(path) เราจะนำโหนดทั้งหมดออกไป (ซึ่งก็คือบุคคลและภาพยนตร์)
  • coalesce จำเป็นเนื่องจากบุคคลมีชื่อและภาพยนตร์มีชื่อเรื่อง นี่จะเอาสิ่งแรกในนั้นที่ไม่เป็นโมฆะ
  • เราใช้ AS ที่นี่เพื่อทำให้สิ่งเหล่านี้ง่ายต่อการอ้างอิงในภายหลัง (ทั้ง node และ text)

ค้นหาองศาในเครือข่าย

คุณสามารถจินตนาการได้ว่านี่คือเครื่องมือแนะนำหรือไม่ คุณอาจต้องการแนะนำนักแสดงคนอื่นๆ โดยอิงจากภาพยนตร์ที่ผู้คนเคยแสดงร่วมกัน เกิดอะไรขึ้นถ้าเราอยากเอา 2 องศานั่นออกมา?

MATCH (Halle:Person)-[:ACTED_IN*1..4]-(Recommendation:Person)
WHERE Halle.name = "Halle Berry"
RETURN DISTINCT Recommendation.name
ORDER BY Recommendation.name;

นี่จะทำให้คุณมีเครือข่ายผู้คนที่ขยายใหญ่ขึ้นในการตรวจสอบ หากคุณต้องการรวมผู้กำกับและนักเขียนเข้าไว้ด้วย เพียงละเว้น :ACTED_IN เพื่อให้เป็น -[*1..4]- และนั่นจะทำให้คุณมีความสัมพันธ์ใดๆ
