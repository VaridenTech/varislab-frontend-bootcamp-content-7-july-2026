เริ่มต้นใช้งาน Neo4j

มาเริ่มสร้างฐานข้อมูลของเรากันเถอะ! เรียกใช้สิ่งต่อไปนี้

docker run -dit --rm --name=my-neo4j -p 7474:7474 -p 7687:7687 --env=NEO4J_AUTH=none neo4j:2026-community-trixie

สิ่งนี้จะหมุนอินสแตนซ์ใหม่ของ Neo4j ในนักเทียบท่าและเปิดเผยทั้งไคลเอนต์ HTTP และพอร์ตการสืบค้น เราจะเริ่มต้นด้วยการสืบค้น commandline ที่เรียกว่า cypher-shell จากนั้นเราจะไปยังประสบการณ์เบราว์เซอร์ที่ยอดเยี่ยม

สิ่งแรกที่ต้องรู้คือฐานข้อมูลเรียกว่า Neo4j และภาษาคิวรีเรียกว่า Cypher เช่นเดียวกับฐานข้อมูลคือ PostgreSQL และภาษาคิวรีคือ SQL มีภาษาคิวรีกราฟอื่นๆ เช่น Gremlin แต่วันนี้เราจะพูดถึง Cypher

เรามาเชื่อมต่อกัน เรียกใช้สิ่งต่อไปนี้:

docker exec -it my-neo4j cypher-shell

หากคุณเห็นคำเตือนเมื่อเริ่มต้นระบบที่เกี่ยวข้องกับ org.fusesource.jansi.internal.JansiLoader ทำการเรียกเมธอดแบบจำกัด นั่นเป็นเพียง Java ที่เป็น Java และ cypher-shell จำเป็นต้องอัปเดตการขึ้นต่อกัน มันไม่เกี่ยวอะไรกับคุณและไม่ส่งผลกระทบต่อสิ่งที่เรากำลังทำอยู่

สิ่งนี้จะทำให้คุณเข้าสู่การโต้ตอบกับ Neo4j สิ่งแรกที่เราจะทำคือใช้คำสั่ง CREATE เพื่อสร้างนักแสดงคนแรกของเรา Michael Cera ฉันชอบหนังเรื่อง Scott Pilgrim vs. the World ดังนั้นเราจะมาอธิบายนักแสดงในเรื่องนี้กัน

CREATE (:Person {name:'Michael Cera', born:1988});

: ที่อยู่ข้างหน้า Person มีความสำคัญมาก - หมายความว่าเป็นป้ายกำกับ หากคุณละทิ้งมันเป็นการประกาศตัวแปร

คุณจะเห็นว่าเราสร้างโหนดใหม่พร้อมป้ายกำกับบุคคลและแอตทริบิวต์สองรายการ: ชื่อของ Michael Cera และปีเกิดปี 1988

แล้วถ้าเราต้องการค้นหาบันทึกเดียวกันนั้นล่ะ?

MATCH (p {name: "Michael Cera"}) RETURN p;
  • ตอนนี้เรากำลังใช้ตัวแปรชวเลข p เราจะเรียกสิ่งนี้ว่าอะไรก็ได้
  • ส่วนแรกแสดงถึงสิ่งที่เรากำลังสืบค้น เราไม่ได้ระบุป้ายกำกับที่นี่ แต่เราระบุได้ จากนั้นมันจะดูเหมือน MATCH (p {name: "Michael Cera"}) RETURN p;
  • คุณต้องการผลตอบแทนในตอนท้าย ไม่เช่นนั้น คุณจะไม่ได้อะไรกลับมา

มาสร้างภาพยนตร์แล้วสอบถามกัน

CREATE (m:Movie {title: 'Scott Pilgrim vs the World', released: 2010, tagline: 'An epic of epic epicness.' }) RETURN m;
  • สิ่งนี้จะสร้างและส่งกลับทั้งหมดในแบบสอบถามเดียวกัน เนื่องจากไม่มีเครื่องหมายอัฒภาค ดังนั้นจึงถือเป็นแบบสอบถามเดียว
  • การสร้างแบบสอบถามที่ซับซ้อนขนาดใหญ่ด้วย Cypher เป็นเรื่องง่าย
  • ฉันไม่ได้แต่งแท็กไลน์นั้นขึ้นมา มันคือแท็กไลน์ของหนังเรื่องนั้นจริงๆ 😄

ตอนนี้เรามาทำให้พวกเขาเชื่อมโยงถึงกันเพื่อให้ Michael Cera แสดงใน Scott Pilgrim vs the World

MATCH (Michael:Person),(ScottVsWorld:Movie)
WHERE Michael.name = "Michael Cera" AND ScottVsWorld.title = "Scott Pilgrim vs the World"
CREATE (Michael)-[relationship:ACTED_IN {roles:["Scott Pilgrim"]}]->(ScottVsWorld)
RETURN relationship;
  • นัดแรกบอกว่าเรากำลังมองหาสองสิ่งที่แยกจากกัน บุคคลและภาพยนตร์
  • จากนั้นเราจะระบุ WHERE (มีสองสามวิธีในการเขียนแบบสอบถามที่ใช้งานได้ทั้งหมด)
  • จากนั้นเราก็ระบุว่าเรากำลังจะสร้างสิ่งใหม่
  • สิ่งนี้อ่านเหมือนศิลปะ ASCII คุณมี (โหนด) - \[RELATIONSHIP] -> (โหนด) ข้อมูลนี้ระบุว่าภาพยนตร์ของ Michael ACTED_IN -> ระบุทิศทางของความสัมพันธ์ เรายังอาจเขียนเป็น (Scott Pilgrim vs the World) <- \[ACTED_IN] - (Michael Cera) ก็ได้ ทั้งทำงาน.
  • relationship เป็นตัวแปรที่อ้างอิงถึงความสัมพันธ์ใหม่ที่เราเพิ่งสร้างขึ้น เป็นทางเลือก แต่ฉันต้องการส่งคืนในตอนท้าย
  • Neo4j แนะนำให้คุณทำ CapitalCasing ด้วยชื่อป้ายกำกับ (เช่น Person และ Movie) และประเภทความสัมพันธ์ SCREAMING_CASE ของคุณ (เช่น DIRECTED และ ACTED_IN) ฉันแค่ทำตามคำแนะนำของพวกเขา ดูที่นี่

เอาล่ะ เรามาเพิ่มความสัมพันธ์ให้กับภาพยนตร์กันดีกว่า คัดลอก/วางสิ่งนี้เพื่อเพิ่มนักแสดงและผู้กำกับอีกสองสามคน (มีนักแสดงดีๆ กี่คนใน Scott Pilgrim!?)

MATCH (ScottVsWorld:Movie) WHERE ScottVsWorld.title = "Scott Pilgrim vs the World"
CREATE (Anna:Person {name:'Anna Kendrick', born:1985})
CREATE (Brie:Person {name:'Brie Larson', born:1989})
CREATE (Aubrey:Person {name:'Aubrey Plaza', born:1984})
CREATE (Mary:Person {name:'Mary Elizabeth Winstead', born:1984})
CREATE (Kieran:Person {name:'Kieran Culkin', born:1982})
CREATE (Chris:Person {name:'Chris Evans', born:1981})
CREATE (Edgar:Person {name:'Edgar Wright', born:1974})
CREATE
(Anna)-[:ACTED_IN {roles:['Stacey Pilgrim']}]->(ScottVsWorld),
(Brie)-[:ACTED_IN {roles:['Envy Adams']}]->(ScottVsWorld),
(Aubrey)-[:ACTED_IN {roles:['Julie Powers']}]->(ScottVsWorld),
(Mary)-[:ACTED_IN {roles:['Ramona Flowers']}]->(ScottVsWorld),
(Kieran)-[:ACTED_IN {roles:['Wallace Wells']}]->(ScottVsWorld),
(Chris)-[:ACTED_IN {roles:['Lucas Lee']}]->(ScottVsWorld),
(Edgar)-[:DIRECTED]->(ScottVsWorld);

ไม่น่าจะมีอะไรน่าประหลาดใจมากนัก แค่มีหลายๆ อย่างมาเพิ่มในคราวเดียว

เรามาทำการสืบค้นความสัมพันธ์กันตอนนี้ ค้นหาภาพยนตร์ทั้งหมดที่ Aubrey Plaza แสดงตามฐานข้อมูลของเรา

MATCH (p:Person)-[:ACTED_IN]->(m:Movie)
WHERE p.name = "Aubrey Plaza"
RETURN m.title;
  • จริงๆ แล้วมันค่อนข้างง่ายเมื่อคุณเห็นมันเขียนออกมา นั่นเป็นหนึ่งในส่วนที่ดีของ Cypher ก็คือสามารถอ่านได้ดีเป็นส่วนใหญ่ เริ่มมี ([{}]) ได้เยอะ ซึ่งก็จะมากหน่อย
  • ส่วน > ของ -> เป็นทางเลือก หากคุณละเว้นทิศทางในข้อความค้นหา ระบบจะถือว่าคุณกำลังพูดว่า "find me aความสัมพันธ์ที่นี่ ฉันไม่สนใจว่าทิศทางจะไปทางไหน" เนื่องจากเป็นนักแสดงที่แสดงในภาพยนตร์และความสัมพันธ์แบบผกผันไม่สมเหตุสมผล (ภาพยนตร์ที่แสดงเป็นนักแสดง?) จึงเป็นเรื่องปกติที่จะตั้งสมมติฐานนั้น

สิ่งหนึ่งที่คุณจะสังเกตได้ก็คือ Aubrey Plaza ไม่ได้เชื่อมต่อกับบุคคลอื่นโดยตรง เพียงแค่ผูกพันกับภาพยนตร์เรื่องเดียวกันเท่านั้น จะเป็นอย่างไรหากเราต้องการค้นหาทุกคนที่แสดงในภาพยนตร์เรื่องเดียวกันกับ Aubrey (ในกรณีนี้คือทุกคนที่เราเพิ่มไว้)

MATCH (p:Person)-[:ACTED_IN]->(Movie)<-[:ACTED_IN]-(q:Person)
WHERE p.name = "Aubrey Plaza" AND q.name <> "Aubrey Plaza"
RETURN q.name;
  • เอาล่ะ! เราแค่อธิบายความสัมพันธ์เพิ่มเติมอีกเล็กน้อยแล้วใช้ตัวแปรเหล่านั้น
  • <> เป็นวิธีที่คุณไม่เท่ากันใน Cypher
  • ในทางเทคนิคแล้ว Aubrey อยู่ในหนังกับตัวเธอเองเหรอ? ไม่ว่าในกรณีใด เราต้องบอกว่าอย่ารวมเธอไว้ในผลลัพธ์ถ้าเราไม่ต้องการมีเธอ

แต่ถ้าเราต้องการค้นหาทุกคนที่อายุน้อยกว่า Aubrey ที่แสดงในภาพยนตร์เรื่องเดียวกันล่ะ?

MATCH (p:Person)-[:ACTED_IN]->(Movie)<-[:ACTED_IN]-(q:Person)
WHERE p.name = "Aubrey Plaza" AND q.born > p.born
RETURN q.name;

ข้อจำกัด

เช่นเดียวกับในฐานข้อมูลอื่นๆ คุณสามารถบังคับใช้เอกลักษณ์ซึ่งจะเป็นประโยชน์ได้ ต่อไปนี้คือวิธีดำเนินการดังกล่าว (แม้ว่าจะเป็นความคิดที่ไม่ดีในกรณีนี้ เนื่องจากมีนักแสดงและผู้กำกับหลายคนที่ชื่อเหมือนกัน เนื่องจากมีภาพยนตร์หลายเรื่องที่เรียกว่าสิ่งเดียวกัน)

CREATE CONSTRAINT FOR (a:Person) REQUIRE a.name IS UNIQUE;
CREATE CONSTRAINT FOR (a:Movie) REQUIRE a.title IS UNIQUE;

Neo4j เวอร์ชัน 5 ลบไวยากรณ์เก่าที่ใช้ ON/ASSERT และตอนนี้คุณต้องใช้ FOR/REQUIRE
