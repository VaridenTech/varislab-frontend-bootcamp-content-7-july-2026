คำศัพท์พื้นฐานเกี่ยวกับฐานข้อมูล

ก่อนที่เราจะเริ่มทำงานกับฐานข้อมูลประเภทต่างๆ เหล่านี้ ฉันต้องการให้แน่ใจว่าเรามีความชัดเจนเกี่ยวกับคำศัพท์ทั่วไปบางประการ และเป้าหมายสำหรับวันนี้คืออะไร สิ่งที่เรากำลังจะกล่าวถึง และสิ่งที่เราไม่ได้กล่าวถึง

ฐานข้อมูลคืออะไรและคำศัพท์ทั่วไปอื่นๆ

ฐานข้อมูลเป็นสถานที่จัดเก็บข้อมูล วิธีคิดอีกวิธีหนึ่งคือเป็นที่สำหรับบันทึกสถานะของแอปพลิเคชันของคุณเพื่อให้สามารถเรียกคืนได้ในภายหลัง สิ่งนี้ช่วยให้คุณทำให้เซิร์ฟเวอร์ของคุณไร้สถานะได้เนื่องจากฐานข้อมูลของคุณจะจัดเก็บข้อมูลทั้งหมด สิ่งต่างๆ มากมายถือได้ว่าเป็นฐานข้อมูลประเภทหนึ่ง เช่น สเปรดชีต Excel หรือแม้แต่ไฟล์ข้อความที่มีข้อมูลอยู่ในนั้น

แบบสอบถามคือคำสั่งที่คุณส่งไปยังฐานข้อมูลเพื่อให้ทำบางสิ่ง ไม่ว่าจะเป็นการรับข้อมูลออกจากฐานข้อมูลหรือเพื่อเพิ่ม/อัปเดต/ลบบางสิ่งในฐานข้อมูล นอกจากนี้ยังสามารถรวบรวมข้อมูลจากฐานข้อมูลเป็นภาพรวมบางประเภทได้

สคีมา

หากฐานข้อมูลเป็นตารางใน Microsoft Excel สคีมาก็คือคอลัมน์ เป็นโครงสร้างที่เข้มงวดซึ่งใช้ในการจำลองข้อมูล

หากฉันมีออบเจ็กต์ JSON ของผู้ใช้ที่ดูเหมือน { "name": "Brian", "city": "Seattle", "state": "WA" } สคีมาก็จะเป็นชื่อ เมือง และรัฐ มันคือรูปร่างของข้อมูล ฐานข้อมูลบางอย่าง เช่น PostgreSQL มีสคีมาที่เข้มงวดซึ่งคุณต้องทราบรูปร่างของข้อมูลล่วงหน้า โปรแกรมอื่นๆ เช่น MongoDB ให้คุณประดิษฐ์มันขึ้นมาได้ทันที

ฐานข้อมูลมีกี่ประเภท

ปัจจุบันมีฐานข้อมูลหลายประเภท เราจะครอบคลุมเพียงห้าประเภทเท่านั้น แต่เป็นการดีที่จะรู้ว่ามีอะไรอีกบ้าง ปัจจุบัน เราจะพูดถึงฐานข้อมูลเชิงสัมพันธ์ (มักเรียกว่าฐานข้อมูล RDBMS หรือ SQL) ฐานข้อมูลตามเอกสาร (มักเรียกว่า NoSQL) ฐานข้อมูลกราฟ และที่เก็บคีย์-ค่า นี่คือบางส่วนที่เรา not ครอบคลุมอยู่

  • เครื่องมือค้นหา เช่น Solr หรือ Sphinx มักจับคู่กับฐานข้อมูลเพื่อให้สามารถค้นหาได้ หากฐานข้อมูลของคุณไม่รองรับการค้นหาข้อความแบบเต็ม นี่เป็นเครื่องมือที่คุณสามารถจับคู่กับฐานข้อมูลเพื่อทำให้เครื่องมือค้นหาทั่วทั้งไซต์เป็นไปได้
  • ฐานข้อมูลคอลัมน์กว้าง ใช้แนวคิดของตาราง แถว และคอลัมน์ เช่น ฐานข้อมูลเชิงสัมพันธ์ แต่มีลักษณะแบบไดนามิกสำหรับรูปแบบของแถวและชื่อเหล่านั้น ด้วยเหตุนี้จึงสามารถแทรกแซงได้เหมือนกับที่เก็บคีย์-ค่าสองมิติ Apache Cassandra และ Google Bigtable เป็นสองตัวอย่างที่มีชื่อเสียงในเรื่องนี้ ฐานข้อมูลเหล่านี้มีชื่อเสียงในด้านความสามารถในการมีขนาดใหญ่และยืดหยุ่นได้มาก
  • ตัวรับส่งข้อความ เป็นสถาปัตยกรรมที่นักพัฒนา Node.js ใช้งานน้อยเกินไป ซึ่งสามารถปรับปรุงความยืดหยุ่นและความสามารถในการปรับขนาดของคุณได้จริงโดยไม่ต้องเพิ่มความซับซ้อนมากนัก อนุญาตให้แอปและบริการเผยแพร่กิจกรรม/ข้อความบนระบบ และอนุญาตให้นายหน้าข้อความเผยแพร่/แจ้งให้สมาชิกทราบถึงเหตุการณ์เหล่านั้นว่ามีบางอย่างเกิดขึ้น มันเป็นกระบวนทัศน์ที่ทรงพลัง Apache Kafka, RabbitMQ และ Celery ล้วนเกี่ยวข้องกับกระบวนทัศน์นี้
  • ฐานข้อมูลหลายรุ่น คือฐานข้อมูลที่สามารถดำเนินการได้จริงด้วยวิธีที่แตกต่างกันหลายวิธี โดยตอบสนองได้มากกว่าหนึ่งกระบวนทัศน์เหล่านี้ Azure Cosmos DB, SurrealDB และ ArangoDB เป็นสองตัวอย่างหลักของสิ่งนี้ ในทางเทคนิคแล้ว MongoDB และ PostgreSQL ต่างก็มีคุณสมบัติเหล่านี้เช่นกัน เนื่องจากมีคุณสมบัติที่ช่วยให้คุณสามารถดัดให้เป็นรูปร่างที่แตกต่างกันได้

กรด

คุณจะเห็นคำนี้ถูกโยนทิ้งไปมากมาย ผู้เชี่ยวชาญด้านฐานข้อมูลแบบเก่าบางครั้งจะถือว่าสิ่งนี้เป็นเหมือนข่าวประเสริฐ: ฐานข้อมูลทั้งหมดจะต้องเป็นไปตาม ACID ฉันอยากจะแสดงให้คุณเห็นว่ามันเป็นการแลกเปลี่ยนที่คุณจะได้ทำ

สิ่งนี้หมายถึงความเป็นอะตอมมิก ความสม่ำเสมอ การแยกตัว และความทนทาน เป็นตัวย่อที่ใช้บ่อยเมื่อพูดถึงฐานข้อมูล เนื่องจากเป็นปัจจัยสำคัญ 4 ประการที่เราควรคำนึงถึงเมื่อคิดถึงการเขียนแบบสอบถาม

  • คำถามนี้เกิดขึ้นพร้อมกันทั้งหมดหรือไม่ หรือแบ่งออกเป็นหลายการกระทำ? บางครั้งนี่เป็นคำถามที่สำคัญมาก หากคุณกำลังทำธุรกรรมทางการเงิน นี่อาจเป็นสิ่งสำคัญยิ่ง ลองนึกภาพหากคุณมีคำถามสองข้อ ข้อหนึ่งเพื่อหักเงินจากบัญชีของบุคคลหนึ่ง และอีกข้อหนึ่งเพื่อบวกจำนวนเงินนั้นในบัญชีของบุคคลอื่นสำหรับการโอนเงินผ่านธนาคาร จะเกิดอะไรขึ้นถ้าไฟฟ้าดับระหว่างคำถามทั้งสอง? เงินก็จะหาย.. นี่เป็นการแลกเปลี่ยนที่ยอมรับไม่ได้ในกรณีนี้ คุณจะต้องให้สิ่งนี้เป็น atomic กล่าวคือ ธุรกรรมนี้ไม่สามารถแบ่งออกได้ แม้ว่าคุณจะส่งใบแจ้งยอดหลายรายการก็ตาม ทุกอย่างเกิดขึ้นหรือไม่เกิดขึ้นเลย แต่ก็ไม่เคยเกิดขึ้นเพียงครึ่งเดียว
  • หากฉันมีเซิร์ฟเวอร์ห้าเครื่องที่ทำงานโดยที่เซิร์ฟเวอร์หนึ่งทำงานเป็นเซิร์ฟเวอร์หลัก (ซึ่งบางครั้งเรียกว่าเซิร์ฟเวอร์หลัก แต่เราชอบคำว่าผู้นำหรือเซิร์ฟเวอร์หลัก) และเซิร์ฟเวอร์หลักขัดข้อง จะเกิดอะไรขึ้น? ขอย้ำอีกครั้งว่า การใช้เงิน จะเป็นอย่างไรหากข้อความค้นหาถูกเขียนไปยังเนื้อหาหลักแต่ยังไม่ถึงเนื้อหารอง? นี่อาจเป็นหายนะและผู้คนอาจสูญเสียเงิน ในกรณีนี้ เราต้องการให้เซิร์ฟเวอร์ของเรามีความสอดคล้อง_
  • Isolation บอกว่าเราสามารถมีฐานข้อมูลแบบมัลติเธรดได้ แต่จำเป็นต้องทำงานเหมือนกันหากคิวรีทำงานแบบขนานหรือหากรันตามลำดับ มิฉะนั้นจะไม่ผ่านการทดสอบการแยกตัว
  • Durability บอกว่าหากเซิร์ฟเวอร์ขัดข้อง เราสามารถคืนค่าเซิร์ฟเวอร์ให้กลับสู่สถานะเดิมได้ ฐานข้อมูลบางแห่งทำงานในหน่วยความจำเท่านั้น ดังนั้นหากเซิร์ฟเวอร์ขัดข้อง ข้อมูลนั้นก็จะหายไป อย่างไรก็ตาม การดำเนินการนี้ช้า การรอให้ฐานข้อมูลเขียนลงดิสก์ก่อนที่จะเสร็จสิ้นการสืบค้นจะทำให้เสียเวลามาก

ไม่ใช่ทุกสิ่งที่คุณทำจะต้องเป็นไปตามข้อกำหนดของ ACID ACID ปลอดภัยแต่ช้า คุณต้องทำการแลกเปลี่ยนที่เหมาะสมสำหรับทุกแอปและคำค้นหาที่คุณกำลังทำ ฐานข้อมูลเหล่านี้จำนวนมากช่วยให้คุณมีความยืดหยุ่นต่อการสืบค้นว่าคุณต้องการ ACID ระดับใดในการสืบค้น คำถามบางข้อที่คุณต้องการให้แน่ใจว่าได้เขียนลงในคำถามรองก่อนที่จะดำเนินการต่อ อย่างอื่นก็ไม่เป็นไรโดยมีความเสี่ยงเล็กน้อยที่อาจสูญเสียได้ ข้อความค้นหาบางรายการจำเป็นต้องเป็นแบบอะตอมมิก ส่วนข้อความค้นหาอื่นๆ ล้มเหลวบางส่วนไม่ใช่จุดจบของโลก เป็นเรื่องเกี่ยวกับการสร้างสมดุลระหว่างความต้องการของแอปกับต้นทุนและความเร็ว

การทำธุรกรรม

นอกเหนือจากอะตอมมิกซิตีแล้วยังเป็นแนวคิดของการทำธุรกรรมอีกด้วย ข้อความค้นหาบางรายการต้องการหลายสิ่งหลายอย่างเพื่อให้เกิดขึ้นพร้อมกัน วิธีที่เกิดขึ้นคือการแปลง ธุรกรรมเปรียบเสมือนซองจดหมายของธุรกรรมที่จะเกิดขึ้นทั้งหมดในเวลาเดียวกัน โดยรับประกันว่าธุรกรรมทั้งหมดจะดำเนินการในคราวเดียวหรือไม่มีเลย หากเรียกใช้ จะรับประกันว่าจะไม่มีการสืบค้นอื่นเกิดขึ้นระหว่างกัน เช่นเดียวกับตัวอย่างการโอนเงินผ่านธนาคาร สิ่งเหล่านี้อาจมีความสำคัญในบางสถานที่ เนื่องจากความล้มเหลวบางส่วนถือเป็นหายนะ ซึ่งจำเป็นต้องเกิดขึ้นทั้งหมดหรือไม่เกิดขึ้นเลย
