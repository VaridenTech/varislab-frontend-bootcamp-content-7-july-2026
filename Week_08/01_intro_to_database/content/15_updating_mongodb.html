การเพิ่ม แก้ไข และลบข้อมูลใน MongoDB

insertOne และ insertMany

เราเคยใช้คำสั่ง Insert ไปแล้ว แต่ควรแยกให้ชัดระหว่าง insertOne กับ insertMany แบบแรกต้องรับ Object หนึ่งตัว ส่วนแบบหลังต้องรับ Array การใช้ Method ที่เฉพาะเจาะจงช่วยให้ SDK แจ้ง Error เมื่อส่งชนิดข้อมูลผิด ส่วน Method เก่าอย่าง insert เลิกใช้และถูกนำออกจาก SDK แล้ว จึงไม่ควรใช้ในโค้ดใหม่

แนวคิดเดียวกันใช้กับ deleteOne/deleteMany และ updateOne/updateMany เลือก Method ให้ตรงกับจำนวน Document ที่ตั้งใจแก้เสมอ

Update

การ Update ต้องส่งสองส่วน: Filter สำหรับเลือก Document และ Update Object ที่บอกว่าจะเปลี่ยนอะไร

db.pets.updateOne(
  { type: "dog", name: "Luna", breed: "Havanese" },
  { $set: { owner: "Varis Dara" } },
);

Object แรกเป็น Filter รูปแบบเดียวกับ .find() ส่วน Object ที่สองระบุการ Update ผ่าน Operator ต่าง ๆ สมมติว่าวันนี้เป็นวันเกิดของสุนัขทุกตัว เราเพิ่มอายุทั้งหมดด้วยคำสั่งเดียวได้ดังนี้

db.pets.updateMany({ type: "dog" }, { $inc: { age: 1 } });

คำสั่งนี้เพิ่มอายุของสุนัขทุกตัวขึ้น 1 ปี MongoDB มี Update Operator อีกหลายแบบ ดูรายการทั้งหมดได้จาก เอกสาร Update Operator

น่าสังเกตว่ามีพารามิเตอร์พิเศษที่คุณสามารถ updateOne และ updateMany พร้อมตัวเลือกเพิ่มเติมได้ เรากำลังจะพูดถึงหนึ่งในนั้นในหัวข้อถัดไป ตื่นเถอะ

MongoDB ยังมี replaceOne ซึ่งคล้าย updateOne แต่แทน Document ทั้งก้อน Field เดิมที่ไม่ได้ส่งมาในข้อมูลใหม่จะถูกลบออก

Upsert

Upsert มาจาก Update + Insert หมายถึงถ้าพบ Document ให้ Update แต่ถ้าไม่พบให้ Insert ใหม่ เช่น สร้าง User จากอีเมลเมื่อยังไม่มี หรืออัปเดตข้อมูลของ User เดิมเมื่อมีอยู่แล้ว

มาดูวิธีการทำกัน สมมติว่าคุณต้องการค้นหาสุนัขชื่อ "Sudo" และอัปเดตเจ้าของเป็น "Sarah Drasner" หากมีอยู่ (ในกรณีของเราไม่ใช่) และสร้างบันทึกใหม่หากไม่มี

db.pets.updateOne(
  {
    type: "dog",
    name: "Sudo",
    breed: "Wheaten",
  },
  {
    $set: {
      type: "dog",
      name: "Sudo",
      breed: "Wheaten",
      age: 5,
      index: 10000,
      owner: "Sarah Drasner",
    },
  },
  {
    upsert: true,
  },
);

ในงานจริง Filter ของ Upsert ควรอ้างถึง Key ที่ไม่ซ้ำ เพื่อไม่ให้ไปแก้ Document ผิดตัว และต้องเตรียมข้อมูลให้ครบสำหรับกรณีที่ MongoDB ต้อง Insert ใหม่ ไม่เช่นนั้นจะได้ Document ที่มี Field ไม่ครบ

Delete

การ Delete ใช้ Filter แบบเดียวกับการค้นหา แต่ลบ Document แทนการคืนผลลัพธ์ เลือก deleteOne หรือ deleteMany ตามจำนวนที่ต้องการ ส่วน delete แบบเก่าเลิกใช้แล้ว ตัวอย่างต่อไปลบข้อมูลที่ชนิดเป็นสัตว์เลื้อยคลานแต่สายพันธุ์เป็น Havanese ซึ่งเป็นข้อมูลที่ไม่สมเหตุสมผล

db.pets.deleteMany({ type: "reptile", breed: "Havanese" });

findOneAnd*

บางครั้งเราต้องแก้ข้อมูลและรับ Document กลับมาใน Operation เดียว เพื่อเลี่ยง Race Condition ระหว่างคำสั่งค้นหากับคำสั่งแก้ไข MongoDB มี findOneAndUpdate, findOneAndReplace และ findOneAndDelete ซึ่งทำงานคล้าย Method แบบ One ปกติ แต่คืน Document กลับมาด้วย

โดยค่าเริ่มต้น Method กลุ่มนี้คืน Document เดิมจากช่วงก่อน Update, Replace หรือ Delete ไม่ใช่ค่าหลังแก้ไข

BulkWrite

เวลาเขียนแอป เราอาจต้องส่งหลาย Operation พร้อมกัน ทั้ง Insert, Update และ Delete แทนการส่งทีละคำสั่งแล้วรอผล bulkWrite รับ Array ของ Operation และส่งให้ MongoDB ประมวลผลเป็นชุด รูปแบบเหมือนคำสั่งที่เรียนมา เพียงรวมหลาย Object ไว้ใน Array เดียว
