เริ่มต้นใช้งาน MongoDB

MongoDB เป็นหนึ่งในฐานข้อมูลที่ได้รับความนิยมมากที่สุดในโลกปัจจุบัน ในช่วงทศวรรษที่ผ่านมา บริษัทได้สถาปนาตัวเองเป็นผู้ดูแลที่เชื่อถือได้สำหรับปริมาณงานฐานข้อมูลทั้งขนาดเล็กและขนาดใหญ่ ฉันคิดว่ามันค่อนข้างจะไม่มีใครโต้แย้งที่จะบอกว่ามันเป็นหนึ่งในฐานข้อมูล NoSQL ที่ได้รับความนิยมมากที่สุดในโลก หากไม่ใช่ฐานข้อมูลที่ได้รับความนิยมมากที่สุด

ก่อนที่จะมีใครบอกว่า "MongoDB ทำข้อมูลหาย" เหตุการณ์นั้นเกิดขึ้นนานมากแล้วและได้รับการแก้ไขไปนานแล้วเช่นกัน ปัจจุบันเรื่องนี้ไม่ใช่ข้อกังวลอีกต่อไป MongoDB สามารถใช้งานในระบบจริงได้อย่างปลอดภัย ตัวอย่างเช่น Stripe เติบโตจากศูนย์จนประมวลผลธุรกรรมมูลค่า 100 พันล้านดอลลาร์ด้วย MongoDB

มาเริ่มต้น MongoDB กันเถอะ

มาดำดิ่งกัน หากคุณใช้ Docker เหมือนฉัน ให้รันคำสั่งต่อไปนี้

docker run --name test-mongo -dit -p 27017:27017 --rm mongo:8.2.5

docker exec -it test-mongo mongosh

ซึ่งจะเรียกใช้คอนเทนเนอร์ MongoDB ใหม่ในเวอร์ชัน 8.2.5 และเรียกว่า test-mongo เพื่อให้เราสามารถอ้างอิงตามชื่อได้ จากนั้นในคำสั่งที่สองให้รันคำสั่ง mongosh ภายในคอนเทนเนอร์ test-mongo เพื่อให้เราสามารถทำสิ่งต่างๆ ภายในคอนเทนเนอร์ได้ คอนเทนเนอร์ mongo (ซึ่งเป็นคอนเทนเนอร์อย่างเป็นทางการที่ Docker รวบรวมเข้าด้วยกัน) รัน MongoDB โดยอัตโนมัติ ดังนั้นเราจึงไม่จำเป็นต้องทำอะไรเลย เราเพียงแค่ต้องเชื่อมต่อภายในคอนเทนเนอร์และรันคำสั่งของเราจากภายในคอนเทนเนอร์ ณ จุดนี้ คุณควรถูกปล่อยลงในเชลล์ MongoDB แบบโต้ตอบ มาทำความรู้จักกับ MongoDB กันเถอะ!

ฐานข้อมูลและคอลเลกชัน

เช่นเดียวกับฐานข้อมูลอื่นๆ MongoDB มีแนวคิดเกี่ยวกับฐานข้อมูลอยู่ภายใน ฐานข้อมูลคือกลุ่มที่ครอบคลุมของคอลเลกชันข้อมูลขนาดเล็ก ขึ้นอยู่กับคุณว่าคุณต้องการจัดโครงสร้างฐานข้อมูลและคอลเลกชันของคุณอย่างไร แต่โดยทั่วไปแล้วคุณต้องการรวมสิ่งที่เหมือนกันไว้ด้วยกัน หากคุณมีคอลเลกชั่นข้อมูลผู้ใช้และการแจ้งเตือนผู้ใช้ คุณอาจพิจารณาจัดเก็บข้อมูลเหล่านั้นไว้ในฐานข้อมูลเดียวกันแต่เป็นคอลเลกชั่นที่แตกต่างกัน (ลองนึกถึงคอลเลกชั่นเช่นตารางใน Postgres) หากคุณมีการรวบรวมข้อมูลผู้ใช้และคอลเลกชันโพสต์บล็อกการตลาดสำหรับไซต์ของคุณ คุณอาจพิจารณาจัดเก็บข้อมูลเหล่านั้นไว้ในฐานข้อมูลแยกต่างหาก หรือไม่! ไม่มีกฎตายตัวที่นี่ จัดระเบียบตามที่เห็นสมควร ข้อควรพิจารณาเล็กๆ น้อยๆ ประการหนึ่ง (ไม่จำเป็นต้องปฏิบัติตามข้อนี้ด้วยซ้ำ) ก็คือ หากคุณมีคอลเล็กชันขนาดใหญ่หนึ่งคอลเลกชั่นที่มีการรับส่งข้อมูลจำนวนมาก และคอลเลกชั่นขนาดเล็กที่ได้รับทราฟฟิกน้อย มันอาจจะง่ายกว่าเชิงตรรกะในการปรับขนาดเซิร์ฟเวอร์ทั้งสองแยกกัน หากคุณแยกฐานข้อมูล

คอลเลกชันคือกลุ่มของเอกสาร กลุ่มของวัตถุ เกือบทุกครั้งคุณต้องการให้แต่ละวัตถุเหล่านี้เป็นตัวแทนของสิ่งเดียว หากคุณมีคอลเลกชัน users หนึ่งอ็อบเจ็กต์ควรแสดงถึงผู้ใช้หนึ่งราย ฉันเคยเห็นผู้คนทำสิ่งต่าง ๆ เช่น โยนสิ่งที่ไม่เหมือนของในคอลเลกชั่น (เช่น เอาผู้ใช้และสินค้ามาขายไว้ในคอลเลกชั่นเดียว) แต่มันก็ออกมาไม่ดีนัก ใช้หลายคอลเลกชัน

คอลเลกชันยังมีความสามารถที่สนุกสนานอีกด้วย คุณสามารถทำคอลเลกชันต่อยอดได้โดยพูดว่า "มีเพียง 100 รายการในคอลเลกชันนี้ และโยนอันที่เก่าที่สุดเมื่อคุณได้รายการที่ 101" คุณสามารถเพิ่มดัชนีได้ แต่เราจะไปที่นั่น

ลองแทรกเอกสารบางอย่าง

ภายในคอนโซล MongoDB ของคุณให้รัน show dbs สิ่งนี้จะช่วยให้คุณเห็นฐานข้อมูลที่มีอยู่ทั้งหมด เพื่อเริ่มใช้งาน คุณต้องทำ use <database name> มาทำของเราเองกันเถอะ รัน use adoption หากคุณรัน db ตอนนี้ มันจะแสดงว่าคุณใช้ฐานข้อมูล adoption

มาสร้างคอลเลกชันชื่อ pets กัน รัน db.pets.insertOne({name: "Luna", type: "dog", breed: "Havanese", age: 14}) แล้วมาดูรายละเอียดของคำสั่งนี้กัน

db อ้างอิงถึงฐานข้อมูลที่คุณเลือกด้วย use adoption หากคุณต้องการใช้ฐานข้อมูลอื่น คุณเพียงแค่ use เป็นอย่างอื่น

pets คือชื่อของคอลเลกชันที่เรากำลังสร้างได้ทันที หากไม่มีคอลเลกชัน ก็จะสร้างขึ้นทันที หากมีอยู่ มันก็จะแทรกเข้าไปในคอลเลกชันนั้น เราอาจเรียก pets อะไรก็ได้

insertOne เป็นฟังก์ชันที่มีอยู่ในคอลเลกชัน ตามชื่อหมายถึงช่วยให้คุณสามารถแทรกเอกสารได้ครั้งละหนึ่งฉบับ การแทรกเอกสารมีหลายวิธี เพียงเรียกใช้ db.pets.help() เพื่อดูทุกสิ่งที่มีให้คุณ เนื่องจากภาษาคิวรีคือ JavaScript ดังนั้น () จึงเป็นเพียงการเรียกใช้ฟังก์ชันเท่านั้น

{name: "Luna", type: "dog", breed: "Havanese", age: 14} เป็นอ็อบเจ็กต์จริงที่ถูกแทรกลงในคอลเลกชัน ที่นี่เราแค่ใช้สตริงและตัวเลข แต่คุณสามารถดูประเภทที่มีอยู่ทั้งหมดได้ ที่นี่

ดีจนถึงตอนนี้? ยอดเยี่ยม! ลองรัน db.pets.count() คุณจะเห็นว่ามันส่งคืน 1 เนื่องจากเรามีสัตว์เลี้ยงหนึ่งตัวในคอลเลกชันสัตว์เลี้ยงของเรา ลองใช้ db.pets.findOne() แล้วคุณจะเห็นว่ามันส่ง Luna กลับมาให้เรา เราจะเข้าสู่การสืบค้นมากขึ้นในไม่กี่วินาที

ใส่เอกสารเยอะๆครับ. เช่น 10,000. เนื่องจากเรากำลังสืบค้นด้วย JavaScript เราจึงสามารถเขียนความเพ้อฝันของ Array เพื่อสร้างอาร์เรย์ของอ็อบเจ็กต์แบบสุ่มได้ คัดลอกและวางสิ่งนี้ลงในคอนโซล MongoDB

db.pets.insertMany(
  Array.from({ length: 10000 }).map((_, index) => ({
    name: [
      "Luna",
      "Fido",
      "Fluffy",
      "Carina",
      "Spot",
      "Beethoven",
      "Baxter",
      "Dug",
      "Zero",
      "Santa's Little Helper",
      "Snoopy",
    ][index % 11],
    type: ["dog", "cat", "bird", "reptile"][index % 4],
    age: (index % 18) + 1,
    breed: [
      "Havanese",
      "Bichon Frise",
      "Beagle",
      "Cockatoo",
      "African Gray",
      "Tabby",
      "Iguana",
    ][index % 7],
    index: index,
  }))
);

โดยพื้นฐานแล้วสิ่งนี้จะทำให้วัตถุสัตว์เลี้ยง 10,000 ตัวในอาร์เรย์ เนื่องจากเราใช้แบบโมดูโล่ ทุกคนจึงได้วัตถุที่เหมือนกันทุกครั้ง ตอนนี้รันคุณเป็น db.pets.count() แล้วดูว่าคุณได้อะไร คุณควรตอบกลับว่าคุณมี 10,000 รายการในฐานข้อมูลของคุณ ยอดเยี่ยม! เรามาเริ่มสืบค้นกันเลย
