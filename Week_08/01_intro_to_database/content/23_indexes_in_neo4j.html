Index ใน Neo4j

เช่นเดียวกับ PostgreSQL และ MongoDB การมีดัชนีบ่อยครั้งมีความสำคัญมากในการสืบค้นประสิทธิภาพสำหรับ "เส้นทางลัด" ของคุณสำหรับพฤติกรรมการสืบค้นฐานข้อมูลของคุณ

สมมติว่าแง่มุมใหม่ของแอปของเราคือผู้คนสามารถค้นหาคนดังที่เกิดปีเดียวกับพวกเขาได้ ข้อความค้นหาของคุณจะมีลักษณะเช่นนี้

MATCH (p:Person) WHERE p.born = 1967 RETURN p;

ข้อความค้นหาที่ค่อนข้างง่ายแต่ก็เหมือนกับที่เราเคยเห็นมาก่อน โดยจะพิจารณาทุกคนในกราฟเพื่อตรวจสอบปีเกิดของตน ลองนึกภาพคุณมีฐานข้อมูลของ IMDB ทั้งหมด; แบบสอบถามนั้นอาจทำให้ระบบเสียหายได้ ลองใช้ EXPLAIN เพื่อดูว่าทำไม

EXPLAIN MATCH (p:Person) WHERE p.born = 1967 RETURN p;

คุณจะเห็นคำตอบที่เจาะลึกมากว่าจะสแกนคนทั้ง 133 คนแล้วจำกัดให้เหลือ 13 คน เรามาสร้างดัชนีให้กับคุณลักษณะที่เกิดของบุคคลกันดีกว่า

CREATE INDEX FOR (p:Person) ON (p.born);
EXPLAIN MATCH (p:Person) WHERE p.born = 1967 RETURN p;
MATCH (p:Person) WHERE p.born = 1967 RETURN p;

คุณควรเห็นดัชนีที่กำลังใช้งานอยู่ ด้วยจำนวนโหนดเพียง 133 โหนด จึงเป็นเรื่องยากที่จะรับรู้ถึงประสิทธิภาพที่เพิ่มขึ้น แต่หากพิจารณาจากรายการใหญ่ๆ ก็มีแนวโน้มว่าจะมีความสำคัญ

Neo4j มีบทความดีๆ เกี่ยวกับการวางแผนแบบสอบถาม หากคุณต้องการเจาะลึกเพิ่มเติมเกี่ยวกับการปรับปรุงประสิทธิภาพการค้นหา

สุดท้ายนี้ บางครั้งการดูดัชนีที่มีอยู่ทั้งหมดก็มีประโยชน์ ลองสิ่งนี้:

SHOW INDEXES;
