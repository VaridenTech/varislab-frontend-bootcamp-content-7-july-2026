รู้จักฐานข้อมูล SQL

ในคอร์สนี้คำว่า SQL Database จะหมายถึง Relational Database หรือ RDBMS แม้ในทางเทคนิคจะไม่ตรงกันทั้งหมด เพราะมี Relational Database บางตัวที่ไม่ได้ใช้ SQL และมี Non-Relational Database บางตัวที่รองรับ SQL ด้วย แต่คำเรียกนี้เป็นคำที่คนส่วนใหญ่ใช้และค้นหาเจอได้ง่ายที่สุด

ฐานข้อมูลเชิงสัมพันธ์คืออะไร

ลองนึกถึง Spreadsheet อย่าง Excel, Numbers หรือ Google Sheets ตารางหนึ่งมีหลายแถวและหลายคอลัมน์ แต่ละแถวแทนข้อมูลหนึ่งรายการ ส่วนแต่ละคอลัมน์แทน Field หรือชนิดข้อมูลหนึ่งอย่าง นี่คือภาพพื้นฐานของ Relational Database

Relational Database ส่วนใหญ่ใช้ Schema ที่กำหนดไว้ล่วงหน้า เวลาเพิ่มข้อมูลจึงต้องใส่ให้ตรงกับโครงสร้างนั้น เช่น ตารางที่อยู่มีคอลัมน์ที่อยู่ เมือง และจังหวัด ถ้าส่ง Field ชื่อ comment ที่ไม่มีใน Schema เข้ามา Database จะไม่รับ วิธีนี้ช่วยบังคับให้ข้อมูลเป็นระเบียบ แต่ก็ยืดหยุ่นน้อยกว่า Document Database อย่าง MongoDB

จุดเด่นอยู่ที่คำว่า “Relational” เพราะเราสามารถแยกข้อมูลเป็นหลายตารางแล้วเชื่อมความสัมพันธ์กันได้ การ JOIN ตารางเป็นเรื่องปกติของฐานข้อมูลแบบนี้ ต่างจาก MongoDB ที่มักออกแบบให้ข้อมูลที่อ่านพร้อมกันอยู่ใน Document เดียวกัน

SQL คืออะไร

SQL ย่อมาจาก Structured Query Language เป็นภาษาที่ใช้สั่งให้ Database สร้าง อ่าน แก้ไข และลบข้อมูล แต่ละ Database มี SQL Dialect ของตัวเอง จึงมี syntax ต่างกันเล็กน้อย แต่แนวคิดหลักคล้ายกัน เราจะส่ง SQL เป็นข้อความให้ Database อ่านและทำงานให้ ภาษา SQL ไปได้ลึกมาก—ในทางเทคนิค SQL มีความสามารถระดับ Turing complete—แต่บทนี้จะเน้นพื้นฐานที่ใช้บ่อยก่อน

เป้าหมายคือให้คุณเข้าใจว่า Relational Database ทำงานอย่างไร แยกข้อมูลออกเป็นตารางที่สัมพันธ์กันได้ และเขียน Query ให้เหมาะกับโครงสร้างนั้น

ภูมิทัศน์ SQL

คอร์สนี้เลือก PostgreSQL แต่ในโลกของ SQL ยังมีตัวเลือกสำคัญอีกหลายตัว ก่อนตัดสินใจว่า PostgreSQL เหมาะอย่างไร เรามาดูภาพรวมของตัวเลือกอื่นกันก่อน

MySQL / MariaDB

MySQL เป็นอีกตัวเลือกยอดนิยม รองรับระบบอย่าง WordPress และถูกใช้งานในบริษัทขนาดใหญ่มากมาย เช่น Facebook, Google และ Netflix ตัวระบบผ่านการใช้งานมานาน Scale ได้ดี และมี Feature ครบสำหรับงานส่วนใหญ่ ปัจจุบัน MySQL อยู่ภายใต้ Oracle ซึ่งอาจเป็นปัจจัยที่บางทีมต้องพิจารณา

หลัง Oracle ซื้อ MySQL ผู้พัฒนากลุ่มเดิมได้ Fork โครงการออกมาเป็น MariaDB ซึ่งออกแบบให้ใช้แทน MySQL ได้ค่อนข้างตรงไปตรงมา และยังเป็นตัวเลือกที่ได้รับความนิยมมากในปัจจุบัน

SQLite

SQLite เป็น Database ขนาดเล็กแต่ทรงพลัง จุดต่างสำคัญคือมันไม่ได้รันเป็น Server แยก แต่เก็บข้อมูลลงไฟล์โดยตรง เมื่อตัดส่วน Network และ Replication ออก ตัวระบบจึงเล็กและฝังไปกับอุปกรณ์ได้ง่าย ตั้งแต่ระบบปฏิบัติการ อุปกรณ์ IoT ไปจนถึงเครื่องเกมอย่าง PlayStation และ Xbox

บริการอย่าง Turso และ Cloudflare นำ SQLite ไปต่อยอดบน Cloud ทำให้ใช้กับ Web App ได้ดีขึ้น โดยเฉพาะระบบที่กระจายตัวหลายจุดหรือมี Database ขนาดเล็กจำนวนมากแทน Database ใหญ่เพียงตัวเดียว

ถ้าอยากศึกษาเพิ่ม ดู คอร์ส SQLite ได้ที่นี่

Microsoft SQL Server / Oracle / DB2

ทั้งสามตัวเป็นผลิตภัณฑ์เชิงพาณิชย์ที่มีประวัติยาวนานและรองรับระบบขนาดใหญ่ได้ดี แต่ค่าใช้จ่ายอาจสูงกว่า Open-Source Database ที่เราจะใช้ในคอร์ส จึงขอเก็บไว้เป็นตัวเลือกให้คุณศึกษาเพิ่มเติมตามบริบทขององค์กร

PostgreSQL

สุดท้ายคือ PostgreSQL หรือที่มักเรียกสั้น ๆ ว่า Postgres เป็น Open-Source Database ที่ได้รับความนิยมมาก มี Feature ครบ ขยายระบบได้ดี และมีผู้ใช้รายใหญ่อย่าง Apple, Microsoft และ Etsy

สำหรับแอปทั่วไป Postgres เป็น Default Choice ที่ดีมาก เพราะรับงานได้หลากหลาย เราค่อยเปลี่ยนไปใช้ Database แบบอื่นเมื่อมีเหตุผลชัดเจนว่าระบบต้องการความสามารถเฉพาะทาง

Postgres ยังขยายความสามารถผ่าน Feature และ Extension จนรองรับงานบางส่วนของ NoSQL หรือ Graph Database ได้ด้วย แต่ถ้าแกนหลักของแอปคือ Graph และ Edge โดยตรง เครื่องมือเฉพาะอย่าง Neo4j ก็ยังเหมาะกว่า ทุกตัวเลือกมี Trade-off และในคอร์สนี้เราจะให้น้ำหนักกับความเรียบง่ายและจำนวนเครื่องมือที่ทีมต้องดูแล
