การใช้ JSON ใน PostgreSQL

JSONB

ข้อมูลบางแบบมีโครงสร้างไม่แน่นอน ถ้าฝืนแยกเป็น Table และ Column อาจต้องสร้าง Field กว้าง ๆ ให้โค้ดตีความเอง หรือแตกเป็นหลาย Table เพื่อรองรับ Schema หลายรูปแบบ งานลักษณะนี้เป็นจุดที่ Document Database อย่าง MongoDB ทำได้ดี

PostgreSQL มี Data Type ชื่อ JSONB ให้เราเก็บ JSON Object ลงใน Column และยังใช้ SQL Query ข้อมูลข้างในได้

ลองนึกถึงระบบกระดานข้อความที่ให้ผู้ใช้ฝัง Poll, รูปภาพ และวิดีโอ วันหน้าอาจเพิ่ม Tweet, เอกสาร หรือ Content แบบอื่นที่เรายังไม่รู้จัก โครงสร้างข้อมูลส่วนนี้จึงต้องยืดหยุ่นต่อ Feature ใหม่

เราออกแบบทั้งหมดด้วย Schema ปกติได้ แต่โครงสร้างจะซับซ้อนและต้องเดาความต้องการในอนาคตมากเกินไป JSONB เหมาะกับส่วนนี้กว่า ตัวอย่างต่อไปสร้าง Table สำหรับ Rich Content ไว้แล้ว จึงไม่ต้องรันซ้ำถ้าคุณโหลด Script ตัวอย่างจากบทก่อนหน้า

DROP TABLE IF EXISTS rich_content;

CREATE TABLE rich_content (
  content_id INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  comment_id INT REFERENCES comments(comment_id) ON DELETE CASCADE,
  content JSONB NOT NULL
);

INSERT INTO rich_content
  (comment_id, content)
VALUES
  (63, '{ "type": "poll", "question": "What is your favorite color?", "options": ["blue", "red", "green", "yellow"] }'),
  (71, '{ "type": "video", "url": "https://youtu.be/dQw4w9WgXcQ", "dimensions": { "height": 1080, "width": 1920 }}'),
  (104, '{ "type": "poll", "question": "Is this your favorite video?", "options": ["yes", "no", "oh you"] }'),
  (201, '{ "type": "image", "url": "https://btholt.github.io/complete-intro-to-linux-and-the-cli/WORDMARK-Small.png", "dimensions": { "height": 400, "width": 1084 }}'),
  (274, '{ "type": "image", "url": "https://btholt.github.io/complete-intro-to-linux-and-the-cli/HEADER.png", "dimensions": { "height": 237 , "width": 3301 }}');
  • JSONB ช่วยให้เก็บ JSON Object แล้ว Query ข้อมูลภายในภายหลังได้
  • PostgreSQL ตรวจรูปแบบให้และจะไม่รับ JSON ที่เขียนไม่ถูกต้อง
  • JSON ซ้อนได้หลายระดับ ตราบใดที่ยังเป็น JSON ที่ถูกต้อง

ตั้งแต่ PostgreSQL 14 เป็นต้นมา เราเข้าถึง Property ด้วยวงเล็บคล้าย JavaScript ได้

SELECT content['type'] FROM rich_content;

ผลลัพธ์จะเป็นแบบนี้

## ?column?

"poll"
"video"
"poll"
"image"
"image"

สังเกตเครื่องหมายคำพูดรอบๆ ค่า—PostgreSQL ส่งคืนค่าเหล่านี้เป็น JSON ไม่ใช่ข้อความธรรมดา ความแตกต่างนั้นสำคัญเมื่อคุณต้องการเปรียบเทียบค่าหรือกรองผลลัพธ์ที่ซ้ำกัน

ผลลัพธ์มี poll และ image ซ้ำเพราะมีข้อมูลชนิดละสองรายการ ถ้าต้องการเฉพาะค่าที่ไม่ซ้ำ ใช้ SELECT DISTINCT ได้ แต่ลอง Query ต่อไปนี้แล้วจะพบ Error

SELECT DISTINCT content['type'] FROM rich_content;

PostgreSQL ไม่ทราบว่าข้อมูลประเภทใดที่จะได้รับกลับมาจาก JSON ดังนั้นจึงปฏิเสธที่จะทำการเปรียบเทียบกับผลลัพธ์ใดๆ เราจำเป็นต้องแยกค่าเป็นข้อความ และเพื่อที่เราจะใช้ตัวดำเนินการ ->>:

SELECT DISTINCT content ->> 'type' FROM rich_content;

->> แยกค่าออกมาเป็น String ธรรมดา PostgreSQL จึงนำไปเปรียบเทียบและตัดค่าซ้ำได้

ถ้าต้องการเฉพาะ Content ชนิด Poll ให้เพิ่มเงื่อนไขดังนี้

SELECT content ->> 'type' AS content_type, comment_id
FROM rich_content
WHERE content ->> 'type' = 'poll';

WHERE ทำงานก่อน SELECT จึงยังอ้าง Alias content_type ในเงื่อนไขไม่ได้ ต้องเขียน Expression เต็มอีกครั้ง

ถ้าต้องการความกว้างและความสูงที่ซ้อนอยู่ใน dimensions เราผสมวงเล็บกับ ->> ได้

SELECT
  content['dimensions'] ->> 'height' AS height,
  content['dimensions'] ->> 'width' AS width,
  comment_id
FROM
  rich_content;

ใช้วงเล็บเข้าถึง Object ที่ซ้อนกัน แล้วใช้ ->> ตอนสุดท้ายเมื่อต้องการค่าเป็น String Query นี้ยังคืน Row ที่ไม่มีความกว้างและความสูง ถ้าต้องการตัดออกให้เพิ่มเงื่อนไขดังนี้

SELECT
  content['dimensions'] ->> 'height' AS height,
  content['dimensions'] ->> 'width' AS width,
  comment_id
FROM
  rich_content
WHERE
  content['dimensions'] IS NOT NULL;

ตัวดำเนินการ JSON และการแยกข้อความ

PostgreSQL มีหลายวิธีในการดึงค่าจาก JSON ให้อยู่ในรูป Text รูปแบบต่อไปนี้เป็นแบบที่พบได้บ่อยใน Codebase จริง

->> (พบบ่อยที่สุด)

แยกค่าเป็นข้อความ นี่คือสิ่งที่รหัสการผลิตส่วนใหญ่ใช้:

SELECT content ->> 'type' FROM rich_content;

-> (ส่งคืน JSON)

แยกค่าแต่คงไว้เป็นประเภท JSON มีประโยชน์สำหรับการเชื่อมโยงหรือเมื่อคุณต้องการรักษาโครงสร้าง JSON:

SELECT content -> 'dimensions' -> 'height' FROM rich_content;

สัญลักษณ์วงเล็บ (PostgreSQL 14+)

ไวยากรณ์สมัยใหม่ที่ให้ความรู้สึกเหมือน JavaScript ส่งคืน JSON ไม่ใช่ข้อความ:

SELECT content['dimensions']['height'] FROM rich_content;

CAST

แปลง JSON เป็น Text อย่างชัดเจน syntax ยาวขึ้นแต่สื่อเจตนาตรงไปตรงมา

SELECT CAST(content['type'] AS TEXT) FROM rich_content;

#>> กับ Path ว่าง

อีกรูปแบบที่อาจพบในบาง Codebase ใช้แยกค่า JSON ออกมาเป็น Text

SELECT content['type'] #>> '{}' FROM rich_content;

ในทางปฏิบัติ ทีมส่วนใหญ่มักใช้วงเล็บเพื่อเข้าถึง JSON ที่ซ้อนกัน แล้วใช้ ->> เมื่อต้องการ Text ส่วนรูปแบบต่อ -> และ ->> แบบเดิมยังใช้ได้ดีและพบได้บ่อยในโค้ดที่มีอยู่

-- Older style (still common)
SELECT content -> 'dimensions' ->> 'height' FROM rich_content;

-- Modern mixed style
SELECT content['dimensions'] ->> 'height' FROM rich_content;

ทั้งสองแบบถูกต้อง เลือกใช้ตาม Convention ของทีม
