เริ่มต้นใช้งาน PostgreSQL

ดังนั้นเราจึงตรวจสอบฐานข้อมูลเชิงสัมพันธ์ทั่วไปเล็กน้อยในส่วนที่แล้ว มาดูการโต้ตอบกับฐานข้อมูลบางส่วนกัน

มาเริ่มต้น PostgreSQL กันเถอะ

เริ่มต้นด้วยการเริ่มต้นใช้งานคอนเทนเนอร์ PostgreSQL ฉันจะใช้เวอร์ชัน 18.0 (คอนเทนเนอร์ล่าสุดที่มีอยู่) และฉันอยากจะแนะนำสำหรับบทช่วยสอนนี้คุณก็ทำเช่นเดียวกัน แม้ว่าอาจมีเวอร์ชันใหม่กว่านี้ แต่เวอร์ชันนี้จะใช้ได้กับบทช่วยสอนนี้

docker run --name my-postgres -e POSTGRES_PASSWORD=mysecretpassword -p 5432:5432 -d --rm pgvector/pgvector:pg18-trixie

docker exec -it -u postgres my-postgres psql
  • เราต้องให้รหัสผ่าน ไม่เช่นนั้น PostgreSQL จะไม่เริ่มทำงานตามค่าเริ่มต้น ไม่ต้องกังวล นี่ไม่ใช่วิธีที่คุณเริ่มต้นใช้งานจริง
  • เรากำลังดำเนินการในฐานะผู้ใช้ postgres
  • เราสามารถใช้รูปภาพ Postgres ปกติได้ แต่เราต้องการใช้รูปภาพ pgvector นี่เป็นอิมเมจเดียวกับ Postgres แต่เพิ่มส่วนขยาย pgvector เข้าไปด้วย ดังนั้นเราจึงไม่ต้องติดตั้งในภายหลัง ไม่อย่างนั้นก็เหมือนเดิม

ฐานข้อมูลและตาราง

สิ่งนี้อาจทำให้เกิดความสับสนได้เนื่องจากคำว่า "ฐานข้อมูล" มีการใช้งานมากเกินไป เมื่อฉันได้ยินคำว่า "ฐานข้อมูล" ฉันคิดว่าโครงสร้างระดับมหภาคเช่น Postgres และ MySQL ซึ่งเป็นเรื่องจริง แต่ผลิตภัณฑ์เหล่านี้ยังใช้คำว่า "ฐานข้อมูล" เพื่อแสดงถึงอินสแตนซ์หนึ่งของโครงสร้างข้อมูลภายใน ดังนั้นด้วย Postgres คุณสามารถมีฐานข้อมูลได้หลายฐานข้อมูล โดยพื้นฐานแล้วมันคือกลุ่มของตาราง ดังนั้นคุณจึงสามารถจัดระเบียบข้อมูลของคุณลงในฐานข้อมูล "การวิเคราะห์" และในฐานข้อมูล "เชิงปฏิบัติ" ได้ หากคุณต้องการแยกความแตกต่างที่ชัดเจนระหว่างทั้งสอง

คิดว่ามันเหมือนกับสเปรดชีต "ฐานข้อมูล" ในแง่นี้จะเป็นสเปรดชีตใหม่ทั้งหมดที่บันทึกไว้แยกต่างหาก คุณจะต้องเปิดไฟล์ใหม่ทั้งหมดจึงจะสามารถเข้าถึงข้อมูลได้ เป็นการยากที่จะเชื่อมโยงเซลล์ระหว่างสองไฟล์ทั้งหมด (แต่ไม่ใช่เป็นไปไม่ได้ โดยทั่วไปแล้วไม่ใช่สิ่งที่คุณต้องการทำ)

นี่จะเป็นกลุ่มของตารางที่เกี่ยวข้องกับพื้นที่ปัญหาที่คล้ายกัน ขึ้นอยู่กับคุณว่าคุณจะเลือกจัดกลุ่มสิ่งเหล่านี้อย่างไร แอพบางตัวมีสมาธิมากพอที่จะรวมไว้ในฐานข้อมูลเดียว อื่นๆ จะต้องมีฐานข้อมูลจำนวนมาก ขึ้นอยู่กับคุณและสถาปนิกข้อมูลของคุณที่จะหาวิธีดำเนินการดังกล่าว โดยทั่วไป สิ่งที่ควรแยกส่วน (เช่น ธุรกรรมการชำระเงินและสินค้าในร้านค้าของคุณ)

ตารางจะคล้ายกับตารางในสเปรดชีต นี่จะเป็นกลุ่มของคอลัมน์และแถว มันเหมือนกับแท็บสเปรดชีต Excel หนึ่งแท็บ เรกคอร์ด (หรือแถว) เป็นสิ่งหนึ่งในตาราง หนึ่งระเบียนจะเป็นผู้ใช้ในฐานข้อมูลผู้ใช้

ตารางจะมีสคีมาที่กำหนดไว้ เช่นเดียวกับใน Excel คอลัมน์หนึ่งจะแสดงข้อมูลหนึ่งบิต ดังนั้นฟิลด์ในระเบียนก็จะแทนข้อมูลหนึ่งบิตเช่นกัน ต้องกำหนดสคีมานี้ล่วงหน้าและไม่สามารถทำได้ทันที การเปลี่ยนแปลงสคีมาของตารางเป็นการดำเนินการที่หนักหน่วง และบนโต๊ะขนาดใหญ่อาจใช้เวลาหลายชั่วโมงหรือหลายวันในการดำเนินการ การคิดล่วงหน้าเป็นสิ่งสำคัญที่นี่

นี่เป็นคำแนะนำง่ายๆ สำหรับสิ่งนี้ ยังมีอะไรอีกมากมายในเรื่องนี้ แต่เราจะพูดถึงเมื่อเราดูตัวอย่างที่เรากำหนดไว้

คำสั่ง SQL แรกของเรา

ลำดับแรกของธุรกิจคือการสร้างฐานข้อมูลใหม่ และเราจะทำสิ่งนั้นโดยใช้ SQL SQL ทั้งหมดค่อนข้างคล้ายกัน แต่ไม่จำเป็นต้องเข้ากันได้กับแต่ละอื่น ๆ ดังนั้นแม้ว่าการเริ่มต้นใช้งาน MySQL จะคล้ายกัน แต่ก็จะไม่เหมือนกัน

สิ่งแรกที่คุณจะสังเกตได้คือ ฉันจะใช้อักษรตัวพิมพ์ใหญ่ของคำสำคัญทั้งหมด เพื่อให้อ่านข้อความค้นหาได้ง่ายขึ้น คุณสามารถดูได้ว่าคำใดเป็นคำสำคัญและคำใดไม่อ่านโดยสรุป และยิ่งไปกว่านั้น มันเป็นเรื่องธรรมดาที่ต้องทำ ฉันจึงยึดหลักปฏิบัติที่ดีที่สุดทั่วไป แล้วก็ลืมทำบ่อยเหมือนกัน😅

ตามค่าเริ่มต้น คุณจะเชื่อมต่อกับฐานข้อมูล "postgres" ซึ่งเป็นเพียงชื่อฐานข้อมูลเริ่มต้น มาสร้างของเราเองชื่อ message_board กันดีกว่า

ดำเนินการต่อและเรียกใช้แบบสอบถามแรกของคุณที่นี่เพื่อสร้างฐานข้อมูลใหม่ ตรวจสอบให้แน่ใจว่าคุณใส่ ; ต่อท้าย แม้ว่าเซมิโคลอนจะเป็นทางเลือกใน JS แต่ไม่ได้อยู่ใน SQL! คิดว่าคุณยังคงดำเนินต่อไปจนกว่าคุณจะรวม ; นั้น

CREATE DATABASE message_boards;

คุณควรเห็น CREATE DATABASE ข้างใต้เพื่อเป็นการยืนยันว่าผ่านไปแล้ว ยอดเยี่ยม! ตอนนี้เรามีฐานข้อมูลใหม่ที่จะเปลี่ยนไป เรามาดำเนินการกันเถอะ

\c message_boards;
-- \connect message_boards works too

สัญกรณ์ \ นี้คือวิธีที่คุณให้คำสั่งผู้ดูแลระบบแก่ PostgreSQL ผ่านทาง psql CLI ซึ่งเป็นสิ่งที่เราใช้อยู่ตอนนี้ ในกรณีนี้ เรากำลังบอกว่าเชื่อมต่อกับฐานข้อมูลใหม่นี้ มาลองใช้คำสั่งอื่น ๆ กันอย่างรวดเร็ว!

-- see all databases
\l

-- see all tables in this database, probably won't see anything
\d

-- see all available commands
\?

-- see available queries
\h

-- run a shell command
\! ls && echo "hi from shell!"

ในกรณีที่คุณไม่รู้ -- คือวิธีแสดงความคิดเห็นใน SQL

ตารางแรก

เอาล่ะ ตอนนี้เรามีฐานข้อมูลและเชื่อมต่อกับฐานข้อมูลแล้ว เรามาสร้างตารางแรกกัน

CREATE TABLE users (
  user_id INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  username VARCHAR ( 25 ) UNIQUE NOT NULL,
  email VARCHAR ( 50 ) UNIQUE NOT NULL,
  full_name VARCHAR ( 100 ) NOT NULL,
  last_login TIMESTAMP,
  created_on TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

มาดูรายละเอียดของคำสั่งนี้กัน

  • CREATE TABLE คือคำสั่งสำหรับสร้างตารางใหม่ โดยในที่นี้เราตั้งชื่อตารางว่า users
  • user_id เป็นฟิลด์ตัวเลขที่เพิ่มค่าอัตโนมัติ ผู้ใช้คนแรกจะมี user_id เป็น 1 คนที่สองเป็น 2 และเพิ่มต่อไปเรื่อย ๆ ซึ่งเป็นหน้าที่ของ GENERATED ALWAYS AS IDENTITY ส่วน PRIMARY KEY ระบุว่าฟิลด์นี้เป็นคีย์หลักและ PostgreSQL จะสร้างดัชนีให้โดยอัตโนมัติ
  • ก่อนหน้านี้ PostgreSQL ใช้ประเภทฟิลด์ชื่อ SERIAL เพื่ออธิบาย ID ที่เพิ่มขึ้นตามลำดับ ไวยากรณ์ GENERATED AS ALWAYS ใหม่กว่า สอดคล้องกับข้อกำหนด SQL ทั่วไปมากกว่า และทำงานได้ดีกว่า ใช้มันทับ SERIAL เสมอ
  • PostgreSQL จะไม่สร้างคีย์หลักให้กับคุณ - หากคุณต้องการคีย์หลัก คุณต้องสร้างคีย์ด้วยตัวเอง (ฐานข้อมูลอื่นๆ เช่น MongoDB จะสร้างให้คุณโดยอัตโนมัติ)
  • เราสร้าง VARCHARS ขึ้นมาสองตัวซึ่งเป็นวิธี SQL ในการบอกสตริง ชื่อผู้ใช้จะต้องมีจำนวนอักขระสูงสุด 25 ตัว และอีเมลจะมีอักขระได้ไม่เกิน 50 ตัว แต่ละชื่อผู้ใช้จะรับประกันว่าไม่ซ้ำกัน (ขอบคุณ UNIQUE) และจะไม่ละเว้น (ขอบคุณไม่เป็นค่าว่าง)
  • อาจยังคงเป็นสตริงว่างที่มี NOT NULL แต่คุณต้องระบุโดยเจตนา
  • full_name ไม่ใช่ชื่อเฉพาะ ดังนั้นคุณจึงสามารถมี Sally Rogers สองคนได้
  • ช่อง Last_login ของเราจะเป็นครั้งสุดท้ายที่ผู้ใช้เข้าสู่ระบบ เราสามารถใช้ข้อมูลนี้ในภายหลังเพื่อล้างบัญชีที่ไม่ได้ใช้งาน โปรดสังเกตว่าสิ่งนี้ไม่มี NOT NULL ดังนั้นเมื่อเราสร้างผู้ใช้ใหม่ พวกเขาสามารถมีเวลาเข้าสู่ระบบที่เป็นโมฆะได้เพราะพวกเขายังไม่ได้เข้าสู่ระบบ
  • เราเพิ่มฟิลด์ created_on ไว้ด้วย หากคำสั่งไม่ได้ระบุเวลา PostgreSQL จะใช้เวลาปัจจุบันเป็นค่าเริ่มต้น แต่เรายังสามารถกำหนดเวลาอื่นเองได้ เช่น เมื่อนำเข้ารายชื่อผู้ใช้จากฐานข้อมูลอื่น
  • เราใช้ CURRENT_TIMESTAMP แต่เราก็สามารถใช้ NOW() ได้เช่นกัน - CURRENT_TIMESTAMP เป็นวิธีมาตรฐานของ SQL ในการทำสิ่งนี้ NOW() คือฟังก์ชัน Postgres ในทางปฏิบัติพวกเขาทำสิ่งเดียวกันอย่างแน่นอน
  • ฟิลด์ created_on ช่วยให้เราติดตามได้ว่าผู้ใช้แต่ละคนถูกสร้างขึ้นเมื่อใด

เราจะไม่ลงข้อมูลประเภท PostgreSQL มากเกินไป แต่มีข้อมูลมากมาย ดูที่นี่

บันทึกแรก

มาแทรกผู้ใช้ลงในตารางใหม่ของเรา เหมือนกับการเพิ่มแถวใหม่ลงในสเปรดชีต

INSERT INTO users (username, email, full_name) VALUES ('btholt', 'lol@example.com', 'Brian Holt');
  • นี่คือวิธีที่คุณแทรกบันทึกใหม่ลงในฐานข้อมูลเชิงสัมพันธ์
  • INSERT INTO จะบอกกลไก SQL ว่าคุณกำลังจะทำการแทรก และเรากำลังทำการแทรกลงใน users
  • () เป็นที่ที่คุณระบุคำสั่งซื้อที่คุณจะมอบฟิลด์ให้กับ PostgreSQL ในส่วน VALUES
  • โปรดสังเกตว่าเราไม่ได้ระบุ user_id เนื่องจาก PostgreSQL จะจัดเตรียมข้อมูลนั้นเอง
  • นอกจากนี้เรายังไม่ระบุเวลา last_login เนื่องจากไม่จำเป็น และตามทฤษฎีแล้วผู้ใช้ยังไม่ได้เข้าสู่ระบบ

คุณควรเห็น INSERT 0 1 เพื่อแจ้งให้คุณทราบว่าการค้นหาสำเร็จ 1 หมายถึง 1 ระเบียนถูกแทรกสำเร็จ และ 0 หมายถึง OID ที่เราไม่ได้ครอบคลุมหรือใช้งาน และจะเป็น 0 สำหรับเราตลอดหลักสูตร กล่าวคือ ไม่ต้องกังวลกับมัน

ดูบันทึกแรกของคุณ

เรากำลังจะเริ่มการสอบถามล่วงหน้ามากขึ้น แต่ฉันอยากให้คุณเห็นผลของความพยายามของคุณ! เรียกใช้แบบสอบถามนี้เพื่อดึงข้อมูลทุกระเบียนและทุกฟิลด์จากตาราง

SELECT * FROM users;

คุณควรเห็นหนึ่งแถวที่คุณแทรกไว้! ทำได้ดีมาก! คุณเริ่มต้นได้ดีมาก เราจะมาดูคำถามที่เราเพิ่งดำเนินการไปในส่วนถัดไป
