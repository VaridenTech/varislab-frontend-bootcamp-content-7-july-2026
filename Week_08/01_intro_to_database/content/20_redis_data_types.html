ชนิดข้อมูลใน Redis

Redis รองรับชนิดข้อมูลหลายแบบ บทนี้จะเลือกเฉพาะชนิดที่ใช้บ่อย ส่วนกรณีขั้นสูงสามารถศึกษาเพิ่มเติมจากเอกสารของ Redis

  • String ซึ่งรองรับ Binary จึงเก็บเนื้อหา JPEG ได้
  • ตัวเลขและ Integer ภายใน Redis ก็สร้างบน String
  • List หรือ Array
  • Set
  • Sorted Set ซึ่งแต่ละค่ามี Score สำหรับจัดลำดับ เช่น Priority Queue หรือ Top 10
  • Hash ซึ่งคล้าย JavaScript Object หรือ Python Hash

ก่อนหน้านี้เราใช้ String มาแล้ว ลองตรวจชนิดข้อมูลด้วย TYPE

SET name Brian
TYPE name # string
SET visits 10
TYPE visits # string

List

ตัวอย่างที่เหมาะกับ List คือรายการ Notification ของผู้ใช้ สมมติต้องเพิ่มการแจ้งเตือนสามรายการ

RPUSH notifications:btholt "Call your mom" "Feed the dog" "Take out trash"
LRANGE notifications:btholt 0 -1
  • RPUSH เพิ่มหนึ่งค่าหรือหลายค่าที่ท้าย List คล้ายการ Push ลง Stack
  • LRANGE ทำหน้าที่เหมือน GET สำหรับ List และต้องระบุช่วง Index โดย 0 -1 หมายถึงทั้ง List ส่วน 1 5 เริ่มจากสมาชิก Index 1 ถึง 5 เลขติดลบนับจากท้าย โดย -1 คือสมาชิกสุดท้าย

หากผู้ใช้ปิด Notification รายการสุดท้าย ให้ใช้

RPOP mylist
  • RPOP คืนค่าและลบสมาชิกตัวสุดท้าย
  • LPOP ทำงานแบบเดียวกันจากด้านหน้า
  • LPUSH เพิ่มสมาชิกด้านหน้า
  • LTRIM notifications:btholt 0 5 ตัดสมาชิกหลังตำแหน่งที่กำหนด เหมาะกับการจำกัดจำนวน Notification

Hash

Hash เปรียบได้กับ Object ใน Redis ตัวอย่าง Profile ของผู้ใช้

HSET btholt:profile title "principal program manager" company "Microsoft" city "Seattle" state "WA"
HGET btholt:profile city
HGETALL btholt:profile

Hash ช่วยรวม Field หลายค่าไว้ใน Key เดียว Operator หลายตัวมีรูปแบบสำหรับ Hash ด้วย เช่น HINCRBY อ่านรายละเอียดได้จาก เอกสาร Hash

Set และ Sorted Set

Set คือกลุ่มค่าที่ไม่ซ้ำและไม่มีลำดับ ตัวอย่าง Set ของสี

SADD colors red blue green yellow
SMEMBERS colors
SISMEMBER colors green # true
SISMEMBER colors gold # false
SPOP colors # removes and returns a random element

Redis คืนค่า 1 แทนจริง และ 0 แทนเท็จ

Sorted Set เพิ่ม Score หรือ Priority ให้แต่ละค่า จึงเรียกข้อมูลตามลำดับได้

ZADD ordinals 3 third
ZADD ordinals 1 first
ZADD ordinals 2 second
ZADD ordinals 10 tenth
ZRANGE ordinals 0 -1

มองได้ว่าเป็น Array ที่จัดเรียงตัวเองตาม Priority ตลอดเวลา ศึกษาต่อได้จาก เอกสาร Sorted Set

JSON

งานส่วนใหญ่ที่ดูเหมือนต้องใช้ JSON มักแก้ได้ด้วยชนิดข้อมูลอื่น บางครั้งเก็บ JSON String ตรง ๆ ก็เพียงพอ เพราะ Redis มีหน้าที่เก็บและคืนค่า ไม่จำเป็นต้องอ่าน Property ภายใน Object ส่วนกรณีที่ต้องเข้าถึง Property จริง ๆ Redis ก็มีชนิด JSON ให้ใช้งาน อ่าน รายละเอียด JSON

ชนิดข้อมูลอื่น

Redis ยังมีชนิดข้อมูลอีกมาก ดูรายการทั้งหมดได้จาก เอกสาร Data Type
