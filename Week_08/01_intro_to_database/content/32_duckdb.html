เริ่มต้นใช้งาน DuckDB

DuckDB ทำงานต่างจาก Server Database ที่ผ่านมา PostgreSQL และ MongoDB เปิด Server แล้วให้ Client อย่าง psql หรือ mongosh ส่งคำสั่งไปประมวลผล แต่ DuckDB เหมือน SQLite คือเป็น Toolkit แบบ All-in-one ที่ CLI อ่านและแก้ไฟล์บน Disk โดยตรง ไม่ได้เชื่อมต่อ Server

MotherDuck ให้บริการ DuckDB บน Cloud คล้าย Turso สำหรับ SQLite และ DuckDB ยังอ่านเขียนไฟล์ Parquet บน S3 จากระยะไกลได้ จึงยืดหยุ่น เรียบง่าย และมีขนาดเล็ก บทนี้แนะนำให้ติดตั้ง DuckDB โดยตรง แต่ใช้ Docker ก็ได้ ดูวิธีติดตั้งจาก เอกสาร DuckDB

เริ่มด้วยการเปิดไฟล์ว่าง

# this will create a file called my-duck.db
duckdb my-duck.db

หากเปิด DuckDB CLI พร้อม Flag -ui จะได้หน้าจอ Browser สำหรับรัน Query

ลอง Query ไฟล์จาก URL ระยะไกลโดยตรง

SELECT * FROM read_parquet(
  's3://us-prd-motherduck-open-datasets/netflix/netflix_daily_top_10.parquet'
) LIMIT 10;

ตัวอย่างนี้ขึ้นกับว่า MotherDuck ยังเก็บไฟล์ไว้ใน S3 Bucket หรือไม่ หลักสำคัญคือ DuckDB Query ไฟล์ Parquet ที่ Host ไว้จาก URL ได้โดยตรง

ต่อไปบันทึกข้อมูลลงฐานข้อมูลในเครื่อง

CREATE TABLE netflix AS SELECT * FROM read_parquet('s3://us-prd-motherduck-open-datasets/netflix/netflix_daily_top_10.parquet');
SELECT DISTINCT title FROM netflix LIMIT 25;
FROM netflix LIMIT 5;
DESCRIBE netflix;

หาก S3 URL ใช้ไม่ได้ ให้ดาวน์โหลด ไฟล์ Parquet สำรอง แล้วเปลี่ยนคำสั่งเป็น CREATE TABLE netflix AS SELECT * FROM read_parquet('<file path to your parquet file here>');

คำสั่งแรกโหลด Parquet จาก S3 สู่ Table netflix จากนั้นเลือกชื่อเรื่องไม่ซ้ำ 25 รายการ ดูตัวอย่างห้า Row ด้วย Syntax ย่อ และใช้ DESCRIBE ดู Column ทั้งหมด Query มีหน้าตาเหมือน SQL ปกติแต่เพิ่มความสามารถที่เหมาะกับงานวิเคราะห์

ใน Columnar Database ค่าใน Column เดียวกัน เช่น Title, Rank และ Last Week Rank ถูกเก็บรวมกัน จึง Aggregate ข้าม Column ได้รวดเร็ว ตรงข้ามกับ PostgreSQL หรือ MongoDB ที่เก็บแต่ละ Row หรือ Document เป็นก้อนเดียวและต้องเปิดทุก Record เพื่อดึง Field ที่ต้องการ นี่คือเหตุผลที่ DuckDB เร็วสำหรับ OLAP แต่ไม่เหมาะกับ OLTP ที่อ่าน Record ครบชุดทีละรายการ

มาดูว่าช่วง Lockdown ผู้คนดูเรื่องใดต่อเนื่องมากที่สุด

SELECT Title, Type, MAX("Days In Top 10") as peak_days
FROM netflix
WHERE "As of" BETWEEN '2020-03-15' AND '2020-06-30'
GROUP BY ALL
ORDER BY peak_days DESC
LIMIT 10;

GROUP BY ALL แสดงแนวคิดที่ DuckDB ออกแบบมาให้งานวิเคราะห์สะดวก PostgreSQL ต้องระบุ GROUP BY Title, Type เอง หาก Query มีเก้า Column และแก้ SELECT บ่อย ก็ต้องแก้ GROUP BY ให้ตรงทุกครั้ง แต่ DuckDB ลดงานซ้ำนี้ให้

SELECT
  Title,
  Type,
  MAX("Days In Top 10") as total_days,
  ROUND(AVG("Viewership Score"), 1) as avg_score
FROM netflix
WHERE "Netflix Exclusive" = 'Yes'
GROUP BY ALL
ORDER BY total_days DESC
LIMIT 10;

Query นี้วิเคราะห์รายการ Exclusive ของ Netflix โดยเปรียบเทียบจำนวนวันที่ติด Top 10 กับคะแนนผู้ชม Insight ลักษณะนี้ช่วยตัดสินใจว่าควรลงทุนกับเนื้อหาแบบใด

COPY (
  SELECT Title, Type, MAX("Days In Top 10") as peak_days
  FROM netflix
  GROUP BY ALL
  ORDER BY peak_days DESC
) TO 'top_titles.csv' (HEADER);

คำสั่ง COPY Export ผลลัพธ์เป็น CSV เพื่อแชร์หรือนำไปใช้ต่อ ฐานข้อมูลอื่นก็ทำได้ แต่ DuckDB ให้ความสามารถนี้เป็นแกนหลักจึงมี Syntax ที่ง่ายและทำงานเร็ว

นี่เป็นเพียงจุดเริ่มต้นของ DuckDB และฐานข้อมูล OLAP เป้าหมายของบทคือให้เข้าใจว่ามันคืออะไร ทำไม Columnar Storage จึงเร็วสำหรับงานวิเคราะห์ และควรเลือกใช้เมื่อใด
