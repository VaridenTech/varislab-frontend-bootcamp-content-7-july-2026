สร้างแอป Express ด้วย TypeScript

ถึงเวลาลงมือแล้ว บทนี้เราจะตั้งต้นโปรเจกต์ Habit Tracker API ติดตั้งของที่ต้องใช้ แล้วสร้าง Server ตัวแรกที่มี Route เดียวคือ Health Check

เริ่มจากอยู่บน Branch main ของโปรเจกต์ หรือจะแตก Branch ของตัวเองออกมาก็ได้ตามสะดวก แล้วรัน npm install ให้เรียบร้อยก่อนเสมอ

ติดตั้งของที่ต้องใช้

ถ้าเริ่มจากศูนย์จริง ๆ ให้สร้าง package.json แล้วติดตั้งแพ็กเกจตามนี้

npm init -y
npm install express
npm install -D typescript @types/node @types/express

express คือตัว Framework ส่วนอีกสามตัวเป็น Dev Dependency ที่ใช้เฉพาะตอนพัฒนา คือ typescript เอาไว้ให้ Editor ตรวจ Type ให้ และ @types/node กับ @types/express คือชุดคำบรรยาย Type ของ Node.js และ Express ซึ่งทำให้ Editor รู้ว่า req กับ res มี Method อะไรให้เรียกบ้าง

จากนั้นเปิด package.json แล้วปรับให้มีส่วนสำคัญเหล่านี้

{
  "main": "src/index.ts",
  "type": "module",
  "scripts": {
    "dev": "node --watch src/index.ts",
    "start": "node src/index.ts"
  }
}
  • "type": "module" บอก Node.js ว่าไฟล์ในโปรเจกต์นี้เป็น ES Modules ทำให้ใช้ import และ export ได้
  • Script dev คือคำสั่งที่เราจะใช้ตอนพัฒนา จุดสำคัญคือ Flag --watch ซึ่งสั่งให้ Node.js เฝ้าดูไฟล์ พอเราเซฟไฟล์ไหนก็ตาม มันจะรีสตาร์ท Server ให้อัตโนมัติ ถ้าคุณเคยเขียน React คุณได้ของแบบนี้มาฟรี ๆ โดยไม่รู้ตัว ส่วน Script start ใช้ตอนรันบน Production ที่ไม่ต้องเฝ้าดูไฟล์
  • สังเกตว่าเราสั่ง node src/index.ts ไปที่ไฟล์ .ts ตรง ๆ ได้เลย ไม่มีขั้นตอน Build เพราะ Node.js เวอร์ชัน 23.6.0 ขึ้นไปรันไฟล์ TypeScript ได้เอง

ตั้งค่า tsconfig.json

สร้างไฟล์ tsconfig.json ที่รากของโปรเจกต์

{
  "compilerOptions": {
    "noEmit": true,
    "target": "esnext",
    "module": "nodenext",
    "rewriteRelativeImportExtensions": true,
    "erasableSyntaxOnly": true,
    "verbatimModuleSyntax": true,
    "allowImportingTsExtensions": true,
    "types": ["vitest/globals"]
  }
}
  • noEmit คือหัวใจของไฟล์นี้ เราไม่ให้ TypeScript สร้างไฟล์ JavaScript ออกมาเลย เพราะ Node.js รันไฟล์ .ts เองได้อยู่แล้ว TypeScript จึงเหลือหน้าที่เดียวคือตรวจ Type ให้เรา ส่วน module: "nodenext" คือให้ใช้ระบบ Module แบบเดียวกับ Node.js รุ่นใหม่
  • allowImportingTsExtensions และ rewriteRelativeImportExtensions ทำให้เราเขียน import app from './server.ts' โดยใส่นามสกุล .ts ไปตรง ๆ ได้
  • erasableSyntaxOnly ห้ามใช้ไวยากรณ์ TypeScript ที่ลบทิ้งเฉย ๆ ไม่ได้ อย่าง enum เพราะ Node.js แค่ลบ Type ออกแล้วรัน ไม่ได้แปลงโค้ดให้ ส่วน verbatimModuleSyntax บังคับให้เขียน import type ให้ชัดเจนเวลา Import เฉพาะ Type
  • types: ["vitest/globals"] มีไว้สำหรับตอนเขียน Test ในบทที่ 29 ตอนนี้ยังไม่ต้องสนใจ

สร้าง src/server.ts

สร้างโฟลเดอร์ src ขึ้นมา ชื่อนี้ไม่ใช่ข้อบังคับของ Node.js หรือ Express แต่เป็นธรรมเนียมที่คนนิยมใช้ เพื่อบอกว่าไฟล์ในนี้คือ Source Code ที่เราเขียนเอง แยกจากผลลัพธ์ที่เครื่องสร้างขึ้น

แล้วสร้างไฟล์ src/server.ts

import express from 'express'

const app = express()

// Health check endpoint
app.get('/health', (req, res) => {
  res.status(200).json({
    status: 'OK',
    timestamp: new Date().toISOString(),
    service: 'Habit Tracker API',
  })
})

export { app }

export default app

มาไล่ดูทีละส่วน

  • express() เรียกใช้แล้วได้ App กลับมาหนึ่งตัว จะตั้งชื่อตัวแปรว่าอะไรก็ได้ แต่ธรรมเนียมคือเรียกว่า app
  • app.get('/health', ...) คือการลงทะเบียน Route ว่าถ้ามีใครส่ง GET Request มาที่ Path /health ให้รันโค้ดก้อนนี้ สังเกตว่าการจับคู่ใช้ทั้ง Path และ HTTP Verb คู่กันเสมอ ส่วน /health เป็นธรรมเนียมที่ Server ส่วนใหญ่มี เอาไว้ให้ระบบภายนอกยิงเข้ามาเช็คเป็นระยะว่า Server ยังไม่ตาย
  • Callback ที่เราส่งเข้าไปจะได้ Argument สองตัวเสมอ คือ req ซึ่งเป็น Request ขาเข้า (มีข้อมูลของ Client ที่ยิงมา เช่น User Agent และ Header ต่าง ๆ) และ res ซึ่งเป็นตัวที่เราใช้ตอบกลับ
  • res.json(...) ส่ง JSON กลับไป ส่วน res.status(200) คือการกำหนด Status Code ซึ่งเป็นตัวเลขสามหลักที่บอก Client ว่าเกิดอะไรขึ้นบน Server โดย 200 แปลว่าสำเร็จ จริง ๆ ถ้าไม่ระบุ Express จะใช้ 200 ให้อยู่แล้ว แต่การเขียนให้ชัดช่วยให้อ่านง่ายขึ้น
  • บรรทัดสุดท้ายเรา Export ทั้งแบบ Named และแบบ Default เพื่อให้ไฟล์อื่นเลือก Import ได้ตามสะดวก ไม่ได้เปลี่ยนพฤติกรรมอะไร แค่เพิ่มทางเลือกให้ตัวเอง

สังเกตว่าไฟล์นี้ไม่มี app.listen() เลย เพราะเราจงใจแยกหน้าที่ "นิยาม App" ออกจาก "สั่งให้ Server เริ่มทำงาน" ประโยชน์ที่ได้คือตอนเขียน Test เรา Import app เข้าไปทดสอบได้โดยไม่ต้องเปิด Server จริง และย้ายไปใช้ในบริบทอื่นได้ง่าย

สร้าง src/index.ts

ไฟล์นี้คือ Entry Point ของแอปเรา มีหน้าที่เดียวคือสั่งให้ Server เริ่มฟัง

import app from './server.ts'

app.listen(3000, () => {
  console.log('Server running on port 3000')
})

Port คือช่องทางที่โปรแกรมเปิดไว้รับการเชื่อมต่อบนเครื่อง ทุกเว็บไซต์ก็มี Port เหมือนกัน (เว็บทั่วไปคือ 80 หรือ 443) เพียงแต่ Browser ตัดมันออกจาก URL ให้เราไม่เห็น สำหรับงานพัฒนา Port ยอดนิยมคือ 3000

กฎเหล็กคือ หนึ่ง Port เปิดฟังได้ทีละโปรแกรมเท่านั้น และจริง ๆ แล้วเครื่องคุณตอนนี้น่าจะมี Server รันอยู่หลายตัวโดยที่คุณไม่รู้ตัว เช่น TypeScript Plugin ใน Editor ก็เปิด Server ของตัวเองไว้คอยตรวจโค้ดทุกครั้งที่คุณพิมพ์

ส่วน Callback ตัวที่สองไม่ใส่ก็ได้ แต่แนะนำให้ใส่ เพราะถ้าไม่มี Log อะไรเลย เวลารันแล้วเทอร์มินัลค้างนิ่ง ๆ เราจะไม่รู้เลยว่ามันทำงานอยู่หรือพังไปแล้ว (ในบทที่ 5 เราจะเปลี่ยนเลข 3000 ที่ Hardcode ไว้ตรงนี้ให้มาจาก Environment Variable แทน)

รัน Server

npm run dev

ถ้าทุกอย่างถูกต้องคุณจะเห็นข้อความที่เรา Log ไว้

Server running on port 3000

ถ้าเจอ Error ว่า EADDRINUSE แปลว่ามีโปรแกรมอื่นใช้ Port นั้นอยู่แล้ว ให้เปลี่ยนไปใช้ 3001 แล้วไล่เลขขึ้นไปจนกว่าจะได้

สิ่งที่ต่างจากโค้ดฝั่ง Browser อย่างชัดเจนคือ คำสั่งนี้จะไม่จบเอง Function ทั่วไปทำงานเสร็จแล้วก็จบ แต่ Server มีหน้าที่อยู่ให้ได้นานที่สุด มันจะรันไปเรื่อย ๆ จนกว่าเราจะสั่งหยุดด้วย Ctrl + C หรือมันพังไปเอง

ตอนนี้ Server ของเราพร้อมแล้ว แต่เรายังไม่ได้ลองยิง Request เข้าไปดูเลย บทถัดไปเราจะใช้ Postman ทำสิ่งนั้นกัน
