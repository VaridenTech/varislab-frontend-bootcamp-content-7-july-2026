Global Middleware

บทที่แล้วเราเข้าใจแนวคิดแล้ว บทนี้เราจะติดตั้งของจริงลงใน src/server.ts เป็นชุด Middleware ที่ผมใส่ให้ทุกโปรเจกต์โดยไม่ต้องคิด และคุณก็ควรใส่เหมือนกัน

app.use() แบบไม่ใส่ Path

ตอนทำ Routing เราใช้ app.use('/api/users', userRoutes) ซึ่งแปลว่า "ใช้สิ่งนี้กับทุก Request ที่ Path ตรงกับ /api/users ไม่ว่า Verb ไหน" แต่ถ้าเราไม่ใส่ Path เลย ความหมายจะกลายเป็น "ใช้สิ่งนี้กับทุกอย่าง ทุก Path ทุก Verb ตลอดกาล" — นั่นคือ Global Middleware

app.use(helmet())   // ไม่มี Path = ทำงานกับทุก Request

และเพราะ Middleware ทำงานตามลำดับที่ลงทะเบียน Global Middleware ต้องอยู่บนสุดเสมอ เพื่อให้ทุกอย่างที่มาทีหลังได้ประโยชน์จากมัน ถ้าเราวาง express.json() ไว้ใต้ Route ของเรา Route นั้นจะอ่าน req.body ไม่เจอ

ติดตั้ง Package

ก่อนอื่นตรวจใน package.json ว่ามีสามตัวนี้แล้วหรือยัง ถ้ายังก็ติดตั้งซะ

npm install cors helmet morgan
npm install -D @types/cors

เกร็ดที่น่าทึ่งคือ Middleware สามตัวนี้อายุเกินสิบปีกันหมดแล้ว แต่ยังถูกใช้อยู่ทุกวันจนถึงวันนี้

helmet — ชุดเกราะสำเร็จรูป

Helmet คือถุงรวมมิตรของ Security Best Practice ที่ทุก Server ควรมี หน้าที่หลักของมันคือเซ็ต HTTP Header ต่าง ๆ ให้เหมาะสม เพื่อป้องกันการโจมตีรูปแบบพื้นฐานที่เราจะโดนได้ถ้าไม่ทำอะไรเลย

ผมไม่ได้จำได้ทุกข้อว่ามันเซ็ตอะไรบ้าง (ไปอ่านใน Docs ได้) แต่ผมใส่มันทุกโปรเจกต์เพราะมันคือของฟรีที่ได้ความปลอดภัยเพิ่มขึ้นทันทีจากโค้ดบรรทัดเดียว

cors — และทำไมคุณเคยเจอ Error ตัวนี้

CORS ย่อมาจาก Cross-Origin Resource Sharing และมันเป็นกลไกที่มีอยู่ใน Browser เท่านั้น หน้าที่ของมันคือปกป้องผู้ใช้ ไม่ให้ Script ที่รันอยู่บนเว็บหนึ่ง แอบไปดึงทรัพยากรจากอีก Origin หนึ่งได้ตามใจชอบ

วิธีทำงานคือก่อนจะส่ง Request จริง Browser จะยิงสิ่งที่เรียกว่า Preflight Check ไปก่อน ซึ่งก็คือ Request ด้วย Method OPTIONS เนื้อความประมาณว่า "คนนี้จะเข้าถึง URL นี้ Origin ของเขาคืออันนี้ Header ที่เขาจะใช้คืออันนี้ อนุญาตไหม" จากนั้น Server จะตอบกลับว่ารายชื่อ Origin และ Header ที่อนุญาตมีอะไรบ้าง แล้ว Browser ค่อยตัดสินใจว่าจะยอมส่ง Request จริงหรือไม่

ดังนั้นเวลาคุณยิง Request จาก Browser บางครั้งมันคือสองครั้ง คือ OPTIONS แล้วตามด้วยของจริง ถ้าไม่ผ่านคุณก็จะเห็นคำว่า CORS Error สีแดงใน Console

สองเรื่องที่ควรจำ

  • ถ้าไม่ตั้ง Policy เลย Browser จะบล็อกทุกอย่าง มันไม่ได้ตีความว่า "ไม่มีกฎแปลว่าอนุญาตหมด" แต่ตีความตรงกันข้าม ดังนั้นต่อให้เราไม่แคร์ว่าใครจะเข้ามาใช้ เราก็ยังต้องเขียนให้ชัด ไม่งั้นไม่มีใครใช้ได้
  • Postman กับ curl ไม่โดน CORS เพราะมันไม่ใช่ Browser ไม่มีการทำ Preflight เหตุผลที่มีกลไกนี้เฉพาะใน Browser ก็เพราะ Browser คือที่ที่ Script ของคนอื่นรันอยู่นอกเหนือการควบคุมของเรา ส่วนถ้ามีคนรัน Script แปลก ๆ ใน Terminal ของคุณได้ คุณมีปัญหาที่ใหญ่กว่านั้นแล้ว

ในคอร์สนี้เราจะเปิดกว้างไปก่อนด้วย cors() เปล่า ๆ ซึ่งแปลว่าอนุญาตทุก Origin

app.use(cors())

พอขึ้น Production จริงที่มี Client ของตัวเอง ค่อยเปลี่ยนเป็นแบบระบุรายชื่อ

app.use(
  cors({
    origin: ['http://localhost:5173'],
    credentials: true,
  })
)

ในโปรเจกต์จริงคนนิยมเก็บรายชื่อ Origin ไว้ใน Environment Variable แล้วอ่านผ่าน env.ts ที่เราทำไว้ในบทที่ 6 จะได้เปลี่ยนตามแต่ละ Environment ได้โดยไม่ต้องแก้โค้ด

express.json() — กุญแจสู่ req.body

ตัวนี้ติดมากับ Express อยู่แล้ว ไม่ต้องติดตั้งเพิ่ม แต่ถ้าไม่ใส่ คุณจะอ่าน req.body ไม่ได้

เหตุผลคือข้อมูลที่วิ่งเข้ามาบนสายเป็น Stream ของ Byte ล้วน ๆ ถ้าไม่มีใครมาอ่านและแปลงให้ สิ่งที่คุณได้ใน Handler จะเป็นข้อมูลดิบ ไม่ใช่ Object ที่ใช้งานได้ Middleware ตัวนี้ทำหน้าที่แปลง JSON Payload ให้กลายเป็น Object แล้ววางไว้ที่ req.body พร้อมใช้

app.use(express.json())

express.urlencoded() — สำหรับ Form และ Query

app.use(express.urlencoded({ extended: true }))

ตัวนี้จัดการข้อมูลที่ถูก Encode มาแบบ URL ซึ่งเจอได้ทั้งใน Query String และใน Body ของ Form แบบดั้งเดิม เพราะบางอักขระในกลุ่มนี้จะถูกแทนที่ด้วยรหัส Middleware ตัวนี้จึงอ่าน Content-Type ของ Request แล้วถอดรหัสให้ถูกวิธี

ส่วน Option extended: true เป็นตัวเลือกว่าจะใช้ Library ไหนในการ Parse ระหว่าง querystring (ถ้าเป็น false) กับ qs (ถ้าเป็น true) ผมใส่ true มาตลอดชีวิตเพราะเคยเจอปัญหากับ Query String ตอนไม่ใส่ ก็เลยใส่ไปตลอด

morgan — Log ทุก Request

Morgan ไม่ใช่ Logger แบบ console.log ที่เราเรียกเองในโค้ด แต่มันคือ Request Logger ที่ Log ทุก Request ที่วิ่งเข้า Server ของเราโดยอัตโนมัติ ซึ่งเป็นสิ่งที่ Server ทุกตัวควรมี

app.use(
  morgan('dev', {
    skip: () => isTest(),
  })
)

Morgan มีหลาย Mode ผมชอบ 'dev' เพราะมันมีสี ส่วน Option skip คือบอกว่า "กรณีไหนไม่ต้อง Log" ตรงนี้เราเสียบฟังก์ชัน isTest() จาก env.ts เข้าไป เพราะเวลารัน Test เราไม่อยากเห็น Log เต็มจอ

Higher-Order Function คือความตั้งใจ

สังเกตไหมว่าเราเขียน helmet() ไม่ใช่ helmet เฉย ๆ ทั้งที่ตอนใส่ Router เราเขียน app.use('/api/users', userRoutes) โดยไม่มีวงเล็บ

นั่นเพราะ Router เป็น Middleware อยู่แล้วในตัวมันเอง แต่ Package พวกนี้ถูกออกแบบมาเป็น Higher-Order Function คือฟังก์ชันที่ Return ฟังก์ชันอีกที เหตุผลคือเพื่อเปิดช่องให้เราส่ง Option เข้าไปได้ อย่างที่เราทำกับ cors({...}) และ morgan('dev', {...}) การเรียกฟังก์ชันชั้นนอกจึงเป็นการ "ผลิต" Middleware ตัวจริงออกมา นี่เป็นธรรมเนียมที่ Middleware และ Plugin ส่วนใหญ่ใช้กัน และเป็นเทคนิคที่เราจะเอาไปเขียนเองในบทหน้า

ประกอบร่างใน src/server.ts

import express from 'express'
import cors from 'cors'
import helmet from 'helmet'
import morgan from 'morgan'
import { isTest } from '../env.ts'
import authRoutes from './routes/authRoutes.ts'
import habitRoutes from './routes/habitRoutes.ts'
import userRoutes from './routes/userRoutes.ts'

const app = express()

// Global middleware
app.use(helmet())
app.use(cors())
app.use(express.json())
app.use(express.urlencoded({ extended: true }))
app.use(
  morgan('dev', {
    skip: () => isTest(),
  })
)

// Health check endpoint
app.get('/health', (req, res) => {
  res.status(200).json({
    status: 'OK',
    timestamp: new Date().toISOString(),
    service: 'Habit Tracker API',
  })
})

// Routes
app.use('/api/auth', authRoutes)
app.use('/api/habits', habitRoutes)
app.use('/api/users', userRoutes)

export { app }

export default app

ลำดับที่ใช้คือหลักการเดียวกับที่ใช้ได้ทุกโปรเจกต์ — ความปลอดภัยก่อน แล้วค่อย Parse ข้อมูล แล้วค่อย Log แล้วค่อยถึง Business Logic

ทดสอบ

รัน npm run dev แล้วยิง GET /health จาก Postman สักสามสี่ครั้ง จากนั้นกลับไปดูที่ Terminal คุณจะเห็นบรรทัด Log ของ Morgan บอกว่า Method อะไร Path ไหน Status Code เท่าไร และใช้เวลากี่มิลลิวินาที ลองยิง Path มั่ว ๆ ดูบ้างก็จะเห็น 404 โผล่มา

อีกเรื่องที่คนเพิ่งเริ่มเขียน Server สับสนกันบ่อย — Console ของ Server คือ Terminal ไม่ใช่ Console ใน Browser ตอนผมเริ่มเขียน Server ใหม่ ๆ ผมก็นั่งเปิด Chrome DevTools หา Log อยู่นาน

ตอนนี้ทุก Request ที่เข้ามาผ่านด่านมาตรฐานครบแล้ว บทหน้าเราจะเขียน Middleware ของเราเองตัวแรก คือตัวที่คอยตรวจว่าข้อมูลที่ Client ส่งมาถูกต้องหรือไม่
