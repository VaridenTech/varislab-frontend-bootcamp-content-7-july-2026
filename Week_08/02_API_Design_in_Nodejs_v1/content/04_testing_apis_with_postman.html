ทดสอบ API ด้วย Postman

ตอนนี้ Server ของเรารันอยู่แล้วที่ http://localhost:3000 แต่เรายังไม่มีหน้าจอไว้กดเรียกมันเลย และเราก็จะไม่สร้างด้วย เพราะการสร้าง UI แค่เพื่อทดสอบ API เป็นการเสียเวลาโดยใช่เหตุ

สิ่งที่เราจะใช้แทนคือ REST Client ซึ่งเป็นโปรแกรมที่ทำหน้าที่เป็น Client ปลอม ๆ ให้เรากรอก URL เลือก HTTP Verb ใส่ Body แล้วกดส่ง จากนั้นมันจะโชว์คำตอบทั้งหมดที่ Server ส่งกลับมาให้เราดูแบบละเอียด

ติดตั้ง Postman

ค้นหาคำว่า Postman ใน Google แล้วเข้าเว็บทางการ ตรงนี้มีจุดที่ต้องระวังนิดหนึ่ง คือหน้าเว็บจะมีปุ่มสีส้มเด่น ๆ ชวนให้ Sign Up ฟรี อย่ากดปุ่มนั้น ให้มองหาปุ่ม Download สีเทาที่กลมกลืนไปกับพื้นหลัง แล้วเลือกเวอร์ชันที่ตรงกับระบบปฏิบัติการของคุณ วิธีนี้จะได้ตัวโปรแกรมมาใช้โดยไม่ต้องสมัครบัญชี

ฟีเจอร์ที่ต้องเสียเงินของ Postman เป็นฟีเจอร์สำหรับทำงานเป็นทีม ซึ่งเราไม่ได้ใช้ในคอร์สนี้

ถ้าคุณมีเครื่องมือที่ถนัดอยู่แล้วก็ใช้ตัวนั้นได้เลย ทางเลือกอื่นที่นิยมกันได้แก่ Insomnia, Extension สำหรับยิง Request ที่ติดตั้งใน VS Code ได้ หรือจะใช้ curl ในเทอร์มินัลก็ได้เหมือนกัน

curl http://localhost:3000/health

ทุกตัวทำงานเหมือนกันหมด ต่างกันแค่หน้าตา เนื้อหาบทนี้อธิบายด้วย Postman เป็นหลัก

ยิง GET Request ตัวแรก

ตรวจให้แน่ใจก่อนว่า npm run dev ยังรันอยู่ในเทอร์มินัล แล้วใน Postman ให้ตั้งค่าตามนี้

  1. เปิด Request ใหม่ แล้วเลือก Verb เป็น GET จากช่อง Dropdown ด้านซ้ายของช่อง URL
  2. ใส่ URL ว่า http://localhost:3000/health
  3. กด Send

คำว่า localhost คือชื่อเล่นของเครื่องคุณเอง เขียนเป็น 127.0.0.1 ก็ได้ผลเหมือนกัน ส่วน :3000 คือ Port ที่เราเปิดไว้ใน src/index.ts ข้อนี้ห้ามลืมใส่ เพราะ Browser ที่เราใช้กันทุกวันมันซ่อน Port ให้ จนหลายคนไม่ชินว่าต้องระบุ

สิ่งที่ควรได้กลับมาคือ JSON ก้อนนี้

{
  "status": "OK",
  "timestamp": "2026-01-15T10:30:00.000Z",
  "service": "Habit Tracker API"
}

ถ้าได้แบบนี้แปลว่า API ตัวแรกของคุณทำงานแล้วจริง ๆ และนี่ก็คือแก่นทั้งหมดของการทำ API เรื่องที่เหลือในคอร์สนี้เป็นเพียงส่วนประกอบที่มาเสริมให้มันแข็งแรงขึ้นเท่านั้น

อ่านคำตอบจาก Server ให้เป็น

อย่ามองแค่ Body ที่ตอบกลับมา เพราะ Postman บอกเราได้มากกว่านั้น ให้สังเกตสามจุดนี้

  • Status Code — ตัวเลขสามหลักที่มุมขวาบน ในกรณีนี้คือ 200 OK ตัวเลขนี้คือสิ่งที่ Client และซอฟต์แวร์อื่น ๆ ดูเพื่อตัดสินว่าเกิดอะไรขึ้น เราจะเรียนเรื่อง Status Code แบบเต็ม ๆ ในบทที่ 7
  • Headers — เปิดแท็บ Headers ในส่วนของ Response คุณจะเห็น Content-Type: application/json; charset=utf-8 ซึ่ง res.json() ตั้งให้เราอัตโนมัติ Header คือข้อมูลกำกับที่บอกว่า Body ที่ส่งมาเป็นข้อมูลชนิดไหน
  • Body — เนื้อข้อมูลจริง Postman มีปุ่มให้สลับดูแบบ Pretty, Raw และ Preview นอกจากนี้ยังบอกเวลาที่ใช้และขนาดของ Response ให้ด้วย ซึ่งมีประโยชน์มากตอนไล่หาว่า Route ไหนช้า

Server ส่งอะไรกลับได้บ้าง

Object res มี Method ให้เลือกใช้หลายตัว ไม่ได้มีแค่ res.json() ลองแก้ Route ชั่วคราวเป็นแบบนี้ดู

app.get('/health', (req, res) => {
  res.send('<button>click me</button>')
})

กด Send อีกครั้ง คุณจะเห็นว่า Postman แสดงผลออกมาเป็น HTML ที่เรนเดอร์เป็นปุ่มจริง ๆ เพราะ res.send() เดา Content-Type ให้ตามชนิดข้อมูลที่เราส่งเข้าไป

บทเรียนตรงนี้คือ Server ส่งอะไรกลับก็ได้ ไม่ได้จำกัดอยู่แค่ JSON แต่มีเงื่อนไขข้อเดียวคือ ของนั้นต้องแปลงเป็นข้อมูลที่วิ่งข้ามเครือข่ายได้ พูดง่าย ๆ คืออะไรที่เขียนลงไฟล์ได้ก็ส่งได้

  • ส่ง Function ไม่ได้ เพราะส่งของที่รันได้ข้ามเครือข่ายไม่ได้ (ส่งเป็น String ที่หน้าตาเหมือน Function ได้ แต่ปลายทางก็ได้แค่ String)
  • ส่ง Object ที่อ้างถึงตัวเองวนไปมา (Cyclic) ไม่ได้ เพราะแปลงเป็น JSON ไม่ได้
  • Date Object จะถูกแปลงเป็น String โดยอัตโนมัติ ซึ่งเป็นเหตุผลที่ใน Route จริงของเราเขียน new Date().toISOString() ไว้ชัดเจน เพื่อควบคุมรูปแบบเอง

ลองเล่นเสร็จแล้วอย่าลืมแก้ Route กลับไปเป็น res.status(200).json({ ... }) เหมือนเดิมนะ

ลองยิง POST Request

เปลี่ยน Verb เป็น POST โดยที่ URL ยังเป็น http://localhost:3000/health เหมือนเดิม แล้วกด Send คุณจะได้ Status 404 Not Found พร้อมข้อความประมาณว่า

Cannot POST /health

นี่ไม่ใช่ความผิดพลาด แต่เป็นหลักฐานยืนยันสิ่งที่พูดไปในบทที่แล้วว่า Express จับคู่ Route ด้วย Path และ Verb คู่กันเสมอ เราลงทะเบียนไว้แค่ app.get('/health', ...) ดังนั้น POST ที่มาที่ Path เดียวกันจึงไม่ตรงกับ Route ไหนเลย

ตอนที่เรามี Route แบบ POST จริง ๆ ในบทถัด ๆ ไป การส่งข้อมูลแนบไปกับ Request ทำได้โดยเปิดแท็บ Body เลือก raw แล้วเลือกชนิดเป็น JSON จากนั้นพิมพ์ข้อมูลลงไป เช่น

{
  "email": "somchai@example.com",
  "password": "supersecret123"
}

Postman จะตั้ง Header Content-Type: application/json ให้อัตโนมัติเมื่อเลือกชนิดเป็น JSON ซึ่งจำเป็นมาก เพราะฝั่ง Server เราต้องมี Middleware คอยแกะ Body ก้อนนี้ออกมา เรื่องนั้นจะได้เรียนกันในบทที่ 11

เก็บ Request ไว้ใช้ซ้ำด้วย Collection

อย่าปล่อยให้ Request หายไปทุกครั้งที่ปิดโปรแกรม เพราะตลอดคอร์สนี้เราจะยิง Route เดิมซ้ำ ๆ อีกหลายสิบครั้ง

  1. สร้าง Collection ใหม่ ตั้งชื่อว่า Habit Tracker API
  2. กด Save ที่ Request ที่เพิ่งยิงไป แล้วเลือกเก็บลง Collection นี้ ตั้งชื่อให้สื่อความ เช่น GET Health Check
  3. ในหน้าตั้งค่าของ Collection ให้เพิ่ม Variable ชื่อ baseUrl ค่าเป็น http://localhost:3000
  4. กลับมาแก้ URL ของ Request ให้เป็น {{baseUrl}}/health

ประโยชน์ของ Variable คือวันไหนที่เราย้าย Port หรือ Deploy ขึ้น Production ในบทที่ 31 เราแก้ค่าที่เดียวจุดเดียว แล้วทุก Request ใน Collection ก็ชี้ไปที่ใหม่ตามทันที

ขอย้ำคำหนึ่งไว้กันสับสน การใช้ Postman แบบนี้เราเรียกว่า "ลองยิงดู" ไม่ใช่การ Test ที่แท้จริง เพราะมันต้องมีคนนั่งกดเอง Test ตัวจริงที่รันอัตโนมัติได้เราจะเขียนกันด้วย Vitest ในบทที่ 29 ถึง 30

บทถัดไปเราจะกลับมาแก้เลข Port ที่ Hardcode ไว้ใน src/index.ts ให้อ่านค่ามาจาก Environment Variables อย่างถูกวิธี
