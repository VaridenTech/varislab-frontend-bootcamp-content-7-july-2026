แนะนำคอร์สและทัวร์โปรเจกต์ Habit Tracker

ยินดีต้อนรับสู่คอร์ส API Design in Node.js ตลอดคอร์สนี้เราจะสร้าง API ตัวหนึ่งขึ้นมาจากศูนย์ด้วยกัน ชื่อว่า Habit Tracker API เป็น API สำหรับบันทึกและติดตามนิสัยที่เราอยากทำให้ได้ทุกวัน

สิ่งที่คุณจะได้เห็นในบทนี้คือ "ปลายทาง" ก่อน เพื่อให้รู้ว่าเรากำลังเดินไปทางไหน แล้วบทต่อ ๆ ไปเราจะค่อย ๆ สร้างมันขึ้นมาทีละชิ้น

เราจะสร้างอะไร

Habit Tracker API เป็น REST API ที่ทำงานเบื้องหลังได้ครบวงจรจริง ๆ ประกอบด้วย

  • ระบบสมัครสมาชิกและเข้าสู่ระบบ พร้อมออก JSON Web Token (JWT) ให้ Client เก็บไว้ใช้ยืนยันตัวตน
  • Route สำหรับ Habit แบบ CRUD ครบทั้งสร้าง อ่าน แก้ไข และลบ
  • Validation ที่ตรวจข้อมูลขาเข้าและตอบ Error Message ที่อ่านรู้เรื่อง เช่น ถ้าลืมส่ง Field ชื่อ Habit มา API จะตอบว่า Validation failed พร้อมบอกว่าผิดที่ Field ไหน
  • Database จริงบนคลาวด์ พร้อม Script สำหรับ Seed ข้อมูลตัวอย่างเข้าไป
  • Integration Test ที่ยิง Request เข้า Route จริง แล้วตรวจว่า Status Code และข้อมูลที่ตอบกลับถูกต้อง
  • การ Deploy ขึ้น Production ให้คนอื่นเรียกใช้ได้จริง

เราจะไม่สร้างหน้าจอ UI เลย เพราะหัวใจของคอร์สนี้คือฝั่ง Backend ล้วน ๆ เราจะใช้เครื่องมือชื่อ Postman เป็นตัวแทน Client ในการยิง Request เข้ามาทดสอบ (ถ้าเรียนจบแล้วอยากต่อยอด การนำ API ตัวนี้ไปทำ UI ครอบเป็นโปรเจกต์ฝึกมือที่ดีมาก)

เครื่องมือที่เราจะใช้

  • Node.js — Runtime ที่รันโค้ดของเรา คอร์สนี้ใช้ Node.js เวอร์ชัน 23.6.0 ขึ้นไป เพราะเราจะรันไฟล์ TypeScript ตรง ๆ โดยไม่ต้องมีขั้นตอน Build
  • Express 5 — Framework สำหรับสร้าง Server ที่นิยมที่สุดในโลก Node.js
  • TypeScript — ช่วยให้เรารู้ตั้งแต่ตอนเขียนว่าข้อมูลแต่ละก้อนหน้าตาเป็นอย่างไร
  • Zod — ใช้ตรวจสอบ (Validate) ข้อมูลขาเข้าและ Environment Variables
  • Prisma ORM — ตัวกลางที่ให้เราคุยกับ Database ด้วย TypeScript แทนการเขียน SQL ดิบ
  • PostgreSQL บน Neon — Database จริงที่โฮสต์อยู่บนคลาวด์ ไม่ต้องติดตั้งลงเครื่อง
  • JWT และ bcrypt — สำหรับ Authentication และการเก็บ Password อย่างปลอดภัย
  • Vitest และ Supertest — สำหรับเขียน Test
  • Render — บริการที่เราจะใช้ Deploy API ขึ้น Production
  • Postman — GUI สำหรับยิง Request เข้า API ของเรา

สิ่งที่ต้องเตรียมก่อนเริ่ม

  • ติดตั้ง Node.js เวอร์ชัน 23.6.0 ขึ้นไป (ตรวจได้ด้วยคำสั่ง node -v)
  • ติดตั้ง Git และตั้งค่าเรียบร้อย
  • Code Editor สักตัว แนะนำ VS Code
  • ติดตั้ง Postman (เราจะพูดถึงวิธีติดตั้งอย่างละเอียดในบทที่ 4)
  • พอใช้ Terminal ได้ระดับหนึ่ง

ถ้าคุณเคยผ่านคอร์ส Node.js เบื้องต้นมาแล้วก็ถือว่าพร้อมมาก เพราะเราจะต่อยอดจากความเข้าใจเรื่อง Module, npm และ HTTP Server ที่เคยเขียนด้วย Module http ล้วน ๆ

ทัวร์โปรเจกต์ฉบับสมบูรณ์

โครงสร้างของโปรเจกต์เมื่อเราสร้างเสร็จแล้วจะหน้าตาประมาณนี้

habit-tracker-api/
├── env.ts                 # อ่านและตรวจสอบ Environment Variables
├── src/
│   ├── index.ts           # Entry Point — จุดที่สั่งให้ Server เริ่มทำงาน
│   ├── server.ts          # นิยาม Express App ทั้งหมด
│   ├── routes/            # authRoutes.ts, habitRoutes.ts, userRoutes.ts
│   ├── controllers/       # โค้ดที่ทำงานจริงเมื่อมี Request เข้ามาแต่ละ Route
│   ├── middleware/        # auth.ts, validation.ts, errorHandler.ts
│   ├── utils/             # jwt.ts, password.ts
│   └── db/                # connection.ts, seed.ts, types.ts, validation.ts
├── prisma/
│   ├── schema.prisma      # นิยามตารางทั้งหมดของ Database
│   └── migrations/        # ไฟล์ Migration ที่ Prisma สร้างให้
├── tests/                 # Integration Test
├── prisma7.config.ts      # ตั้งค่า Prisma CLI
├── vitest.config.ts       # ตั้งค่า Vitest
├── tsconfig.json          # ตั้งค่า TypeScript
├── .env.example           # ตัวอย่างรายการ Environment Variables ที่ต้องมี
└── package.json

ไม่ต้องตกใจกับจำนวนโฟลเดอร์ เพราะแทบทุกไฟล์ในนี้คุณจะเป็นคนเขียนเองทีละไฟล์ตามลำดับบทเรียน มีเพียงไฟล์ Config ไม่กี่ตัวเท่านั้นที่เตรียมมาให้แล้ว

ข้อควรรู้เรื่อง Repository ตัวอย่าง

โปรเจกต์ตัวอย่างมี Branch main เป็นจุดเริ่มต้นที่ยังว่างเปล่า และมี Branch เฉลยของแต่ละบทให้เทียบโค้ดทีหลังได้

ข้อควรระวังคือ ถ้าคุณ Clone โค้ดฉบับสมบูรณ์มาแล้วสั่งรันทันที มันจะยังทำงานไม่ได้ เพราะโค้ดชุดนั้นต้องการ Database ที่ตั้งค่าไว้แล้วและต้องการ Environment Variables อย่าง DATABASE_URL กับ JWT_SECRET ซึ่งเป็นค่าเฉพาะของแต่ละคน เราจะค่อย ๆ ตั้งค่าพวกนี้กันในบทที่ 5 และบทที่ 18

ทุกครั้งที่คุณ Clone โปรเจกต์ใหม่ หรือดึงโค้ดใหม่มาลง Branch ของตัวเอง ให้รัน npm install เสมอ ติดเป็นนิสัยไว้จะช่วยคุณได้เยอะมาก

ประเด็นสำคัญ

คอร์สนี้ไม่ได้สอนแค่ "เขียน API ให้ทำงานได้" แต่สอนวิธีออกแบบ API ที่ดูแลต่อได้จริง คือแยกหน้าที่ของแต่ละไฟล์ให้ชัด ตรวจข้อมูลก่อนเชื่อ จัดการ Error อย่างเป็นระบบ มี Test คอยการันตี และ Deploy ขึ้นจริงได้

บทถัดไปเราจะถอยกลับมาตั้งหลักกันก่อนว่า Server ในโลกของ Node.js คืออะไรกันแน่ แล้วทำไมเราถึงเลือกใช้ Express
